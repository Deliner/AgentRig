# P155 — base-protection: коммит всегда проходит гейт, а базу меняет только `feature-merge`

## Feature

[B156](../Backlog/156.md): коммит всегда проходит гейт, а базу меняет только `feature-merge`. Выбор — пользователь
2026-11-19: «Со 142 по 168 можешь последовательно делать». Карточка в Git на ревизии `40bd894`, согласование текста
в `577777c`. Границы VAC — за исполнителем.

## User capability

Правила AGENTS.md о хуке и базе выполняются командами, а не держатся только на тексте.

## Acceptance

Карточка **B156 (AC1–AC2)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/base-protection` от master `5a2ae0f`. Решение [D204](../../Decisions/204.md).

- VAC 1 `3203d32`: `write` от `init` и рига запрещает у `git` флаги `--no-verify` и `-n`. Раннер даёт каждому
  процессу каталога переменную `WORKER_CATALOG_ROOT` с каноническим корнем проекта. Охранник `reference-transaction`
  отказывает изменению ветки базы, если переменная называет корень репозитория. `feature-merge` убирает переменную у
  своих процессов Git.
- VAC 2: пин `3203d32` командой `just bootstrap HEAD`, перенос P155 и B156 в архив.

| Критерий | Итог |
| --- | --- |
| AC1 | выполнен: `denied_flags_are_refused_in_every_spelling_their_program_reads` получает отказ хука с причиной «does not run» для `git commit --no-verify`, `--no-ver` и `-qnm`; без новых запретов тест падает на причине. Соседний `git rebase --no-ff` проходит. Живой `just write -- git commit --no-verify -qm probe` получил «write does not run git with --no-verify» |
| AC2 | выполнен: `write_commands_cannot_change_the_base` во временном репозитории запускает через `just run write` команды `branch -f`, `checkout -B`, `switch -C` и `branch -D` для базы с ветки задачи, затем на базе rebase, cherry-pick и коммит при пустом `.git/MERGE_HEAD`; каждая получает отказ с сообщением охранника, база не сдвигается; без метки первая команда сдвигает базу и тест падает. Живой `just write -- git branch -f master HEAD` получил «master changes only through feature-merge», master остался на `5a2ae0f` |

Остаток: rebase и cherry-pick на ветке задачи создают коммиты без pre-commit; всю ветку проверяет гейт
`feature-merge`. Команда каталога, которую определил агент, может убрать переменную; правку `.agentrig` и `.git`
закрывает B157. Флаг `-n` запрещён и там, где он означает пробный запуск, например у `git add`.
