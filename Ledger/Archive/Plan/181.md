# P181 — список сопровождаемых файлов строится один раз и без обхода каталогов там, где нужны только файлы

## Feature

[B188](../Backlog/188.md): список сопровождаемых файлов строится один раз и без обхода каталогов там, где нужны только
файлы. Выбор — пользователь 2026-11-21: «Сам заведи карточку и аппрувни ее, мне показывать не надо». Карточка в Git в
первом VAC ветки `feature/file-listing` от master `e7ad50e`. Границы VAC — за исполнителем.

## User capability

Проверка памяти в каждом гейте, список файлов гейта и lint запускают меньше процессов Git и идут быстрее.

## Acceptance

Карточка **B188 (AC1–AC3)** — критерии и формулировки там; идентификаторы те же.

## Delivery

- Ветка `feature/file-listing` от master `e7ad50e`, автономно по поручению пользователя. Ветка сливается без пина,
  пин ставит пользователь командой `! just approve`.
- VAC 1 `b7d4260`: карточка B188 сохранена и выбрана.
- VAC 2 `d130870`: построение списка в `Project/structural_lint/targeting/file_discovery/versioned.rs` разделено на
  два. `maintained_files` возвращает только файлы и запускает один `git ls-files`. `maintained_inventory` строит
  прежний перечень файлов и каталогов для lint и его отчётов. Отбор файлов у них общий. Проверка памяти строит список
  один раз и передаёт его проверке ссылок на решения и проверке исключений. Список файлов гейта и проверка архитектуры
  берут список без обхода каталогов. Чтение идентификаторов инвариантов вынесено в `invariant_ids`, чтобы функция
  `references` осталась в пределах 40 строк.
- Список теперь строится перед проверкой ссылок, а раньше строился внутри неё после чтения таблицы инвариантов.
  Тексты ошибок те же. Порядок отличается в одном случае: если в одном вызове сломана таблица инвариантов и не
  строится сам список, первой будет ошибка списка.
