# P004

## Feature

P004: Composable AgentRig environments.

## User capability

Use a ready AgentRig binary to configure, inspect and prepare a project interactively or from reusable YAML packages; create isolated delegates from the same environment declarations and explicitly migrate an existing worker installation.

## Acceptance

- AgentRig configuration uses strict YAML exclusively, including lint, review and delegation. Invalid types, unknown or duplicate keys, unsupported composition syntax and incompatible capabilities are actionable errors. Old TOML is accepted only by explicit migration, never a runtime fallback; external tool formats and machine protocols remain their own contracts.
- Local configuration/resource packages can be reused across independent projects and delegate profiles. Stable identities, explicit overrides, resource-relative paths, project-relative selectors, cycle/conflict validation and fixed versions/digests produce an inspectable deterministic configuration with value provenance.
- One existing setup mechanism prepares project and delegate resources. An external root configuration can target a selected project and service directory; preview reports changes before application. Repeated setup preserves custom resources and memory. Interactive init writes the same editable declaration and uses the same setup as noninteractive execution.
- Delegates receive selected custom skills, hooks, programs and MCP settings inside their allowed sandbox. Supported hooks actually execute; unsupported hooks are rejected. Mandatory runner controls remain authoritative. Read, artifact and code modes retain verified results, ownership, cancellation, recovery and concurrent isolation.
- Ready agentrig and standalone agentrig-lint executables use the existing shared core. A real discipline-worker 0.2.0 installation can explicitly migrate to AgentRig with reviewed conflicts and recoverable apply/rollback, preserving user settings and memory without parallel legacy commands or configuration fallback.
- Independent consumers verify shared packages with different overrides, discovery, setup, interactive equivalence, migration/recovery and all delegate modes. Current documentation, schemas, skills, generated resources and actual capabilities agree. Full configured gates and feature integration pass.
