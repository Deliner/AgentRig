# P178 — хук ссылок Git отвечает быстрее

## Feature

[B185](../Backlog/185.md): хук ссылок Git отвечает быстрее. Выбор — пользователь 2026-11-21: «Сам заведи карточку и
аппрувни ее, мне показывать не надо». Карточка в Git в первом VAC ветки `feature/faster-hooks` от master `a556dd6`.
Границы VAC — за исполнителем.

## User capability

Переключение ветки, коммит и слияние тратят меньше времени на хук ссылок, а гейт и слияние заканчиваются раньше.

## Acceptance

Карточка **B185 (AC1–AC3)** — критерии и формулировки там; идентификаторы те же.

## Delivery

- Ветка `feature/faster-hooks` от master `a556dd6`, автономно по поручению пользователя. Ветка сливается без пина,
  пин ставит пользователь командой `! just approve`.
- VAC 1 `b0ddbe6`: карточка B185 сохранена и выбрана.
- VAC 2 `1949bd6`: `guard-reference` стал отдельной командой диспетчера, как `guard-commit`. Фаза `prepared`
  загружает конфигурацию и проверяет обновления ссылок как прежде; другие фазы отвечают кодом 0 до загрузки. Git
  не читает код выхода хука в фазах кроме `prepared`, поэтому решение об отказе не меняется.

Замеры на одной машине, до — master `a556dd6`, после — голова ветки:

| Замер | До | После |
| --- | --- | --- |
| вызов `guard-reference committed` в тестовом проекте, среднее из 30, мс | 10,0 | 2,1 |
| вызов `guard-reference prepared`, среднее из 30, мс | 10,5 | 10,2 |
| `git switch` с хуками в тестовом проекте, среднее из 60, мс | 213 | 165 |
| процессы хука ссылок за прогон тестов, вызовов | 1568 | 1568 |
| время процессов хука ссылок за прогон, с | 32,7 | 12,7 |
| время всех процессов рига за прогон, с | 435,8 | 387,5 |

Из 1568 вызовов хука после правки 631 приходятся на фазу `prepared`, 12,5 с, а 619 `committed` и 318 `aborted`
вместе занимают 0,2 с. Полный прогон 614 тестов на ветке занял 75,7, 77,7 и 77,1 с, на master под той же нагрузкой
79,5 с; более ранний замер master 73,4 с снят при меньшей нагрузке машины, поэтому сравнение идёт с прогоном того же
часа.
