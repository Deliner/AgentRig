# P031 — Тестовая дисциплина

## Feature

[B022](../Backlog/022.md): тестовая дисциплина как durable-policy — размещение теста
по области поведения, тестирование только через публичную поверхность, проверка
поведения, а не внутреннего состояния, с enforcement статически проверяемых пунктов
и навыком-нормой для остального. Исходный контракт — ревизия этой карточки в Git
(2d4ca6f); согласовано и выбрано на исполнение пользователем 2026-10-28.

## User capability

Тесты переживают рефакторинг, давление тестов не течёт в публичный API продукта, а
место теста выводится из области поведения — и это проверяется у потребителя из
коробки, а не держится в голове.

## Acceptance

Карточка **B022 / TC1–TC7**, включая её границы и неизвестное. Статически проверяемые
пункты (кандидаты TC1/TC2) становятся правилом линтера/инвариантом и уезжают в
поставку `init`; осуществимость каждого подтверждается на этапе реализации, иначе
пункт остаётся нормой с явной записью причины — без «притворного» инварианта
(norm-or-choice). Непроверяемое (TC3, во многом TC4) — навык-норма, отданная
потребителю наравне с существующими навыками. Уровень реализации и границы VAC
выбирает исполнитель.

## Delivery

Выполнено на ветке feature/test-discipline двумя VAC (d208b78, 75d3a81); контракт —
ревизия B022 в 2d4ca6f. Статус: complete.

Дисциплина доставлена навыком-нормой `testing-discipline` (Project/shared/skills),
отданным потребителю через project_setup/assets.rs (SKILLS + поставленные инструкции)
и обязательным в репозитории (AGENTS.md: «When a VAC adds or changes tests, apply
testing-discipline…»). Политика — решение D054 (отдать навыком, статически проверяемое
становится правилом). Оба статических кандидата проверены на осуществимость при
реализации и отклонены, поэтому правил линтера, видов правил, инвариантов и оракулов
не добавлено; набор видов правил стража I020 не изменился.

- TC1 — размещение по области: норма (пункт 1 навыка). Кандидат на правило отклонён
  (D055): движок видит лишь факт импорта, но не то, является ли зависимость предметом
  проверки или попутной общей ссылкой; пример — structural_lint/languages/tests/mod.rs
  использует общий тип structural_lint/rules/kind.rs, хотя проверяет languages. Правило
  «зависимость теста вне поддерева владельца» дало бы ложные срабатывания на общей
  оснастке (`tests`/`testing`) и словаре.
- TC2 — только публичная поверхность: норма (пункт 2). Статически нереализуемо (D054):
  нет извлечения видимости и обратного индекса ссылок, которые отличили бы `pub`,
  используемый только тестами.
- TC3 — поведение, а не состояние: норма (пункт 3); механически не детектируется.
- TC4 — без чёрных ходов: норма (пункт 4); тот же пробел возможностей, что у TC2.
- TC5 — имя по поведению: норма (пункт 5).
- TC6 — без дублей через нижний уровень: норма (пункт 6).
- TC7 — enforcement и докфудинг: принцип разделения зафиксирован D054; при реализации
  оба кандидата (TC1, TC2) отклонены с записью причины (D054/D055) — норма без
  «притворного» инварианта. Навык отдан потребителю и обязателен при приёмке; страж
  докфудинга I020 считает навык и в поставке `init`, и в репозитории (18/18).

Границы совпали с карточкой: Rust-осуществимость TC2 подтверждалась при реализации и
отклонена; Python TC2/TC4 и TC3 были нормой изначально. Проверка: оба VAC прошли
коммит-гейт (build, lint, memory, rustfmt, clippy, rust-test, ruff/ruff-format/mypy,
pytest, typos, vulture); memory-check зелёный после переноса карточек в Archive.
