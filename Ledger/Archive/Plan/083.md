# P083 — impact-coverage: config-check находит пути вне карты влияния

## Feature

[B077](../Backlog/077.md): `config-check` сообщает исходные файлы, которые совпадают только с группами карты
`affected` без целей, и тесты, которые не выбирает ни одна группа; карта AgentRig исправлена. Источник — карточка
B077 (ревизия в Git `e90d81a`); выбор и авторизация — пользователь 2026-11-07. Порядок и границы VAC — за
исполнителем.

## User capability

Новый каталог или тест без записи в карте влияния виден в `config-check` до коммита.

## Acceptance

Карточка **B077 (AC1–AC3, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/impact-coverage` (база master `f10cb30`), один VAC: модуль `project_setup/coverage.rs` у владельца
`config-check`, тесты, README гейта и установки, ремонт карты, решение D124, Delivery, ротация P083/B077. Первый
вариант рядом с выбором целей в `change_delivery/gate` отвергнут линтом: чтение файлов сделало бы гейт 21-м
зависимым `shared/fs` при бюджете 20, а `project_setup` уже читает через него. Сопоставление путей с группами
осталось у гейта: `selection.rs` даёт тип `AffectedMap`, которым пользуются и выбор целей, и новая проверка; своя
копия глобов в `project_setup` дублировала бы его и превышала бюджет `shared/paths`, 14 при 13.

- Выбор при доставке. Какие файлы обязаны выбирать тесты, определяет язык команды проверки: элемент argv `pytest`
  даёт Python и файлы `.py`, `cargo` с последующим `test` — Rust и файлы `.rs`; другие команды не проверяются. Явное
  поле в карте отвергнуто: оно повторяло бы то, что уже говорит команда, а обязательное поле сломало бы строгую
  загрузку конфигураций потребителей. Файл вне всех групп не находка: для него гейт и так запускает команду целиком.
  Модуль Rust-файла считается от ближайшего предка с `lib.rs`, иначе с `main.rs`; файл вне такого крейта не
  оценивается.
- AC1 выполнен: случаи `rust-silent-source` и `python-silent-source` теста
  `test_config_check_reports_paths_the_affected_map_leaves_untested` — файл только под группой без целей даёт
  `ERROR [tests] <путь>` с навыком, подсказкой `::` или `.` и повтором `config-check`, код 1.
- AC2 выполнен: случай `python-sibling-unselected` — цель называет один файл, соседний тест в подкаталоге найден,
  как в 36b7823; `rust-unselected-test` — модуль с `#[test]` вне префиксов целей. Не находки: каталог, узлы
  `файл::тест`, цели от рабочего каталога команды, имя теста внутри модуля, файл вне групп, команда `make`. Тест — 11
  passed.
- AC3 выполнен: на исходной карте `just candidate config-check` дал ровно три находки — `Project/shared/console/mod.rs`
  и `Project/shared/mod.rs` в `rust-test` и пример `Project/shared/testing/examples/python/application/test_sample.py`
  в `test`, который полный прогон pytest собирает. Первые два сопоставлены с `::`, пример добавлен в цели группы
  `Project/shared/testing/**`; после ремонта `config-check` чист: «Scaffold configuration is valid». Решение
  [D124](../../Decisions/124.md).
- Гейт коммита `f2b4962`: все проверки PASS, rust-test 151 и test 224 passed. Пин D051 — `stable.txt` =
  `f2b4962`, `just bootstrap` прошёл.
