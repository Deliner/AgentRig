# P049 — Эволюция API/данных: glob-импорт не тянет всю растущую поверхность чужого модуля (Rust/Python)

## Feature

[B040](../Backlog/040.md): новое правило `wildcard-import` сообщает о glob/wildcard-импорте без
ссылки-обоснования на строке прямо выше — Rust `use …::*` вне тестового кода и Python `from … import *`.
Кластер C10 Набора II (agent-native, переносимо на любое приложение) — следующий после C5. Исходный
контракт — ревизия карточки B040 в Git; согласовано пользователем 2026-10-31 в составе набора C1–C10.

## User capability

Проект получает из коробки защиту поверхности импортов от молчаливой эволюции API: glob-импорт,
привязывающий файл ко всей растущей публичной поверхности чужого модуля, — находка до коммита. Агент
сужает его до явного списка имён либо обосновывает ссылкой `DECISION:`/`INVARIANT:` на строке прямо выше
(прелюдии, сознательный ре-экспорт). Тестовый код не затрагивается. Так неявная связь с чужим API
ловится так же, как паник-путь или выключенный тест.

## Acceptance

Карточка **B040 (AC1–AC3)**, включая границы. AC1: Rust `use …::*` (узел `use_wildcard`, верхнего
уровня или внутри группы) вне тестов без ссылки прямо выше — находка error; со ссылкой — нет; тесты
исключены `in_test_context` + exclude живого правила. AC2: Python `from … import *` (узел
`wildcard_import` в `import_from_statement`) без ссылки прямо выше — находка error; со ссылкой — нет.
AC3: новый вид правила `wildcard-import` в `catalog::ALL` + новый навык `narrow-import`; и виды правил,
и навыки растут на один (I020 сбалансирован); наш код зелёный. Границы: только glob/wildcard-импорты;
escape — ссылка-обоснование и исключение тестов. Исчерпываемость `match`/wildcard-рука, `#[non_exhaustive]`,
версионирование serde/схем — норма (высокий FP / нерелевантно бинарному крейту / исчерпываемость enum
стережёт компилятор). Притворного инварианта нет.
