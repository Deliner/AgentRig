# P165 — parallel-index: индекс из одного массива не читает другой массив

## Feature

[B168](../Backlog/168.md): индекс из одного массива не читает другой массив. Выбор — пользователь 2026-11-19: «Со 142
по 168 можешь последовательно делать». Карточка в Git на ревизии `065fe89`. Границы VAC — за исполнителем.

## User capability

Связанные значения меняются в одном месте и не расходятся по позициям.

## Acceptance

Карточка **B168 (AC1)** — критерии и формулировки там; идентификаторы те же.

## Delivery

- VAC 3: пин `0d9d481` командой `just bootstrap HEAD`, перенос P165 и B168 в архив.

| Критерий | Итог |
| --- | --- |
| AC1 | выполнен: индекс из `.position(..)` по одной коллекции, прочитанный из другой через `[]`, `.get(..)` или `.get_mut(..)`, даёт ошибку lint `parallel-index`. Тест `rust_flags_an_index_found_in_one_collection_and_read_from_another` находит пример ревью `[MOVEMENT, JUMP, LOOK][role]` после `if let Some(role) = role`, параметр замыкания, прямой индекс, `let .. else` и `if let`; та же коллекция, `skip`, свой метод `position`, `swap`, строка со ссылкой и тестовый модуль не сообщаются. Навык велит держать прямоугольник и роль в одной записи |

В коде рига мест нет. В voxel-rust чтение мест `.position(` даёт пример ревью и ещё три пары параллельных списков:
`layouts.rs:68`, `executor.rs:65` и `section.rs:219`. Остаток: переименование при перепривязке, `match` по
результату, диапазон и арифметика в индексе, свой метод `position` и адаптеры итератора правило не видит; псевдоним
той же коллекции с другим текстом сообщается.
