# P156 — enforcement-files: агент не выключает и не ослабляет механизмы контроля

## Feature

[B157](../Backlog/157.md): агент не выключает и не ослабляет механизмы контроля. Выбор — пользователь 2026-11-19:
«Со 142 по 168 можешь последовательно делать». Карточка в Git на ревизии `40bd894`, согласование текста в `577777c`.
Открытые вопросы карточки о задуманном изменении решает пользователь. Границы VAC — за исполнителем.

## User capability

Проверки рига нельзя выключить или ослабить изнутри сессии агента.

## Acceptance

Карточка **B157 (AC1–AC3, неизвестное)** — критерии и формулировки там; идентификаторы те же.

## Delivery

- **Пауза до начала поставки, ветки нет.** Неизвестное карточки решает пользователь: как вносится задуманное изменение
  файлов контроля и какие части `.agentrig` агент меняет сам. Пользователю 2026-11-19 предложены варианты: файлы
  контроля меняет только пользователь; агент готовит правку, а пользователь подтверждает её командой `! just approve`,
  это рекомендовано. К началу P156 ответа нет, поэтому по выбору пользователя P156 и P157 стоят на паузе.
- **Условие продолжения:** ответ пользователя о способе изменения. Затем ветка от master и поставка AC1–AC3.
- Пользователь 2026-11-19 ответил «B 1»: агент готовит изменение механизма контроля, пользователь подтверждает его
  командой `! just approve`, гейт принимает только подтверждённые изменения. Пауза снята, ветка
  `feature/enforcement-files` от master `f06c9bc`. Решение [D213](../../Decisions/213.md).
- VAC 1 `26b6b72`: защищённый набор строится вместе с конфигурацией. Хук агента отказывает правке и операнду
  `just write`, которые касаются набора; у Git проверяются только операнды `rm`, `mv`, `restore` и `checkout`, чтобы
  подтверждённые файлы можно было закоммитить. Отказ называет пути и абсолютный путь навыка `propose-protected-change`.
- VAC 2 `f699fc2`: `just approve` применяет предложение из `proposal/` в каталоге среды, при неверной конфигурации
  возвращает прежние файлы и записывает подтверждённое содержимое в `approved`; агенту хук эту команду не даёт. Гейт
  коммита на ветке задачи отклоняет неподтверждённое содержимое защищённых путей и пин, ревизия которого не потомок
  закреплённой; `bootstrap.sh` так же отказывает такой ревизии. `init` подтверждает защищённые файлы, которые пишет.
- VAC 3 `a3e80b5`: недоступное или испорченное состояние маршрутов больше не превращает обязательные маршруты в
  подсказки.
- Пин `d61536e`. Пользователь выполнил `just approve` для `hooks.protected: [tooling/worker,
  tooling/distribution/bootstrap.sh, .cache/development]` и `git.pin: tooling/distribution/stable.txt`; коммит
  `e8ac7dd` прошёл гейт, 580 тестов. Пин `db743e7` гейт принял как потомка прежнего.

Неизвестное карточки решено так. Задуманное изменение готовит агент в `proposal/`, подтверждает пользователь
командой `just approve`. Агент сам не меняет модули `project.yaml`, `git.yaml`, `commands.yaml` и `hooks.yaml`, поэтому
команда каталога тоже идёт через подтверждение; остальные модули `.agentrig` он меняет сам, их ослабление закрывает
B158. Остаток описан в последствиях D213: тесты и `just candidate` исполняют код проекта, команды Git вроде `switch`
или `rebase` могут принести другие файлы контроля.
