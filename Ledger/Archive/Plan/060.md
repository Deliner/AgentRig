# P060 — tuple-as-record внутри обобщённого типа

## Feature

[B054](../Backlog/054.md): расширение правила `tuple-as-record` ([D088](../../Decisions/088.md)) на
кортеж из трёх и более элементов с хотя бы одним примитивом/`String`/`&str` внутри обобщённого
типа (на любой глубине, в том числе под ссылкой) в позиции параметра или возврата. Источник —
исследовательская дуга (`coverage-map.md` шаг 4, решение пользователя 2026-11-02 п. 2); реализация
авторизована пользователем 2026-11-04 (/goal). Исходный контракт — ревизия карточки B054 в Git.
Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: безымянная запись в `Vec<(String, u64, bool)>`/`Option<(…)>`/
`&[(…)]` в сигнатуре — находка; пары, кортежи без примитивов, псевдонимы и поля структур не
трогаются; форма D088 для верхнеуровневого кортежа не меняется. Навык `name-the-record`
дополняется.

## Acceptance

Карточка **B054 (AC1, границы)**.
- **AC1** — `tuple_type` внутри `generic_type` в параметре/возврате, ≥3 элементов, ≥1 примитив,
  без обоснования над объявлением → находка; два элемента, без примитивов, `type`-псевдоним, поле
  структуры — нет.

Изменение существующего детектора без изменения `lint.yaml` → ожидается только финальный пин
([D051](../../Decisions/051.md)); decision, расширяющий D088, при доставке; догфуд
`just candidate lint` → 0 находок (в продакшн-сигнатурах таких кортежей нет); живая проба. Пороги
не ослабляются.

## Delivery

Ветка `feature/tuple-as-record-ext` (база master `a2dc929`). Один VAC: `record_signature` в `languages/rust.rs`
теперь вызывается для `function_item`, `function_signature_item` и `closure_expression`; `annotations` собирает типы
параметров и возврата, `nested_record`/`contained_record` ищут `tuple_type` под контейнером `generic_type`/`array_type`
на любой глубине, `unnamed_record` — не меньше трёх именованных детей и хотя бы один `scalar` (`primitive_type`,
`String`, ссылка на примитив); верхнеуровневая форма D088 по-прежнему только для именованных функций; исключения
`justified`/`in_test_context` прежние; [D101](../../Decisions/101.md). Дескриптор и навык `signature/name-the-record`
описывают вложенную форму. Тесты `tuple-as-record` (помощник D088, прежний тест и новый) вынесены в
`languages/tests/tuple_as_record.rs` — находка `file-size` 511 > 500 в `markers.rs` после добавления теста (ссылки
`tests` в строках D088/D101 мигрировали). Наблюдаемая верификация 2026-11-04 на рабочем дереве: `cargo fmt --check`
OK, `cargo clippy --all-targets -D warnings` OK, `cargo test --lib` — 121 passed (AC1: находки строк 1, 6, 7 и 14
фикстуры — `Vec<(String, u64, bool)>` в возврате, `&[(String, u64, bool)]`, `Option<&mut Vec<(u8, u8, u8)>>`,
замыкание с `Vec<(&str, usize, char)>`; не-находки — строка с DECISION выше, пара `Vec<(String, u64)>`,
`Vec<(PathBuf, Config, Rules)>`, голая `&(String, u64, bool)`, псевдоним `type`, поле структуры, тестовый модуль);
догфуд `tooling/worker/run run candidate -- lint` — 0 находок (exit 0); `lint-rule tuple-as-record` (кандидат)
описывает расширенную метрику (file, навык `name-the-record`, Rust); живая проба —
`fn probe(rows: Vec<(String, u64, bool)>) {}` в `shared/vcs/git.rs` даёт `ERROR [tuple-as-record] … git.rs:247
