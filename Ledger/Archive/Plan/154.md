# P154 — write-sandbox: программы `just read` и `just write` не выходят за пределы проекта

## Feature

[B155](../Backlog/155.md): программы `just read` и `just write` не выходят за пределы проекта. Выбор — пользователь
2026-11-19: «Со 142 по 168 можешь последовательно делать». Карточка в Git на ревизии `40bd894`, согласование текста
в `577777c`. Границы VAC — за исполнителем.

## User capability

Команда агента ничего не меняет вне проекта и не запускает процессы мимо песочницы.

## Acceptance

Карточка **B155 (AC1–AC2, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/write-sandbox` от master `4e231ff`. Решение [D203](../../Decisions/203.md).

- VAC 1 `cb7faef`: поле `access` со значениями `read-only`, `project` и `unconfined` заменило `read_only` в командах
  и записях заданий. Запуск `project` идёт в песочнице платформы, которая пишет ещё и корень проекта; песочница macOS
  отказывает `lsopen` и `appleevent-send`. Программа каталога может задать свой `access`. `write` от `init` получает
  `project`, а его `git` получает `unconfined`, потому что хуки Git запускают гейт, чьи инструменты пишут кэш вне
  проекта. Пока установленный runtime не читал `access`, кандидат принимал и прежний `read_only`, а старая форма
  `write` рига была записана как отличие рига.
- VAC 2 `86773b7`: пин `cb7faef` командой `just bootstrap HEAD`; `read` рига получил `read-only`, `write` получил
  `project`, его `git` получил `unconfined`; команды больше не принимают `read_only` и булево `access`; отличие рига
  удалено.
- VAC 3: пин `86773b7` командой `just bootstrap HEAD`, перенос P154 и B155 в архив.

| Критерий | Итог |
| --- | --- |
| AC1 | выполнен: `write_programs_change_only_the_project` в проекте после `init` запускает `just run write -- cp note ПУТЬ` с путём вне проекта; команда завершается с ошибкой, называет путь, файл не появляется; если `write` без песочницы, тест падает. `write_runs_git_and_its_hooks_outside_the_sandbox`: `git commit` через `write` запускает хук, который пишет вне проекта; если `git` в песочнице, тест падает. Живой `just write -- cp Ledger/State.md` в домашний каталог получил «Operation not permitted», файл не появился; коммит VAC 2 через `just write -- git commit` прошёл полный гейт из хука |
| AC2 | выполнен: `read_commands_cannot_start_a_program_outside_the_sandbox` на macOS собирает приложение-пробу и запускает его из `just run read` через `open -g -j -n` и `osascript … launch`; файл-метка не появляется за 3 секунды; без `(deny lsopen)` тест падает |
| Границы | соблюдены: Git внутри `just write` пишет в `.git` как раньше и запускает хуки вне песочницы |

Остаток: тест не отправляет Apple Event уже запущенному приложению, для этого нужно согласие пользователя на
Automation, поэтому запрет `appleevent-send` стоит в профиле без отдельной проверки. Вариант для Linux ждёт запуска на
Linux (B112). Git и его хуки работают без песочницы; правку настроек `.git` закрывает B157.
