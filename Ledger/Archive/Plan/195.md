# P195 — линтер не судит сигнатуру, которую задаёт чужой код

## Feature

[B202](../Backlog/202.md): линтер не судит сигнатуру, которую задаёт чужой код. Выбор — пользователь 2026-11-21,
после показа карточки целиком: «сохрани и сделай». Карточка в Git в первом VAC ветки `feature/foreign-signatures` от
master `0587ad2`. Границы VAC — за исполнителем.

## User capability

Проект под ригом может реализовать любой чужой интерфейс, переопределить метод чужого класса и объявить внешнюю
функцию без обходных путей. Свои интерфейсы проекта остаются под всеми правилами.

## Acceptance

Карточка **B202 (AC1–AC10)** — критерии и формулировки там; идентификаторы те же.

## Delivery

- Ветка `feature/foreign-signatures` от master `0587ad2`, решение [D229](../../Decisions/229.md).
- VAC 1 `94b8c2a`: карточка B202 сохранена и выбрана.
- VAC 2 `aab7dae`, Rust: новый `Project/structural_lint/languages/rust/exemptions/foreign_trait.rs` находит, где
  объявлен трейт реализации. Он идёт по пути трейта и импортам файла и блоков: списки, псевдонимы, `self`, путь от
  `::`, вложенный блок, не больше 8 шагов. Трейт чужой, если путь ведёт к крейту из `external.rust` архитектуры (по
  умолчанию `std`, `core`, `alloc`) или к трейту стандартной прелюдии. Трейт, объявленный в проекте, импорт через `*`
  и неразрешённое имя считаются своими. Функции блока `extern` чужие всегда. `rust/mod.rs` и `tuple_record.rs` не
  мерят у чужих сигнатур три правила. Анализ получает взгляд на проект через `Context`, ответ даёт
  `rule_evaluation/foreign_code.rs`. Гейт: 545 тестов.
- VAC 3 `64c9ec6`, Python: новый `Project/structural_lint/languages/python_override.rs` смотрит метод класса уровня
  модуля с декоратором, который ведёт к `typing.override`. Каждая база должна дойти до чужого класса: модуль из
  `external.python`, встроенное имя или класс без баз. По пути проходят класс того же файла и класс модуля проекта.
  Модуль проекта читается через резолвер Python правила архитектуры, который `architecture/mod.rs` теперь отдаёт
  наружу. Объявленное в классе проекта имя, импорт через `*`, неразрешённый модуль, вызов в списке баз или больше 8
  шагов — метод судится. `python.rs` не мерит у такого метода `parameter-count` и `boolean-parameter`. Гейт: 551 тест.
- Тесты: `languages/tests/signature/foreign_signature.rs` (5, Rust), `languages/tests/signature/python_override.rs`
  (5, Python), два теста `rule_evaluation/tests/mod.rs` через `evaluate` с настоящей конфигурацией и резолвером.
- Проверка сценария: `just candidate lint` на черновом проекте с `parameter-count` (ошибка выше 4), `boolean-parameter`,
  `tuple-as-record` и `external` `rust: [std, core, alloc, rustls]`, `python: [logging, typing]`. Без находок прошли
  `ServerCertVerifier::verify_server_cert` с 5 параметрами, `Iterator::size_hint` с кортежем и
  `logging.Logger.makeRecord` с 10 параметрами и `@override`. Контрольные свои функции `own` в обоих файлах получили
  находки всех трёх правил.
- Пин: `just propose-pin HEAD` подготовил пин `64c9ec6`; согласие пользователя не действует, пин ставит пользователь
  командой `! just approve`.
- Пределы: псевдоним `extern crate` не прослеживается, и метод судится. Метод вложенного класса Python судится.
  `override` признаётся только из `typing`.
