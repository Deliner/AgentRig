# P145 — read-only-sandbox: команды для чтения работают в песочнице без записи

## Feature

[B146](../Backlog/146.md): команды для чтения работают в песочнице без записи. Выбор — пользователь 2026-11-19: «Со
142 по 168 можешь последовательно делать». Карточка в Git на ревизии `564868f`. Границы VAC — за исполнителем.

## User capability

Агент в песочнице без записи читает файлы, навыки и проверки через команды рига и может выполнять его правила.

## Acceptance

Карточка **B146 (AC1, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/read-only-sandbox` от master `de8cb13`. Решение [D193](../../Decisions/193.md).

Проба до правки: в песочнице без записи `lint`, `config-check` и `resume` уже работали, а `read` падал на каталоге
журнала. Следом мешали бы ещё два места: macOS не применяет вложенную песочницу (`sandbox_apply: Operation not
permitted`), а временный каталог песочницы рига создать нельзя.

- VAC 1 `2732ea1`: если каталог журнала создать нельзя, команда для чтения пробует временный файл в своём рабочем
  каталоге и только при отказе по правам или по файловой системе только для чтения идёт прямо в этой среде, без
  песочницы рига и журнала. Любой другой исход возвращает прежнюю ошибку. Тесты
  `read_commands_run_inside_an_environment_that_refuses_writes` и
  `read_commands_without_a_run_log_in_a_writable_directory_are_refused`.
- VAC 2: пин `2732ea1` по D051 с `just bootstrap` и перенос P145 и B146 в архив.

| Критерий | Итог |
| --- | --- |
| AC1 | выполнен: Codex 0.170 с `-s read-only` и моделью `gpt-6.1-sol` в пустом проекте после `init` кандидатом выполнил `just read -- head -n 5 AGENTS.md`, `just lint`, `just config-check` и `just resume`, каждая вернула 0 и напечатала результат; тест `read_commands_run_inside_an_environment_that_refuses_writes` читает файл через `run read` внутри песочницы платформы без записи, а без правки падает с ошибкой каталога журнала |
| Границы | соблюдены: в той же сессии Codex `just write -- touch probe.txt` вернул 127, файла нет; тест видит отказ записывающей команды и неизменный файл после попытки записи через `read`; вне такой среды журнал прежний, тест `read_commands_without_a_run_log_in_a_writable_directory_are_refused` видит отказ без журнала в каталоге, доступном для записи |
