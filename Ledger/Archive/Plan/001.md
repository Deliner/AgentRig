# P001 — Isolated review MCP

## Feature

Provide a configurable MCP service that evaluates an exact project revision with multiple independent reviewer roles.

## User capability

The user can select the project revision, review boundary, visible project files, reviewer models, and reviewer instructions, then receive one report containing every role's verdict and evidence.

## Acceptance

Configurable MCP tools and shared CLI/Just runner select arbitrary reviewer definitions, models, efforts, prompts and project resources resolved relative to their configuration. Linux bubblewrap exposes only approved candidate tracked files, review inputs, validator/hook runtime and each critic's own work directory. Resolve full Git hashes; reject out-of-scope changes including deletions and renames before any model call. Do not expose live checkout, .git, whole user home, runner sources or other reviewers.

An explicit machine contract assigns requirements and N/A policy. One validator verifies regular bounded JSON files, schema, run/candidate/digest/role identity, exact assigned IDs, status evidence/fixes and verdict consistency. Verify installed Codex blocking Stop hooks before the main workflow; if unavailable, separately select the bounded runner correction loop. Timeout or exhausted formatting attempts are technical failures, never PASS. Critics cannot modify validator, hook or attempt counter. Prove isolated config, skills/hooks and authentication with a real CLI smoke test.

Aggregate deterministically: only successful valid reviewer results satisfying all mandatory checks may PASS. Preserve nonblocking observations. Re-review keeps original base, includes changes since the previous candidate and old findings, explicitly defines carry-forward of closed checks, and requires contract identity, a late-finding marker and omission explanation for newly blocking findings in unchanged scope.

Every run gets a unique package-local runtime directory. Preserve JSON/Markdown reports containing revisions, selected tool, visible-file hashes, contracts/configuration/prompts/schema versions, models/efforts, exact responses, verdicts, technical failures and attempt counts. Save a failure report on error. Remove temporary work after reporting and separately report cleanup failure. Test long calls through a real MCP client; use run IDs and result retrieval only if its timeout requires that interface. Provide a small project skill adapter. The service does not repair projects, mutate ledger or accept workflow stages.

## Delivery

Delivered the user's configurable Linux review service as the review library (now under tooling/worker/review) on feature/review-mcp. CLI, Just and dynamically listed MCP tools use the same runner. Supplied configuration, machine contracts, prompts, response/argument schemas and a validated short project skill adapter support configuration-based project adoption.

Twenty-one Rust behavioral tests pass: configuration-relative resources and invalid contracts; response identity/schema/exact coverage/N/A/failure semantics and unsafe files; real-Git snapshot visibility, deletions and renames; actual bubblewrap permissions and overlapping parallel critics; timeout/format exhaustion; persisted pre-model failures and emergency report retention; original-base repair diff, late FAIL/BLOCKED findings, separate cleanup errors; MCP discovery and argument rejection. The prior execution and MCP VACs each passed the complete staged gate, including the 208 existing worker tests. The final acceptance VAC must pass its normal commit gate and feature-merge before integration is complete.

Installed Codex 0.153.4 blocking Stop continuation was verified before the main runner. Official Python MCP SDK 1.29.1 completed real gpt-5.6-luna/high calls in 69 and 96 seconds and received a technical timeout report after 120 seconds. The final smoke verified isolated authentication/configuration and absent host skills/hooks/home/.git/siblings, retained exact response/diagnostics, and removed runtime. COMPATIBILITY.md records evidence and distinguishes model probes from deterministic permission tests. The tested client supports long calls when configured above the runner deadline, so no background job API is required.

All assigned requirements are rechecked on each repeated review; closed statuses are never carried forward. Source documents supplement the explicit machine contract. Reports preserve versions/digests and exact answers, while the service leaves project files and workflow memory untouched. Linux/bubblewrap is the supported platform; allowlist credential checks do not claim universal secret detection.
