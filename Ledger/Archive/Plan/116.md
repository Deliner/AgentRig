# P116 — gate-rebuild: проверка перед коммитом не пересобирает лишнее

## Feature

[B110](../Backlog/110.md): проверка перед коммитом не пересобирает лишнее. Источник — карточка B110 в коммите её
сохранения на ветке `feature/rust-tests`; выбор и авторизация — пользователь 2026-11-11, сразу после P115. Порядок и
границы VAC — за исполнителем.

## User capability

Коммит заметок снова проверяется быстро, а проверка не теряет точности.

## Acceptance

Карточка **B110 (AC1–AC2)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/gate-rebuild` от master `40131e1`. VAC 1 `2bf6c43`, решение [D160](../../Decisions/160.md): файл с
неизменённым объектом Git получает в выгрузке прежнее время изменения, а команды собирают в отдельную цель
`<runtime>/staged/target`. VAC 2 `f18031e`, решение [D161](../../Decisions/161.md): выгрузка лежит по временному пути,
который повторяется от прогона к прогону, и прежние времена действуют только на этом пути. Лаунчеры и помощник тестов
читают `CARGO_TARGET_DIR` вместо `WORKER_TARGET_DIR`.

### Найдено при поставке

После VAC 1 программа, которая читает `env!("CARGO_MANIFEST_DIR")`, получила путь в удалённую выгрузку прошлого
прогона: cargo счёл сборку свежей и не пересобрал её, программа вышла с кодом 7. Проект, который читает файлы по пути
времени сборки, проверялся бы не на застейдженном содержимом, это нарушало AC2. VAC 2 исправляет это.

### AC1

Один замер на свежих копиях, прогоны строго по очереди, без других сборок. «До» — master `41c227f` с пином `aabb525`,
до переноса тестов. P116 — копия на `f18031e` с её кандидатом. Каждый прогон меняет файл по-новому. Прогон 0 —
прогрев, в зачёт идут прогоны 1–3.

| Сценарий | Прогон 0, с | Прогоны 1–3, с |
| --- | --- | --- |
| До, правка только `Ledger/State.md` | 14,9 | 14,5; 14,5; 14,4 |
| P116, правка только `Ledger/State.md` | 28,5 | 7,9; 7,8; 7,8 |
| До, правка `Project/project_memory/mod.rs`, 12 проверок с pytest | 68,8 | 68,5; 68,8; 71,0 |
| P116, правка `Project/project_memory/mod.rs`, 11 проверок | 42,6 | 41,9; 42,1; 41,9 |

Коммит одних заметок проверяется за 7,8–7,9 с против 14,4–14,5 с до переноса тестов: AC1 выполнен. Прогон 0 у P116
пересобирает крейт, потому что запись VAC 1 не хранит путь дерева. Первый прогон с пустой целью в замере VAC 1 шёл
53,1 с. Цель занимает 1,3 ГБ. После всех прогонов во временной папке не осталось ни одного дерева `agentrig-staged-`.

### AC2

Тест `change_delivery::gate::tests::staged::staged_cargo_check_reuses_unchanged_builds_and_checks_only_staged_code`.
Программа фикстуры печатает свой `CARGO_MANIFEST_DIR` и выходит с кодом 7, если в нём нет `Cargo.toml`.

| Этап | Ожидание |
| --- | --- |
| Первая проверка | код 0, «Compiling value» |
| Застейджены заметки, код без stage изменён на `exit(3)` | код 0, без компиляции |
| Застейджена правка кода со старым временем файла | код 3 |
| Прежняя временная папка удалена, проверка с другой | код 3, «Compiling value» |
| Каталог прошлого прогона занят | код 3, «Compiling value» |

Пробы поломки на этом тесте; исходник после каждой восстановлен и сверен с копией.

| Поломка | Результат |
| --- | --- |
| Без сравнения объекта Git, на VAC 1 | код 0 вместо 3 |
| Без сравнения пути дерева | код 7 вместо 3: программа видит удалённый каталог |
| Без запасного случайного имени | код 101 вместо 3: создание каталога падает |
