# P027 — Структурированные инструменты с единым реестром и управляемым удалением

## Feature

[B014](../Backlog/014.md), контракт `30bf0e08faa6053d77b7a4370168ec008c9e3bfb`.
Выбран 2026-10-27 вместе с остальными карточками Backlog.

## User capability

Агент использует доступные возможности, свободно выполняет временные исследования и получает компактные результаты. Обвязка контролирует маршруты запуска и принимаемую структуру, очищает одноразки и сохраняет историю удалённых инструментов.

## Acceptance

Исходная карточка **B014 / К1–К9**, включая её границы и приёмку.

## Delivery

Ветка feature/target-state. К4 использует общий механизм
[P021](021.md). B015 и runner ревью удалены
([D033](../../Decisions/033.md)): смысловую проверку К5 и К7 выполнил
исполнитель при приёмке.

Начальные правила выбраны исполнителем из действующих механизмов;
пользователь меняет их конфигурацией (К1, К3):

- Инструмент — файл с shebang, битом исполнения или совпадением с
  `tools.recognize`. Постоянные места этого репозитория — `tooling/**` и
  `.agentrig/hooks/*`; временная область — `<paths.runtime>/scratch/<ветка>/`.
- Базовые `just read` и `just write` принимают только настроенные программы,
  подкоманды и разрешённые формы аргументов; временный код идёт через
  `scratch -- TEXT`.
- Задача — ветка фичи; завершение — успешный `feature-merge`. Прерывание,
  суммаризация и конец сессии завершением не считаются.
- После merge сохраняется `results/`, удаляются остальные файлы области и
  журналы её временных запусков; ошибка очистки сообщается явно с ненулевым
  кодом, merge не откатывается.
- Реестр — каталог команд (`purpose`, `doc`) и `.agentrig/tools.yaml`
  (`recognize`, `locations`, `entries`, `removed`) с ролями и владельцами из
  architecture.yaml. Проверка `tools` выполняется перед merge и пропускается
  коммитом VAC.

Коммиты: `77860e8`, `bbedc1a`, `4d039cc` (К3); `3cced20`, `937d3f0` (К9);
`c79ea8e` (К1, К2, К4–К8); `3bde0f1`, `4f87df6` и закрывающий коммит —
закрепление ревизий с конфигурацией этого репозитория.

- К1 — выполнено: CLI-тест обнаруживает инструмент вне мест по shebang без
  записи в реестре и незарегистрированный исполняемый файл в разрешённом месте.
- К2 — выполнено: `just list` выводит назначение, `just run` с параметрами,
  файл инструмента с ролью и владельцем, документацию, затем инструменты точек
  входа и отдельно удалённые; проверено тестом и на этом репозитории.
- К3 — выполнено: хук и runtime отклоняют неизвестные программы, подкоманды,
  запрещённые формы и `sh -c` через `read`/`write`, называя маршруты; встроенные
  Read/Edit/Write не затронуты.
- К4 — выполнено: skill develop-tools задаёт последовательность и запреты;
  диагностика проверки `tools` указывает на него; повторного чтения при
  корректных запусках нет.
- К5 — выполнено: тест воспроизводит все формальные нарушения, корректная
  структура проходит; коммит VAC печатает `SKIP [tools]: checked before
  merge`. Смысловая оценка: новых инструментов нет; `build`, `candidate` и
  `lint` используют один файл для разных возможностей и дубликатами не являются.
- К6 — выполнено: тест merge оставляет только `results/` и удаляет журналы
  временных запусков; до merge область сохраняется.
- К7 — выполнено: проверка находит удалённый инструмент на диске и ссылки на
  него вне памяти. Инструменты этого репозитория не удалялись.
- К8 — выполнено: тест восстанавливает реализацию через `git show` по ревизии;
  незакоммиченная запись помечена как невосстановимая.
- К9 — выполнено: одинаковые настройки дают одинаковый ответ при 5 и 500 строк
  шума, статус сохраняется, полный вывод остаётся в журнале задачи; после
  `937d3f0` журнал проверки staged-индекса лежит в runtime репозитория.
