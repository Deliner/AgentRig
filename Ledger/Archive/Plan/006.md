# P006 — Directory architecture contracts and lint

## Feature

Make directory responsibilities, allowed dependencies and public boundaries explicit and checkable across source languages, with architectural guidance for repairs.

## User capability

The user keeps a small description file in each directory covered by the architecture policy. It describes the directory's purpose, permitted and forbidden dependencies on other directories, and public versus private access. Lint identifies violations in actual code and directs the agent toward a cohesive architectural repair.

## Acceptance

- A documented, minimal directory description format expresses responsibility, dependency restrictions and public boundaries. Every source directory in the configured scope requires this file. Service directories, generated content and external dependencies may be excluded through configuration; missing or invalid required descriptions produce actionable diagnostics.
- Actual source dependencies are compared with these declarations. Forbidden edges, access to private parts and dependency cycles report the relevant directories and source evidence; cycle diagnostics show the cycle.
- Shared graph checks support Rust, Python, JavaScript and TypeScript in the first delivery. Discovery states exact language support and resolution limits; unsupported or unresolved forms cannot silently count as verified absence of dependencies. Acceptance demonstrates all four languages and records the supported forms.
- Rules integrate with AgentRig's own linter and its discovery, configuration, scope, severity and repair routing. Embedded execution and standalone agentrig-lint agree and preserve the checked project.
- Strengthen the existing directory-refactoring skill around responsibilities, dependency direction, public interfaces, private implementation and consumers. Diagnostics link the applicable skill. Moving files merely to satisfy a count, inventing arbitrary buckets or widening permissions merely to pass is not a valid repair.
- Independent consumer fixtures demonstrate a valid architecture and detected missing descriptions, forbidden dependencies, private access and cycles. Verify a repaired example retains behavior and satisfies its architecture contract. Document actual parser/resolver limits and pass the configured delivery gates.

Unresolved references and recognized unsupported forms produce incomplete-analysis findings; no full compiler or arbitrary runtime dependency proof is claimed. Package export ambiguity, loader aliases/values and module factories, macro expansion and conditional/unknown attributes are diagnosed rather than silently accepted.
