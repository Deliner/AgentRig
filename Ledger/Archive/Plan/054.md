# P054 — Medium-находки повторного обзора: макросы, тест-контекст, сигналы, дренаж

## Feature

[B045](../Backlog/045.md): четыре находки уровня medium из повторного воркфлоу-ревью
(`wf_5e9ed727-485`, 2026-11-01). Две — поведение поставляемого линтера (видимость паттернов
внутри макросов; честное определение тест-контекста); две — робастность worker-рантайма
(управляемость сигналами между запусками; ограниченный по времени дренаж). Исходный контракт —
ревизия карточки B045 в Git; согласовано и выбрано на исполнение пользователем 2026-11-01
(«бери в работу и приступай»). Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: (1) правила `panic-path`/`eager-fallback-with-?`/`disabled-raii`
находят свой паттерн и когда вызов записан в теле макроса (`json!`, `format!`, `vec!`, …), эскейп
`// DECISION:`/`// INVARIANT:` сохраняется; (2) исключение по тест-контексту применяется только к
действительно тест-онли коду (`#[cfg(not(test))]` не глушит правила, `#[tokio::test]` распознаётся
как тест). Оператор worker получает: (3) worker остаётся завершаемым сигналами
(SIGINT/SIGTERM/SIGHUP) между выполнениями команд и после них; (4) выполнение команды возвращает
управление за ограниченное время и не повисает на отсоединённом потомке, держащем конец пайпа.

## Acceptance

Карточка **B045 (AC1–AC4 + границы)**.
- **AC1** — `panic-path`/`eager-fallback-with-?`/`disabled-raii` находят паттерн внутри тела макроса;
  `record.finished.unwrap_or(now()?)` в `json!(…)` без ссылки — находка `eager-fallback`, со ссылкой —
  нет. Граница движка (нет вывода типов, [D059](../../Decisions/059.md)) сохраняется; FP от обзора тел
  макросов измеряется на репозитории, при неясности граница сужается (norm-or-choice).
- **AC2** — тест-контекст истинен только для настоящего тест-онли кода: `#[cfg(not(test))]` — не тест,
  `#[cfg(feature = "…")]` — не тест, `#[tokio::test]` — тест; закреплено негативными фикстурами по
  публичной поверхности линтера.
- **AC3** — worker управляем сигналами между/после выполнений команд (а не только при первом).
- **AC4** — `execute()` завершается за ограниченное время при отсоединённом потомке с удерживаемым
  пайпом; намеренно фоновые задания под AC4 не попадают.

AC1/AC2 меняют поведение существующих правил/детекторов → двухфазная доставка с мид-веткой бутстрапом
и финальным пином ([D051](../../Decisions/051.md)) там, где это нужно stable-бинарю; это способ доставки,
не критерий. AC3/AC4 — поведение рантайма, проверяется поведенческими тестами worker. Приёмка заземлена
на near-zero-FP бар ([D035](../../Decisions/035.md)); пороги не ослабляются, притворных инвариантов нет.
Наш код приводится к зелёному (догфуд).

## Delivery

Ветка `feature/medium-findings` (база master `125bd20`), сохраняется после интеграции. Приёмка
заземлена на near-zero-FP бар ([D035](../../Decisions/035.md)) и границу движка (нет вывода типов,
[D059](../../Decisions/059.md)); пороги не ослаблены, притворных инвариантов нет (norm-or-choice). Все
четыре AC выполнены как поведение; новых видов правил (`kind:`) ни один AC не вводит, поэтому мид-бранч
пин для десериализации `lint.yaml` не потребовался — только финальный пин D051.

- **AC2 — честный тест-контекст, выполнено.** VAC-B `3c2758f`: кластер вынесен в
  `structural_lint/languages/test_context.rs`, предикаты `cfg` разбираются честно —
  `#[cfg(not(test))]` не глушит правила, `#[cfg(feature = "…")]` трактуется как не-тест,
  `#[tokio::test]` распознаётся как тест. Закреплено негативными фикстурами по публичной поверхности
  линтера в `languages/tests/markers.rs`; `test_context.rs` внесён в `languages/architecture.yaml`.
- **AC1 — обзор тел макросов, выполнено ([D094](../../Decisions/094.md)).** VAC-C `740b85b`:
  `rust.rs` переразбирает тело `token_tree` (`macro_body`/`scan_fragment`), поэтому `panic-path`,
  `eager-fallback-with-?` и `disabled-raii` видят свой паттерн внутри `json!`/`format!`/`vec!` и т.п.;
  эскейп `// DECISION:`/`// INVARIANT:` сохраняется. Это синтаксический обзор содержимого, не
  разворачивание макросов — граница D059 цела. Попутно исправлен eager-fallback-баг в `jobs/mod.rs`
  (ленивый `now()?`). FP замерен на репозитории: `just candidate lint` по всему дереву — 0 находок.
- **AC3 — worker управляем сигналами после форвардинга, выполнено ([D095](../../Decisions/095.md)).**
  VAC-D `3f64de5`: `process.rs` после join форвардинга сбрасывает SIGINT/SIGTERM/SIGHUP в `SIG_DFL`
  (`signal-hook` при drop оставляет свой OS-обработчик и иначе глотает сигналы). Поведенческий тест
  `test_worker_stays_signal_controllable_after_child_exits`: SIGTERM завершает worker в дренаже
  (код −15).
- **AC4 — ограниченный дренаж `execute`, выполнено ([D095](../../Decisions/095.md)).** VAC-D `3f64de5`:
  `streams.rs` читатель ждёт готовность пайпа через `libc::poll` и останавливается, когда общий флаг
  `exited` (ставится после `child.wait()`) истинен и данных нет — `execute` возвращается, осушив все
  байты главного ребёнка, не дожидаясь write-end отсоединённого потомка и не убивая его; фоновые
  задания намеренно вне AC4. Поведенческий тест
  `test_foreground_drain_is_bounded_when_descendant_holds_pipe`: worker возвращается сам (код 0). Оба
  новых `unsafe` (`libc::poll`, `libc::signal`) помечены `// DECISION: D095`, расширяющим
  [D066](../../Decisions/066.md); его заявление об одиннадцати сайтах не изменено.

Финальный пин stable.txt на голову ветки ([D051](../../Decisions/051.md)) + bootstrap выполняется
отдельным коммитом до `just feature-merge`. **Все четыре medium-находки повторного обзора
(`wf_5e9ed727-485`) закрыты.**
