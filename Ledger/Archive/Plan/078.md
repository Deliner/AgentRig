# P078 — boolean-expression: длинное логическое выражение

## Feature

[B071](../Backlog/071.md): выражение, где больше заданного числа частей соединены `&&` и `||` или `and` и `or`, —
находка в любом месте кода. Источник — карточка B071 (ревизия в Git `759a2eb`); выбор и авторизация — /goal
пользователя 2026-11-07. Порог и счёт частей в скобках и цепочках `if let … &&` исполнитель выбирает замером на
корпусе и записывает в Delivery. Порядок и границы VAC — за исполнителем.

## User capability

Каждое условие читается с одного взгляда; обход named-if через имя над длинным выражением закрыт.

## Acceptance

Карточка **B071 (AC1–AC2, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/boolean-expression` (база master `2ddd7c8`). VAC 1 `073c9cf` (фаза 1: инертный пороговый вид,
измерение, тесты, решение D120), мид-бранч пин `9319114`, VAC 2 (фаза 2: правило, навык, ассет, ремонт своих 12
выражений; Delivery, ротация P078/B071). Гейт VAC 1 зелёный: rust-test 122 passed, test 216 passed, остальные
проверки PASS.

- Выбор при доставке. Порог из карточки: находка выше трёх частей, уровень error, без предупреждения. Скобки
  группируют части, но не обрывают выражение: `(a && b) || (c && d)` — четыре части. Отрицание, сравнение, вызов,
  замыкание и макрос — одна часть, выражение внутри меряется отдельно. Привязка `let` в цепочке `if let … &&` не
  считается частью, логические условия цепочки считаются. Тестовый код не исключён. Измерение общее для Rust и
  Python в `languages/measure/mod.rs`.
- AC1 выполнен: тест `rust_counts_operands_of_each_boolean_expression_wherever_it_stands` — `let` из пяти частей,
  `while` из четырёх, охранное условие `match` из четырёх; тест
  `python_counts_and_or_operands_with_parentheses_and_not_as_one` — присваивание из пяти частей, `while` из
  четырёх, скобки дают четыре. Сквозная проверка: потребители после `just candidate init` с `--language rust` и
  `--language python` получают правило с `error: 3` и навык `split-boolean-expression`; `just candidate lint`
  выдаёт `ERROR [boolean-expression] Project/src/lib.rs:3 (expression): boolean-expression measures 4, exceeds 3`
  и такую же находку `Project/app.py:3`.
- AC2 выполнен: в тех же файлах потребителя выражения из двух частей в строке 2 и из трёх в строке 4 находок не
  дают; тесты показывают меру 3 для `let short = a && b && c` и фильтра генератора из трёх частей.
- Границы: тест `rust_groups_parentheses_and_measures_negations_let_bindings_and_macros_apart` — скобки, отрицание
  с внутренним выражением из четырёх частей, цепочка `if let` с тремя логическими условиями даёт 3, цепочка из двух
  привязок и одного условия даёт 1, аргументы вызова меряются отдельно, тело `assert!` не меряется.
- Замер на корпусе r8, 18 627 Rust-файлов: bun, переведённый машиной, даёт 2 561 из 3 918 выражений выше трёх.
  Без bun из 21 136 выражений от двух частей выше трёх 1 357, примерно одно на 4 700 строк, выше пяти 240. Счёт
  привязок `let` добавил бы 250 находок, почти все последовательные привязки. В Python-файлах AgentRig находок нет.
- Свои 12 выражений в Rust переписаны именами групп без изменения поведения: `command_runner/registry/check.rs`,
  `project_memory/evidence/mod.rs` дважды, `shared/vcs/export.rs`, `shared/vcs/git.rs`,
  `architecture/resolution/rust/macros.rs` дважды, `architecture/resolution/rust/paths.rs`,
  `architecture/source/python.rs`, `structural_lint/config/mod.rs`, `languages/rust/mod.rs`,
  `rules/architecture.rs`.
- Навык в группе `control-flow` рядом с `reduce-branching`; назначение группы дополнено длинными логическими
  выражениями.
