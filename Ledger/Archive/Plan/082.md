# P082 — ratchet-baseline: внедрение строгих правил в проект с историей

## Feature

[B064](../Backlog/064.md): команда фиксирует baseline находок, `lint` в режиме ratchet проваливается только при росте,
`init` в существующем репозитории предлагает ratchet. Источник — карточка B064 (ревизия в Git `f1c574a`); выбор и
авторизация — /goal пользователя 2026-11-07. Формат baseline, гранулярность и взаимодействие с `--staged` исполнитель
решает при доставке и записывает в решении и Delivery. Порядок и границы VAC — за исполнителем.

## User capability

Строгие правила включаются в проект с историей без выключения гейта.

## Acceptance

Карточка **B064 (AC1–AC2, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/ratchet-baseline` (база master `0bf9d8d`), один VAC: модуль `structural_lint/baseline.rs`, команда
`lint-baseline` с рецептом здесь и в шаблоне `init`, предложение в `init` и мастере, тесты, README, решение D123,
Delivery, ротация P082/B064. Новый файл дал бы каталогу линта 16 записей при лимите 15, поэтому точка входа
процесса `agentrig-lint` переехала из `structural_lint/standalone.rs` в `command_line/lint.rs` к точке входа
`agentrig`. Вариант с каталогом `structural_lint/evaluation/` отвергнут: он создавал цикл каталогов и поднимал семь
бюджетов входящих зависимостей.

- Выбор при доставке. Файл `<имя конфигурации>-baseline.yaml` рядом с конфигурацией линта, у потребителя
  `.agentrig/lint-baseline.yaml`; режим ratchet действует, пока файл есть. Формат — строгий YAML: правило → путь →
  число принятых ошибок. Гранулярность — правило и путь, как в карточке: строки сдвигаются от любой правки, а счёт
  только по правилу позволил бы исправлением в одном файле оплатить новую ошибку в другом. Считаются только ошибки;
  предупреждения и ошибки конфигурации нет. `--staged`: гейт проверяет выгрузку индекса, поэтому читает baseline
  из индекса, особого случая нет.
- AC1 выполнен: тест `test_baseline_accepts_recorded_errors_and_fails_when_a_path_gains_one` — после записи две
  ошибки файла становятся предупреждениями с пометкой о baseline, код 0; третья длинная строка — все три снова
  ошибки, сообщение называет принятые 2 из 3, код 1. Тест
  `test_baseline_suggests_lowering_and_recording_never_raises_a_count` — снижение даёт код 0 и подсказку
  `lint-baseline` в stderr; повторная запись опускает число, а рост в другом файле и новый файл не принимает и
  называет 2 такие пары.
- AC2 выполнен: тест `test_init_offers_a_lint_baseline_for_errors_in_existing_files` — `init` в каталоге с
  README, где строка в 130 символов, печатает число ошибок и `just lint-baseline`; рецепт есть в `just/lint.just`;
  `lint` даёт 1 до записи и 0 после. Чистый `init` предложения не печатает. Мастер вызывает то же предложение.
- Сквозная проверка на потребителе: `init` в Git-репозитории с таким README, `check --staged --only lint` — код 1
  без baseline и пока baseline только в рабочем дереве, код 0 после `git add` файла baseline.
- Граница: переименование файла с принятыми ошибками уводит их на незаписанный путь, нужен новый baseline;
  отдельный `agentrig-lint` baseline применяет, но не пишет. Решение [D123](../../Decisions/123.md).
