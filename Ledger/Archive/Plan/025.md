# P025 — Запрет комментариев кроме ссылок на решения и инварианты

## Feature

[B008](../../Backlog/008.md), контракт `30bf0e08faa6053d77b7a4370168ec008c9e3bfb`.
Выбран 2026-10-27 вместе с остальными карточками Backlog.

## User capability

Обычные комментарии не накапливаются. Значимые объяснения и проверяемые свойства сохраняются в предназначенных для них записях, а агент получает понятный способ исправления непосредственно из ошибки.

## Acceptance

Исходная карточка **B008 / К1–К6**, включая её границы и приёмку.

## Delivery

Ветка feature/target-state. Правило comment-reference для Rust и Python и
skill replace-comment существовали до выбора ([D037](../../Decisions/037.md)).
VAC: `7955912` (общий формат ссылки в shared/syntax, проверка существования
записей в memory-check), `1bd1cf8` (CLI-эвал правила, уточнение skill),
`0d6ce60` (сканирование ссылок до обнаружения оракулов, пропуск не-UTF-8),
`6032647` (восстановлен оракул I002, сломанный в P021, и его выбор картой).
Языки первой поставки — Rust и Python ([D033](../../Decisions/033.md)). B004,
B015 и B016 удалены: эвалы К6 выполняются через CLI, смысловую оценку К4
выполняет исполнитель, проверки выбирает действующая карта затронутых тестов.

- К1 — выполнено: обычные, документационные, блочные и служебные комментарии
  (`# type: ignore`, `# noqa`, `// SAFETY:`) и docstring отклоняются; точная
  ссылка принимается, ссылка с пояснением — нет; текст в строках не считается
  комментарием (нативные тесты языков и CLI-эвал для Rust и Python).
- К2 — выполнено: memory-check сообщает файл и идентификатор ссылки без
  записи в Decisions.md или Invariants.md; нарушенная привязка инварианта к
  тесту и оракулу обнаруживается существующей проверкой (I002). Файлы не в
  UTF-8 пропускаются, как и в линтере.
- К3 — выполнено: ошибка линтера останавливает VAC (код 1); текст содержит
  правило, `путь:строка`, skill в ACTION и RERUN; повторные находки одной
  причины объединены под одним требованием ([P021](021.md), K8); исправленный
  вариант проходит только при повторной проверке.
- К4 — выполнено: replace-comment различает удаление, уточнение кода, решение,
  инвариант и директиву через norm-or-choice и skills памяти, допускает одну
  запись для нескольких комментариев и запрещает фиктивные записи и чужие ID.
- К5 — выполнено: skill требует сохранить поведение и предъявить конфликт
  вместо ослабления правила; код репозитория соблюдает правило при
  прохождении поведенческих проверок gate.
- К6 — выполнено: CLI-эвалы с заданными ожиданиями — формы, ссылки, пояснение,
  данные и исправление (`test_comment_references_through_cli`), отсутствующие
  записи (`test_source_references_name_recorded_entries`), сломанные связи
  решений (`test_decision_source_markers`) и инвариантов
  (`test_independent_project_delivery`); неожиданных находок нет.
