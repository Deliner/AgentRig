# P057 — allow-justification: `expect`, `cfg_attr` и `[lints]` Cargo.toml

## Feature

[B053](../Backlog/053.md): расширение правила `allow-justification` ([D080](../../Decisions/080.md))
на `#[expect(...)]`, условное подавление `#[cfg_attr(cond, allow|expect|ignore…)]` и уровень
`"allow"` в таблицах `[lints.*]`/`[workspace.lints.*]` Cargo.toml (разбор TOML, новое расширение
`.toml`). Источник — исследовательская дуга (`coverage-map.md` «cfg-attr-suppression», принято
2026-11-02); реализация авторизована пользователем 2026-11-04 (/goal). Исходный контракт —
ревизия карточки B053 в Git. Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: подавление линта в любой из трёх форм без строки-обоснования
прямо выше — находка, как для `#[allow]`; `reason = "…"` внутри атрибута обоснованием не считается
(знание остаётся в Ledger). Навык `justify-allow` описывает все формы.

## Acceptance

Карточка **B053 (AC1–AC4, границы)**.
- **AC1** — `#[expect]`/`#![expect]` без обоснования → находка.
- **AC2** — `cfg_attr` со второй-аргументной головой `allow`/`expect`/`ignore` без обоснования →
  находка; внешний и внутренний атрибуты одинаково.
- **AC3** — `"allow"`/`{ level = "allow" }` в `[lints.*]`/`[workspace.lints.*]` Cargo.toml без
  `# DECISION:`/`# INVARIANT:` прямо выше ключа → находка в этом файле и строке; разбор как TOML.
- **AC4** — `reason=` не заменяет ссылку; сообщение находки это называет.

Новое расширение `.toml` у существующего правила должно приниматься stable-бинарём из `lint.yaml`
→ двухфазная доставка с мид-бранч пином ([D051](../../Decisions/051.md)); decision, расширяющий D080,
при доставке; догфуд `just candidate lint` → 0 находок (форм в нашем коде нет; `[lints]` в
`Project/Cargo.toml` нет); живая проба каждой формы. Пороги не ослабляются.
