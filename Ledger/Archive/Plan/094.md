# P094 — revision-gate: `check --revision` выполняет `tools`, отказанное переключение ветки не меняет дерево

## Feature

[B093](../Backlog/093.md): `check --revision` выполняет `tools`, отказанное переключение ветки не меняет дерево.
Источник — карточка B093 на ревизии `54aa528`; выбор и авторизация — пользователь 2026-11-10. Порядок и границы VAC — за
исполнителем.

## User capability

Проверка ревизии не падает на ложной ошибке git, а отказанное переключение ветки не оставляет смешанное рабочее дерево.

## Acceptance

Карточка **B093 (AC1–AC2, границы)** — критерии и формулировки там; идентификаторы те же.

## Delivery

Ветка `feature/revision-gate` (база master `e9fc137`): правка и тесты — VAC A `cca748c`; ротация — завершающий VAC.
Гейт коммита `cca748c`: все проверки PASS, rust-test 11 и test 136 passed.

- AC1 — выполнен. Проверка `tools` под `check --revision` берёт список файлов из дерева ревизии и читает Git
  исходного репозитория (`command_runner/registry/check.rs`). Установленный рантайм `9ba4fad`:
  `check --revision HEAD --only tools` на AgentRig — «not a git repository», код 2; кандидат — PASS [tools] на
  AgentRig и на voxel-rust `71440d0`. Тест `test_tools_check_reads_the_checked_revision`: HEAD проходит при
  неотслеживаемом инструменте в рабочем дереве, ревизия с инструментом вне `tools.locations` даёт находку.
- AC2 — выполнен. Если `git switch` в `feature-merge` отказан, индекс и дерево возвращаются к HEAD через
  `git read-tree -u --reset HEAD` (`change_delivery/git/integration.rs`); дерево перед переключением чистое.
  Тест `test_refused_switch_to_base_keeps_the_feature_tree`: хук reference-transaction из дерева базы отказывает в
  обновлении HEAD; до правки `git status --porcelain` показывал `M  .agentrig/hooks/reference-transaction`, после —
  пусто, ветка и HEAD прежние.
- Границы — соблюдены: правка не зависит от проекта. В дереве voxel-rust обхода нет: смешанное дерево там
  возвращали вручную `git restore --source=HEAD`, теперь это делает `feature-merge`.
