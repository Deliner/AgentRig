# B178 — Чужую директорию используют только через её вход

## Context

- 2026-11-20 пользователь: если от фичи что-то нужно, она даёт для этого API. Проверять на каждом уровне. Тесты тоже
  проверяются и тестируют только через публичные входы.
- Решение D043 убрало поля `public`, `allow`, `deny` и проверку вместе с ними. Эти поля не возвращаются: входом служит
  входной файл.
- Решение D057 оставляло доступ тестов нормой ревью. Пользователь перевёл его на проверку.
- Замер рига, пары файлов в обход входа: 289 в рабочем коде, 159 в тестах.
- 2026-11-20 пользователь: входом считается только файл, который требует риг; проект, который хочет пользоваться
  ригом, приводит себя к нему. Бюджеты меняются вместе с поставкой без отдельного согласия.

## Proposal

- **AC1. Находка.** Правило `entry-bypass` даёт ошибку, когда цель лежит в директории, внутри которой нет источника, и
  цель не является входом самой верхней такой директории. Рабочий и тестовый код проверяются одинаково.

  Проверка: `cli/main.rs` использует `lint/reporting/tree.rs`: находка. Использует `lint/mod.rs`, который отдаёт
  нужное: находки нет. `lint/evaluation.rs` использует `lint/architecture/graph.rs`: находка.
  `lint/tests/coupling.rs` использует `lint/architecture/graph.rs`: находка. Использует `lint/architecture/mod.rs`:
  находки нет. Файл использует соседа по директории: находки нет.
- **AC2. Текст находки.** Источник со строкой, цель и входной файл, через который надо идти.
- **AC3. Группа.** В `architecture.yaml` директории есть необязательное поле `group: true`. Оно объявляет директорию
  группой независимых частей. Своей границы у группы нет. Её части это её файлы и поддиректории, и граница есть у
  каждой поддиректории. Без поля директория остаётся обычной. Так объявлен `shared`.

  Проверка с полем: файл использует `shared/x.rs` или `shared/paths/mod.rs`: находки нет. Использует
  `shared/paths/glob_patterns.rs`: находка. Проверка без поля: `shared/paths/mod.rs` даёт находку.
- **AC4. Навык `go-through-entry`.** Порядок починки рабочего кода:
  1. Потребитель делает работу владельца: перенести её владельцу.
  2. Возможность нужна нескольким и не принадлежит этой директории: вынести отдельному владельцу.
  3. Иначе дать во входе одну функцию под задачу.
  4. Реэкспорт только для того, что и есть API.

  Порядок починки теста:
  1. Тест проверяет поведение, обещанное наружу: переписать его на вызов через вход.
  2. Тест проверяет внутренности директории: перенести его в `tests/` этой директории.

  В Rust после починки объявить часть через `mod`, чтобы границу держал компилятор. Запрещает открывать через вход
  всё подряд и расширять API только ради теста.
- **AC5. Риг и проекты.** Правило включено в риге и после `init`, для Rust и Python. Код и тесты рига приведены к
  правилу. Навык `refactor-large-directory` различает реэкспорт как API и реэкспорт ради прохождения. README правила
  `architecture` описывает поле `group`.
- **AC6. Бюджеты.** Агент меняет бюджеты `fan_out` и `dependents` по замеру в той же поставке, отдельное согласие не
  нужно. Отчёт о поставке показывает числа до и после.

**Границы.**

- Отдельного правила «поддиректория не берёт сверху» нет. Когда вход отдаёт свою поддиректорию, а она берёт у
  родителя, это цикл директорий, который lint уже ловит. Шесть таких пар рига чинятся здесь.
- Входом считается только `mod.rs`, `lib.rs`, `main.rs` и `__init__.py`. Файл `foo.rs` рядом с `foo/` риг уже
  запрещает через Clippy `self_named_module_files`. У директории без входа снаружи доступа нет: любое обращение даёт
  находку.
- Смысл API правило не проверяет: вход, открывший всё, пройдёт.
- Тест, лежащий внутри директории, обращается к её файлам напрямую, как и рабочий код этой директории.

## Expected benefit

Внутренности директории перестраиваются без правки потребителей и чужих тестов. Всё, что она обещает наружу, видно в
одном файле.
