# B051 — self-находки межпроектного обзора: гигиена собственного кода

## Context

Тот же межпроектный обзор (`rust-lint-mining` `wf_f2a6f63a-7ff`, 2026-11-01) при сверке паттернов с
собственным кодом AgentRig выявил три мелкие находки. Ни одна не является ошибкой корректности
сегодня; все — о гигиене/согласованности и о точности обоснований. Собрано одной карточкой по
прецеденту B045 (находки одного обзора — один набор с независимыми AC). Проверено прямым грепом по
`Project` и чтением `jobs/process.rs`, `jobs/group.rs`, `jobs/identity/macos.rs`.

## Proposal

Наблюдаемое поведение (три независимых AC):

- **AC1 — проза D066/D095 совпадает с кодом (дрейф обоснования).** `jobs/process.rs` отбрасывает
  возвращаемое значение/errno у `libc::signal` (стр. 52) и `libc::kill` (стр. 97, 113), тогда как
  текст обоснований D066/D095 утверждает, что «return value and errno checked». Поведение намеренно
  best-effort (восстановление `SIG_DFL`; best-effort терминация группы), проверять errno там нечему.
  Признак достижения: текст соответствующего обоснования больше не заявляет проверку errno для
  best-effort сайтов signal/kill (а относит это утверждение к проверяющим сайтам `group.rs`
  `== 0`/`ensure!`); код не меняется. Контраст: `group.rs:16,34` реально проверяют. Механизм:
  statements/detail-contents D066/D095 неизменяемы (D020) → правка идёт через decision-преемник
  (edit-decisions при доставке), не редактированием D066/D095. Эта находка также демонстрирует, что
  `unsafe-justification` проверяет лишь наличие обоснования, а не соответствие его текста коду
  (ограничение движка D059) — отдельным правилом не чинится.

- **AC2 — согласованность сужающего каста PID.** `jobs/process.rs:35` и `:108` используют
  `child.id() as i32` (u32→i32), тогда как `jobs/group.rs` использует `i32::try_from` (стр. 14, 34).
  Признак достижения: оба преобразования PID в `process.rs` идут тем же проверяемым путём, что в
  `group.rs`; поведение для корректных PID не меняется.

- **AC3 — явное условие валидности `MaybeUninit::zeroed`.** `jobs/identity/macos.rs:45,63`
  используют `MaybeUninit::<T>::zeroed().assume_init()` для обобщённого `T`; сегодня безопасно
  (`T` ∈ `proc_bsdinfo`/`proc_taskinfo`, all-zero валиден), обосновано D066. Признак достижения:
  сайт zeroed-инициализации явно фиксирует предусловие «all-zero валиден для T»
  (`// DECISION:`/`// INVARIANT:`), чтобы будущий `T` не нарушил его незаметно; поведения не меняет.

**Границы и неизвестное.** Все три — гигиена/согласованность, не исправление ошибки корректности;
для текущих входов поведение не меняется. AC1 затрагивает прозу decision (механизм — преемник по
D020, уточняется edit-decisions при доставке), AC2/AC3 — собственный код в `command_runner/jobs`.
Три AC независимы и при необходимости бьются на отдельные VAC.

## Expected benefit

Собственный код AgentRig соответствует той дисциплине, которую проект предлагает shipped-правилами:
проза обоснований перестаёт переобещать, преобразование PID согласовано, предусловие
zeroed-инициализации явно. Чистота на нашем коде для правил B046–B050 подтверждена.
