# B173 — Новую ревизию рига ставит и закрепляет только пользователь

## Context

- 2026-11-20 пользователь после отчёта по P157 выбрал для остатка 3 вариант А: «по пункту 3 давай вариант А». Каждый
  перенос пина требует `! just approve`.
- Наблюдение: код правил lint, хуков и гейта в Project не защищён. Агент сам запускает `just bootstrap HEAD`, команда
  сразу ставит ревизию и пишет пин. Гейт по D213 принимает пин, если тот потомок прежнего. Ослабленное правило,
  закоммиченное без нарушающего кода, после пина судит следующие коммиты, как записано в последствиях D217.

## Proposal

- **AC1.** Агент готовит перенос пина. Новая ревизия ставится и записывается в пин только после `! just approve`, а
  до этого хуки и гейт работают на прежней ревизии. Сам поставить ревизию, отличную от закреплённой, агент не может:
  хук отказывает и называет навык.

  Проверка: тест, в котором без подтверждения установленная ревизия и пин остаются прежними, а после подтверждения
  меняются; тест хука на отказ.
- **AC2.** Гейт коммита принимает изменённый пин только с подтверждённым содержимым.

  Проверка: тест гейта, в котором пин вперёд без подтверждения отклонён, а с подтверждением принят.
- **AC3.** Перед подтверждением пользователь видит список файлов Project, изменённых с прошлого пина.

  Проверка: тест на вывод подготовки.
- **AC4.** Тексты для агентов больше не велят запускать `just bootstrap HEAD` без вопроса. Вместо этого агент готовит
  пин и просит `! just approve`, в том числе посреди ветки при поставке в две фазы.

  Проверка: в AGENTS.md и навыках не осталось указания ставить ревизию самому.

Границы: `just bootstrap` после клонирования по-прежнему ставит уже закреплённую ревизию без подтверждения.

## Expected benefit

Ослабленное правило, хук или проверка гейта не начинают действовать без ведома пользователя.
