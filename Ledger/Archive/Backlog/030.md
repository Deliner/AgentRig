# B030 — Структура как карта функционала

## Context

Кластер 5 набора улучшений качества (мозгоштурм 2026-10-29). Цель — по дереву каталогов и
именам файлов понимать устройство проекта без чтения кода; продолжение `architecture.yaml`
и типов фич ([D044](../../Decisions/044.md)). Согласовано пользователем 2026-10-29.

## Proposal

- **5.1 Семьи вместе.** Трейт и его `impl`-ы; базовый класс и наследники лежат в одном
  каталоге. Имя трейта/родителя — явный путь, резолвится путь→файл без вывода типов.
  *[правило]*
- **5.2 Качество `architecture.yaml`.** Нет пустых и дженерик `purpose`-описаний
  (валидация существования контрактов уже есть). *[правило]*
- **5.3 Одна возможность = один файл.** Усиление «фасад + листья»: отдельная CLI-команда /
  правило / обработчик — свой файл. *[норма/декларация]*

**Границы.** Только `Project`; возможность уезжает в `init`
([D053](../../Decisions/053.md)/[I020](../../Invariants/020.md)); что не проверяется чисто —
норма (norm-or-choice). Догфуд: наш код к зелёному.

## Expected benefit

Структуру проекта читаешь по дереву, а не по коду; семьи и возможности видны сразу.
