# B130 — Ветки уходят в удалённый репозиторий после коммита и слияния

## Context

Запрос пользователя 2026-11-13: «Все feature ветки тоже нужно пушить. Они не должны теряться». Из двух показанных
вариантов пользователь выбрал Б: отправлять ветку и после каждого коммита, а не только при слиянии.

До этого вся работа жила только на этой машине. В `origin` было 6 из 135 веток `feature/*`, а master отставал на
796 коммитов. `just feature-merge` сливает ветку в базу и сохраняет её, но ничего не отправляет. Сам агент может
отправить ветку только через `just scratch`, потому что `just write` не разрешает `git push`.

## Proposal

**AC1. Настройка.** В `.agentrig/git.yaml` появляется необязательный ключ `remote` с именем удалённого
репозитория, например `remote: origin`.

- Без этого ключа коммиты и feature-merge работают как сейчас и ничего не отправляют.
- В риге ключ стоит: `remote: origin`.

**AC2. Отправка при слиянии.** Если `remote` задан и слияние прошло, feature-merge отправляет туда две ветки,
базовую и слитую feature-ветку.

- Удалённые копии указывают на те же коммиты, что и локальные.
- База отправляется без перезаписи.
- Feature-ветка отправляется с проверкой `--force-with-lease`, потому что перед слиянием feature-merge мог
  перестроить её на новую базу. Удалённая копия перезаписывается, только если совпадает с той, что этот клон видел в
  последний раз.
- Отчёт feature-merge показывает, какие ветки отправлены.

Признак: в тесте с временным удалённым репозиторием после feature-merge обе ветки стоят на локальных коммитах, в
том числе после перестройки ветки. Без ключа в этом репозитории ничего не появляется.

**AC3. Сбой отправки при слиянии.** Отправка может не пройти: нет сети, нет доступа или удалённую копию изменил
кто-то другой. Тогда:

- слияние остаётся в локальной базе;
- feature-merge завершается с ненулевым кодом;
- сообщение называет неотправленные ветки, причину от git и команду для повтора.

Признак: есть два теста, с недоступным удалённым репозиторием и с удалённой веткой, изменённой другим клоном. В
обоих слияние есть, код ненулевой, а сообщение называет ветки. Чужая удалённая копия не затёрта.

**AC4. Отправка после коммита.** Если `remote` задан, после каждого коммита в ветке с префиксом из `git.yaml` эта
ветка отправляется в `remote` с той же проверкой `--force-with-lease`.

- Если отправка не прошла, коммит остаётся. Печатается предупреждение с причиной от git. Следующий коммит или
  feature-merge отправят ветку снова.
- В базу коммитов не делают, поэтому её отправляет только feature-merge.

Признак: в тесте коммит в feature-ветке появляется в удалённом репозитории. С недоступным удалённым репозиторием
коммит есть и есть предупреждение. После перестройки ветки на новую базу следующий коммит обновляет удалённую копию.
Копию, изменённую другим клоном, коммит не затирает.

**Границы.**

- init не пишет ключ `remote` в проекты. Проект включает отправку одной строкой.
- Удалённые ветки не удаляются. Перезаписать можно только feature-ветку и только с проверкой `--force-with-lease`.
  Базу перезаписать нельзя.
- Хуки не обходятся. Свой pre-push хук проекта работает как обычно.

## Expected benefit

Ни слитая, ни незаконченная, ни отложенная работа не теряется вместе с машиной. Агенту не нужно помнить об отправке
и обходить `just write`.
