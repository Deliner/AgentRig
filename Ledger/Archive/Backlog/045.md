# B045 — Закрыть medium-находки повторного обзора (линтер + worker)

## Context

Повторный обзор исправленного кода (workflow `wf_5e9ed727-485`, 2026-11-01) подтвердил
четыре находки уровня medium. Две — о поведении линтера на собственном коде и у
потребителей, две — о робастности worker-рантайма при выполнении команд. Пользователь
попросил закрыть все medium одной карточкой. Все четыре — предсуществующие (не регресс
Tier A/B); вторую Tier A/B лишь расширил, добавив ей новых потребителей. Ниже near-zero-FP
бар (D035) не нарушается: это не новые эвристики, а устранение слепых зон и ложных
исключений существующих правил и рантайма.

## Proposal

Один набор для автономной доставки. Наблюдаемое поведение:

- **AC1 — правила видят паттерн внутри макросов.** `panic-path`, `eager-fallback-with-?`,
  `disabled-raii` находят свой паттерн, даже когда вызов записан в теле макроса (`json!`,
  `format!`, `vec!`, `println!`, `assert!` и т.п.). Признак достижения:
  `record.finished.unwrap_or(now()?)` внутри `json!(…)` без ссылки-обоснования — находка
  `eager-fallback`; тот же код со строкой `// DECISION: …`/`// INVARIANT: …` над ним — не
  находка. Внешне похожее нарушенное состояние (сегодня): такой код молча проходит гейт.
  Граница движка (нет вывода типов, D059) сохраняется — это синтаксический обзор
  содержимого `token_tree`, не разворачивание макросов.

- **AC2 — исключение по тест-контексту только для действительно тест-онли кода.** Признак:
  `#[cfg(not(test))] fn f(){ x.unwrap() }` — находка (это продакшн-ветка);
  `#[cfg(feature = "latest")]` классифицируется как не-тест (правила применяются),
  `#[tokio::test]` — как тест (исключается). Внешне похожее нарушенное состояние (сегодня):
  любой атрибут, в тексте которого есть подстрока `test`, глушит все правила, выводимые
  через тест-контекст, в т.ч. на продакшн-коде у потребителей. Закрепить негативными
  фикстурами по публичной поверхности линтера.

- **AC3 — worker управляем сигналами между запусками и после них.** Признак: после
  завершения первой выполненной команды повторный `SIGTERM`/`SIGINT`/`SIGHUP` завершает
  worker штатно. Внешне похожее нарушенное состояние (сегодня): после первого `execute()`
  эти сигналы игнорируются — worker завершается только `SIGKILL`.

- **AC4 — выполнение команды завершается за ограниченное время.** Признак: команда,
  оставившая отсоединённого потомка с удерживаемым концом пайпа, возвращает управление
  (дренаж ограничен/пайпы закрываются после терминации группы), а не блокирует `execute()`
  бессрочно. Граница: намеренно фоновые задания, живущие, пока населена их группа, под AC4
  не попадают — речь о переднеплановом `execute()`/гейте.

**Границы и неизвестное.** AC1: объём ложных срабатываний от повторного обзора тел макросов
не измерен — замерить на этом репозитории до активации; при неясности сузить до флага `?`
в eager-аргументе внутри макроса (решение о границе — через norm-or-choice, если потребуется).
AC1/AC2 меняют поведение существующих правил и их детекторов → доставка новой/изменённой
возможности правила идёт двухфазно с мид-бранч пином и финальным пином (D051); это способ
доставки, не критерий приёмки. AC3/AC4 — поведение рантайма команд, вне модели правил линтера;
проверяются поведенческими тестами worker, а не самим гейтом. Четыре AC независимы; при
необходимости бьются на отдельные VAC внутри одного Plan-выбора.

## Expected benefit

Переносимый гейт ловит ровно те паттерны, ради которых существует, не теряя их в макросах
и не отключаясь молча на боевом коде проектов-потребителей; worker остаётся завершаемым
оператором и не повисает на чужом потомке.
