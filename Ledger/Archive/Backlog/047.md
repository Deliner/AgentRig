# B047 — discarded-result-variants: молча отброшенные Option-комбинаторы (Rust)

## Context

Межпроектный обзор (`rust-lint-mining` `wf_f2a6f63a-7ff`, 2026-11-01) показал паттерн в
openidea/rustdesk: выражение-инструкция вида `opt.map(|x| x.fallible());` молча роняет
получившийся `Option`, а встроенный `unused_must_use` компилятора сквозь `Option` этого не видит
(подтверждено на rustdesk `record.rs:217/223/229/368`). Действующее правило `discarded-result`
(shipped, D090) покрывает `let _ = …` и инструкцию-уровня `.ok()`. Собственный код AgentRig этого
паттерна не содержит (проверено).

## Proposal

Расширить существующий вид правила `discarded-result` (D090) двумя под-паттернами. Наблюдаемое
поведение:

- **AC1 — отброшенный Option-комбинатор на уровне инструкции.** Выражение-инструкция, чьё значение
  отбрасывается и чья последняя операция — `.map(…)` / `.and_then(…)` / `.map_or(…)` /
  `.map_or_else(…)`, → находка. Внешне похожее нарушенное состояние (сегодня): такой код молча
  проходит гейт. То же значение в позиции присваивания/возврата/аргумента (не отброшено) → не
  находка.
- **AC2 — `.err()` на уровне инструкции.** К существующей проверке инструкции `.ok();` добавить
  `.err();` (симметрично: молча отброшенный `Option` ошибки).

**Границы и неизвестное.** Проверяется только отбрасывание значения цепочки, а не фаллибельность
тела замыкания (она требует типов, D059) — поэтому `opt.map(|x| x + 1);` без побочных эффектов
формально тоже под AC1; это принято как near-zero-FP, поскольку в чистом коде такой отброшенный
`map` почти не встречается. Расширение существующего вида → поведение детектора меняется, доставка
двухфазная (D051). Decision, расширяющий D090, — при доставке.

## Expected benefit

Молча отброшенные результаты Option-комбинаторов (частый носитель «забыл присвоить/вернуть»)
ловятся из коробки, в дополнение к уже покрытым `let _ =` и `.ok()`. Переносимо.
