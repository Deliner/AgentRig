# B142 — State описывает текущую VAC

## Context

- 2026-11-14 пользователь: «надо в правилах агента настроить так, что текущий state md файл, ты обновляешь после
  каждого коммита. То есть ты закоммитил и пишешь в стейте, что ты будешь делать в следующем коммите,
  соответственно. Ну, не в коммите, а вот это verified atomic change я имею в виду. Ну, соответственно, те комметы,
  которые мерж ветки, тебе там ничего писать не надо».
- 2026-11-19 пользователь: «я ожидаю, что у нас появятся в правилах требования, что state — это описание текущего
  VAC. Соответственно, после коммита state должен автоматически обнуляться, и после мержа тоже. Вот, и ограничение
  на размер файла — это типа 100 строк при ширине 120. При ошибке нужно, соответственно, скилл показывать, который
  будет говорить, как правильно стейтом пользоваться».
- 2026-11-19 пользователь: «каждый комит несет стейт. Своей VAC. Они должны быть в гите. Я не знаю, а мы можем в фича
  старт и фича мердж добавить так, чтобы они коммитили, а не игнорировали. … Не хочу игнорировать стейт из гита, но
  не хочу, чтобы у агента было больше команд для поддержки».
- Требование 2026-11-19 заменяет прежнее направление карточки: запись о прошлой VAC после коммита.
- Сейчас AGENTS.md велит обновлять State на значимых границах задачи и VAC и включать его в соответствующую VAC. Хук
  по D047 останавливает первый коммит VAC в контексте, пока агент не прочтёт навык edit-state; заполнен ли State, хук
  не проверяет. Размер и ширину State lint не проверяет.
- В voxel-rust похожее правило агент выполняет вручную: после коммита переписывает State заново, лимит 150 строк.

## Proposal

- **AC1. Правило.** Правила рига и `init` говорят, что State описывает только текущую VAC и что каждый коммит несёт
  State своей VAC.

  Проверка: текст AGENTS.md, CLAUDE.md и навыка edit-state.
- **AC2. Сброс после коммита.** После коммита на ветке State сам становится пустым шаблоном в рабочем дереве.
  Следующий коммит несёт State следующей VAC.

  Проверка: тест в проекте после `init`.
- **AC3. Пустой State не проходит.** Коммит на ветке с пустым шаблоном State отклоняется, и ошибка называет
  абсолютный путь к навыку edit-state. Коммит настройки после `init` тоже описывает свою VAC.

  Проверка: тест гейта.
- **AC4. Слияние.** `feature-merge` сам коммитит сброшенный State отдельным коммитом на ветке и затем сливает её.
  После слияния база чистая, и State на ней пустой. `feature-start` коммитить ничего не нужно: после слияния дерево
  чистое, а незакоммиченное B147 переносит на новую ветку. Новых команд у агента нет.

  Проверка: тест слияния.
- **AC5. Размер.** Если в State больше 100 непустых строк или есть строка шире 120 символов, lint даёт ошибку и
  коммит не проходит. Ошибка называет абсолютный путь к edit-state.

  Проверка: тест lint.

**Границы.**

- Долгосрочные заметки из раздела Focus в State рига переезжают в карточки, к которым они относятся.

## Expected benefit

State всегда описывает текущую VAC и остаётся коротким, каждый коммит несёт State своей VAC, а агенту не нужны
лишние команды, чтобы так его вести.
