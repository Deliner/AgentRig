# B106 — Свои структурные правила, вторая партия

## Context

- После разметки 2026-11-10 эти формы остались без проверки. По D151 проверку нужно держать, если она повышает
  качество, даже когда в риге такого кода нет.
- Clippy этих форм не видит, а проверить их можно по синтаксису без типов.

## Proposal

- Каждая форма получает свой вид правила и навык исправления.
- II-7 становится параметром существующего правила `boolean-expression`. Отдельного правила для него нет.

| Группа | Формы |
| --- | --- |
| Позиция и имена | II-2 два параметра одного типа; II-3 tuple struct и вариант с двумя полями одного типа; III-12 позиционные аргументы-выражения; III-13 значение с именем соседнего поля |
| Обёртку не обойти | II-5 type-алиас на примитив; III-1 открытые поля при проверяющем конструкторе; III-2 Deref у обёртки; III-3 From<примитив>; III-4 открытый &mut-геттер |
| Полнота | II-14 ручной impl без полной деструктуризации; III-6 == с вариантом и matches!; III-7 охранные условия match со сравнением; III-8 тело метода трейта по умолчанию без self |
| Состояния | II-22 Option<bool>; III-21 поле-состояние рядом с Option-полями; III-25 Option<коллекция> |
| Условия и циклы | II-7 смешение && и \|\|; III-14 затенение имени из объемлющего блока; III-29 счётчик с continue; III-30 булев флаг в цикле |
| Прочее | III-24 строковый ключ; III-26 парные вызовы с выходом между ними, список пар настраивается |

- **AC1.** Точность каждого правила на риге и voxel-rust не ниже 90%. Правило ниже этого порога не поставляется, и
  отказ записывается.
- **AC2.** Находки в коде рига исправлены.
- **AC3.** `init` ставит эти правила в проекты.

**Границы.**

- У каждой формы один владелец.
- Неизвестно, сколько находок дадут правила и насколько они точны. Для II-3, III-21, III-24, III-26 и III-29 карточки
  списков сами ждут много ложных находок.

## Expected benefit

Формы ошибок, которые не видят ни Clippy, ни правила рига, запрещены и в риге, и у потребителей.
