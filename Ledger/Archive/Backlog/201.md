# B201 — Запись одобрения кладёт в Git только файлы, где бывают исключения lint

## Context

- 2026-11-21 пользователь, уходя: «Как закончишь, то продолжай автономно улучшать проект без изменения поведения с
  точки зрения бизнес правил. Можешь оптимизировать и ускорять, упрощать и рефачить. Все в рамках текущих правил. Сам
  заведи карточку и аппрувни ее, мне показывать не надо». Позже в тот же день: «Даю ок на еще 10 часов работы».
  Карточки B181–B200 этого поручения выполнены.
- `init` и `just approve` записывают одобрение: идентификаторы содержимого защищённых файлов и новые исключения lint
  рабочего дерева. Для этого `git update-index` кладёт в базу объектов Git каждый изменённый файл, а проверка
  исключений читает каждый из них обратно. Исключение бывает только в файлах yaml, toml, rs, py, pyi и sh; в остальных
  проверка всегда находит пустой список.
- Временный таймер на master `8eddf53`, тест хуков с одним `init`: запись одобрения занимает 0,75 с из 1,05 с всего
  `init`, из них 0,48–0,50 с `git update-index` для 125 файлов шаблона. Среди них исполняемый файл рига, в тестах это
  тестовый бинарник 37,8 МБ. В полном прогоне 617 тестов `init` запускается 164 раза, и под нагрузкой эта команда
  занимает 0,5–3,4 с на запуск.

## Proposal

- **AC1. Поведение то же.** Команды рига, их вывод, находки и их порядок, тексты ошибок, коды выхода, форматы файлов
  и конфигурации не меняются.

  Проверка: все тесты проходят, ни один не удалён и не отключён, их число не уменьшается.
- **AC2. Запись одобрения кладёт в базу объектов Git только файлы yaml, toml, rs, py, pyi и sh; для остальных она
  берёт только идентификатор содержимого, тот же, что даёт индексирование. Проверка исключений при одобрении и при
  коммите читает содержимое только таких файлов.**

  Проверка: в Delivery замер записи одобрения при `init` и полного прогона тестов, одним способом до и после.
- **AC3. Правка не добавляет находок lint.**

  Проверка: `just lint` на голове ветки без находок.

**Границы.** Новые правила, виды проверок, зависимости и решения о поведении не вводятся. Пороги, селекторы,
исключения и бюджеты lint не ослабляются. Защищённые файлы не меняются. Пин ветки ставит пользователь командой
`! just approve`.

## Expected benefit

`init` и `just approve` идут быстрее, а тесты рига и гейт меньше пишут на диск и заканчиваются раньше.
