# B022 — Тестовая дисциплина: поведение через публичную поверхность на правильном уровне

## Context

Тесты сейчас лежат в `tests/` владеющей фичи и названы по поведению, но политика
выбора уровня размещения, запрета тестировать приватную реализацию и требования
проверять наблюдаемое поведение нигде не записана и не проверяется. Пользователь
зафиксировал три принципа и поручил дополнить теми, к которым пришли при доведении
кодовой базы до хорошего состояния. Источник: обсуждение тестовой дисциплины,
согласовано пользователем 2026-10-28.

## Proposal

Зафиксировать тестовую дисциплину как durable-policy. Статически проверяемые пункты
становятся правилом линтера/инвариантом с оракулом и уезжают в поставку `init` (по
[D053](../../Decisions/053.md)/[I020](../../Invariants/020.md)); непроверяемые остаются
нормой-навыком, обязательной при приёмке VAC, и тоже уезжают к потребителю.

**TC1 — размещение по области.** Тест лежит рядом с тем, что он проверяет. Если тест
проверяет поведение шире одной единицы — поднимается к общему владельцу этого
поведения; если уже — опускается к конкретной единице. Уровень выводится из области
поведения и владельца (architecture.yaml), а не из удобства.

**TC2 — только публичная поверхность.** Тесты обращаются только к публичным
входам/методам того, что тестируют. Элемент, сделанный публичным лишь ради
возможности его протестировать, — дефект: он выявляется и исправляется (становится
приватным / `pub(crate)` / тестовым либо покрывается через публичный путь).

**TC3 — поведение, а не состояние.** Тесты проверяют наблюдаемое пользователем
поведение системы в том виде, как он её видит, а не её внутреннее состояние.

**TC4 — без чёрных ходов.** Запрещён доступ к приватным внутренностям в обход
публичного API (прямое чтение полей, рефлексия, хуки «только для тестов») — следствие
TC2/TC3.

**TC5 — имя по поведению.** Имя и намерение теста описывают проверяемую возможность,
а не приём реализации.

**TC6 — без дублей через нижний уровень.** Если поведение покрыто тестом на правильном
уровне, его не дублируют тестом, лезущим во внутренности более низкого уровня;
предпочитается один ценный поведенческий тест. Связка с правилом «тест судится по
коду, который он трогает».

**TC7 — enforcement и докфудинг.** Где принцип статически проверяем, он становится
правилом линтера/инвариантом и уезжает в поставку `init`: в первую очередь Rust —
`pub`-элемент, на который ссылаются только тесты (кандидат на TC2), и размещение
тестового файла относительно architecture.yaml владельца (кандидат на TC1). Где
статически непроверяемо (TC3, во многом TC4) — остаётся нормой-навыком, обязательной
при приёмке VAC, и тоже уезжает к потребителю.

**Границы и неизвестное.** Статическое выявление TC2 в Rust (pub, используемый только
тестами) требует реальной реализации измерения — осуществимость подтверждается на
этапе реализации. В Python приватность не форсируется языком, поэтому там TC2/TC4 —
норма ревью, а не линт. TC3 в общем случае механически не детектируется и остаётся
нормой.

## Expected benefit

Тесты переживают рефакторинг и не ломаются от смены внутренностей; давление тестов не
протекает в публичный API продукта; место теста однозначно выводится из области
поведения — и всё это проверяется у потребителя из коробки, а не держится в голове.
