# B075 — профиль dev-гейта: пять линтов clippy, которым нужны типы

## Context

Пользователь 2026-11-07 (/goal, п. 3): новые правила искать в разборе clippy, где проверки с типами уже написаны и
отлажены. Разбор `agentrig-research/clippy-triage.md` (clippy 1.98.1 — версия гейта, master `c1935e4`): прогон
pedantic, nursery и restriction по продуктовому коду без тестов дал 81 линт с 5 400 срабатываниями. Отобраны пять
линтов: каждому нужны типы, которых не видит правило tree-sitter, и ни один не дублирует правило AgentRig. Остальные
отвергнуты в разборе с причинами: шум без дефектов, дубль существующего правила, класс, отвергнутый пользователем
(D107).

| Линт | Группа | Класс дефекта | Сайтов на `c1935e4` |
| --- | --- | --- | --- |
| `string_slice` | restriction | срез `&str` по байтовому смещению внутри символа UTF-8 паникует; AgentRig режет Markdown с `—`, исходники, TOML и YAML | 16, все безопасны за счёт инварианта в другом месте |
| `iter_over_hash_type` | restriction | обход `HashMap`/`HashSet` даёт разный порядок от запуска к запуску, а диагностика и отчёты сравниваются | 1, безвреден |
| `collection_is_never_read` | nursery | локальная коллекция только пишется: собранные находки не возвращаются, и гейт проходит молча | 0 |
| `read_zero_byte_vec` | nursery | `read` в `Vec::with_capacity(n)` возвращает 0, и цикл чтения принимает это за EOF | 0 |
| `unchecked_time_subtraction` | pedantic | `Duration - Duration` и `Instant - Duration` паникуют при переполнении | 0 |

## Proposal

- **AC1–AC5 — по одному VAC на линт.** Профиль clippy в `.agentrig/commands.yaml` получает `-D clippy::string_slice`,
  `-D clippy::iter_over_hash_type`, `-D clippy::collection_is_never_read`, `-D clippy::read_zero_byte_vec` и
  `-D clippy::unchecked_time_subtraction`; гейт зелёный. Признак работы каждого: пробный фрагмент с нарушением
  проваливает clippy, его удаление возвращает зелёный.
- **AC1, ремонт.** Сайты `string_slice` переписаны без среза строки (`strip_prefix`, `get(..)`, `trim_start_matches`,
  обход `chars()`). Единственный владелец срезов по диапазонам узлов tree-sitter, `text()` в
  `structural_lint/languages/mod.rs`, остаётся со срезом под `#[allow(clippy::string_slice)]` и строкой DECISION
  (D080).
- **AC2, ремонт.** Граф ссылок в `project_memory` хранится в упорядоченной карте; порядок обхода не зависит от запуска.
- **AC6 — запись.** Решение, расширяющее D060, фиксирует набор и отвергнутые линты с причинами из разбора.

**Границы и неизвестное.** Только dev-гейт этого репозитория (D060), потребителям не поставляется.
`iter_over_hash_type` видит только циклы `for` по карте и её итераторам, `collect()` из карты не ловит. Linux-ветки
`command_runner/jobs/identity` и `command_runner/sandbox.rs` на macOS не компилируются, и clippy их не проверяет ни
сейчас, ни после. Число сайтов взято на `c1935e4` и пересчитывается при доставке.

## Expected benefit

Dev-гейт ловит паники среза строк на не-ASCII тексте, нестабильный порядок вывода, молча потерянные находки, обрезанное
чтение и паники вычитания времени: классы, которые синтаксическое правило не видит.
