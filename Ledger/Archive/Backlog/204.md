# B204 — После слияния ветки риг удаляет всё, что Git игнорирует, кроме явно сохраняемого

## Context

Незакоммиченные файлы в репозитории рига заняли около 52 ГиБ и заполнили диск на 99 %: сборки Cargo, Python-окружения,
кеши линтеров и тестов, около 220 старых версий рантайма и журналы 65 тысяч завершённых запусков. Пользователь удалил
их вручную, и свободное место выросло с 8,5 до 61 ГиБ. Он хочет, чтобы после слияния ветки это происходило само, во
всех проектах с ригом, а сохранялось только то, что явно помечено. Сейчас `feature-merge` после слияния лишь
останавливает фоновые запуски слитой ветки и файлов не удаляет.

## Proposal

Очистка после слияния:

- **Когда:** после каждого успешного `just feature-merge` в любом проекте с ригом, включая сам риг. Отдельную команду
  вызывать не нужно.
- **Что удаляется:** все файлы и каталоги проекта, которые Git игнорирует. В риге среди них старые версии рантайма в
  `.cache/development`.
- **Что сохраняется:**
  - рабочее состояние рига: закреплённый рантайм, согласие и одобрения, предложения, ждущие одобрения, требование
    компактизации, записи ещё идущих запусков (включая само слияние);
  - пути из списка сохраняемых, который ведёт проект;
  - всё, что Git отслеживает, и всё за пределами проекта, например `~/.cargo` или кеш `uv` в профиле.
- **Что видно пользователю:** вывод слияния называет удалённое и освобождённый объём.
- **Если удалить не удалось:** слияние остаётся выполненным. Вывод называет путь и причину, а следующее слияние пробует
  снова.

Список сохраняемых:

- Проект перечисляет в своих настройках `.agentrig/` пути, которые очистка не трогает. Допускаются шаблоны, например
  `.env*`.
- По умолчанию список пуст.
- Изменить список можно, как и другие настройки, защищённым изменением через `just approve`.
- Чтобы не пересобирать проект после каждого слияния, в список можно внести каталог сборки.

Последствия:

- Без такого исключения первая сборка и проверки после слияния идут с нуля и длятся дольше. Это цена освобождённого
  места.
- Список по умолчанию пуст, поэтому в проектах, установленных раньше, первое слияние на новом рантайме удалит `.env` и
  другие локальные файлы, если их заранее не внести в список.

Приёмка:

- **AC1.** В проектах Python и Rust, созданных `init`, после успешного `just feature-merge` удалены игнорируемые файлы
  и каталоги: `__pycache__`, `.ruff_cache`, каталог сборки, журналы завершённых запусков. Вывод слияния называет
  удалённое и освобождённый объём.
- **AC2.** Путь из списка сохраняемых (например `.env`) после слияния на месте. Если убрать путь из списка, следующее
  слияние его удаляет.
- **AC3.** После слияния на месте закреплённый рантайм, согласие, одобрения, предложения, требование компактизации и
  записи идущих запусков. `just jobs` показывает идущие запуски, а хуки и рецепты работают без `just bootstrap`.
- **AC4.** В риге после слияния в `.cache/development` остаётся только закреплённая версия рантайма.
- **AC5.** Файлы, которые Git отслеживает, и всё за пределами проекта после слияния не меняются.
- **AC6.** Если путь удалить нельзя, слияние выполнено, вывод называет путь и причину, а следующее слияние пробует
  удалить его снова.

## Expected benefit

Незакоммиченные файлы не копятся на диске от ветки к ветке. Чистить вручную и помнить, что удалять нельзя, не нужно:
сохраняемое помечено явно.
