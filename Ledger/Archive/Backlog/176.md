# B176 — Свой код не берёт из входа

## Context

- 2026-11-20 пользователь выбрал: вход это оглавление, то есть части, API и сборка. Типы живут в файлах.
- Сейчас навык `refactor-large-directory` и README правила разрешают держать типы во входе. Отсюда 17 директорий с
  петлёй через `mod.rs`.
- Замер рига: из 83 входов 26 используются изнутри, это 76 рабочих файлов.

## Proposal

- **AC1. Находка.** Правило `entry-use` даёт ошибку, когда рабочий файл использует вход своей директории или
  директории выше. Реэкспорт во входе не помогает: свой код обращается к файлу-владельцу напрямую.

  Проверка: `jobs/cleanup.rs` пишет `use super::Job`, а `Job` определён или реэкспортирован в `jobs/mod.rs`: находка.
  `use super::job::Job`: находки нет. `jobs/guard/x.rs` использует `jobs/mod.rs`: находка. Файл из другой директории
  использует `jobs/mod.rs`: находки нет.
- **AC2. Тесты.** Тестовый код вход использовать может.

  Проверка: `jobs/tests/mod.rs` с `use super::*`: находки нет.
- **AC3. Текст находки.** Источник со строкой и входной файл.
- **AC4. Навык `move-out-of-entry`.** Перенести тип или функцию из входа в файл с именем по смыслу; своему коду
  обращаться к этому файлу. Если тип нужен поддиректории, которую использует вход, положить его в отдельную
  часть-соседа, иначе выйдет цикл директорий. Запрещает свалки `types`, `common`, `utils`.
- **AC5. Риг и проекты.** Правило включено в риге и после `init`, для Rust и Python. Код рига приведён к правилу.
  Навыки `refactor-large-directory`, `anchor-at-crate` и README правила `architecture` не противоречат правилу.

**Границы.** Вход может содержать сборку и функции API; пустым быть не обязан.

## Expected benefit

Вход каждой директории читается одинаково: что в ней есть и что она отдаёт. Вместе с проверками циклов в графе файлов
не остаётся ни одного цикла.
