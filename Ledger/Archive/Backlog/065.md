# B065 — Поставка `init` и диагностика lint соответствуют записанным решениям (находки раунда 8)

## Context

В раунде 8 мета-цикла (2026-11-05) поставка `agentrig init` ревизии `1fad15d` прогонялась на 18 чужих
Rust-репозиториях; критик (Codex gpt-6.1-sol) подтвердил закрытый список расхождений между поставкой, решениями Ledger и
документацией: (1) правила, чьи решения обещают поставляемые исключения `**/tests/**` / `**/tests.rs` (D082, D084, D085,
D088, D089, D090, D092, D096, D100), поставляются без них — у super-super-reach тестовый путь даёт 0/5 полезных хитов
против 19/20 вне его; (2) `init` для Rust выводит `rust_roots` как `<source>/src/lib.rs` и тестовую команду
`cargo test --manifest-path <source>/Cargo.toml`, что при стандартной раскладке (`--source src`) даёт несуществующие
`src/src/lib.rs` и `src/Cargo.toml` (vaultwarden: 7 438 находок «no successfully analyzed Rust crate root» из 12 130);
(3) `unsafe-justification` флагует токен `unsafe` атрибута `#[unsafe(method(..))]` внутри аргументов макроса, хотя D103
выводит `#[unsafe(..)]` из правила (2 из 25 свежей выборки); (4) поле `rerun` находки теряет флаги `--json`/`--warnings`;
(5) находка `configuration` при отсутствии файла навыка печатает «No such file or directory (os error 2)» без пути;
(6) `Project/README.md` называет поле `measurement` вместо `actual` и не называет `message`; (7) навыки ремонта
расходятся с реализацией: remove-debug разрешает удалить `dbg!(expr);` вместе с вычислением (bevy
`function_reflection.rs:74–84` — побочный эффект), anchor-at-crate не называет видимость `pub(in super::super)` и
поставляемую границу файлов, justify-unsafe/-allow/-skip не называют единственную принимаемую форму обоснования,
split-boolean-parameter, own-the-resource, name-the-record и remove-secret описывают предикат неточно.

## Proposal

- **AC1.** `agentrig init` (любой язык) и `lint-rule <kind> --example` выдают `exclude` ровно с теми селекторами, которые
  обещает решение каждого правила (`**/tests/**`, `**/tests.rs`), ровно для девяти правил: panic-path (D082),
  debug-assertion (D084), wildcard-import (D085), tuple-as-record (D088), eager-fallback (D089), discarded-result (D090),
  disabled-raii (D092), global-state (D096), super-super-reach (D100); остальные правила — без `exclude`. Проверка через
  публичную поверхность: после `init` файл `<source>/tests/x.rs` с `.unwrap()` не даёт panic-path, файл `<source>/x.rs` —
  даёт; `unsafe` без ссылки в `<source>/tests/x.rs` даёт unsafe-justification (исключения нет).
- **AC2.** `init --language rust` выводит `rust_roots`, `rust_crates` и манифест тестовой команды из реального манифеста
  (`<source>/Cargo.toml`, иначе `<root>/Cargo.toml`): корни — существующие `[lib] path`/`src/lib.rs` и `[[bin]]
  path`/`src/main.rs` пакета и каждого члена workspace (`members` с глобами); `rust_crates` — имя пакета (`-` → `_`) →
  корень lib; тестовая команда — `cargo test --manifest-path <найденный манифест>`; без манифеста — прежние формулы.
  Проверки: одиночный бинарный крейт (`Cargo.toml` в корне, `src/main.rs`, `--source src`) → `rust_roots: [src/main.rs]`,
  команда `cargo test --manifest-path Cargo.toml`, `lint --json` без находок `architecture` «crate root is missing» / «no
  successfully analyzed Rust crate root»; workspace (`crates/a` — lib, `crates/b` — bin) → оба корня и
  `rust_crates: {a: crates/a/src/lib.rs}`; раскладка AgentRig (`--source Project`) — без изменений.
- **AC3.** `unsafe-justification` не флагует `unsafe`, открывающий атрибут `#[unsafe(..)]` внутри `token_tree` (D103), и
  продолжает флаговать `unsafe { … }` и `unsafe fn` в теле макроса; фикстура с `define_class!` в
  `languages/tests/unsafe_site.rs`.
- **AC4.** `rerun` каждой находки при `lint --json --warnings` содержит `--json` и `--warnings` и выполняется бинарником.
- **AC5.** Находка `configuration` при отсутствии файла навыка содержит путь отсутствующего файла: `init`, удалить навык,
  `lint --json` → `message` содержит путь.
- **AC6.** `Project/README.md` перечисляет фактические поля JSON находки: rule, path, line, symbol, actual, limit, level,
  message, skill, rerun.
- **AC7.** Канонические навыки ремонта совпадают с реализацией: remove-debug — `dbg!(expr);` с побочным эффектом
  заменяется на `expr;`, удаляется только безэффектное (политика D081 «committed `dbg!` has no legitimate use» остаётся);
  anchor-at-crate — называет пути видимости `pub(in super::super)` и поставляемое исключение `**/tests/**`/`**/tests.rs`;
  justify-unsafe, justify-allow, justify-skip — называют единственную принимаемую форму (ссылка `DECISION:`/`INVARIANT:`
  строкой выше) и то, что `// SAFETY:`, `# Safety`, `reason = ".."`, `#[ignore = ".."]` правило не читает, как
  соглашение проекта; split-boolean-parameter — флагуются и фактические аргументы, ремонт — именованный тип;
  own-the-resource — `.keep()`/`.into_path()` узнаются по имени метода без проверки получателя (D092); name-the-record —
  обращение с unit-типом как в реализации (`rust.rs::record_signature`); remove-secret — точные форматы литералов из
  `Project/shared/syntax/mod.rs`. I020 (`test_delivery`) остаётся зелёным.

**Границы и неизвестное.** PF3 (эвристика «файл с тестовой fn и без `pub` — тестовый код») не поставляется (Tier 2);
`include: src/**` не меняется; формы обоснования (`// SAFETY:`, `reason =`, `#[ignore = ".."]`) не принимаются —
политика, решение пользователя; silent-error (D097) и recursive-deletion (D102 — о правиле репозитория) — без
поставляемого исключения; предикаты D081, D092 и global-state не меняются; новых решений нет — статьи D020
неизменяемы, ссылки применения переезжают к новым владельцам, если проверка консолидации того требует.

## Expected benefit

Консумер получает поставку, совпадающую с записанными решениями: на стандартной раскладке уходят 7 438 ложных находок
`architecture`, тестовые хиты правил с обещанием исключения и PE D103; `rerun` воспроизводит находку; диагностика
называет файл; навыки не ведут агента к ошибочному ремонту.
