# B074 — проверка архитектуры видит модули под фичами (Rust)

## Context

Прогон линтера на voxel-rust 7 ноября 2026. В корне крейта модуль подключён по условию
фичи:

```rust
#[cfg(all(feature = "native", not(target_family = "wasm")))]
#[path = "../native/mod.rs"]
pub mod native;
```

Анализ зависимостей понимает в `cfg` только `test`, `unix`, `windows`, `target_os` и
`target_family`. Условие `feature` он не разбирает, объявляет корень крейта
непроанализированным, и проверка архитектуры выключается для всего крейта: 4667 находок
«анализ зависимостей неполный» и ни одной проверки циклов, бюджета зависимостей и зон.
Модули под фичами в Rust обычны, так что потребитель теряет проверку из-за одной строки
в `lib.rs`. Карточка заведена как кандидат; в Plan не выбрана.

## Proposal

- **AC1 — условие фичи разбирается.** `cfg` с `feature = "…"`, в том числе внутри `all`,
  `any` и `not` вместе с уже понятными условиями: модуль под таким условием считается
  подключённым, его файлы участвуют в проверке архитектуры, находки «Rust conditional
  expansion is not analyzed» на такой строке нет.
- **AC2 — проверка работает сквозь такой модуль.** Фикстура: модуль под фичей импортирует
  модуль, который импортирует его обратно → находка цикла. Сегодня на таком крейте
  проверка не выполняется.

**Границы и неизвестное.** Другие причины неполного анализа не входят: `include!`
Rust-файлов, макросы, порождающие зависимости, прочие ключи `cfg`, например
`target_arch`. Правило «один неразобранный элемент в корне выключает анализ крейта» не
меняется. Перепроверка на копии voxel-rust при доставке: находка «нет проанализированного
корня крейта» исчезает.

## Expected benefit

Проверка архитектуры, включая циклы зависимостей, работает на крейтах с модулями под
фичами, а не выключается целиком из-за одной строки в `lib.rs`.
