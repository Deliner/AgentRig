# B078 — политика `disallowed` ловит методы файловой системы с ошибкой без пути

## Context

Пользователь 2026-11-07 (/goal, п. 3): правила из реальных ошибок агентов. Разбор `agentrig-research/agent-errors.md`,
класс C3 «ошибка ввода-вывода без пути или с ложным контекстом»: исправления 0d6ce60, 579474d и 324326e → 3765724.
Функциональную форму `fs::read_to_string(path)?` теперь ловит политика `disallowed` для `std::fs` (D105, D106).
Методная форма её обходит: после переезда на `shared::fs` в 324326e остался `root.join(value).canonicalize()?`, его
ошибка «No such file or directory (os error 2)» не называла путь, и нашла её только критика B065.

На HEAD разбора `ff23ad9` 15 строк (16 вызовов) вне `Project/shared/fs` пробрасывают `io::Error` без пути через `?`
или `.map_err(Into::into)`: `try_exists()?` в `project_memory/mod.rs`, `file.metadata()?` в
`shared/artifacts/mod.rs`, сайты в `structural_lint/architecture`, `structural_lint/cli.rs`, `command_runner`,
`agent_hooks/transcript.rs`, `project_config/mod.rs`, `project_setup/initialization/init.rs` и
`command_line/main.rs`. В voxel-rust около 25 доменных вызовов `world.metadata()`, ни один не под `?`; поэтому
условие проброса обязательно.

## Proposal

- **AC1 — методы в политике.** Запись `disallowed` может перечислить имена методов. Вызов перечисленного метода без
  аргументов, результат которого сразу пробрасывается через `?` или `.map_err(Into::into)`, в файле вне `allow`
  записи — находка в строке вызова с причиной и заменой из записи. Не находки: тот же вызов без проброса
  (обработанный `match`, `.ok()`, `if let`), вызов с аргументами, вызов в разрешённом файле. `lint-config-check`
  отвергает пустое имя метода; `lint-rules` описывает поле.
- **AC2 — догфуд.** Запись `std::fs` в `.agentrig/lint.yaml` перечисляет `canonicalize`, `read_dir`, `metadata`,
  `symlink_metadata`, `read_link` и `try_exists`. Текущие сайты вызывают обёртки `crate::shared::fs`, недостающие
  обёртки добавлены во владельца, ошибки этих вызовов называют действие и путь; `just candidate lint` — 0 находок.

**Границы и неизвестное.** Методы дескриптора (`write_all`, `sync_all`, `read_to_end`) не входят: они обслуживают и
stdin/stdout, исправлений по ним нет. Метод определяется по имени, без типа получателя: доменный метод с тем же именем
под `?` тоже станет находкой; в обоих деревьях таких нет. Добавляет ли вызывающий контекст выше по стеку, по сайтам
не проверялось. Поставляемый потребителям `lint.yaml` по-прежнему без записей (D105). Изменение существующего правила
доставляется в две фазы с пином (D051).

## Expected benefit

Ошибка файловой системы в продукте всегда называет действие и путь, и агент не обходит владельца `shared/fs`,
переписав вызов функции вызовом метода.
