# B034 — Зоны и границы окружения

## Context

Набор II улучшений качества (переносимо на любое приложение, agent-native) — мозгоштурм и
экспертный разбор 2026-10-31. Пользователь согласовал весь набор (10 кластеров C1–C10) на
автономное исполнение по моей рекомендации. Спайк по C1 (зонирование) показал: класс зоны —
новое измерение (поле `type`/`Kind` D044 — про форму фичи, не про эффекты), но механизм без
потребителя нарушает complexity-discipline. Поэтому по решению пользователя 2026-10-31 C1
(зонирование) и C2 (границы окружения) объединены в одну фичу: зона вводится вместе с первым
правилом, которое её читает. Контракт — ревизия карточки в Git.

## Proposal

Модуль помечается классом зоны из фиксированного набора (напр. `pure`, `io-adapter`,
`api-surface`, `hot-core`, `test`); класс определяет, что модулю разрешено по части окружения.
Так единый переносимый набор дисциплины ложится на любой домен: интенсивность правил берётся из
класса зоны, а не хардкодится под приложение. Граница зоны явная (модуль/каталог).

- Класс зоны объявляется в архитектурном контракте модуля; значение из фиксированного набора;
  неизвестный класс — ошибка конфигурации (`lint-config-check`). *[контракт]*
- Зонозависимая граница окружения: прямой доступ к окружению/ОС/IO (фиксированный набор std-путей,
  напр. `std::env`/`std::fs`/`std::net`/`std::process`/часы) вне зоны, где это разрешено (напр.
  `io-adapter`), — находка до коммита; escape `DECISION:`/`INVARIANT:`. *[правило/зона]*
- Импорт платформенных/IO-крейтов ограничен по зоне через существующий external-механизм. *[контракт]*
- Возможность уезжает в `init` ([D053](../../Decisions/053.md)/[I020](../../Invariants/020.md)); наш
  код зелёный под новым поведением (догфуд).

**Границы.** Только Rust-движок и `Project`. Централизация чтения конфигурации и протечка типов
зависимостей в публичную поверхность — норма (norm-or-choice, [D035](../../Decisions/035.md)/D059),
не правило. Расширение схемы `architecture.yaml` новым полем требует решения (сейчас
[D043](../../Decisions/043.md) ограничивает поля purpose/files/directories) — фиксируется в первом
VAC. Притворный инвариант не вводится. Точный набор классов зон и std-путей выбирает исполнитель
спайком.

## Expected benefit

Один переносимый набор дисциплины качества адаптируется к любому приложению через метки зон;
платформенная/IO-связанность не протекает в ядро незаметно — код остаётся портируемым, а радиус
правки для агента малым.
