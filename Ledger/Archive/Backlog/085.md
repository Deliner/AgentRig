# B085 — config-check: покрытие affected только в границах проверки

## Context

- При переносе voxel-rust у проекта две проверки на `cargo test`.
- Проверка `tests` запускает тесты без фич, и её include охватывает src/core, src/render, src/schema и файлы сборки.
- Проверка `native-tests` запускает `cargo test --features native --lib`.
- Тесты в src/native/game.rs, hardware.rs, worker.rs и src/native/storage/tests.rs существуют только с фичей native:
  `tests` их не компилирует, и её include их не касается.
- Правило D124 смотрит все .rs файлы репозитория и требует, чтобы цели `tests` выбирали эти тесты.
- Пройти можно только целями, которые под командой `tests` ничего не выбирают.

## Proposal

- **AC1.** `config-check` проверяет карту affected каждой проверки только на файлах из её include. Файл вне include не
  даёт для этой проверки ни ошибку «только группы без целей», ни ошибку «тест не выбран». Проверка: конфигурация voxel
  проходит `config-check` без этих 4 ошибок, а тестовый файл внутри include, который не выбран ни одной целью, по-прежнему
  даёт ошибку.
- **AC2.** Гейт выбирает тесты так же, как раньше. Проверка: существующие тесты выбора проходят без изменений.
- **AC3.** Новое решение уточняет D124 только в части того, какие файлы проверяются.

**Границы.**

- Проверка с include по умолчанию, то есть на все файлы, ведёт себя как сейчас.
- Модули, подключённые через `#[path]`, получают префикс от ближайшего main.rs.
- В voxel я обошёл это целями без префикса `native::`, например `game::tests::`: они выбирают те же тесты.
- Карточка это не меняет.

## Expected benefit

Проекты с отдельными наборами тестов под разные фичи проходят `config-check` честной картой, без целей, которые ничего
не выбирают.
