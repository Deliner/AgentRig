# B057 — disallowed-path: запрещённые пути по политике и владелец `shared/fs`

## Context

Исследовательская дуга (`coverage-map.md` шаг 6 «fs-context»/`disallowed-path`, критика r0:
главный кандидат Tier 1; `meta/register.md`, ремонты 1 и 5). Голый `std::fs::X(..)?` возвращает
`io::Error` без пути: агент видит «os error 2» и ищет файл по коду; наш код — худший в корпусе
(43 сайта, 311 на 100k строк). Общий механизм — список запрещённых путей с причиной и заменой,
применяемый через существующий резолвер архитектуры (псевдонимы, локальные крейты,
`use`-привязки) с исключениями по каталогам-владельцам. Продуктовый исход для нашего кода —
владелец `shared/fs` с обёртками, несущими путь. Авторизовано 2026-11-04 (/goal).

## Proposal

- **AC1 — политика `disallowed`.** Настройки правила `directory-architecture` принимают список
  записей `{path, reason, replacement, allow: [glob…]}`. Ссылка в анализируемом файле,
  разрешённая резолвером в `path` или его подпуть (по сегментам), → находка в строке ссылки с
  сообщением «`<путь>` is disallowed here: <reason>; use <replacement>», если файл не подпадает
  под `allow`. Неразрешимая или локальная ссылка (в том числе локальный модуль с тем же именем)
  — не находка. `lint-config-check` отвергает нелитеральный путь, пустую причину и невалидный
  glob; `lint-rules` описывает поле.
- **AC2 — владелец `shared/fs`.** Новый лист `Project/shared/fs` владеет доступом к файловой
  системе: чтение, запись, создание, удаление, обход, метаданные, ссылки, права; каждая ошибка
  несёт путь и действие, обход каталога отдаёт ошибки элементов с путём каталога; типы
  (`File`, `Permissions`), нужные вызывающим, реэкспортируются владельцем. Продакшн-код вне
  владельца не ссылается на `std::fs` и `std::os::unix::fs`; тесты могут.
- **AC3 — догфуд.** Наш `lint.yaml` содержит записи для `std::fs` и `std::os::unix::fs` с
  `allow: [Project/shared/fs/**, '**/tests/**', '**/tests.rs']`; `just candidate lint` — 0
  находок; поведение продукта не меняется (существующие тесты зелёные).

**Границы и неизвестное.** Изменение существующего правила → двухфазная доставка (D051);
decision при доставке. Поставляемый потребителям `lint.yaml` получает пустой список (политика —
проектная). Сообщение находки само несёт ремонт; навык правила остаётся
`refactor-large-directory`.

## Expected benefit

Проект объявляет, какие пути запрещены вне владельца, и гейт это держит; ошибки файловой системы
в AgentRig называют путь. Механизм переносим, ремонт — наш.
