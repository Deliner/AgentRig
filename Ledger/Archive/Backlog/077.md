# B077 — config-check находит пути, которые карта влияния проверки не покрывает

## Context

Пользователь 2026-11-07 (/goal, п. 3): правила из реальных ошибок агентов. Разбор `agentrig-research/agent-errors.md`,
класс C4 «карта влияния тестов пропускает путь»: 4 исправления в 2 репозиториях.

- 36b7823: цели называли один файл теста, и новые тесты того же каталога не выбирались.
- 6032647: оракул поставки не выбирался для изменений `Project/**`.
- da1a126: новый `Project/shared/fs/**` отсутствовал в карте `rust-test`.
- voxel-rust 744c366: `src/core/mesh_tests.rs` вне карты, нативный прогон шёл целиком.

Живой случай на master `3a5bcf2`: `Project/shared/console/**` и `Project/shared/mod.rs` попадают в карту `rust-test`
только через общую группу `{include: ['**'], targets: []}`, поэтому изменение там молча не выбирает ни одного
Rust-теста. Сейчас это нигде не проверяется: гейт считает непокрытым только пустой список групп, а общая группа делает
любой другой пропуск тихим.

## Proposal

- **AC1 — непокрытый исходный файл.** `just config-check` для каждой проверки с картой `affected` сообщает каждый
  поддерживаемый файл, изменение которого должно выбирать тесты этой проверки, но который совпадает только с группами
  без целей. Сообщение называет проверку и путь и предлагает ремонт: добавить путь в группу, чьи цели его проверяют,
  или сопоставить с `::` (все тесты), если потребители неизвестны; код возврата ненулевой.
- **AC2 — невыбираемый тест.** `config-check` сообщает тест, который не выбирает ни одна группа проверки: Python-файл
  `test_*.py` вне целей всех групп проверки `test`, Rust-модуль с тестами вне префиксов целей `rust-test`. Это ловит
  случай 36b7823.
- **AC3 — ремонт карты AgentRig.** `.agentrig/checks.yaml` покрывает `Project/shared/console/**` и
  `Project/shared/mod.rs`; `just config-check` чист.

**Границы и неизвестное.** Какие файлы обязаны выбирать тесты проверки — по языку её команды (`*.rs` для cargo test,
`*.py` для pytest) или по явному объявлению в карте, — решает исполнитель при доставке и записывает решение; Markdown
и Ledger находками не становятся. Проверка статическая: тесты не запускаются, и верность выбранных целей не
оценивается. Карту поставляет шаблон `init`, поэтому потребитель получает ту же проверку.

## Expected benefit

Новый каталог или тест без записи в карте влияния виден в `config-check` до коммита, а не после того, как гейт молча
пропустил его тесты.
