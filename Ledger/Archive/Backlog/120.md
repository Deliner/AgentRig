# B120 — Граница с внешним миром

## Context

Пользователь 2026-11-11 принял эти формы из списка IV, файл list-4-candidates.md. Clippy их не видит, видит не
целиком или в риге не проверяет. Найти их можно по синтаксису, без типов.

## Proposal

Каждая форма либо получает новое правило рига с навыком исправления, либо входит в существующее правило, как указано в
таблице.

| Форма | Владелец |
| --- | --- |
| IV-27 запуск оболочки с `-c`, где команда собрана не из литерала | новое правило |
| IV-28 `format!`, `write!`, `writeln!` с JSON `{{"` или SQL `SELECT`, `INSERT`, `UPDATE`, `DELETE` и подстановкой | новое правило |
| IV-30 `exists()`, `is_file()` или `is_dir()`, а затем действие над тем же путём | новое правило |

- **AC1. Шум.** Протокол записан до первого замера: находка верна, если к месту применима опасность из карточки списка
  и не подходит её пункт «Оставить». Стиль чужого проекта не оправдание. Правила прогоняются на копиях рига и
  voxel-rust и на открытых Rust-проектах корпуса r8. Clippy гоняется только на риге и voxel-rust, потому что сборка
  чужого проекта запускает его код. Если находок много, проверяется выборка, и правило выборки записано заранее. Если
  верных находок меньше 90%, правило не поставляется, а причина записывается.
- **AC2. Польза.** Для каждого поставленного правила показаны настоящие находки: путь, строка и что там может
  сломаться. Если формы нет ни в одном проекте, это записано прямо, и правило поставляется по D151 с тестами поведения.
- **AC3.** Находки в коде рига исправлены.
- **AC4.** `init` ставит эти правила в проекты.

**Границы.** У каждой формы один владелец. Неизвестно, сколько находок дадут правила и насколько они точны.

## Expected benefit

Данные не меняют команду, запрос или формат, а между проверкой и действием нет гонки.
