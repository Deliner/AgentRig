# B001 — Исправление конфигурации без блокировки агента

## Context

Ошибка в `agentrig.yaml` не должна лишать агента возможности исправить конфигурацию в текущей сессии. Основание — описанный пользователем сбой на AgentRig 0.3.0; повторное воспроизведение в текущей версии не проводилось.

## Proposal

Загрузка или проверка конфигурации обнаружила ошибку → агент получает диагностику и ссылку на repair skill → читает и исправляет конфигурацию → штатная проверка подтверждает исправление → обычная работа продолжается.

**K1. Диагностика сообщает действительную причину.**
Различаются отсутствие файла, повреждённый YAML, неизвестные поля и некорректные настройки команд или проверок. Сообщение указывает файл и доступные сведения о месте ошибки.

Приёмка: повреждённое содержимое не выдаётся за отсутствие файла или необходимость миграции.

**K2. Необходимые действия восстановления остаются доступны.**
Агент может прочитать конфигурацию и инструкцию исправления, напрямую отредактировать файл и запустить проверку конфигурации. Обычное редактирование допускается без `just write`.

Приёмка: после ошибки агент действительно выполняет эти действия в той же сессии. Одной подсказки «исправьте файл» недостаточно.

**K3. Восстановление не зависит от повреждённых настроек.**
Доступность действий из K2 не требует успешной загрузки настроенных команд. Запасная исправная конфигурация, чистое рабочее дерево и вмешательство пользователя вне сессии не требуются.

Приёмка: ошибка в настройках команд не препятствует исправлению и повторной проверке.

**K4. Посторонние изменения сохраняются.**
Исправление конфигурации не требует отката файлов из Git и не теряет незавершённую работу.

Приёмка: сценарий выполняется при наличии посторонних изменений; после восстановления они сохранены.

**K5. Восстановление не разрешает обход ограничений.**
Доступ к действиям из K2 не разрешает произвольные команды и не отменяет проверки commit и merge.

Приёмка: агент может восстановить конфигурацию, но не может использовать её повреждение для обхода проверок.

**K6. Возврат к обычной работе определяется результатом проверки.**
Основание — успешная штатная проверка текущего содержимого конфигурации. После неё команды и настроенные ограничения действуют обычным образом. Если ошибка сохраняется, остаётся доступен путь исправления.

Приёмка: исправленная конфигурация позволяет продолжить работу; сохранение всё ещё ошибочного файла или заявление агента «готово» не заменяют проверку. Постоянного режима обхода не остаётся.

**K7. Сценарий работает в установленных пользовательских окружениях.**
K1–K6 проверяются в отдельных потребительских проектах для Codex и Claude Code.

Приёмка: в обоих окружениях проходит цепочка «ошибка → исправление в сессии → успешная проверка → продолжение работы» с сохранением посторонних изменений и ограничений.

**K8. Инструкция ведёт к работоспособному исправлению.**
Диагностика направляет к существующему каноническому repair skill. Он указывает доступный путь исправления и повторной проверки.

Приёмка: следуя инструкции, агент завершает сценарий восстановления. Чтение skill само по себе не подтверждает исправление.

**Детерминированные опоры:** ошибка загрузки или валидации; доступность конкретных действий восстановления; результат проверки текущей конфигурации; проверки на границах commit и merge.

**Границы.** Используются существующие валидатор и repair skill. Действующий формат конфигурации сохраняется. Отдельная система восстановления и общий режим отключения хуков не требуются.

## Expected benefit

Агент самостоятельно устраняет ошибку настройки и возвращается к продуктовой задаче без потери работы и ручного вмешательства пользователя.
