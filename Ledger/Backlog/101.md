# B101 — Повторный lint-baseline возвращает преждевременно пониженную запись

## Context

- В voxel-rust `lint-baseline` понизил запись world/tests.rs до 0: находка цикла в тот момент печаталась на
  world/metadata.rs.
- Коммит отказал по другой причине, код поменялся, и находка вернулась на world/tests.rs.
- Следующий коммит отказал с «baseline accepts 0». Повторный `lint-baseline` запись не поднимает: он только понижает.
- Пришлось вернуть файл из HEAD через `git checkout` и записать базовую линию заново.
- Пользователь 2026-11-10 поручил завести карточку по этому пункту и выполнить её вместе с остальными.

## Proposal

- `lint-baseline` отсчитывает понижение от закоммиченной базовой линии, а не от рабочей копии файла.
- Повторный запуск может вернуть запись к значению из HEAD, но не выше, и не добавляет пар, которых нет в HEAD.
- **AC1.** После понижения записи до 0 и возврата находки повторный `lint-baseline` восстанавливает значение из HEAD,
  и гейт коммита принимает дерево.
- **AC2.** Запись не поднимается выше значения из HEAD, пара, которой нет в HEAD, не добавляется.
- **AC3.** Без закоммиченной базовой линии `lint-baseline` ведёт себя как сейчас.

**Границы.**

- Правило D123 «только понижает» уточняется новым решением: понижение отсчитывается от HEAD.
- Поведение проверяется тестами AgentRig на переносимых фикстурах, затем на voxel-rust, где снимается названный обход.
- Под voxel-rust риг не подгоняется.

## Expected benefit

Повторный `lint-baseline` исправляет преждевременное понижение без ручного возврата файла из Git.
