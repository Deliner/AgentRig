# B108 — Тесты рига на Rust

## Context

- Запрос пользователя 2026-11-11: переписать тесты рига с Python на Rust, чтобы они работали быстрее и проверяли
  эффективнее. Тесты проверяют только через публичные интерфейсы и лежат в тех фичах, которые проверяют. Если
  поведение можно проверить Rust-тестом, Python-тест для него не нужен. Требования 16 и 17 и дополнение о прогоне
  тестов от 2026-10-26 в [Requests](../Requests.md) говорят то же: тесты в основном на Rust рядом с кодом, тестирование
  ускорять, лишнее не тестировать.
- Сейчас в риге 47 файлов Python-тестов, 6932 строки, 233 тестовые функции и 527 случаев с параметрами. Полный прогон
  занимает около 180 с: каждый тест запускает собранный рантайм отдельным процессом, тесты идут по одному, а многие
  строят временный репозиторий и гоняют в нём гейт. 202 Rust-теста проходят за 2 с. Инварианты I001–I021, кроме
  I013, проверяются Python-тестами.

## Proposal

Поведение рига проверяют Rust-тесты, а Python-тест уходит везде, где его поведение проверяет Rust-тест.

- **AC1. Rust вместо Python.** Каждое поведение, которое сейчас проверяет Python-тест, проверяет Rust-тест.
  Python-тест остаётся, только если его предмет лежит вне Project и у него нет владельца на Rust, например лаунчеры
  `tooling`; для каждого такого файла причина записана в поставке.
- **AC2. Через публичную поверхность фичи.** Rust-тест лежит в фиче, чьё поведение проверяет, по норме
  testing-discipline. Когда поведение это возвращаемые данные, тест вызывает публичную функцию фичи. Когда поведение
  это код выхода, вывод, ввод, окружение, дочерние процессы или Git-хуки, тест запускает команду рантайма отдельным
  процессом. Ради теста ничего не открывается, и в продуктовом коде нет веток только для тестов.
- **AC3. Покрытие сохранено, лишнее не переносится.** Для каждой функции и каждого случая с параметрами удалённого
  Python-теста поставка называет Rust-тест, который его проверяет: новый или уже существующий. Повторная проверка
  одного поведения не переносится.
- **AC4. Инварианты.** Каждый инвариант, привязанный к Python-тесту, привязан к Rust-тесту оракулом cargo, и
  `memory-check` проходит. Для каждого перенесённого оракула показано, что тест падает, когда его поведение сломано.
- **AC5. Быстрее.** Полный прогон тестов рига и гейт коммита на одних и тех же сценариях идут быстрее, чем до
  переноса. Замеры до и после на одной машине записаны в поставке.
- **AC6. Гейт выбирает тесты как раньше.** Карта влияния выбирает перенесённые тесты для изменений тех же путей,
  `config-check` проходит, `just check` запускает все тесты.

**Границы.**

- Поведение продукта не меняется. Поддержка Python у потребителей остаётся: `init --language python`, оракул pytest
  и правила линтера для Python. Их тесты становятся Rust-тестами с примерами кода на Python.
- Проверки Python в гейте остаются, пока в репозитории есть код на Python.
- Неизвестно, как Rust-тест получает собранный кандидат рантайма для запуска процессом: `cargo test --lib` бинарник
  не собирает. Способ выбирает исполнитель.
- Неизвестно, насколько ускорит перенос: время Python-тестов в основном уходит на Git, процессы и гейт во временных
  репозиториях, а не на сам Python.

## Expected benefit

Тесты рига идут быстрее, проверяют поведение через публичную поверхность фичи и лежат рядом с кодом, который
проверяют.
