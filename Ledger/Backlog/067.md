# B067 — Поставка D1 без расхождений с контрактом B065 и D103 (ремонты по критике D1)

## Context

Критика Codex поставки D1 (2026-11-06) нашла расхождения с принятым контрактом B065 и решением D103:
(1) обнаружение Cargo (B065 AC2 обещает «члены workspace с глобами»): `**` в `members` раскрывается ровно на один
уровень; `[lib] path`/`[[bin]] path` с `..` молча отбрасывается даже внутри корня репозитория; `workspace.exclude` не
читается; (2) сценарий B065 AC5 в проектном режиме (`lint --json` без `--config`) даёт текст в stderr, а не JSON-находку
`configuration`; (3) `unsafe-justification` флагует `unsafe`, открывающий атрибут в форме `#[cfg_attr(cond,
unsafe(..))]`, хотя атрибут не является небезопасным сайтом (намерение D103); (4) навык split-boolean-parameter
утверждает, что нелитеральные значения по умолчанию не флагуются (Python флагует по аннотации) и что каждый вызов
содержит буквальный true/false; (5) обслуживание: карта влияния `.agentrig/checks.yaml` не связывает
`Project/shared/fs/**` с группой `shared::fs::`, `Ledger/State.md` устарел, `Ledger/Backlog.md` без перевода строки в
конце.

## Proposal

- **AC1.** `init --language rust` находит корни и крейты по манифесту так, как обещает B065 AC2: `members` с `**`
  раскрывается на любую глубину (`crates/**` находит `crates/a/b/Cargo.toml`); `[lib] path`/`[[bin]] path` с `..`
  принимается, если разрешённый путь остаётся внутри корня репозитория (`crates/x/Cargo.toml` с `path =
  "../shared/lib.rs"` даёт корень `crates/shared/lib.rs`); члены, перечисленные в `workspace.exclude`, корней не дают;
  путь с `..`, выходящий за корень, по-прежнему отбрасывается. Проверка через CLI (`init` во временном каталоге →
  `rust_roots`/`rust_crates` в `lint.yaml`) для трёх новых сценариев; прежние сценарии AC2 без изменений.
- **AC2.** В проектном режиме (`agentrig lint --json` без `--config`) ошибка конфигурации — отсутствующий файл навыка
  после `init` и удаления — выдаётся JSON-находкой `configuration`, чей `message` содержит путь отсутствующего файла,
  как с `--config`; код выхода и текстовый режим (без `--json`) не меняются. Проверка: `init`, удалить навык,
  `lint --json` → JSON с находкой `configuration` и путём.
- **AC3.** `unsafe-justification` не флагует `unsafe`, открывающий атрибут в форме `#[cfg_attr(cond, unsafe(..))]`
  (прямой аргумент после запятой верхнего уровня, как D098 для `allow`), и продолжает флаговать `unsafe { … }`,
  `unsafe fn`, `unsafe impl` и `unsafe` в теле макроса; фикстура в `languages/tests/unsafe_site.rs`; дескриптор правила
  называет обе формы атрибута.
- **AC4.** Канонический навык split-boolean-parameter описывает предикат так, как он реализован (Rust и Python, по коду),
  без утверждений «non-literal defaults are not flagged» и о буквальных аргументах вызова; I020 (`test_delivery`)
  зелёный.
- **AC5.** Обслуживание: `.agentrig/checks.yaml` связывает `Project/shared/fs/**` с группой `shared::fs::` (проверка:
  `just check --only <ID>` при изменённом `Project/shared/fs/*` выбирает тесты `shared::fs`); `Ledger/State.md` освежён
  на границах VAC по edit-state; `Ledger/Backlog.md` оканчивается переводом строки.

**Границы и неизвестное.** Политика не меняется (формы обоснования `// SAFETY:` и подобные не принимаются; предикаты
D081, D092, global-state прежние); абзац `Project/README.md` о файлах с ошибкой разбора (строки 38–41) не трогается —
он принадлежит другой карточке; новых видов правил, навыков и оракулов нет; статьи решений неизменны (D020); новое
решение — только если AC3 выходит за статью D103 (тогда D112), иначе ссылка применения D103.

## Expected benefit

Поставка совпадает с принятым контрактом: workspace с вложенными членами и относительными путями библиотек получает
верные корни без ложных `architecture`; потребитель JSON видит ошибки конфигурации в JSON; условный атрибут `unsafe` не
даёт ложной находки; навык не ведёт к ошибочному ремонту; гейт выбирает тесты `shared::fs` при их изменении.
