# B013 — Хук на 80% контекста: фиксация и исправление проблем рабочего процесса

## Context

Агент замечает препятствия и неудачные способы работы, но после суммаризации может потерять наблюдения и повторить ошибки. Одноразовая запись переносит этот опыт в следующий участок сессии.

## Proposal

Настроенный порог контекста (по умолчанию 80%) → skill фиксации → запись проблем → подтверждённая суммаризация → skill исправления → проверка результата → удаление устранённых проблем → продолжение исходной задачи.

Все проблемы устранены → файл удалён. Остались нерешённые → файл содержит только их.

**К1. Порог определяется по достоверным данным текущего контекста.**
Используются текущая заполненность и максимальная ёмкость контекстного окна по правилам [B012](012.md). Суммарный расход токенов не подменяет заполненность. Отсутствие данных обозначается явно.

Приёмка: известные измерения дают ожидаемое срабатывание; неизвестные значения не превращаются в выдуманный процент.

**К2. Фиксируются проблемы, встреченные с последней суммаризации.**
Перед вызовом инструмента при достижении или превышении настроенного порога риг требует применить skill фиксации. Агент фиксирует замеченные проблемы рабочего процесса с момента последней подтверждённой суммаризации до момента фиксации. Если суммаризации ещё не было — с начала сессии.

Проблем может быть несколько. Для каждой сохраняются наблюдение, свидетельство, влияние на работу, предпринятые попытки, их результат и следующий необходимый шаг. Уже устранённая проблема отмечается соответствующим результатом, чтобы после суммаризации не исправлять её заново.

Предположения отделены от фактов. Запись «проблем нет» означает, что за весь этот период проблем не замечено. Ранее сохранённые нерешённые проблемы также не теряются.

Приёмка: требование закрывается после корректной фиксации для текущего участка сессии. Прочтения skill или наличия старого файла недостаточно. Необходимые для чтения и записи действия остаются доступны; повторные вызовы не создают повторную фиксацию после выполнения требования.

**К3. После суммаризации агент возвращается к сохранённым проблемам.**
После подтверждённой суммаризации при наличии записи хук передаёт её путь и требует применить skill исправления. Содержание агент читает с диска.

Текст указания:

> Сопоставь сохранённые проблемы с текущим состоянием. Исправь актуальные препятствия в пределах разрешённой работы и проверь результат. Сохрани нерешённые проблемы с причиной и следующим действием. После обработки продолжи исходную задачу. Не считай описание намерения или повторную запись подтверждением исправления.

Приёмка: агент использует сохранённые наблюдения и учитывает результаты предыдущих попыток. Повторная суммаризация во время обработки возвращает его к оставшимся проблемам. Уменьшение счётчика токенов само по себе не запускает этот переход.

**К4. Запись удаляется после подтверждённого устранения проблем.**
После исправления всех зафиксированных проблем и проверки результата агент удаляет файл. При частичном исправлении удаляются только устранённые записи; остальные сохраняются с необходимым контекстом продолжения.

Запись «проблем нет» после обработки также удаляется. Следующая фиксация создаёт файл заново либо обновляет сохранившиеся нерешённые проблемы.

Приёмка: после полного исправления файл отсутствует; после частичного содержит только нерешённое. Прочтение skill, попытка исправления или простое исчезновение файла не считаются подтверждением устранения проблем. Файл не становится накопительным журналом.

**К5. Порог задаётся в конфигурации.**
80% — значение по умолчанию. Пользователь может установить другой порог, выбрать skills и расположение файла. Выполняется одна фиксация между суммаризациями и обработка сохранённого после суммаризации.

Измерения, состояние требований и их согласование используют [B002](002.md) совместно с [B012](012.md).

Приёмка: при изменении порога хук срабатывает согласно новому значению; фиксация охватывает несколько проблем из разных моментов указанного периода. Пользовательские настройки определяют инструкции и путь записи. Одновременное требование другого хука обрабатывается общим координатором; необходимые действия для фиксации и исправления не оказываются заблокированы самим этим требованием.

**К6. Исправление остаётся в пределах разрешённой работы.**
Агент самостоятельно устраняет доступные ему проблемы процесса. Запись не разрешает расширять продукт, менять согласованные требования или ослаблять проверки.

Если исправление требует отдельного решения или недоступного условия, сохраняются причина и следующий шаг. После обработки записей агент продолжает исходную задачу. Пока причина отсрочки не изменилась, повторять заведомо бесполезную попытку не требуется.

Приёмка: каждая проблема получает подтверждённое исправление либо явный нерешённый статус с причиной. Отсрочка не называется исправлением. Проверяются отсутствие проблем, неудачная попытка, частичное исправление и повторная суммаризация.

**Детерминированные опоры:** измеренный порог; событие перед инструментом; запись за период с последней суммаризации; подтверждённая суммаризация; результаты проверок; сохранение остатка или удаление обработанного файла.

**Границы и неизвестное.** Для каждого клиента нужно подтвердить доступность измерений и событий, а также возможность выполнить необходимые действия при активном требовании.

Обвязка контролирует события и формальные результаты обработки. Наличие заполненного файла не доказывает полноту наблюдений или правильность самооценки агента. Отдельная система задач, архив одноразовых записей и автоматическое ревью каждой фиксации не создаются.

## Expected benefit

Агент использует опыт предыдущего участка сессии, исправляет повторяющиеся препятствия и сохраняет только необходимый остаток нерешённых проблем.
