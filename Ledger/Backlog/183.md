# B183 — Файлы кода разделены по ответственности

## Context

- 2026-11-21 пользователь, уходя: «Как закончишь, то продолжай автономно улучшать проект без изменения поведения с
  точки зрения бизнес правил. Можешь оптимизировать и ускорять, упрощать и рефачить. Все в рамках текущих правил. Сам
  заведи карточку и аппрувни ее, мне показывать не надо». Карточки B181 и B182 этого поручения выполнены.
- `just lint --warnings` на master `5825f42` предупреждает о 16 файлах кода в Project длиннее 300 непустых строк.
  Навык этого правила, refactor-large-file, велит разделить такой файл по ответственности или назвать, почему
  защитимого раздела нет.

## Proposal

- **AC1. Поведение то же.** Команды рига, их вывод, тексты ошибок, коды выхода, форматы файлов и конфигурации не
  меняются.

  Проверка: все тесты проходят, ни один не удалён и не отключён, их число не уменьшается. Тест меняется только вместе
  с переносом проверяемого кода в другой файл и проверяет то же поведение.
- **AC2. Большие файлы разделены по ответственности.** Каждый файл кода в Project, о котором `just lint --warnings`
  предупреждает по `file-size`, разделён на части, каждая из которых владеет одной ответственностью и названа по ней.
  Файл без защитимого раздела остаётся.

  Проверка: отчёт поставки называет каждый такой файл и его новые части либо причину, по которой он остался.
- **AC3. Раздел не добавляет находок lint.** Новых находок и предупреждений lint нет, а предупреждений `file-size` о
  файлах Project меньше 16.

  Проверка: `just lint` без находок; `just lint --warnings` на голове ветки против master `5825f42`.

**Границы.** Новые правила, виды проверок и решения о поведении не вводятся. Пороги, селекторы, исключения и бюджеты
lint не ослабляются. Защищённые файлы и файлы памяти в Ledger не делятся. Пин ветки ставит пользователь командой
`! just approve`.

## Expected benefit

Каждый файл кода читается и меняется ради одной причины.
