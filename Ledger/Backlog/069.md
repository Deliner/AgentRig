# B069 — форк tree-sitter-rust в составе AgentRig: разбор правильного Rust, который не знает грамматика 0.24.2

## Context

Разборщик tree-sitter-rust 0.24.2, последний релиз от 27 марта 2026, не знает части
правильного синтаксиса Rust. Три формы дают 87 % строк, потерянных линтом в корпусе из
10 репозиториев, раунды 9–11 исследовательской дуги: `safe fn` и `safe static` внутри
`unsafe extern` (42 %), макрос с именем примитивного типа, `str![…]` из snapbox (33 %),
время жизни первым после `dyn`, `dyn 'static + Trait` (11 %). Такой файл компилируется,
но получает одну находку `syntax` и ноль находок правил; у cargo это 58,5 % непустых строк.
Починенные побайтно копии тех же файлов вернули разбор 713 из 838 потерянных файлов.

Наверху починки нет и не предвидится: issue #250 открыт с февраля 2025, PR #256 с правкой
для `safe` не слит с февраля 2025, последние коммиты в нём от марта 2026; для `dyn 'static`
есть только упоминание в сводном issue #229; `str!` не поднимался вовсе. Обновлением
зависимости это не лечится, ждать чужого срока мы не хотим. Текстовая починка перед
разбором отвергнута как костыль, смена разборщика на rust-analyzer означала бы переписать
все правила. Собственный код AgentRig этих форм не содержит; выигрывают потребители.
Карточка заведена как кандидат в Plan.

## Proposal

Иллюстрация. Файл правилен для Rust 1.82 и новее:

```rust
use std::fs;

unsafe extern "C" {
    pub safe fn abs(x: i32) -> i32;
}

pub fn load(path: &str) -> String {
    fs::read_to_string(path).unwrap()    // строка 8
}
```

Сегодня: `syntax` на блоке `extern`, про `.unwrap()` гейт молчит. После карточки: находок
`syntax` нет, на строке 8 `panic-path`, остальные правила работают как на любом файле.

- **AC1 — три формы разбираются.** `safe fn`, `safe static` и `unsafe static` внутри
  `unsafe extern`, вызов макроса с именем любого примитивного типа, `str![…]`, `u8![…]`,
  и время жизни первым после `dyn` разбираются без ошибки. Фикстуры с каждой формой
  получают находки правил и ни одной `syntax`; `unsafe fn` в таком блоке по-прежнему
  требует обоснования, `safe fn` нет.
- **AC2 — всё остальное без изменений.** На 17 103 файлах корпуса без ошибки разбора вывод
  линта побайтно равен выводу с грамматикой 0.24.2; на 838 потерянных файлах `syntax`
  исчезает не менее чем у 713. Это проверка на корпусе при доставке; фикстуры AC1 остаются
  постоянной защитой.
- **AC3 — форк едет в репозитории и в релизе.** Копия крейта tree-sitter-rust 0.24.2 с
  нашей правкой `grammar.js` и перегенерированным `parser.c` лежит в репозитории и
  подключается в `Project/Cargo.toml` как путь. Имя крейта и `tree_sitter_rust::LANGUAGE`
  в коде не меняются. Чистый клон, `just bootstrap`, `just check`, `just release` и CI
  обходятся без сети к какому-либо форку и без генератора tree-sitter. Лицензия MIT и
  авторы наверху сохранены, `cargo-about` показывает крейт в атрибуции.
- **AC4 — почему так, записано.** Решение D112 фиксирует: причины форка, три формы,
  отвергнутые варианты с мотивами, исходный тег 0.24.2 и коммит, версию генератора и
  ABI, правило обновления: новый релиз наверху берётся только через повтор нашей правки
  и AC2. Ссылка `// DECISION: D112` стоит у подключения зависимости, у изменённых правил
  `grammar.js`, у `tree_sitter_rust::LANGUAGE` в `Project/shared/syntax/mod.rs` и у
  исключений линта и typos. Абзац README о пределах разборщика переписан.

**Границы и неизвестное.** Каталог форка исключается из линта и typos целиком: `parser.c`
это 6,5 МБ и 205 906 строк, `.c` и `.json` входят в правило `file-size`. Он не становится
членом workspace, иначе Clippy гейта с запретом `unwrap` упал бы на чужом `build.rs`.
Правка `safe` берётся из PR #256, 14 строк `grammar.js`; две другие формы пишем сами,
конфликты грамматики на `str!` до сборки не известны. Генератор `tree-sitter` ставится
один раз разработчику, `node` уже есть; текущий `parser.c` собран на ABI 15, рантайм
tree-sitter 0.26 его принимает. Размещение каталога определяет D112 при доставке; D051,
пин stable.txt, обязателен. Остальные 125 файлов корпуса, 14 мелких классов, форк не
чинит; это отдельная идея B066. Правки можно предложить наверх после доставки, в
обязательства карточки это не входит.

## Expected benefit

Три самые частые формы правильного Rust, которые сегодня выключают линт на целом файле,
разбираются как любой другой код; больше половины строк cargo и 85 % потерянных файлов
корпуса возвращаются под правила без ложных срабатываний. Причина форка и правило его
обновления записаны и видны из кода.
