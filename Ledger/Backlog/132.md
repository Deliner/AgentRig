# B132 — Свои правила рига для форм списка V

## Context

Пользователь 2026-11-13 разобрал список V, файл list-5-candidates.md, и согласился: сильные формы, которых нет ни у
Clippy, ни у рига, измерить на корпусе; слабые формы оставить до замера; V-6, V-20 и V-23 закрыть. «по всем трем
пунктам я согласен», «обязательно проведи замеры». Формы списка написал генератор без кода, их частота и точность
неизвестны. Найти их можно по синтаксису, без типов.

## Proposal

Каждая форма, прошедшая замер, получает новое правило рига с навыком исправления или входит в существующее правило,
как указано в таблице. Несколько форм могут стать одним правилом, если у них одна опасность и одно исправление.

| Форма | Владелец |
| --- | --- |
| V-1 остаток `%` в сравнении с ненулевым литералом или в неравенстве | новое правило |
| V-2 `partial_cmp(..).unwrap_or(..)` и `unwrap_or_else` с `Ordering` | новое правило |
| V-3 `EPSILON` прямым операндом сравнения | новое правило |
| V-5 проверка в тесте только внутри `if` или `if let` без `else` | новое правило |
| V-7 `compare_exchange_weak`, `thread::park` и `park_timeout` вне цикла | новое правило |
| V-8 вызов `std::fs` или `std::net` в async-коде | расширение `blocking-in-async` |
| V-9 `DefaultHasher`, `type_name` и `type_name_of_val` | новое правило |
| V-10 `sort_unstable_by` и `sort_unstable_by_key` | новое правило |
| V-11 `remove(0)` | новое правило |
| V-12 вызов через имя трейта `From`, `Into`, `TryFrom`, `TryInto` или `FromStr` | новое правило |
| V-13 `transmute` и `transmute_copy` | новое правило |
| V-14 `unsafe impl Send` или `Sync` с параметром типа без такой границы | новое правило |
| V-15 вызов функции или метода `*_unchecked` и `unchecked_*` | новое правило |
| V-24 `with_extension` или `set_extension` с литералом, начинающимся с точки | новое правило |
| V-25 литерал из всех unit-вариантов enum того же файла в порядке объявления | новое правило |
| V-27 `let _ = имя;` | новое правило |
| V-28 фиксированный ненулевой порт в `bind` теста | новое правило |
| V-29 запись по литеральному пути в тесте | новое правило |

- **AC1. Шум.** Протокол записан до первого замера: находка верна, если к месту применима опасность из карточки списка
  и не подходит её пункт «Оставить». Стиль чужого проекта не оправдание. Правила прогоняются на копиях рига и
  voxel-rust и на открытых Rust-проектах корпуса r8. Если находок много, проверяется выборка, и правило выборки
  записано заранее. Если верных находок меньше 90%, правило не поставляется, а причина записывается.
- **AC2. Польза.** Для каждого поставленного правила показаны настоящие находки: путь, строка и что там может
  сломаться. Если формы нет ни в одном проекте, это записано прямо, и правило поставляется по D151 с тестами поведения.
- **AC3.** Находки в коде рига исправлены.
- **AC4.** `init` ставит эти правила в проекты.

**Границы.** У каждой формы один владелец. V-13, V-14 и V-15 стоят в unsafe-коде, где `unsafe-justification` уже
требует ссылку на решение; ссылка над той же строкой снимает обе находки. Неизвестно, сколько находок дадут правила и
насколько они точны.

## Expected benefit

Ошибки знака остатка, порядка с NaN, допуска сравнения, unsafe-преобразований, общих портов и файлов в тестах и
другие формы, которые сборка пропускает молча, ловятся в момент написания кода.
