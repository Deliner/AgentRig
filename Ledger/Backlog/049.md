# B049 — rust-silent-error: проглоченные ошибки обхода каталога (Rust)

## Context

Межпроектный обзор (`rust-lint-mining` `wf_f2a6f63a-7ff`, 2026-11-01) показал в openidea
(`ide-agent/src/lib.rs:265`) паттерн: обход каталога, укоренённый в `read_dir(..)`, сворачивает
поток `Result<DirEntry>` через `.flatten()` / `.filter_map(Result::ok)` / `.map_while(Result::ok)`,
молча роняя пер-элементные ошибки ввода-вывода — нечитаемый каталог незаметно становится пустым.
Python-аналог `silent-error` (shipped, D069) ловит `except: pass`, но Rust-аналога нет. Собственный
код AgentRig повсюду использует безопасную форму `for entry in fs::read_dir(..)? { let entry =
entry?; … }` (проверено: `evidence/content.rs:97`, `evidence/mod.rs:86`, `vcs/directories.rs:24`,
`scratch.rs:37`, `jobs/storage.rs:38`, `inventory/mod.rs:107`), поэтому по AC1 принятие правила
на нашем коде проходит без находок. Дополнение 2026-11-04 (исследовательская дуга,
`coverage-map.md` шаг 2/4 «silent-err-arm (b)»; авторизовано пользователем /goal): AC2 — рукав
ошибки, молча дающий отрицательный вердикт; единственный наш сайт —
`change_delivery/git/mod.rs:146` (`merged_reference`), чинится fail-closed при доставке (B062 AC1).

## Proposal

Наблюдаемое поведение:

- **AC1 — проглоченные ошибки чтения каталога.** Цепочка, укоренённая в `read_dir(` , чей поток
  `Result<DirEntry>` сворачивается одной из операций `.flatten()` / `.into_iter().flatten()` /
  `.filter_map(Result::ok)` / `.filter_map(|e| e.ok())` / `.map_while(Result::ok)`, → находка.
  Внешне похожее нарушенное состояние (сегодня): такой код молча проходит гейт; безопасная форма
  с `entry?` находкой не является.

- **AC2 — рукав ошибки, возвращающий вердикт.** В функции, чей объявленный тип возврата
  записан литерально как `Result<bool, …>`, рукав `match`/`if let` с образцом `Err(_)`/`Err(..)`
  и телом `Ok(false)`, `return Ok(false)`, `Ok(true)` или `return Ok(true)`, без строки
  `// DECISION: …`/`// INVARIANT: …` непосредственно над рукавом → находка: ошибка проверки молча
  становится ответом «нет»/«да». Рукав с иным телом (проброс `Err(e)`, `return Err(…)`, лог) и
  функция с иным типом возврата — не находки; тестовый код исключён.

**Границы и неизвестное.** Намеренно узкие под-паттерны (обход каталога от `read_dir`; рукав
`Err` → `Ok(bool)` при литеральном `Result<bool, …>`; псевдонимы типа возврата не разрешаются —
граница D059). Отклонено как идиоматичное/требующее потока (понижено до нормы, не правило):
общий `let Ok(x) = … else { return }`, рукава `Err(_) => {}` с иным телом,
`parse().unwrap_or(default)`. Механизм (новый `kind:` или расширение `silent-error` на Rust) — за
исполнителем; доставка двухфазная с мид-бранч пином (D051) в обоих случаях. Новый decision — при
доставке.

## Expected benefit

Потребитель не может незаметно превратить нечитаемый каталог в пустой список: пер-элементные
ошибки обхода, молча проглоченные при итерации `read_dir`, ловятся гейтом. Переносимый Rust-аналог
правила silent-error.
