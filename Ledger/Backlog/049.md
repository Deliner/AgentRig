# B049 — rust-silent-error: проглоченные ошибки обхода каталога (Rust)

## Context

Межпроектный обзор (`rust-lint-mining` `wf_f2a6f63a-7ff`, 2026-11-01) показал в openidea
(`ide-agent/src/lib.rs:265`) паттерн: обход каталога, укоренённый в `read_dir(..)`, сворачивает
поток `Result<DirEntry>` через `.flatten()` / `.filter_map(Result::ok)` / `.map_while(Result::ok)`,
молча роняя пер-элементные ошибки ввода-вывода — нечитаемый каталог незаметно становится пустым.
Python-аналог `silent-error` (shipped, D069) ловит `except: pass`, но Rust-аналога нет. Собственный
код AgentRig повсюду использует безопасную форму `for entry in fs::read_dir(..)? { let entry =
entry?; … }` (проверено: `evidence/content.rs:97`, `evidence/mod.rs:86`, `vcs/directories.rs:24`,
`scratch.rs:37`, `jobs/storage.rs:38`, `inventory/mod.rs:107`), поэтому принятие правила на нашем
коде проходит без находок.

## Proposal

Наблюдаемое поведение:

- **AC1 — проглоченные ошибки чтения каталога.** Цепочка, укоренённая в `read_dir(` , чей поток
  `Result<DirEntry>` сворачивается одной из операций `.flatten()` / `.into_iter().flatten()` /
  `.filter_map(Result::ok)` / `.filter_map(|e| e.ok())` / `.map_while(Result::ok)`, → находка.
  Внешне похожее нарушенное состояние (сегодня): такой код молча проходит гейт; безопасная форма
  с `entry?` находкой не является.

**Границы и неизвестное.** Намеренно узкий под-паттерн (только обход каталога от `read_dir`).
Отклонено как идиоматичное/требующее потока (понижено до нормы, не правило): общий
`let Ok(x) = … else { return }`, рукава `Err(_) => {}`, `parse().unwrap_or(default)`. Новый
`kind:` → доставка двухфазная с мид-бранч пином (D051). Новый decision — при доставке.

## Expected benefit

Потребитель не может незаметно превратить нечитаемый каталог в пустой список: пер-элементные
ошибки обхода, молча проглоченные при итерации `read_dir`, ловятся гейтом. Переносимый Rust-аналог
правила silent-error.
