# B208 — North Star и словарь проекта приходят агенту в начале каждой сессии

## Context

- 2026-11-25 пользователь: «Я хочу, чтобы был файл типа North Star … Этому файлу ограничение на
  размер поставим 30 строчек и 120 символов каждый. Описание проекта. Что, для чего, зачем,
  почему, что делаем, основные какие задачи решаем, этим проектом чего хотим получить».
- 2026-11-25 пользователь: «у проекта должен быть свой словарь, и чтобы мы на одном языке
  говорили во всем этом проекте»; «чтобы перед началом сессии или после сжатия контекста у нас и
  северная звезда, и словарь подавались в агента сразу же».
- 2026-11-25 пользователь: «словаря давай 100 строк до 120 символов. Да, North Star меняется
  только с моим аппрув. слово в Словарь попадает с моего согласия в чате».
- 2026-11-25 пользователь о словаре: «пусть Риг проверяет формат строки словаря и то, что слово
  повторяется».
- Сейчас на старте агент получает только напоминание прочитать State и Plan. Описание проекта
  стоит первым абзацем `AGENTS.md`, словаря нет.
- В этом обсуждении агент понял слово «очередь» как порядок выполнения, а пользователь говорил
  об очереди трекера.

## Proposal

- **AC1. North Star.** `Ledger/NorthStar.md` кратко описывает проект: что это, для чего и зачем,
  какие задачи решаем, что хотим получить. В файле не больше 30 непустых строк, считая
  заголовок, в строке не больше 120 символов.
- **AC2. Словарь.** `Ledger/Glossary.md` хранит слова проекта и их толкование. Первая строка —
  заголовок. Каждая следующая непустая строка — одна запись вида `- **слово** — толкование`,
  слово и толкование непустые. Одно слово записано один раз; регистр букв при сравнении не
  учитывается. В файле не больше 100 непустых строк, считая заголовок, в строке не больше 120
  символов.

  | Дано | Когда | Тогда |
  | --- | --- | --- |
  | North Star из 30 строк по 120 символов | коммит | проходит |
  | в North Star 31 непустая строка | коммит | отказ: названы файл и предел 30 |
  | в словаре 101 непустая строка | коммит | отказ: названы файл и предел 100 |
  | в любом из двух файлов строка в 121 символ | коммит | отказ: названы файл, строка и предел |
  | в словаре строка `очередь: трекер` | коммит | отказ: названы файл, строка и вид записи |
  | в словаре запись `- **очередь** —` без толкования | коммит | отказ: названы файл и строка |
  | в словаре записи `- **очередь** — …` и `- **Очередь** — …` | коммит | отказ: названы файл, обе строки и слово |

- **AC3. Оба файла приходят агенту целиком.** Когда контекст агента начинается заново (запуск
  сессии, очистка, сжатие), агент получает полный текст обоих файлов. Напоминание о State и Plan
  остаётся.

  | Дано | Когда | Тогда |
  | --- | --- | --- |
  | оба файла заполнены | запуск сессии | в сообщении старта есть текст обоих |
  | оба файла заполнены | сжатие контекста | текст обоих приходит снова |
  | словаря нет | запуск сессии | сообщение называет отсутствующий файл, сессия работает |

- **AC4. North Star меняется только с одобрения пользователя.** Коммит с изменением файла
  проходит только после `! just approve`, как у остальных защищённых файлов.

  Проверка: коммит с изменённым North Star без одобрения получает отказ с именем файла; после
  `! just approve` проходит.
- **AC5. Слово попадает в словарь после согласия пользователя в чате.** При правке словаря агент
  получает навык с этим правилом: добавить, изменить или убрать слово можно только после явного
  согласия пользователя. Само согласие риг не проверяет.

  Проверка: правка `Ledger/Glossary.md` выдаёт агенту навык.
- **AC6. Проект после `init`.** `init` создаёт оба файла с одним заголовком. AC1–AC5 действуют в
  нём так же.

  Проверка: после `init` оба файла есть, запуск сессии выдаёт их, 31-я строка North Star
  останавливает коммит.
- **AC7. Риг.** В риге есть оба файла. Описание проекта переезжает из первого абзаца `AGENTS.md`
  в North Star, его текст пользователь одобряет через `! just approve`. Словарь рига создаётся с
  одним заголовком.

**Границы.**

- Смысл текста риг не проверяет: у North Star он проверяет только размер, у словаря — размер,
  вид записи и повтор слова.
- Кто ещё, кроме основного агента, получает эти файлы, карточка не задаёт.
- Каталоги карточек, формат карточки и режимы — отдельные карточки.
- В проект, созданный прежним ригом, файлы добавляют руками (D185).

**Неизвестное.** Сообщает ли Codex ригу о сжатии контекста. Проверяется при поставке; если нет,
в Codex файлы приходят при запуске и очистке.

## Expected benefit

Каждая сессия с первого сообщения знает, зачем существует проект, и понимает его слова так же,
как пользователь.
