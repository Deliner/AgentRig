# B035 — Локальность правки и радиус поражения

## Context

Набор II улучшений качества (переносимо на любое приложение, agent-native), согласован
пользователем 2026-10-31 на автономное исполнение по моей рекомендации. Следующий по плану
кластер после слитого C1+C2 — C4 «Локальность правки и радиус поражения»: ядро agent-native —
может ли агент менять модуль, не читая весь мир. Из пяти под-пунктов кластера три уже
обеспечены (циклы/обратные рёбра ловит граф зависимостей; файл/функция как замкнутая единица —
правила `file-size`/`function-lines`) или норма (смена публичного контракта без обновления всех
потребителей — требует тестов/отвергнутого тип-фронтенда, [D059](../Decisions/059.md)).
Единственное новое статическое ядро — высокая входящая связность модуля («слишком многие
зависят → хрупко»), которую пользователь сам пометил `[контракт: граф зависимостей — у нас уже
есть]`. Контракт — ревизия карточки в Git.

## Proposal

Движок уже строит граф межкаталожных зависимостей и ловит по нему циклы. Добавляется метрика
входящей связности (fan-in) каждого каталога = число различных других каталогов, зависящих от
него, — это и есть радиус поражения правки этого каталога. Каталог с радиусом выше объявленного
бюджета — находка до коммита. Бюджет живёт в архитектурном контракте: легитимный хаб (общий код)
объявляет свой радиус явно, так что он виден и ограничен прямо в контракте, а случайно
разросшийся хаб ловится гейтом.

- AC1: движок считает входящую связность каждого каталога с контрактом из уже существующего
  графа зависимостей — различные каталоги-источники; свои файлы (тот же каталог) и модульные
  объявления не считаются. *[контракт]*
- AC2: каталог, чья входящая связность превышает бюджет, — находка `directory-architecture` на
  уровне error; сообщение называет фактическое число и бюджет. Аддитивно, без ослабления
  действующих порогов ([D035](../Decisions/035.md)). *[правило]*
- AC3: бюджет объявляется опциональным полем `dependents` в `architecture.yaml` (неотрицательное
  целое); при отсутствии действует порог-константа по умолчанию. Расширение схемы контракта новым
  полем фиксируется решением (сейчас [D078](../Decisions/078.md) ограничивает набор полей). *[контракт]*
- AC4: возможность уезжает в `init` ([D053](../Decisions/053.md)/[I020](../Invariants/020.md));
  наш код зелёный под новым поведением, легитимные хабы объявляют реальный радиус (догфуд), без
  ослабления дефолта.

**Границы.** Только Rust-движок и `Project`; проверяются каталоги, имеющие контракт. Остальные
под-пункты C4 вне этого правила: циклы/обратные рёбра уже ловятся графом; файл/функция как
замкнутая единица — правила `file-size`/`function-lines`; смена публичного контракта без
обновления потребителей — норма (тесты/тип-фронтенд, [D059](../Decisions/059.md));
action-at-a-distance (глобальные мутабельные синглтоны) — норма либо узкое будущее правило, не в
этом VAC. Притворный инвариант не вводится. Точные гранулярность подсчёта, значение дефолта и
исключение тестовых каталогов выбирает исполнитель спайком/догфудом, не ослабляя порог.

## Expected benefit

Радиус поражения правки виден и ограничен: агент видит из контракта, сколько каталогов затронет
изменение модуля, а случайно разросшийся хаб ловится гейтом до коммита. Легитимный общий код
объявляет свой радиус явно. Код остаётся локально-правимым и переносимым на любое приложение.
