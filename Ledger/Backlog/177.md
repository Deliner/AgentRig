# B177 — Тестовый код не живёт в файлах кода

## Context

- 2026-11-20 пользователь: тесты только через публичные входы. Он считал, что тесты внутри файла с кодом запрещены.
- Решение D145 и правило `test-placement` разрешают тестовый модуль с телом в файле кода. В Rust тестовый модуль,
  вложенный в файл, видит его приватное, и lint этого не замечает.
- Замер рига: модули с телом есть в 4 файлах, в них 7 тестов. Один тест вызывает приватную `grouped` в
  `shared/diagnostics/actionable_findings.rs`. Других тестовых элементов в файлах кода нет.
- voxel-rust: 6 модулей с телом. Тестовые модули объявлены и из обычных файлов. Есть тестовые помощники вроде
  `#[cfg(test)] impl Game` в `host/session/game.rs`.

## Proposal

- **AC1. Находка.** Правило `test-in-code-file` даёт ошибку на элемент под `#[cfg(test)]`, включая `all(test, ..)`,
  или под `#[test]` в файле кода Rust. Файлом кода считается любой файл, кроме `tests.rs` и файлов внутри `tests/`.
  Исключение одно: объявление модуля без тела во входе директории. Вход это `mod.rs`, `lib.rs`, `main.rs` или
  `foo.rs` рядом с директорией `foo/`.

  Проверка:

  | Что в файле | Итог |
  | --- | --- |
  | `#[cfg(test)] mod tests { ... }` в `foo.rs` | находка |
  | `#[cfg(test)] #[path = "tests/foo.rs"] mod tests;` в `foo.rs` | находка |
  | `#[cfg(test)] fn helper()` в `foo.rs` | находка |
  | `#[cfg(test)] mod tests;` в `mod.rs` | находки нет |
  | `#[cfg(test)] mod tests { ... }` в `mod.rs` | находка |
- **AC2. Текст находки.** Файл и строка. Кроме них, куда переносить: в `tests.rs` или `tests/` этой директории с
  объявлением во входе.
- **AC3. Навык `move-test-code-out`.** Шаги навыка:
  - перенести тест в `tests.rs` или `tests/` директории и объявить его во входе;
  - вызывать только то, что файл открывает директории;
  - приватную функцию проверять через ту, что её использует;
  - тестовый помощник, которому нужны приватные поля, заменить построением через открытые функции.

  Навык запрещает открывать функцию или поле ради теста.
- **AC4. Риг и проекты.** Правило включено в риге и после `init` в Rust-проектах. Код рига приведён к правилу.
  Навыки `relocate-tests` и `testing-discipline` правилу не противоречат.

**Границы.**

- Только Rust: в Python нет тестового кода, которому видно приватное.
- Выражение `cfg!(test)` внутри функции правило не проверяет. Это остаётся за навыком `testing-discipline`.
- Тест из `tests.rs` по-прежнему видит приватное во входе своей директории и выше. После B176 там остаются только
  части, API и сборка.

## Expected benefit

Тест не может опереться на приватное файла. Внутренности файла меняются без правки тестов.
