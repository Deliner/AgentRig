# B043 — Tier A: три правила из отчёта воркфлоу (закрытие дыр + реальные баги)

## Context

Отчёт воркфлоу-ревью Rust-кода (10 ревьюеров Sonnet, run `wf_b944977a-5c3` / task `we6yjitjd`,
96 находок, кросс-валидация по числу независимых ревьюеров + ручная проверка по исходнику). Tier A —
сильнейшие находки: near-zero-FP, подтверждены в коде, закрывают дыры в УЖЕ действующих правилах и
ловят реальные латентные баги. Пользователь согласовал все пункты Tier A и Tier B 2026-11-01 на
исполнение через догфудинг. Полный разбор — в чате; эфемерный дамп был в scratchpad/digest2.txt.

## Proposal

Три новых правила `init` + починка двух найденных багов в нашем коде (догфуд). Каждое — новый вид
правила (двухфазная доставка: source → мид-ветка бутстрап → delivery), свой навык ремонта → I020
растёт согласованно.

- AC1 **tuple-as-record** (7 ревьюеров): параметр или возврат функции типа-кортежа (≥2 элементов, либо
  кортеж, содержащий `bool`) вне тестов — находка; закрывает обход `parameter-count` и `boolean-parameter`
  ([D062](../Decisions/062.md)) через упаковку аргументов в кортеж. Эскейп — `// DECISION:`/`// INVARIANT:`
  (механизм `justified`, [D065](../Decisions/065.md)). Примеры: `command_runner/sandbox.rs:12`
  (`options: (bool, Capture)`), `change_delivery/gate/mod.rs:164` (`(&Path, &[String])`), `:183`
  (`(&Path, Option<&str>, &[String])`), `architecture/runner/analysis.rs:203`. *[правило]*
- AC2 **eager-fallback-with-?** (6 ревьюеров): `try_expression` (`?`) внутри аргумента eager-метода
  `unwrap_or`/`ok_or`/`map_or` — аргумент вычисляется всегда, поэтому ошибка пробрасывается и когда
  значение уже есть. Находка; FP почти нулевой. Примеры: `command_line/main.rs:58` и
  `structural_lint/cli.rs:49` (дубль: `.unwrap_or(env::current_dir()?)` падает даже при заданном `--root`),
  `command_runner/jobs/mod.rs:263`. **Починить баг** в main.rs/cli.rs (вынести `env::current_dir()` в
  `unwrap_or_else`/`match`, не дёргать при заданном `--root`). *[правило + баг]*
- AC3 **discarded-result** (6 ревьюеров): молча выброшенный `Result` — `expr.ok();` на уровне
  statement и рука `Err(_) =>` без обоснования; дыра в `silent-error` ([D069](../Decisions/069.md),
  ловит только Python `except:pass`) и в clippy-dev-гейте (ловит `let _ =`, но не `.ok();`). Находка;
  эскейп — `// DECISION:` (как `panic-path`, [D082](../Decisions/082.md)). Исключить легитимный
  `JoinHandle::join().map_err(|_|…)` и `impl Display`. Примеры: `command_runner/jobs/process.rs:101-102`
  (`child.kill().ok(); child.wait().ok();`), `change_delivery/git/mod.rs:146` (`Err(_) => return Ok(false)`
  схлопывает любой сбой git в определённый ответ). **Починить/обосновать** эти места; проверить
  направление fail-open/fail-closed в `merged_reference`. *[правило + баг]*

**Границы.** Три новых вида правила + три навыка ремонта; двухфазная доставка с мид-веткой бутстрапом.
Формулировки с near-zero-FP ([D035](../Decisions/035.md)); где при реализации вскроется высокий FP — честно
перевести в норму (norm-or-choice), а не ослаблять бар. Притворных инвариантов нет. Наш код приводится к
зелёному (догфуд), включая починку двух багов.

## Expected benefit

Закрываются дыры в `parameter-count`/`boolean-parameter`/`silent-error` (их больше не обойти кортежем или
`.ok();`), а класс латентных багов (`?` в eager-фолбэке, проглот ошибки) ловится до коммита. Два реальных
бага в нашем коде исправлены. Переносимо на любой Rust-проект, agent-native.
