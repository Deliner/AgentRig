# B010 — Bash-файлы без импорта логики из других файлов

## Context

Bash-файл содержит собственную логику и не подгружает функции или исполняемый код из других файлов. Самодостаточность не означает отсутствие внешних программ и данных.

## Proposal

Выбранные Bash-файлы в снимке VAC → синтаксическая проверка → обнаружение подключения кода → ошибка и требование прочитать skill → исправление → повторная проверка.

Предсказывать изменения произвольной shell-команды до её выполнения не требуется.

**К1. Пользователь задаёт область применения правила.**
Правило включается для выбранных Bash-файлов через существующую конфигурацию линтера. Объяснение проверки показывает применённую настройку и причину включения файла в проверку.

Приёмка: запрещённое подключение обнаруживается в выбранном файле; настройка области меняет состав проверяемых файлов без изменения остальных правил.

**К2. Линтер обнаруживает операции подключения внешнего кода.**
Обязательно распознаются `source` и `.` с прямыми и вычисляемыми путями. Для обнаружения нарушения достаточно операции подключения: определять содержимое или конечный путь подключаемого файла не требуется.

Упоминание команды внутри обычной строки или комментария не считается импортом. Проверяемый скрипт не запускается для поиска нарушений.

Приёмка: подключения обнаруживаются независимо от способа записи пути. Похожие текстовые данные не вызывают срабатывания. Поддерживаемые формы вызова и ограничения анализа описаны явно.

**К3. Ошибка направляет агента к исправлению через существующий механизм.**
Диагностика показывает файл, место подключения, правило, назначенный skill и команду повторной проверки. Требование чтения обрабатывает координатор [B002](002.md).

Приёмка: нарушение обнаруживается на VAC и участвует в обычном допуске линтера. Агент получает требование прочитать skill. Чтение само по себе не устраняет нарушение; исправленный файл проверяется повторно.

**К4. Skill помогает выбрать подходящий язык реализации.**
При обнаружении импорта агент получает указание:

> Подключение внешней логики может означать, что задача переросла простой Bash-сценарий. Сложную логику следует реализовать на Python, JavaScript или TypeScript — с учётом используемых языков и правил репозитория. Bash оставляй для простых команд и запуска инструментов.

Агент выясняет назначение импортируемой логики. Если скрипт стал сложным, переносит эту логику на подходящий язык проекта. Выбор учитывает существующие инструменты и ограничения на языки.

Копирование импортируемой библиотеки внутрь Bash-файла или маскировка импорта не считается содержательным исправлением. Само срабатывание линтера — сигнал проверить сложность; ненужное подключение можно просто удалить.

Приёмка: сложная логика реализована на подходящем языке, сохранены необходимое поведение и способ запуска. Оставшаяся Bash-часть проста. Проверяются отсутствие запрещённых импортов и работоспособность результата; смысл выбора языка и достаточность переноса оцениваются на merge.

**К5. Правило проверяется настоящими CLI-эвалами.**
В окружении [B004](004.md) проверяются самодостаточный скрипт, запрещённые подключения с прямыми и вычисляемыми путями, похожие строки и комментарии, допустимое чтение данных, запуск внешней команды и исправленный вариант.

Приёмка: находки и код завершения соответствуют заранее заданным ожиданиям; неожиданных нарушений нет.

Запуски выбираются по [B016](016.md): VAC — изменённые и новые файлы; merge — затронутые фичи или модули всей ветки; полный набор — явный запуск.

**Детерминированные опоры:** конфигурация области проверки; фактический снимок файлов; распознанная операция подключения; диагностика; чтение skill; повторный линт; результаты поведенческих проверок.

**Границы и неизвестное.** До реализации нужно зафиксировать поддерживаемые формы косвенного подключения помимо обязательных `source` и `.`. Полное статическое понимание произвольного динамического Bash-кода не обещается; пределы анализа не скрываются за утверждением о полной самодостаточности.

Используются существующие линтер, skills, координатор требований и эвалы. Изоляция исполнения и контроль каждого shell-вызова не добавляются.

## Expected benefit

Основную логику Bash-файла можно понять без обхода цепочки подключаемых файлов. Агент получает конкретное нарушение и способ исправления при обычной проверке изменений.
