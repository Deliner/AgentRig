# B070 — blocking-in-async: блокирующий вызов внутри async-кода (Rust)

## Context

Идея из интервью 6 ноября 2026, в корпусе не измерялась. `std::thread::sleep` внутри
`async fn` останавливает поток исполнителя: на однопоточном исполнителе встают все задачи,
на многопоточном один рабочий поток выпадает на время сна. Вложенный `block_on` внутри
async-кода у tokio паникует по документации рантайма, у futures блокирует поток до
завершения. Компилятор обе формы пропускает, clippy правила на них не имеет. Правило
опирается на имена std и рантаймов и переносится между проектами. Соседняя карточка B050
ловит гард std-блокировки через `.await`; `block_on` она сознательно не берёт. Собственный
код AgentRig синхронный, находок на нём не будет. Карточка заведена как идея; в Plan не
выбрана.

## Proposal

Иллюстрация:

```rust
async fn poll_status(client: &Client) -> Status {
    loop {
        if let Some(status) = client.status().await {
            return status;
        }
        std::thread::sleep(Duration::from_millis(200));   // строка 6
    }
}

async fn load(runtime: &tokio::runtime::Runtime) -> Config {
    runtime.block_on(fetch_config())                      // строка 11
}
```

Сегодня обе функции молча проходят гейт. По карточке: находка на строке 6 с подсказкой
`tokio::time::sleep(...).await` или аналог рантайма, находка на строке 11 с подсказкой
`fetch_config().await`.

- **AC1 — блокирующий вызов в async-контексте.** Вызов `thread::sleep`, путь оканчивается на
  `thread::sleep` либо `sleep` ввезён из `std::thread` в этом файле, или вызов функции либо
  метода с именем `block_on`, стоящий внутри `async fn` или `async`-блока, без замыкания и без
  обычной `fn` между вызовом и async-границей → находка на строке вызова, уровень warn.
- **AC2 — законные формы не отмечаются.** Те же вызовы внутри замыкания в async-коде, например
  `spawn_blocking(|| thread::sleep(..))`; внутри обычной `fn`; `tokio::time::sleep(..).await`
  и другие пути, не оканчивающиеся на `thread::sleep` → не находка.

**Границы и неизвестное.** Частота и точность на корпусе неизвестны; перед выбором в Plan
нужен замер на корпусе r8 и набор положительных и отрицательных случаев. Правило
синтаксическое, граница D059: метод `block_on` чужого типа с тем же именем считается
попаданием, отсюда warn. Если доставляются обе карточки, B050 и эта, async-контекст
определяется одним общим механизмом. Исключение тестов, как у соседних правил, решается при
выборе. Python не входит: `time.sleep` внутри `async def` уже ловит ruff, правило ASYNC251.
Новый `kind:` → двухфазная доставка по D051; решение при доставке.

## Expected benefit

Блокирующий сон и вложенный `block_on` внутри async-кода ловятся до того, как остановят
исполнитель или упадут паникой в рантайме; правило переносимо и не требует настроек проекта.
