# B014 — Структурированные инструменты с единым реестром и управляемым удалением

## Context

Агент теряет созданные инструменты, повторно реализует существующие возможности и расходует контекст на восстановление способов запуска. Одноразовые и устаревшие реализации накапливаются. Обвязка должна обеспечивать порядок, сохраняя возможность быстро исследовать данные и проверять гипотезы.

## Proposal

Выполнение команды → проверка выбранного маршрута существующим хуком → запуск → компактный результат.

Подготовка merge → проверка структуры и регистрации → существующее ревью назначения и дублирования.

Завершение задачи → сохранение необходимых результатов → очистка одноразок.

**К1. Пользователь определяет размещение и область контроля инструментов.**

В конфигурации задаются правила распознавания файлов инструментов, допустимые места хранения и точки входа. Постоянные инструменты размещаются по ответственности, временные — в выделенной области соответствующей задачи. Разрешённых областей может быть несколько.

Приёмка: проверка обнаруживает инструмент вне разрешённого места, включая незарегистрированный файл. Наличие записи в реестре не является единственным способом обнаружения инструмента.

**К2. Реестр позволяет найти существующую возможность без чтения реализации.**

Постоянная возможность имеет назначение, владельца, расположение, точку запуска, параметры и ссылку на подробную документацию. Сначала доступны действующие инструменты, отдельно — удалённые.

Реестр использует существующий каталог команд и архитектурные описания, связывая сведения без конкурирующих копий настроек запуска.

Приёмка: агент находит подходящую возможность и способ использования без предварительного знания пути, чтения всех реализаций и загрузки полной документации.

**К3. Команды проходят через три явно определённых маршрута.**

| Категория | Назначение | Порядок запуска |
|---|---|---|
| Постоянная возможность проекта | Повторяемая операция с определённой ответственностью | По зарегистрированному идентификатору с допустимыми параметрами. |
| Базовая операция | Обычные действия просмотра, поиска, сравнения, работы с файлами и репозиторием | Через настроенные разрешённые команды и формы аргументов. Каждый вызов отдельно не регистрируется. |
| Временный сценарий | Разовое исследование, преобразование данных или проверка гипотезы | Через общую операцию временного запуска с автоматическим учётом задачи, результатов и файлов. |

Пользователь настраивает разрешённые базовые вызовы и правила временного запуска. Временный сценарий может передаваться текстом команды или файлом; отдельная постоянная регистрация ему не нужна.

Перед исполнением Bash / Shell / exec_command существующий хук проверяет маршрут и аргументы по правилам, согласованным с исполнителем. Префикс `just` сам по себе не разрешает произвольную программу через `read` или `write`. Произвольный код не становится базовой операцией только из-за названия обёртки.

Неправильный вызов → короткий отказ с причиной и известным допустимым маршрутом. Правильный вызов проходит автоматически.

**Встроенные Read / Search / List работают напрямую:** эта маршрутизация не требует для них Just, регистрации, чтения skill или дополнительных блокировок. Edit / Write / apply_patch также не требуют Just; применяются существующие правила редактируемых файлов.

Приёмка: проверяются допустимые вызовы каждой категории, неизвестная операция, недопустимые аргументы и обход через универсальную обёртку. Встроенные средства агента сохраняют прямой доступ. Хук не использует модель для угадывания назначения команды.

**К4. Один skill направляет развитие и исправление инструментов.**

Skill задаёт последовательность:

> Найди существующие возможности → установи, какого требуемого результата недостаёт → используй или расширь подходящую → создавай новую при недостаточности существующих → соблюдай ответственность, размещение и документированный запуск → обнови связанные сведения.

Skill запрещает неподтверждённые режимы, ненужную универсальность и создание дубликата лишь из-за другого имени или расположения.

При нарушении правил инструментов перед merge диагностика через [B002](002.md) требует применить этот skill.

Приёмка: исправление устраняет нарушение и сохраняет требуемое поведение. Прочтение skill не заменяет исправление. Обычные корректные запуски не требуют его повторного чтения.

**К5. Структура проверяется перед merge без дополнительных процедур на VAC.**

Существующий линтер проверяет размещение, регистрацию постоянных инструментов, обязательные сведения, уникальность идентификаторов, существование файлов, точек входа и актуальность ссылок после переносов и удалений.

Нарушение → merge заблокирован → конкретная диагностика и skill → исправление → повторная проверка.

Существующее merge-ревью по [B015](015.md) проверяет новые и изменённые инструменты по фиксированным пунктам: соответствие назначению, смысловое дублирование и сохранение необходимых возможностей.

Приёмка: проверочные примеры обнаруживают перечисленные формальные нарушения; корректная структура проходит. Смысловая проверка входит в существующее ревью без отдельного запуска модели. На VAC карточка не добавляет проверок, напоминаний или отчётов.

**К6. Завершение задачи автоматически очищает её одноразовые инструменты.**

Обвязка использует существующую связь с задачей и явное событие её завершения: сохраняет предусмотренные результаты и удаляет временные реализации. Учёт не требует отдельной карточки или ручного отчёта на каждый сценарий.

Прерывание и суммаризация не считаются завершением. Нужная для повторяемой работы возможность оформляется как постоянная.

Приёмка: после завершения одноразовые файлы удалены, результаты доступны. При прерывании сохраняется возможность продолжения. Неудавшаяся очистка сообщается явно и не объявляется выполненной.

**К7. Ненужные постоянные инструменты удаляются с сохранением действующих возможностей.**

Перед удалением устанавливается отсутствие дальнейшей необходимости и проверяются потребители. Редкое использование само по себе не является основанием.

Приёмка: удалённый инструмент отсутствует среди действующих; оставшиеся зарегистрированные команды, проверки и инструкции не ссылаются на него. Обоснованность удаления рассматривается существующим merge-ревью.

**К8. Удаление сохраняет сведения для поиска и восстановления.**

Отдельная часть реестра содержит назначение, причину удаления, прежний путь и Git-ревизию с реализацией, если она была сохранена в Git.

Приёмка: реализация восстанавливается по указанной ревизии. Для незакоммиченной одноразки явно обозначена недоступность восстановления. Коммит каждой одноразки не требуется.

**К9. Настроенные команды возвращают компактный результат с доступом к подробностям.**

Полный вывод сохраняется на диск. Пользователь определяет показываемые сведения при успехе и неуспехе. Представление формируется по явным правилам без свободного пересказа моделью.

Приёмка: одинаковые данные и настройки дают одинаковый ответ; скрытый служебный вывод не увеличивает его объём. Подробности доступны без повторного запуска. Сохраняется фактический статус. Ошибка обработки сообщает невозможность сформировать сводку и путь к логу; показатели не придумываются.

**Границы и неизвестное.** Изоляция исполнения и отключение shell исключены. Проверка маршрута не доказывает смысловую правильность произвольного временного кода и отсутствие всех дубликатов.

До реализации определяются начальные правила распознавания инструментов и базовых вызовов, событие завершения задачи, порядок сохранения результатов и очистки логов.

## Expected benefit

Агент использует доступные возможности, свободно выполняет временные исследования и получает компактные результаты. Обвязка контролирует маршруты запуска и принимаемую структуру, очищает одноразки и сохраняет историю удалённых инструментов.
