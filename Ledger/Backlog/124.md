# B124 — Детерминированный замер понятности структуры и навык её правки

## Context

В P128 понятность структуры мерил слепой тест: Sonnet по одному дереву описывал проект, судья оценивал описание. Так
найдена структура v36: 76,9 % против 51,6 % у текущей. Эталон лежит в `Ledger/Assets/P128/`. Пользователь
2026-11-12: этот перебор нужно отдать детерминированному инструменту. Инструмент на любом Rust-репозитории числами
показывает, где структура непонятна. Агент с навыком по этим числам приводит репозиторий к понятной структуре, и
слепой тест больше не нужен.

## Proposal

- **AC1.** Команда рига принимает путь к Rust-репозиторию и печатает для каждого каталога и файла оценку проблемы и
  её вид. Она читает только сам репозиторий: дерево, код, зависимости между модулями, число записей в каталогах и
  `architecture.yaml`, если он есть. LLM и агентов команда не использует. На одном и том же репозитории её вывод
  совпадает побайтно.
- **AC2.** Команда работает на любом Rust-репозитории без настройки под него. Проверка: она печатает числа на Project
  и хотя бы на одном чужом Rust-репозитории. В её правилах нет имён из Project и v36.
- **AC3.** Навык правки структуры ведёт агента по числам команды. Он говорит:
  - какое место править первым;
  - какой правкой: переименованием, переносом, разбиением или слиянием;
  - когда остановиться.

  Агент правит копию проекта и следит, чтобы после правок копия собиралась. Затем он снова запускает команду и
  повторяет цикл, пока числа улучшаются. Имена придумывает агент: команда показывает, где имя не отражает содержимое,
  но имени не предлагает. Агент оставляет карту своих правок того же вида, что `v36-plainnames.map`.
- **AC4.** Проверка связки идёт вслепую. Правила команды и текст навыка записываются в Delivery до сравнения с v36.
  Правка после сравнения даёт новый вариант. Агент с навыком несколько раз приводит копию текущего Project к новой
  структуре. Решают два числа:
  - совпадение с v36: какая доля каталогов, изменённых в v36, изменена агентом и какая доля изменённых агентом
    изменена в v36;
  - оценка Sonnet итогового дерева по вопросу и рубрике P128 рядом с 51,6 % и 76,9 %.

  Рядом итог показывает две вещи. Первая: насколько порядок каталогов текущего Project по числам команды совпадает с
  их порядком по слепым оценкам P128. Вторая: разброс результатов между запусками агента. При близких числах
  выбирается связка с меньшим разбросом.
- **AC5.** Срок поиска выбирает исполнитель. Итог:
  - таблица вариантов с числами;
  - выбранные команда и навык;
  - рекомендации для Project.

  Файлы вариантов лежат в `Ledger/Assets` карточки плана по D172.

**Границы.** Файлы кода Project не меняются: агент правит только копию. Отдельными карточками по согласию
пользователя идут:

- поставка команды и навыка в проекты через `init`;
- блокирующие правила lint на этих числах;
- правка самого Project.

**Неизвестное.**

- Эталон один, и исполнитель знает v36. Команду подбирают по тому же ответу, на котором её проверяют. AC2 проверяет
  только, что команда работает на чужом репозитории, но не что там её числа верны.
- Какие детерминированные числа отражают понятность. В P128 больше всего дали имена ролей, точные имена и разбиение
  `mod.rs` по обязанностям. Имя без модели можно оценить только косвенно, например по совпадению слов имени со
  словами кода внутри.

## Expected benefit

Понятность структуры любого Rust-репозитория меряется детерминированно и дёшево, без слепого теста. Агент по числам и
навыку приводит структуру к понятной.
