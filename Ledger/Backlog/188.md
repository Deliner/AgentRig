# B188 — Список сопровождаемых файлов строится один раз и без обхода каталогов там, где нужны только файлы

## Context

- 2026-11-21 пользователь, уходя: «Как закончишь, то продолжай автономно улучшать проект без изменения поведения с
  точки зрения бизнес правил. Можешь оптимизировать и ускорять, упрощать и рефачить. Все в рамках текущих правил. Сам
  заведи карточку и аппрувни ее, мне показывать не надо». Карточки B181–B187 этого поручения выполнены.
- Замер на master `e7ad50e` в новом проекте после `init`, на новой ветке: проверка памяти, которая идёт в каждом
  гейте, длится 112–120 мс в медиане. Список сопровождаемых файлов в ней строится дважды: для ссылок на решения и для
  исключений lint. Одно построение длится около 31 мс: `git ls-files` около 11 мс и обход каталогов около 18 мс, где
  каждый каталог без известного файла проверяется отдельным процессом `git check-ignore`. Каталоги из этого списка
  нужны только lint и его отчётам, остальные места берут одни файлы:

  | Место | Что берёт из списка | Построений за вызов |
  | --- | --- | --- |
  | проверка памяти | файлы | 2 |
  | список файлов гейта | файлы | 1 |
  | проверка архитектуры в lint | файлы | 1 на правило архитектуры |

## Proposal

- **AC1. Поведение то же.** Команды рига, их вывод, тексты ошибок и их порядок, коды выхода, форматы файлов и
  конфигурации не меняются.

  Проверка: все тесты проходят, ни один не удалён и не отключён, их число не уменьшается.
- **AC2. Список строится один раз и только из файлов.** Проверка памяти строит список сопровождаемых файлов один раз
  за вызов. Места таблицы, которым нужны только файлы, строят список без обхода каталогов.

  Проверка: в Delivery число процессов Git на построение списка до и после и медиана времени проверки памяти,
  измеренная одним способом до и после.
- **AC3. Правка не добавляет находок lint.**

  Проверка: `just lint` на голове ветки без находок.

**Границы.** Новые правила, виды проверок, зависимости и решения о поведении не вводятся. Пороги, селекторы,
исключения и бюджеты lint не ослабляются. Защищённые файлы не меняются. Пин ветки ставит пользователь командой
`! just approve`.

## Expected benefit

Проверка памяти в каждом гейте, список файлов гейта и lint запускают меньше процессов Git и идут быстрее.
