# B011 — Запрет файлов с выбранными расширениями

## Context

Пользователь ограничивает используемые в проекте языки и форматы через список запрещённых расширений. Агент учитывает эти ограничения при выборе средств реализации.

## Proposal

Снимок файлов на VAC → сопоставление расширений с настройкой → нарушение → требование прочитать skill → исправление → повторная проверка.

Проверка использует фактические имена файлов независимо от того, каким инструментом они созданы.

**К1. Пользователь определяет запреты и область проверки.**
В существующей конфигурации линтера задаются запрещённые расширения и проверяемые пути. Список выбирает пользователь; агент не дополняет его по собственным предположениям о подходящих языках.

Приёмка: изменение списка или области меняет результат следующей проверки. Объяснение показывает применённую настройку и её источник.

**К2. Запрет применяется независимо от содержимого файла.**
Файл с запрещённым расширением в проверяемой области вызывает нарушение, в том числе если он пустой. Файлы с незапрещёнными расширениями не нарушают это правило.

Приёмка: одинаковое запрещённое расширение даёт нарушение для пустого файла, исходника и произвольных данных. Изменение содержимого без изменения расширения не устраняет нарушение.

**К3. Диагностика требует применить skill исправления.**
Ответ показывает путь, запрещённое расширение, применённое ограничение, назначенный skill и команду повторной проверки. Требование чтения обрабатывается через [B002](002.md).

Приёмка: нарушение выявляется при проверке VAC и участвует в обычном допуске линтера. Чтение skill не снимает нарушение; исправленный снимок проверяется повторно.

**К4. Skill сохраняет нужный результат допустимыми средствами.**
Агент выясняет назначение файла. Нужная функциональность реализуется средствами, допустимыми в проекте; ненужный файл удаляется.

Простое переименование, скрывающее прежний язык или формат, не считается исправлением. Агент не добавляет исключения и не меняет список запретов ради прохождения проверки.

Приёмка: запрещённый файл устранён, необходимое поведение сохранено, затронутые ссылки и команды работают. Смысловой обход ограничения оценивается существующим ревью на merge по [B015](015.md).

**К5. Правило подтверждено CLI-эвалами.**
В окружении [B004](004.md) проверяются запрещённые и незапрещённые расширения, пустые файлы, область применения настройки и исправленные варианты.

Приёмка: находки и код завершения соответствуют заранее заданным ожиданиям. Изменение настройки проверяется повторным запуском; содержимое файла не влияет на решение этого правила.

Запуски выбираются по [B016](016.md): VAC — изменённые и новые файлы; merge — затронутые фичи или модули всей ветки; полный набор — явно.

**Детерминированные опоры:** конфигурация запретов; состав снимка; имена файлов; сопоставление расширений; диагностика; чтение skill; повторная проверка.

**Границы и неизвестное.** Перед реализацией нужно зафиксировать правила сравнения регистра и обработки составных расширений. Они должны одинаково работать во встроенном линтере и отдельном `agentrig-lint`.

Правило проверяет расширения. Оно не распознаёт произвольный язык по содержимому и не ищет встроенный код внутри разрешённых файлов. Используются существующие настройки, линтер, skills и эвалы.

## Expected benefit

Нежелательные файлы обнаруживаются обычной проверкой изменений, а агент получает направление исправления с сохранением нужной функциональности.
