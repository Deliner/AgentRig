# B145 — Риг устроен так же, как проект после `init`

## Context

- 2026-11-18 пользователь: «я ожидаю, что в нашем проекте AgentRig все будет точно так же, как и в любом другом
  проекте, который мы инициализируем с помощью него. То есть у нас идет полный догфудинг».
- Сверка 2026-11-18: код рига с master `aac2bb1` скопирован во временный каталог, там запущен `init --language rust`
  установленного рантайма `05f345a`. Его `.agentrig`, `justfile`, `just/` и `.codex` сравнены с ригом.
- Законно отличаются добавки рига, который сам разрабатывает рантайм: запуск через `tooling/worker/run` и сборка
  кандидата, Python-проверки вместе с `typos`, свои инварианты, карта влияния тестов, исключение вендорной грамматики.
- Без причины расходятся 9 мест:

| # | Что | Риг | Проект после `init` |
| --- | --- | --- | --- |
| 1 | Навыки | `.agents/skills`, ссылка на `Project/shared/skills` | `.agentrig/skills`, копия |
| 2 | Состояние рантайма | `.cache/runtime` | `.agentrig/runtime` |
| 3 | Имена 3 правил lint | `function-lines`, `named-if-condition`, `parameter-count` | `function-size`, `named-if`, `parameters`; пороги те же |
| 4 | Где работает lint | весь репозиторий, включая размер Markdown в `Ledger` | только `Project` |
| 5 | `feature_root: Project` в правиле `architecture` | есть | нет; lint с настройками `init` даёт на коде рига 116 ошибок `architecture` о типе feature |
| 6 | Проверка `rustfmt` | есть | нет |
| 7 | Отправка веток в `origin` | настроена, `remote: origin` | нет |
| 8 | Рецепты just | `just read`, `just write`, `just test`, `just lint-rules` | только `just run read` и `just run write` |
| 9 | Клиенты и таймаут хука | Codex и Claude Code сразу, 30 с | один клиент через `--frontend`, 10 с |

- Инвариант I020 сравнивает только виды правил, навыки, маршруты и проверки, поэтому эти расхождения не ловит.
- 2026-11-19 пользователь попросил хранить таблицу расхождений в карточке, чтобы эти знания не потерялись.
- 2026-11-19 пользователь: «источник правды текущий сетап рига надо по нему делать». Навыки он предложил хранить в
  `.agentrig`, а в каталогах Codex и Claude Code держать на них символические ссылки. Сообщение о навыке показывает
  путь через ссылку в каталоге конкретного агента.
- 2026-11-19 пользователь уточнил: «источник истины – текущий сетап рига... Так и должно быть в любых других
  проектах»; агента можно узнавать через хук начала сессии; в хуках и ошибках нужны абсолютные пути до конкретного
  навыка, а не до каталога навыков. Он велел проверить работу с установленным Codex и на пустом проекте после `init`,
  взять карточку в работу и делать автономно.
- Сейчас хук раскрывает ссылку: Claude Code видит `Project/shared/skills/memory/edit-plan/SKILL.md`, а lint называет
  навык относительным путём из настроек.
- Проба 2026-11-19: Claude Code передаёт своим командам `CLAUDECODE=1`, Codex 0.167 передаёт `CODEX_THREAD_ID`. Хук
  Codex таких переменных не получает, а его вход не называет агента.

## Proposal

`init` даёт проекту ту же настройку, что сейчас у рига. Отличаться могут только названные добавки рига.

- **AC1. Пути, имена и охват как у рига.** После `init` у проекта:
  - состояние рантайма лежит в `.cache/runtime`, а каталог `.cache/` не попадает в Git;
  - правила lint называются `function-lines`, `named-if-condition` и `parameter-count`, пороги прежние;
  - lint проверяет весь репозиторий, включая размер Markdown в `Ledger`, а у правила `architecture` есть
    `feature_root: Project`;
  - есть рецепты `just read`, `just write`, `just test` и `just lint-rules`;
  - хуки Codex и Claude Code настроены сразу, с таймаутом 30 с, а опции `--frontend` больше нет.

  Проверка: тест сравнивает `.agentrig`, `justfile`, `just/`, `.codex` и `.claude` рига с результатом `init` и находит
  только разрешённые различия.
- **AC2. Проверки и отправка веток.** `init` для Rust добавляет проверку `rustfmt`. Если у репозитория есть `origin`,
  `init` настраивает отправку веток туда.

  Проверка: тест `init` на проекте Rust с `origin`.
- **AC3. Добавки рига названы.** Каждое оставшееся отличие рига записано в одном перечне вместе с причиной.

  Проверка: тест из AC1 берёт разрешённые различия только из этого перечня.
- **AC4. Навыки в одном месте для обоих агентов.** `init` кладёт навыки в `.agentrig/skills` и создаёт ссылки на этот
  каталог: `.agents/skills` для Codex и `.claude/skills` для Claude Code. У рига `.agentrig/skills` ссылается на
  исходники `Project/shared/skills`. Это добавка рига, она записана в перечне из AC3.

  Проверка: тест `init` показывает, что оба пути ведут к тем же файлам навыков.
- **AC5. Сообщение называет навык абсолютным путём через каталог агента.** Хук, lint и гейт показывают абсолютный путь
  к файлу `SKILL.md` конкретного навыка через каталог агента, который их вызвал, и не раскрывают ссылку. Claude Code
  видит `<корень>/.claude/skills/edit-plan/SKILL.md`, Codex видит `<корень>/.agents/skills/edit-plan/SKILL.md`. Хук
  узнаёт агента по своей регистрации у клиента, начиная с хука начала сессии. Lint и гейт узнают его по переменной,
  которую агент передаёт своим командам. Без такой переменной, например при коммите человека из терминала, путь идёт
  через `.agentrig/skills`.

  Проверка: тесты хука для каждого агента и тест lint с переменной каждого агента; пустой проект после `init`, где
  Codex и Claude Code получают пути из своих каталогов.

**Границы.** Проекты, настроенные раньше, обновляются вручную по D185.

## Expected benefit

Риг проверяет на себе ровно то, что получает любой проект. Новое расхождение сразу роняет тест. Каждый агент открывает
навык по абсолютному пути из своего каталога.
