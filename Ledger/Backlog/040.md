# B040 — Эволюция API/данных: glob-импорт не тянет всю растущую поверхность чужого модуля (Rust/Python)

## Context

Набор II улучшений качества (переносимо на любое приложение, agent-native), согласован
пользователем 2026-10-31 на автономное исполнение по моей рекомендации. Следующий по плану кластер
после C5 — C10 «эволюция API/данных». Под давлением агент (и человек) тянет glob-импорт
(`use foo::*;`, `from foo import *`), чтобы не перечислять имена. Glob привязывает файл ко **всей**
растущей публичной поверхности чужого модуля: когда тот добавляет, убирает или переименовывает имя,
набор имён в области видимости меняется молча — затенение, коллизии, непрозрачное происхождение имени,
которого агент при чтении/правке не видит, а компилятор о молча появившемся имени не предупреждает.
Явный список импорта делает поверхность зависимости стабильной и обозримой по мере эволюции
вышестоящего API. Существующие правила glob-импорт не ловят. Прочие под-пункты C10 статически
near-zero-FP ([D035](../Decisions/035.md)) не ловятся: исчерпываемость `match`/wildcard-рука `_` — высокий
FP (скаляр-`match` и `#[non_exhaustive]`-enum чужого крейта законно требуют `_`, нужен вывод типов);
требование `#[non_exhaustive]` нерелевантно бинарному крейту; версионирование serde/схем конфиг-специфично
и шумно; исчерпываемость enum уже стережёт компилятор. Контракт — ревизия карточки в Git.

## Proposal

Новое правило `wildcard-import` сообщает о glob/wildcard-импорте без ссылки-обоснования `DECISION:`/
`INVARIANT:` на строке прямо выше. Переиспользует механизм `justified` (как D065/D082) и обход предков
`in_test_context` (D082).

- AC1: в Rust `use …::*` (узел `use_wildcard`, верхнего уровня или внутри группы `use {…}`) вне
  тестового кода без ссылки-обоснования на строке прямо выше — находка на уровне error; со ссылкой —
  без находки (механизм `justified`); тестовый код исключён обходом предков `#[cfg(test)]`/`#[test]`
  (`in_test_context`) плюс паттернами exclude живого правила (`**/tests/**`, `**/tests.rs`). *[правило]*
- AC2: в Python `from … import *` (узел `wildcard_import` внутри `import_from_statement`) без
  ссылки-обоснования на строке прямо выше — находка на уровне error; со ссылкой — без находки (механизм
  `justified`). *[правило]*
- AC3: новый вид правила `wildcard-import` доставляется потребителю через `catalog::ALL` с новым
  навыком ремонта `narrow-import` (заменить явным списком импорта или обосновать ссылкой); и виды
  правил, и навыки растут на один → наборы сбалансированы ([I020](../Invariants/020.md)). Наш код
  зелёный (реальных glob-импортов в репозитории нет). *[правило]*

**Границы.** Только glob/wildcard-импорты (Rust `use_wildcard`, Python `from … import *`). Escape —
ссылка-обоснование прямо выше (прелюдии, сознательный ре-экспорт `__init__.py`/фасад, как `# noqa: F403`
в экосистеме) и исключение тестов. Исчерпываемость `match`/wildcard-рука `_`, `#[non_exhaustive]`,
версионирование serde/схем — норма (высокий FP / нерелевантно бинарному крейту / исчерпываемость enum
уже стережёт компилятор). Притворный инвариант не вводится.

## Expected benefit

Проект получает из коробки защиту своей поверхности импортов от молчаливой эволюции API: glob,
привязывающий файл ко всей растущей поверхности чужого модуля, ловится гейтом до коммита — агент
сужает его до явного списка либо обосновывает ссылкой. Свойство agent-native и переносимо на любое
Rust/Python-приложение.
