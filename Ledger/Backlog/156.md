# B156 — Коммит всегда проходит гейт, а базу меняет только `feature-merge`

## Context

- 2026-11-19 пользователь об отчёте аудита обходов: «не хочется все твои находки терять… давай их все исправим».
  Затем: «Пока только карточки заведи». Текст сохранён без показа в чате; до выбора в Plan его нужно согласовать.
- Аудит 2026-11-19, пункт C3. `just write -- git commit --no-verify` и `-n` не запрещены; такой коммит пропускает
  гейт и запрет коммита в базу. Прослежено по коду; в пробе первый коммит остановил маршрут edit-state, а не запрет
  флага.
- Пункт C4. Базу можно сдвинуть без слияния: `git branch -f master X`, `git checkout -B`, `git switch -C`,
  cherry-pick и rebase на базе; `feature-merge` потом отправит её. Прослежено по коду.
- Пункт C5. Пустой файл `.git/MERGE_HEAD` разрешает коммит в базу (`Project/shared/vcs/git.rs:108-112`). Прослежено
  по коду.
- Пункт F2. AGENTS.md запрещает обходить хук и коммитить в базу, а `just write` позволяет и то и другое.

## Proposal

- **AC1.** Коммит через `just write` всегда проходит pre-commit: `--no-verify` и `-n` в любой записи получают отказ.

  Проверка: тест хука.
- **AC2.** Ветку базы из `.agentrig/git.yaml` меняет только `feature-merge`. Команда `just write`, которая
  создаёт, сдвигает, переписывает или удаляет базу либо коммитит в неё, получает отказ, в том числе при поддельном
  `.git/MERGE_HEAD`.

  Проверка: тест во временном репозитории на каждый пример C4 и C5.

## Expected benefit

Правила AGENTS.md о хуке и базе выполняются командами, а не держатся только на тексте.
