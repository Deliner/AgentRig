# B121 — Действие без предварительной проверки пути

## Context

Замер IV-30 в [P125](../Archive/Plan/125.md) нашёл в риге 5 мест, где код проверяет путь, а потом действует над ним.
Путь может исчезнуть между двумя шагами, и тогда команда падает, хотя должна была считать его отсутствующим.

## Proposal

- **AC1.** Каждое место сразу выполняет действие. Ответы «пути нет» и «это не каталог» обрабатываются так же, как
  сейчас при проверке:
  - список запусков без каталога `jobs` пуст;
  - запись в `jobs` без `record.json`, в том числе посторонний файл, пропускается;
  - очистка без каталога области задачи ничего не удаляет;
  - проверка памяти без каталога деталей не ищет неучтённых файлов;
  - разбор шаблона путей Cargo пропускает отсутствующий каталог.
- **AC2.** Другие ошибки, например отказ в доступе, теперь останавливают команду с указанием пути и действия. Сейчас
  `exists()` и `is_dir()` молча принимают их за отсутствие.
- **AC3.** Тесты закрепляют поведение из AC1 для отсутствующего пути. Замороженный детектор IV-30 из замера P125 на
  риге больше не находит этих пяти мест.

**Границы.** В `cleanup` есть похожая гонка другого вида, «перечислить, потом удалить». Если две очистки идут
одновременно, вторая падает на уже удалённой записи. В карточку это не входит, но её можно добавить. Место в voxel
только сообщается.

## Expected benefit

Параллельные команды рига не падают от чужой очистки, а настоящие сбои файловой системы не прячутся.
