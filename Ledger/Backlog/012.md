# B012 — Хук на 50% контекста: соразмерность проверок

## Context

В длительной сессии агент может выбирать слишком затратные способы проверки гипотез. Напоминание возвращает его к наименее затратной достаточной проверке, сохраняя обязательные требования.

## Proposal

Перед вызовом инструмента → доступные данные текущего контекста → сравнение с порогом → однократное напоминание через [B002](002.md) → продолжение работы.

Подтверждённая суммаризация → возможность нового напоминания при следующем достижении порога.

**К1. Процент определяется по данным текущего контекстного окна.**
Риг получает текущую заполненность и максимальную ёмкость активного контекстного окна. Накопленный расход токенов за всю сессию не подменяет текущую заполненность.

Используются последние доступные достоверные данные клиента. Неизвестные значения не выдаются за измеренные.

Приёмка: известные заполненность и ёмкость дают ожидаемый процент. При отсутствии необходимых данных порог не считается достигнутым; причина недоступности измерения видна в объяснении состояния хука.

**К2. Напоминание выдаётся один раз между суммаризациями.**
Перед вызовом инструмента проверяется условие: заполненность не ниже порога и напоминание ещё не выдавалось в текущем участке сессии. Порог по умолчанию — 50%.

После доставки повторные вызовы инструментов не дублируют сообщение. Новая сессия или подтверждённая суммаризация разрешает новое срабатывание. Простое уменьшение счётчика не считается суммаризацией.

Напоминание включается в общий ответ координатора [B002](002.md). Само оно не блокирует действие и не отменяет блокировки других хуков.

Приёмка: ниже порога сообщения нет; при достижении или перескоке порога оно выдаётся перед следующим вызовом инструмента. Повторная попытка команды не повторяет уже доставленное сообщение. После подтверждённой суммаризации цикл работает заново.

**К3. Пользователь управляет напоминанием через конфигурацию.**
Настраиваются порог, текст и включение хука. Настройка применяется через существующие механизмы конфигурации и координации требований.

Приёмка: заданный порог определяет момент срабатывания, пользовательский текст доставляется без подмены, отключённый хук не выдаёт напоминаний.

**К4. Напоминание направляет к достаточной проверке с меньшими затратами.**
Текст по умолчанию:

> Определи наблюдение, необходимое для проверки текущей гипотезы. Выбери наименее затратный по времени способ получить его, сохранив условия достоверности. Исключи подготовку, промежуточные действия и область выполнения, не влияющие на проверяемое свойство. Используй пригодные результаты повторно. Расширяй проверку только при недостаточности меньшего объёма. Сохраняй обязательные проверки и исходный смысл требования.

Агенту не требуется подтверждать получение сообщения, создавать отдельный план проверки или записывать отчёт ради этого хука.

Приёмка: доставка проверяется на последовательностях событий с заданными измерениями. На сценариях применения отдельно оценивается, сокращены ли ненужные действия при сохранении достоверности результата. Наличие сообщения само по себе не подтверждает улучшение поведения.

**Детерминированные опоры:** событие перед вызовом инструмента; доступные измерения; настроенный порог; факт доставки; идентичность сессии; подтверждённое событие суммаризации.

**Границы и неизвестное.** Для каждого поддерживаемого клиента нужно проверить доступность заполненности, максимальной ёмкости, события суммаризации и доставки сообщения без блокировки. Эти возможности пока не подтверждены.

Используется координатор [B002](002.md). Отдельный сервис мониторинга, автоматический оптимизатор проверок и дополнительный механизм подтверждения прочтения не создаются. Обязательные проверки VAC, merge и приёмки сохраняются.

## Expected benefit

Агент своевременно пересматривает слишком длинный проверочный сценарий, не расходуя контекст на повторяющиеся напоминания и дополнительные процедуры.
