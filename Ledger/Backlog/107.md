# B107 — Имена узлов сверяются с грамматикой

**Требует дополнительного согласования; реализовывать пока нельзя.** Пользователь 2026-11-10 поручил сохранить
карточку, не брать её в работу и вернуться к ней позже. В Plan она попадает только после нового согласования.

Код рига ищет конструкции по именам узлов и полей. Каждое такое имя проверяется по грамматике того языка, который
этот код разбирает. Если имени в грамматике нет, гейт останавливается. Сейчас такое имя молча выключает часть правила.

## Context

- Деревья tree-sitter обходят три части рига: правила линта, анализ архитектуры и поиск отметок DECISION. Узлы и
  поля в их коде названы строками:
  - сравнение вида узла с именем;
  - ветви match по виду;
  - выборка дочернего узла по имени поля;
  - списки видов.
- Замер на master 2026-11-10, только прямые сравнения и выборки полей без тестов:

| Где | Мест | Разных имён |
| --- | --- | --- |
| Модули Rust | 346 | 77 |
| Модули Python | 19 | 16 |
| Общие для языков модули | 20 | 13 |
| Всего | 385 | |

- В Bash прямых мест нет: его разбирают только общие модули.
- Ни одно имя не сверяется с грамматикой при сборке или в гейте. Строка с опечаткой компилируется и проходит гейт.
  Узла с таким именем не бывает, поэтому ветвь правила никогда не срабатывает. Тест заметит это, только если
  покрывает именно эту ветвь.
- Разовая сверка показала:
  - 365 мест в модулях одного языка совпадают с его грамматикой;
  - 20 мест в общих модулях сверены только с объединением грамматик;
  - ветви match и списки видов не сверялись.
- Грамматика Rust лежит в риге, Python и Bash приходят пакетами. Каждая грамматика содержит полный список своих
  узлов и полей.

## Proposal

Проверка входит в обычный гейт: хук коммита и `feature-merge`. Отдельная команда не нужна. Проверка охватывает:

- все формы, которыми код рига называет узел или поле;
- знаки и ключевые слова, если код сравнивает их как вид узла.

Имя сверяется с грамматикой языка, который разбирает этот код. Если код общий для нескольких языков, имя сверяется с
грамматикой каждого из них. При отказе сообщение называет файл, строку, имя и грамматику.

| ID | Сценарий | Признак выполнения |
| --- | --- | --- |
| AC1 | В правиле Rust вид узла написан с опечаткой, например `closure_expression` с пропущенной буквой | Гейт коммита падает, сообщение называет файл, строку, имя и грамматику Rust |
| AC2 | Опечатка в имени поля при выборке дочернего узла | Такой же отказ |
| AC3 | Опечатка в ветви match по виду узла или в списке видов | Такой же отказ: проверяются не только прямые сравнения |
| AC4 | В правиле Rust стоит имя, которое есть только в грамматике Python или Bash, например `function_definition` | Отказ: имя сверяется с грамматикой Rust, а не с объединением грамматик |
| AC5 | Грамматику обновили, и узел из неё убран или переименован | Гейт перечисляет все места со старым именем до слияния ветки |
| AC6 | Текущий код рига | Все имена проходят проверку. Опечатки, найденные при внедрении, исправлены, и ветвь, которую они выключали, подтверждена тестом |

**Границы.**

- Проверяется только код рига. Потребителям это правило линта не поставляется.
- Сравнение текста узла не проверяется: проверка `cfg` как текста пути не сверяет вид узла.
- Механизм выбирает исполнитель: проверка при сборке, тест или типизированные имена.
- Находки у потребителей меняются только там, где AC6 исправляет опечатку.
- Неизвестно, как сверять имя в общем модуле, если ветвь нужна только одному из языков. Это решается при доставке и
  записывается в решении.

## Expected benefit

Опечатка в имени узла больше не выключает часть правила молча: коммит останавливается и показывает точное место.
После обновления грамматики все затронутые места видны до слияния.
