# B036 — Запрет немотивированного подавления линтов и отладочных артефактов (Rust)

## Context

Набор II улучшений качества (переносимо на любое приложение, agent-native), согласован
пользователем 2026-10-31 на автономное исполнение по моей рекомендации. Следующий по плану
кластер после C4 — C9 «долговременная гигиена»: агент под давлением гейта склонен глушить
правило, а не чинить причину. Два артефакта глушения в Rust не ловятся существующими правилами:
широкий `#[allow(...)]`/`#![allow(...)]` — атрибут, а не комментарий, поэтому баном комментариев
не ловится и выключает проверки надолго и незаметно; `dbg!` — отладочный макровывод, случайно
оставленный в коммите. Остальные под-пункты C9 уже обеспечены: бан комментариев
([D037](../Decisions/037.md)) ловит Python `# noqa`/`# type: ignore`, закомментированный код и
`TODO`/`FIXME` (всё — комментарии, разрешён только `DECISION:`/`INVARIANT:`); свежесть
самоописания каталога — [D070](../Decisions/070.md); `println!`/`eprintln!` намеренно исключены
([D060](../Decisions/060.md)). Контракт — ревизия карточки в Git.

## Proposal

Линтер в поставке `init` сообщает о двух Rust-артефактах глушения гейта. Для `#[allow]`
переиспользуется механизм justified (как unsafe [D065](../Decisions/065.md) и disabled-test
[D074](../Decisions/074.md)): ссылка `DECISION: DNNN`/`INVARIANT: INNN` на строке прямо выше
снимает находку.

- AC1: каждый Rust-атрибут `#[allow(...)]` или `#![allow(...)]`, над которым на строке прямо выше
  нет ссылки `DECISION:`/`INVARIANT:`, — находка на уровне error; с такой ссылкой прямо выше —
  без находки. *[правило]*
- AC2: находка только у `allow`; прочие атрибуты (`#[derive(...)]`, `#[test]`, `#[path=...]`;
  `#[ignore]` обрабатывается своим правилом disabled-test) не затрагиваются. Разбор по AST:
  `#[allow(...)]` внутри строкового литерала/фикстуры — не находка. *[правило]*
- AC3: каждый вызов макроса `dbg!` в Rust — находка на уровне error безусловно (у отладочного
  вывода нет легитимного обоснования в коммите); обычные макросы (`println!`, `vec!`) не
  затрагиваются. *[правило]*
- AC4: ремонт у `allow` — убрать подавление и починить исходную находку либо записать обоснование
  ссылкой; у `dbg!` — убрать вызов. Навыки ремонта поставляются вместе с правилами.
- AC5: возможность уезжает в `init` ([D053](../Decisions/053.md)/[I020](../Invariants/020.md));
  наш код зелёный под новым поведением (единственный реальный `#[allow]` в репозитории разрешён по
  правилу), набор возможностей потребителя и репозитория совпадает.

**Границы.** Только Rust-движок. Python-подавление (`# noqa`/`# type: ignore`), закомментированный
код и `TODO`/`FIXME` уже под баном комментариев ([D037](../Decisions/037.md)); `println!`/
`eprintln!` — сознательный выбор [D060](../Decisions/060.md), не возвращается; свежесть
самоописания каталога — [D070](../Decisions/070.md); единый локальный стиль ошибок/логов/имён —
норма. Правило `allow` условное (снимается обоснованием), `dbg!` безусловное. Притворный инвариант
не вводится. Расширение набора правил новыми видами фиксируется решениями в VAC.

## Expected benefit

Гейт нельзя тихо выключить: подавление правила обязано нести записанное обоснование, а отладочные
остатки не доезжают до коммита. Свойство agent-native и переносимо на любой проект — агент,
споткнувшись о правило, чинит причину или явно обосновывает исключение, вместо того чтобы
заглушить проверку.
