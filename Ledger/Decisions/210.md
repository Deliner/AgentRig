# D210 — Report a subtraction from a bit count and from a count passed alone through a call

## Context

B166 under D151. The voxel-rust review at `2304625` found that the light validator subtracts before it checks a
subset: `src/core/light/codec.rs:103` subtracts the number of dense blocks from the `count_ones()` of the changed
blocks, both widened to `usize` by `widen_u32_to_usize`, before checking that the dense blocks lie among the changed
ones. A build with overflow checks panics where the decoder expects `false` and an ordinary error. `length-subtraction`
(D155) reports only `.len()` and `.count()` directly left of the minus. The card asks that `.count_ones()` and
`.count_zeros()` left of the minus, also inside a call with one argument, give the same lint error as `.len()`.

## Chosen

`length-subtraction` and its skill `subtract-checked` keep their names and grow. The rule reports a binary `-` whose
left operand is a `.len()`, `.count()`, `.count_ones()` or `.count_zeros()` method call without arguments, or a call
with exactly one argument that is such a call, a function call or a method call alike. Test code stays skipped and a
`DECISION:` or `INVARIANT:` reference on the line directly above still lifts a finding. The finding names the counting
method. The kind is already known to the installed runtime, so it needs no inert phase; the branch ends with the pin
of D051.

## Rejected

- Unwrap a call only around a bit count, as the card words it: `usize::from(items.len()) - 1` underflows the same
  way, and a second condition for one form would split one rule in two.
- A separate kind and skill for bit counts: D155 keeps one owner per form, and the repair is the same checked or
  saturating subtraction.
- Only a function call as the wrapper: `limit.min(items.len()) - 1` underflows on an empty collection the same way.
- A wrapper with several arguments, or wrappers nested at any depth: a call with several arguments combines values, so
  its result is no longer the count; one level covers the review's widening function.
- A count on the right of the minus and `-=`: left out, as D155 left them.

## Rationale

A bit count, like a length, is a count that input decides, so subtracting from it underflows on the data that should
produce an ordinary error. A widening call keeps the count's value, so wrapping it must not hide the subtraction.

## Consequences

In voxel-rust the extended rule reports the review's site at `src/core/light/codec.rs:103`; a search of its source for
a bit count left of a minus or a count passed alone through a call finds no other site. The rig has no such site. A
count wrapped twice, a count on the right side and `-=` stay unreported.
