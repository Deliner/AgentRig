# D015 — Native hook runtime

## Context

The user explicitly requests migration of hook services to Rust for lower invocation overhead, with the existing complexity discipline and repository contracts preserved. D014's Python runtime entrypoint and D006's Python state service are on the repeated hook path.

## Chosen

Supersede D014's runtime-language choice with one Rust binary for hook dispatch, command validation, transcript scanning, reminder storage, and Git commit/reference guards. Preserve D005, D006, D010, and D013 behavior. Build a locked release binary through a content-fingerprinted launcher; retain old Python implementations as parity references for historical links and regression comparisons.

## Rejected

Rewrite unrelated product functionality, silently change reminder semantics, execute a stale binary after source changes, or fall back to Python when native compilation fails.

## Rationale

Native execution removes Python startup and interpretation from registered hooks while parity tests constrain the migration. A minimal launcher connects source-controlled code to an untracked native artifact on fresh checkouts and after edits.

## Consequences

The pinned Rust toolchain and locked crates are build requirements. First use may compile; subsequent calls use the cached release artifact after source fingerprint validation. Reminder locks, atomic replacement, full-refresh text, and existing state keys remain compatible. Staged verification builds staged Rust code. Python Just orchestration, branch integration, and the Ledger checker remain outside the migrated hook runtime. Existing hook registration tests are updated to the native entrypoint.
