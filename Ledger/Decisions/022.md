# D022: Actionable verification and recovery

## Context

The requested agent-native improvements connect VAC intent, observed checks and the next action after a fresh context. Existing output gives repair skills but not consistent executable retries; resume lacks Git operations and durable check evidence.

## Chosen

Describe the intended observable outcome and falsifiable check in VAC context, then observed verification in the commit. Share diagnostic formatting and provide focused check retries while preserving complete commit/integration gates. Keep only the latest check attempt in the configured transient runtime directory, bound to observed HEAD and content, with atomic progress replacement. Resume reports evidence freshness and live Git merge/rebase facts. Repeated check failures prompt comparison of actual failures and applied guidance.

## Rejected

A separate VAC registry, manager, scheduler, mandatory checkpoint or automatic skill rewrite. HEAD-only proof ignores dirty or staged content; a displayed skill does not prove it was read or helped. A repeated failing check ID does not prove a repeated root cause.

## Rationale

These facts support the next action without creating another delivery workflow. Shell-quoted retry commands preserve arguments and remain usable after staged exports disappear. Content and revision comparisons expose the scope of evidence instead of manufacturing current success.

## Consequences

Evidence is local and disposable, not an acceptance authority or complete history. Partial, unfinished and changed-input checks cannot claim a current full passing gate. External dependencies and environment are outside the content fingerprint. Existing consumers obtain the runtime and canonical skills through their distribution process; automatic version migration remains outside this task. I018 and I019 bind selected recovery guarantees to executable tests.
