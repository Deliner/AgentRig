# D240 — A profile lint's finding names the skill that repairs it

## Decision

Each lint of the rig's Clippy profile in `structural_lint/clippy/profile.rs` names, in the same entry, the skill that
repairs it, and a finding of that lint names `SKILL.md` of this skill under `paths.skills` of
`.agentrig/project.yaml` in lint output and in `--json`. A lint that catches what a rig rule catches names that rule's
skill, and lints with one repair share one skill. Every other compiler message, such as a lint that `-D warnings` or
`[lints.clippy]` denies and a build error, and a run that cannot check the project keep the configuration skill. The
profile, its lint levels and each finding's rule, file, line and level stay as D239 sets them.

## Reasons

- B138 requires that a profile lint's finding name its skill in lint output and in `--json`, and that the skill exist
  after `init` and name the lint (AC1). It also requires that a lint caught by a rig rule lead to that rule's skill
  (AC2) and that findings outside the profile lead to the general skill (AC3).
- The profile entry is the one place that denies a lint (D239), so a skill in that entry cannot be missing for a
  profile lint.
- `init` writes every skill to `paths.skills`, and a finding names its `SKILL.md` through the calling agent's
  directory (D188). The lint command and the gate already load `.agentrig/project.yaml` for `manifest` (D239).
- B138 adds no skills for lints outside the profile, including those a project denies in `[lints.clippy]`.

## Alternatives

- Keep the configuration skill on every Clippy finding (D239): one skill for all messages. Not applied: it gives no
  rewrite by the rig's standard and no exception rule for a profile lint (B138).
- A separate table from lint to skill beside the profile list: the profile stays a plain list of names. Not applied:
  two lists can diverge, and a lint added to the profile would fall back to the configuration skill unseen.
- Derive the skills directory from the path of `config_skill`: the Clippy run needs no project setting. Not applied:
  `config_skill` may name any file, and with `skill_root` it resolves outside `paths.skills`, where `init` writes the
  skills.
- A separate skill for each lint, also where a rig rule's skill repairs the same code: each lint gets its own text.
  Not applied: B138 AC2 requires one skill for one repair.
