# D202 — A denied flag is matched in every spelling its program reads, and a test command takes only operands

## Context

B154 AC1–AC2, from the audit of 2026-11-19. A `deny` entry of a catalog program was compared with the start of each
argument, while the program reads the flag in more spellings. Git took the abbreviation `--exe=id` and the cluster
`-qxid` for `git rebase --exec`. `git grep` took `--open-files-in-pa=cat` and `-iOcat` for its pager option. Find took
`-okdir` for `-ok`. `rg --pre` was not denied, and `rg --hostname-bin` runs a program as well. A catalog command with
`accepts_args: true` passed every word to its program. In a Rust project, `just run test -- --config FILE` let cargo
read a target runner from a file the agent wrote. In a Python project, `-p NAME` made pytest import a module.

## Chosen

A `deny` entry is a typed flag, parsed once when the configuration loads, and an entry in no form below is refused:

| Entry | Denies |
| --- | --- |
| `--name` | `--X` and `--X=V` when X is a nonempty prefix of name, which covers the abbreviations getopt and Git accept |
| `-c` | any single-dash word that contains c, which covers clusters such as `-qx` and attached values such as `-Ocat` |
| `-name` | any word that starts with `-name`, which covers find primaries such as `-execdir` and `-okdir` |

Checking goes past `--`, because find primaries still run after it. The rig's `rg` denies `--pre` and
`--hostname-bin`.

`accepts_args` takes `operands` besides `true` and `false`. Such a command refuses any word of the agent that starts
with `-`, so its program reads them only as names and paths. The `test` command that init writes takes operands. The
rig's own test command does so once its pinned runtime reads the form.

## Rejected

| Alternative | Why |
| --- | --- |
| End the generated test argv with `--` | pytest refuses a node ID after `--`, and libtest still reads options such as `--logfile` |
| Keep a list of allowed options per test runner | each runner and version accepts other options, so the list would need a parser per program |
| Expand each entry into every abbreviation in the configuration | the configuration would grow with each option and still miss clusters |
| Check the shell words in the hook only | the runner also starts catalog commands from gates and jobs, and the hook calls the same check |

## Rationale

A program reads a flag through its own option parser, so the rig matches the three forms such parsers accept instead of
a literal prefix. A test command needs only test names and paths, so refusing every option closes the options that run
code without knowing the runner. Parsing entries once keeps an entry that matches nothing out of the configuration.

## Consequences

A short entry such as `-c` also denies other single-dash words that contain c; a program whose options need such a
word lists the program without that entry. A deny list names only flags that run another program or command, not
those that run a fixed program, such as `rg -z`. GNU sed runs code through its `e` command, a script rather than a
flag. Pytest paths may still name test files outside the project. A test command with operands cannot take runner
options, which a project adds to its argv instead.
