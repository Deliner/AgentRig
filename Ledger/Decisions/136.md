# D136 — The Rust analyzer measures includes, macro_rules! bodies, globs and attributes without expansion

## Context

On 2026-11-07 the user asked to make voxel-rust ready for AgentRig. Version 95ee9dc with the `init` configuration
reported 5212 errors there, about 4700 of them analyzer limits: the crate root `src/core/lib.rs` was not analyzed, so
every file of the crate was incomplete, and the rest came from `include!("core.rs")`,
`include!(concat!(env!("OUT_DIR"), "/…rs"))`, `macro_rules!`, `#[wasm_bindgen]` and `#[unsafe(no_mangle)]`. Once the
crate was analyzed, glob imports, block-local `use` aliases and item-position macro calls left about 980 more. `init`
also left example, test and bench targets, `build.rs` and dependency names out of the configuration. The user agreed
B083 and chose the analyzer repair.

## Chosen

- **Includes.** `include!` with a string literal is a `RustInclude` reference: the included file is loaded with the
  module path of the calling module, its references count as if its text stood at the call, and the edge is
  composition like a module declaration. A file outside the source inventory is an incomplete finding at resolution.
  `include!(concat!(env!("OUT_DIR"), "/name.rs"))` marks the calling module generated; other computed paths stay
  incomplete.
- **macro_rules!.** Paths in rule bodies are references of the defining module, `$crate` maps to `crate`, `Self::`
  token paths are skipped. A macro defined by `macro_rules!` resolves to its defining file through the module scope
  chain. A macro call in item position, also as an expression statement at module level, marks its module generated.
- **Generated names.** A name unresolved in a generated module resolves to that module; through a glob of a generated
  module it resolves to the glob target.
- **Globs.** Local glob imports resolve precisely, following nested globs with cycle protection and the facade rule of
  ordinary imports. Prelude names fall back to their std origin only when the module has globs. External globs are
  assumed not to rebind std prelude names; exactly one external glob supplies an otherwise unbound name.
- **Block-local use.** A path whose first segment is bound by a `use` in an enclosing block is rewritten to the full
  imported path.
- **Attributes.** Builtin attributes, also inside `unsafe(...)`, give no reference; `no_mangle` and `export_name` are
  builtin. Other attributes are macro references: an external one depends on its crate, a local one stays incomplete.
  The whitelist of known function-like macros is removed; the derive whitelist stays.
- **init.** Example, test and bench target paths and the build script, by default `build.rs`, become crate roots;
  every dependency table, development, build and target tables included, adds its names with `-` replaced by `_` to
  `external.rust` together with std, core and alloc.

## Rejected

Expanding macros or running `build.rs`: the engine stays syntactic and executes no project code. Excluding the
affected files: unresolved local relationships cannot be hidden (refactor-large-directory). Reading OUT_DIR output: it
exists only after a build and its path differs per profile. Keeping the macro whitelist: every external macro would
need an entry, while its origin already resolves through imports and declared externals.

## Rationale

These forms are ordinary in generated, FFI and wasm Rust. Each choice keeps the measurement syntactic and attributes
every visible path to the module that owns it, so cycles and fan-out use real edges. Names produced by expansion are
invisible either way; attributing them to the generating module keeps the edge on the module that owns the macro call.

## Consequences

voxel-rust analyzes its crates and shows its real cycles and missing contracts. A path assembled from metavariables,
code in OUT_DIR, including prost `extern_path` references to project types, and a name generated by a macro defined in
another crate under a glob stay unseen. A local attribute macro and a computed include stay incomplete.
