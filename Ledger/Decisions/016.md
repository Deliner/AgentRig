# D016 — Configurable structural lint and repair guidance

## Context

The user requests extensible Rust lint rules with declared file/directory and language applicability, configurable selectors and thresholds, soft warnings, hard blocks, and corresponding repair skills. D002 and D007 currently combine hardcoded structural policy with the Python Ledger checker.

## Chosen

Supersede D002's structural-check ownership and D007's hardcoded configuration with the Rust linter and strict versioned TOML. Implement nonblank-lines for selected UTF-8 language files and directory-entries for directories. Require rule IDs, compatible targets, selectors, ordered threshold overrides, and warning/error skill paths. Run the same linter on each staged commit and integration candidate. Map external gate failures to configured repair skills too.

## Rejected

Infer rule capabilities from extensions alone, silently ignore unknown configuration, print unrepairable diagnostics without skills, introduce dynamic plugins before an actual rule needs them, or disable the staged/merge gate for speed.

## Rationale

TOML is already used in the worker and supports readable comments and typed configuration. One native engine owns structural measurements while the existing Ledger checker retains durable-knowledge validation. An explicit registry provides a bounded extension point for future implemented rules and language parsers.

## Consequences

Default numeric limits are preserved and expanded to configured language suffixes. Warnings exit successfully; rule errors block with exit 1; invalid configuration blocks with exit 2. Every diagnostic points to a repair skill. Overrides apply in order and must produce valid effective thresholds. Symlinks and missing files are excluded from inventory; directory counts use immediate names represented by selected files. I004 now uses a native oracle, with native hook and configuration invariants added. New rule implementations must declare capabilities and have tests and a repair skill before activation.
