# D161 — Staged checks run their export at a temporary path reused across runs

## Context

D160 reuses cargo builds of each staged run's fresh export, which lives in a new random temporary directory per run.
Cargo's fingerprint of a path package does not include the package's location, so a reused artifact keeps the paths
compiled into it: a program reading `env!("CARGO_MANIFEST_DIR")` pointed into the deleted export of an earlier run while
cargo reported the build fresh. A project whose code or tests reach files through compile-time paths would then be
checked against files that no longer exist instead of the staged content (B110 AC2). A tree inside the worktree, such
as under the runtime directory or `.git`, would let unstaged configuration that cargo, rustfmt, Clippy, ruff and typos
look up in ancestor directories reach the staged check. In a temporary directory shared by several users, another user
can create a fixed or derivable name first.

## Chosen

After taking the lock of D160, the gate reads the tree path recorded in `<runtime>/staged/stamps.json` and creates a
directory with that path's last component in the current temporary directory, exclusively, so an existing directory
fails the creation. Without a record, or when the creation fails, it creates a new directory with a random
`agentrig-staged-` name. It moves the fresh export onto the created directory, loads the configuration again from
there and stamps the files. Recorded times apply only when the canonical tree path equals the recorded one; otherwise
every file gets the current time. The record stores the tree path beside the stamps. The tree is removed when the run
ends, before the lock is released. The filesystem owner gains `rename`.

## Rejected

A persistent parent directory reused with ownership and permission checks: the gate would trust a directory it did not
just create, and a default temporary directory follows the umask, so a permission check does not identify it. A tree
under the runtime directory or `.git`: ancestor configuration from the worktree reaches it. A name derived from the
project path: another user can create it first. `--remap-path-prefix`: it does not change `CARGO_MANIFEST_DIR`. A
persistent export tree updated in place stays rejected for the reasons of D160; each run still exports afresh.

## Rationale

A reused artifact is used only at the path it was built at, and in each run that path holds exactly the staged content.
The gate runs only in a directory it has just created, so no other user can prepare its contents.

## Consequences

An interrupted run leaves its tree behind; the next run takes a new name and builds from scratch once, and the old tree
stays until the system cleans its temporary directory. A run with a different temporary directory also builds from
scratch once. On macOS the per-user temporary directory is the same across login sessions.
