# D086 — Anti-duplication ships as a norm, not a static clone rule

## Context

C7 (cluster of Набор II, agreed 2026-10-31 for autonomous delivery) targets
duplicated logic: under pressure an agent copies a block instead of giving the
behavior a single owner, leaving divergent copies that drift when one is edited
and another forgotten. The structural engine is purely syntactic (tree-sitter):
it measures per-file scalars and a directory dependency graph, and the
architecture analyzer extracts references and item names/scopes, not function
bodies. So it has no corpus of code bodies to compare, and duplication is the
canonical agent-native smell that nonetheless resists static near-zero-FP
detection.

## Chosen

C7 ships as a norm. A portable anti-duplication principle is added to the
delivered `complexity-discipline` skill, next to its existing consolidation
clause: do not introduce a second representation of behavior that already has an
owner; reuse or extend the existing definition instead of copying it, so one
change cannot leave divergent copies behind. No init rule, rule kind, or
skill-for-a-rule is added; the principle rides the same init scaffold to every
consumer as the rest of the discipline.

## Rejected

A static clone rule. Broad and fuzzy (Type-2/3) and cross-file clone detection
needs a tuned corpus/windowing subsystem whose similarity threshold is inherently
false-positive-prone (generated code, boilerplate, legitimately parallel
constructs) and whose cost conflicts with the fast gate and portable install —
the same grounds that rejected the type-resolving frontend (D059), measured
against the near-zero-FP bar (D035). The only variant below the new-subsystem
rung — within-file exact byte-identical whole-body duplication — fires too rarely
to earn a new rule kind, a repair skill and a new per-file aggregation pass:
agents seldom emit byte-identical whole bodies within one file, while real
duplication is cross-file and fuzzy, so the machinery would carry near-zero
enforcement value. A pretend invariant is forbidden by norm-or-choice.

## Rationale

Norm-or-choice: a rule fits a decidable, high-signal, near-zero-FP check; a norm
fits a behavior not statically checkable without false positives or
disproportionate machinery. Duplication similarity is fuzzy and semantic or needs
a corpus clone engine, so it stays a norm. Existing shipped rules already apply
structural pressure against the conditions where duplication accumulates: the size
budgets (file-size, function-lines, directory-entries), the junk-drawer ban
(dump-name), and directory-architecture's purpose-quality, cycle-free and fan-in
checks (D070/D079).

## Consequences

C7 adds no rule kind, no skill-for-a-rule and no invariant, so the I020 delivery
sets stay balanced — only `complexity-discipline`'s text grows by one portable
principle, delivered through the same init scaffold. Reassessing duplication as a
rule would need the corpus clone subsystem or the type/data-flow frontend the
syntactic engine lacks (D059). Набор II C7/P050 is complete with this. It
supersedes nothing.
