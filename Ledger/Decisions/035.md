# D035 — Select affected tests for the whole branch at feature merge

## Context

The user asked on 2026-10-26 that a feature-branch merge run only the tests
touched by the change, not every test, as the first step toward a faster
pipeline (Requests.md). Commits already select tests through the configured
affected-path map, while feature-merge ran every command in full and D022
preserved complete integration gates.

## Chosen

feature-merge runs the gate on the rebased feature worktree and applies the
same affected-path map to every path changed between the configured base
branch and the feature HEAD. Lint, memory, formatting and other unmapped
checks still run in full. Merge proceeds when this gate passes on unchanged
inputs; it no longer requires full_gate_passed. `check` without options still
runs the full suite.

## Rejected

Keep the full suite at merge, infer affected tests from coverage before a map
exists, or let the agent choose the merge subset.

## Rationale

The branch diff is the union of the commits it integrates, so the same map
that accepted each commit selects the tests for the integrated result,
including interactions between commits. Coverage-based selection remains
future work.

## Consequences

D022's complete integration gate is superseded for test commands. Merge speed
depends on the map; an outdated map can skip affected tests, and a catch-all
smoke group never falls back to the full suite. Selective merge evidence keeps
full_gate_passed false.
