# D197 — No scratch; the pin and the baseline run as recipes

## Context

B150: `just scratch -- TEXT` ran `sh -c TEXT` from the repository root with write access to the repository and Git and
no sandbox, so it bypassed the program lists of `just read` and `just write`. The user doubted that scratch was needed
beside read and write and asked to keep it only if they are not enough. Two steps that the rig's rules and messages
require were possible only through scratch: the hook refused `just bootstrap` and `just lint-baseline`, which are in
neither its recipe list nor the rig's catalog. On P148 the pin was written first and bootstrap run next: the agent
hook, which runs the pinned launcher, then stopped every call, bootstrap included, until the user ran it by hand.

## Chosen

The `scratch` command, recipe, hook branch, task area and its merge cleanup are removed from the runtime, the rig and
the `init` template. The hook passes `just lint-baseline` with its arguments like the other lint recipes. The rig's
catalog holds `bootstrap`, so the hook passes the rig's `bootstrap` recipe as it passes `candidate`. Bootstrap takes an
optional revision: given one, it resolves it to a full hash, installs it unless installed, and only then writes it to
stable.txt; without one it installs the pinned revision as before.

## Rejected

| Alternative | Why |
| --- | --- |
| Keep scratch, limited to its task area and without network | no required step needed it once bootstrap and the baseline pass the hook |
| Name `bootstrap` in the hook's recipe list | the product would carry a recipe of the rig's development only |
| Write stable.txt, then run `just bootstrap` | hooks stop every call while the pin names an uninstalled revision |
| A separate pin recipe | bootstrap already installs the revision; one command keeps install before pin |

## Rationale

Without scratch every shell call passes the program lists or a catalog command, the owner of each capability. A pin
written only after its installation leaves the hooks a runnable launcher at every moment.

## Consequences

Temporary work uses `just read`, `just write`, catalog commands and editing tools; work they cannot do needs a catalog
command. D051's pin is `just bootstrap HEAD` at the gate-accepted head instead of writing stable.txt and running
bootstrap in one command; the rest of D051 remains. `feature-merge` deletes only its run logs.
