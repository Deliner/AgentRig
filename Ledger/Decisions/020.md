# D020 — One runtime and current context

## Context

The user explicitly requested removal of all duplicated implementations and stale or conflicting context. The portable runtime had been delivered alongside a still-active Python command runner, Git workflow and memory checker. Separate skill copies and legacy dispatch paths allowed behavior and instructions to diverge.

## Chosen

Use worker.toml and the Rust runtime for this repository as well as consumers. Keep Just and Git adapters thin, one configured gate, and one physical skill tree shared by agent discovery and binary packaging. Remove Python policy implementations and legacy runtime dispatch. Keep Python behavioral tests and their external tooling where they have an independent verification role.

Preserve committed decision IDs, statements and detail contents. Treat Applies in as the current ownership map, updating it when code moves or is removed; Git retains previous paths. This replaces D002's Python checker choice, D005's JSON/Python catalog implementation and command-review counter, D019's hardcoded path-migration exceptions, and corresponding path-preservation instructions. Current links must exist and supported source applications retain the appropriate decision marker. D008's local Project/Ledger layout remains a repository fact, not a hardcoded consumer requirement.

## Rejected

Deleting callers without migrating their checks; keeping a second compatibility runtime; adding historical path exceptions to the native engine; copying instructions into separate packaged and agent-facing skills; rewriting historical decision details to describe present behavior.

## Rationale

One behavioral owner and one maintained instruction source remove the observed causes of drift. An ownership map must follow actual code rather than retaining dead paths. Historical reasoning remains recoverable independently of current navigation.

## Consequences

I001 includes native Rust, Python and shell marker checks. I003 preserves decision identity and detail history while current application coverage is validated instead of old paths being append-only. I013's duplicate compatibility assertion is superseded by the specific hook, command and reminder contracts. Old checker tests migrate to native behavioral tests; obsolete implementation-specific tests disappear. No new scheduler or persistent coordination system is introduced. Future inconsistencies remain detectable through configuration, links, markers and behavior checks rather than a claim that context can never become stale.
