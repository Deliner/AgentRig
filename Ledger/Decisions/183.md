# D183 — `--force-warn` in the rig's flag list needs a reference like the other flags lowering lint levels

## Context

B135 under D151 and D182. D182 checks only `-A`, `--allow` and `--cap-lints` in the `rustflags` list of
`.agentrig/rust.yaml` and leaves other level flags, such as `--force-warn`, unreported. A probe on Clippy 1.100 on
2026-11-13 ran `cargo clippy -- -D warnings -D clippy::panic` with the flags in `CARGO_ENCODED_RUSTFLAGS`, as the rig
passes them, on code with an unused variable, `panic!` and `unwrap`: `--force-warn` for the three lints turned all
three into warnings and Clippy exited 0 when the manifest denied `unwrap_used`, both as a separate item and with `=`.
A manifest `forbid` held. `-W` for the same lints left three errors, because `-D warnings` raises them again, and
`--force-warn warnings` is rejected by rustc.

## Chosen

- `allow-justification` reports an item of a YAML `rustflags` sequence starting with `--force-warn` without a
  `DECISION:` or `INVARIANT:` reference on the line directly above, like `-A`, `--allow` and `--cap-lints`.
- Its violation text names the four flags as compiler flags lowering lint levels, and the skill `justify-allow`
  describes what each does and how to delete the item or reference a decision; `move-rustflags` lists the same four.
- The kind and the repository rules stay unchanged, so no mid-branch pin is needed; the branch ends with the D051 pin.

## Rejected

| Alternative | Why |
| --- | --- |
| Also reporting `-W` and `--warn` | under the gate's `-D warnings` they did not let the probe pass |
| A separate kind for `--force-warn` | `allow-justification` already owns flags lowering lint levels and their repair |
| Reading flags in `.agentrig/commands.yaml` argv | B135 leaves them out; `-A` and `--cap-lints` there are not read either |

## Rationale

`--force-warn` lowers a denied lint below what `-D warnings` restores, so it makes the gate pass on a finding as
`-A` does. One prefix list owns every flag the rig treats as lowering lint levels, so the YAML check, its message and
its skill name the same set.

## Consequences

Supersedes D182's consequence that `--force-warn` is not reported. Init still copies a `--force-warn` from
`build.rustflags` into the list, where this check reports it until it is removed or referenced. Flags in command argv
and `-W` stay unchecked.
