# D076 — Flag a declared external dependency that is never imported

## Context

B033 (cluster 8 of the quality set, agreed 2026-10-29) asks that dependency
hygiene be enforced so a declared dependency that nothing uses is caught before
it accumulates (8.1). The `directory-architecture` rule already asks each subtree
to declare its external modules (`external.rust`/`external.python`) and already
errors on an *undeclared* external reference; the opposite direction — an external
that is declared but never imported — was not checked, yet it is decidable from
the same resolution pass the rule already runs (D035). Resolution produced an
`external` origin per reference but dropped it on the Rust path and never
aggregated it anywhere.

## Chosen

Extend the existing `directory-architecture` rule, not add a new `Kind`. During
dependency resolution, aggregate the first path segment of every successfully
resolved external reference into a used-set per language; after the pass, every
declared external that is neither used nor a seed member becomes a finding
("declared external … dependency is never imported: …") reported on the feature
owner. Two seed sets are exempt from the never-imported check: `RUST_SEED`
(`std`, `core`, `alloc`) because they are the always-available default and
declaring them is baseline, and `PYTHON_SEED` (`__future__`) because
`from __future__ import …` parses as a distinct `future_import_statement` the
source inspector does not record, so it would be a false positive. Because the
rule kind is already delivered, the stricter binary ships the check to consumers
through the pin; no `lint.yaml` kind, `catalog::ALL` entry or skill is added, so
the delivered rule-kind and skill sets are unchanged (I020) and the repair skill
stays `refactor-large-directory`.

## Rejected

A new `Kind`/rule for dependency hygiene: the `directory-architecture` rule
already owns the external declarations and the resolution pass, so a separate rule
is unnecessary indirection. Scoping the check to configs that set `feature_root`
(so test fixtures would be exempt): that would weaken the check to pass fixtures
rather than fix them, and the check is correct without a feature owner. Merging
the seed into the declared set instead of exempting it: `#[serde(default)]`
replaces the seed when a config provides `external.rust`, and exemption keeps the
"declared but unused" meaning precise for `std`/`core`/`alloc`. Recording
`__future__` by teaching the inspector the `future_import_statement` node: more
change than the near-zero-false-positive bar needs for one pseudo-module (D035).

## Rationale

A declared-but-unused external is unambiguous and decidable from the resolution
the rule already performs, meeting the high-signal, type-free bar for the gate
(D035). Extending the existing rule is the lowest sufficient rung (no new kind,
skill or invariant), mirroring D070's tightening of the same rule. The two seed
exemptions are grounded in a real always-available default (Rust) and a
demonstrated tree-sitter blind spot (`__future__`), not in convenience.

## Consequences

A consumer's or this repository's `architecture` external list with a module that
no scanned source imports becomes a gate error on `init` and before commit;
removing the stale declaration, or importing the dependency, passes. This
repository's config dropped seven genuinely unused Python externals (`contextlib`,
`copy`, `hashlib`, `io`, `re`, `tarfile`, `tomllib`) to go green. The engine now
preserves and aggregates the external origin it previously dropped. It extends the
contract-tightening approach of D070 and the fixed-set/seed philosophy of
D067/D070; the delivered rule-kind and skill sets are unchanged (I020). It
supersedes nothing.
