# D074 — Flag silently disabled tests without a justifying reference

## Context

B032 (cluster 7 of the quality set, agreed 2026-10-29) asks that tests be
explicitly justified rather than silently disabled (7.1). A Rust `#[ignore]`
attribute or a Python `@pytest.mark.skip`/`skipif` decorator disables a test: the
suite stays green while the behavior it pinned goes unchecked. Whether a test
carries such a marker, and whether a reference sits on the line directly above
it, is decidable from syntax alone with no symbol or type resolution (D035). The
`justified` reference-escape mechanism already exists for unsafe (D065) and
except-pass (D069).

## Chosen

Add a `disabled-test` rule kind (target file, error level), cross-language in both
the Rust and Python handlers: a Rust `#[ignore]` attribute, or a Python decorator
whose callee is one of the fixed set `pytest.mark.skip` or `pytest.mark.skipif`,
without a `DECISION:` or `INVARIANT:` reference comment on the line directly above
it, is a finding. It reuses the existing `justified` measurement helper. The kind
ships to consumers through `catalog::ALL` and the delivered per-kind config
template, with a repository rule over `.rs`/`.py`/`.pyi`. A new repair skill
`justify-skip` joins the `references` group — re-enable, delete, or justify — and
ships through `project_setup/assets.rs`, so the delivered and live skill sets both
grow by one and stay equal (I020); the rule-kind set grows too.

## Rejected

Reusing an existing repair skill: `testing-discipline` explicitly disclaims
linting and concerns placement and public surface, not disabled tests, and
`justify-unsafe`/`handle-error` are construct-specific; the justification-rule
family each owns a tailored skill (D065/D069). A larger marker set (`xfail`,
`unittest.skip`): `xfail` still runs the test (different semantics) and the
repository uses pytest; a wider set raises false positives against the
near-zero-false-positive bar (D035). Scoping detection to "test files": the
markers appear only on tests anyway, so identifying a test file adds a dimension
without changing results.

## Rationale

The markers are unambiguous and syntactic, meeting the high-signal, type-free bar
for the gate (D035). The fixed decorator set keeps the Python half decidable and
near-zero-false-positive, mirroring the fixed-set philosophy of the
hardcoded-secret (D067) and dump-name (D072) rules; reusing `justified`
(D065/D069) is the lowest sufficient mechanism. This repository has no disabled
tests, so the rule is green on delivery.

## Consequences

A consumer's or this repository's Rust `#[ignore]` or Python
`@pytest.mark.skip`/`skipif` without a reference on the line directly above
becomes a gate error on `init` and before commit; a re-enabled, deleted or
referenced test passes. The rule-kind set and the skill set both grow by one and
stay equal across delivery and repository (I020). It extends the reference-escape
family (D065/D069) and the fixed-set approach (D067/D072). B032's 7.2
(nondeterminism) and 7.3 (name/placement) are not shipped as rules and remain
norms, recorded separately. It supersedes nothing.
