# D018 — Explicit lint configuration validation

## Context

The user requests a standalone configuration checker, declared rule capabilities and an error when a language-specific rule is configured for an unsupported language. D017 currently skips unsupported files when extensions are omitted, which can hide mistaken applicability.

## Chosen

Add lint-config-check using the same config loader and target/override selection as lint, without source analysis. Preserve existing lint-rules capability discovery and derive supported suffix validation and catalog extensions from the same handler table. Add enabled, default true; disabled entries remain schema-valid but do not select or measure files.

Supersede D017's implicit unsupported-file skipping: after include/exclude and extension filtering, selected files must have a handler for syntax rules. Reject explicit unsupported suffixes in extensions and literal-suffix include globs even without existing files. Validate other glob applicability and effective numeric overrides against the current inventory.

## Rejected

Duplicate the schema in a separate checker, infer language support from the user's configuration, silently skip selected unsupported files, or analyze source just to validate configuration. Do not attempt to predict every future glob match.

## Rationale

One selector owns target compatibility and effective thresholds for both commands. Existing suffix selectors are enough to configure language scope; no second language-selection syntax is needed. Explicit enablement makes rule activation visible without deleting its configuration.

## Consequences

Invalid configuration exits 2 with the configuration skill. Mixed directories need supported extensions or exclusions. Existing default syntax rules already specify extensions, so their coverage is preserved. Configuration validity does not imply valid source or passing measurements. I016 tests unsupported language rejection through both entrypoints; companion tests cover schema, enablement, overrides, empty inventories and parser independence.
