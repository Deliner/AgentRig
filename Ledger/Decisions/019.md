# D019 — Remove legacy hook and size implementations

## Context

The user requests removal of duplicate lint and hook implementations, Rust execution for all hooks including complexity discipline, and one hook code/build location. Registered Codex and Git hooks already invoke the native worker, but parity tests retain obsolete Python copies. Historical application links currently require those copies to exist.

## Chosen

Remove all four Python files under .codex/hooks and tooling/size_policy.py, plus the unused Python Git guard commands/functions from branch_workflow.py. Keep hooks under tooling/worker/src/hooks, moving native Git guards there too; retain minimal Codex registration and Git shell launch adapters to the single worker build. Replace Python-reference comparisons with direct native contract tests for routing, guards, token thresholds, retries, transcript offsets, compaction and persistence failures.

Supersede D015/D016's retention of historical executable references. Supersede D001's application-link immutability only for five explicit migrations: agent_context.py and commit_checkpoint.py to hooks/mod.rs, complexity_discipline_reminder.py to hooks/reminder.rs, just_command_guard.py to hooks/guard.rs, and size_policy.py to lint/mod.rs. The checker accepts only these deleted-path replacements; all decision identities, statements and detail files remain immutable. Existing tests and Python Ledger/Just orchestration remain where they have independent responsibilities.

## Rejected

Keep executable duplicates or empty compatibility stubs solely for historical links, rewrite all Python tooling unrelated to hooks, maintain a second Rust hook crate/build, or remove behavioral coverage along with the reference code.

## Rationale

Runtime consolidation already exists; removing stale implementations and moving test observations to the native entrypoint completes it without adding another subsystem. Explicit link migrations preserve traceability while allowing actual deletion rather than creating an archival runtime.

## Consequences

Only native code implements hooks and structural size checks. Python test helpers invoke the binary and contain no hook decisions. Complexity schedule configuration stays beside its skill; the Rust reminder reads it. I003 now permits only the named native application-link migrations; I013 uses direct native behavior as its oracle. Prior implementation contents remain available in Git history. The launcher remains the single source-fingerprinted Cargo build path.
