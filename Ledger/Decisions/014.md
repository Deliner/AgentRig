# D014 — Shared pre-edit guidance

## Context

The user requests one place for pre-edit hooks and a compact skill reminder for Plan, Decisions, Invariants, and State. Existing shell and complexity hooks already own their checks and must keep their behavior without returning to per-edit checkpoints.

## Chosen

Register one agent_context.py entrypoint for SessionStart and PreToolUse. Reuse the existing command guard and complexity implementation, and route Ledger edits to edit-plan, edit-decisions, edit-invariants, or edit-state. Include index/detail targets and patch additions, updates, deletions, and moves. File guidance adds context without a new permission decision or read-tracking state.

## Rejected

Register separate hooks for each file, duplicate existing guard/reminder logic, block every edit until a skill-read acknowledgement, or claim arbitrary shell script targets can be statically determined.

## Rationale

One dispatcher owns routing while focused skills describe how to edit each memory type. Context-only prompts keep VAC correction loops free, and existing owners retain actual enforcement.

## Consequences

Direct edit payloads receive only relevant deduplicated skill paths. Opaque just write calls receive a conditional mapping; agents apply the corresponding skills themselves. Existing complexity denials include any relevant Ledger guidance. Old guard/reminder adapters remain available for historical links and already loaded configurations; current sessions use the shared registration. Updated hook-registration tests replace the old direct-reminder expectation without changing I006's VAC commit predicate.
