# D034 — Contain jobs with process groups and sandbox read-only commands per platform

## Context

The user requires macOS and Linux support without systemd (Requests.md,
answers of 2026-10-26). Job identity read /proc, background and optional
foreground containment used systemd user scopes with cgroup limits, and
read-only commands required bubblewrap, so neither jobs nor the gate ran on
macOS.

## Chosen

A background runner leads its own process group; stop sends SIGTERM and then
SIGKILL to that group and waits until it is empty. A group is trusted only
while its leader PID is absent or still has the recorded start time and boot
identity. Linux reads identity from /proc; macOS uses sysctl and proc_pidinfo.
Foreground commands keep signal forwarding to their own group. Read-only
commands run under bubblewrap on Linux and under sandbox-exec on macOS with
writes limited to a private temporary directory and no network. Memory and
process-count limits and the processes configuration section are removed.

## Rejected

Keep systemd scopes on Linux beside a macOS backend, emulate cgroups with
launchd jobs, or run read-only commands without a sandbox on macOS.

## Rationale

One containment model on both platforms keeps the behavior testable on the
developer's machine and in CI. Process groups need no service manager, and
both sandboxes enforce the same read-only and offline policy.

## Consequences

Descendants that start a new session or process group escape job stop and
cleanup. Resource limits are no longer enforced. sandbox-exec is deprecated
by Apple; its replacement must keep the same policy. CI runs on both
platforms.
