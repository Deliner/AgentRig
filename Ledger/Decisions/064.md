# D064 — Enable ruff bandit (S) for Python, scoped to production code

## Context

The user selected the code-quality set (clusters 1–8, B026–B033) on 2026-10-29
for dogfooded delivery. Backlog B026 sub-rule 1.2 asks for Bandit through ruff's
`S` group to catch `shell=True`, `eval`/`exec`, injections and hardcoded
credentials in Python. Enabling `S` surfaced 914 findings, all from three noise
checks and all in test code: S101 (assert, 800), S603 (subprocess without
`shell=True`, 71) and S607 (partial executable path, 43). No `shell=True`,
`eval`/`exec` or hardcoded-credential finding appeared. Asserts are how pytest
tests state expectations, and the test and test-helper code spawns the worker
binary under test by name. As with the clippy/ruff profile (D060), `init` does
not ship ruff, so this is the repository's own dev-gate profile, not an
init-universal capability.

## Chosen

Add `S` to the ruff `select`. Scope S101, S603 and S607 to test code — the
`tests/` and `testing/` trees and `conftest.py` — through `per-file-ignores`,
leaving the full `S` group active on production Python. Production Python is
green.

## Rejected

Exclude S603/S607 globally, which would blind production code to real subprocess
risk; hand-pick a subset of `S` rules, which is fragile and misses future
bandit rules; leave S101 firing on tests, which punishes the normal
assert-based test mechanism; or not enable `S` at all, losing the `shell=True`,
`eval`/`exec` and credential guard the card asks for.

## Rationale

The stated threats map to S602, S102/S307, S105–S107 and S506, which stay
enforced everywhere, including production code. S101, S603 and S607 inside test
code are the test mechanism — asserting and spawning the CLI under test — not
vulnerabilities, so scoping them to test code is principled rather than a
weakened selector. Keeping `S` active on production code guards consumer code
written later. Bandit runs inside ruff, adding no tool or gate step, so the fast
gate (D035) is preserved.

## Consequences

Repository Python gains bandit scanning in the dev-gate: `shell=True`,
`eval`/`exec` and hardcoded credentials become pre-commit findings on production
code. Test code is exempt from the three noise checks. `init` still does not ship
ruff (D060), so 1.2 improves this repository's dev-gate rather than the init
delivery; B026's init-universal capabilities are its structural rules — 1.1
`unsafe`-justification and 1.3 secret scanning. D064 supersedes nothing.
