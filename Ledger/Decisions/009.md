# D009 — User-facing feature plan

## Context

Development must proceed by requested functionality without preregistering implementation details.

## Chosen

Give each Plan entry one user-facing feature, capability, and observable acceptance contract. Let the executing agent choose implementation.

## Rejected

Use Plan entries as implementation task lists or encode architecture before the feature is executed.

## Rationale

Feature contracts preserve user intent while allowing implementation to respond to the actual code and constraints.

## Consequences

Exactly one Plan feature is active, and the execution skill treats its detail as the required result rather than a prescribed solution.
