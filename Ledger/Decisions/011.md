# D011 — Verified atomic changes

## Context

User-authorized delivery now requires cohesive verified changes that may span multiple edits. D003 tied progress to tool calls and required a failed commit before corrections could proceed, adding work without establishing semantic atomicity.

## Chosen

Supersede D003 with VACs: identify the result and verification, edit and correct freely, then commit one coherent change through the existing full staged-tree gate. Replace I006 with executable commit-boundary behavior. Keep the retired checkpoint adapter inert for historical links and sessions that already loaded it.

## Rejected

Keep per-edit locks, build a second VAC state registry, require failed commits to permit fixes, or routinely run the same full gate manually before pre-commit.

## Rationale

Git commits already represent durable independently revertible changes. The executing agent owns semantic scope and focused verification; the pre-commit hook owns mechanical acceptance of staged contents.

## Consequences

Multiple edits and failed checks do not block correction. VAC commit messages describe the result and verification; unrelated work stays out of the index. The complete gate remains mandatory on commits and integration, including verification after rebase. Complexity reminders and command routing remain unchanged. Historical checkpoint state is ignored, and D003 remains an immutable historical record.
