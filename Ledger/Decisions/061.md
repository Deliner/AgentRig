# D061 — Limit control-flow nesting depth per function

## Context

The user selected the code-quality set (clusters 1–8, B026–B033) on 2026-10-29
for dogfooded delivery. Backlog B029 sub-rule 4.1 asks that deep control-flow
nesting be caught by the gate before review, purely syntactically, only on
Project, as a capability that ships to `init` (D053/I020). Rust and Python are
the supported languages. The existing strict defaults (D017: named conditions,
function size, input count) deliberately do not cover nesting depth (I017).

## Chosen

Lint gains the nesting-depth rule kind for Rust and Python. The measurement is
the deepest chain of nested control-flow blocks in one function: `if`, `match`,
`loop`, `while` and `for` each add a level. A Rust else-if (an `if` whose parent
is an else clause) and a Python `elif` continue the same level rather than
deepening it. A nested function or closure body is a boundary: it is measured on
its own, not counted inside the enclosing function. The threshold is error 4
(a finding at depth 5 and deeper), with no warning level, routed to the
flatten-nesting skill. The rule is delivered to consumers through `rules::ALL`
like the other language rules.

## Rejected

Count else-if and elif as added depth; count a nested function or closure body
inside the enclosing function's depth; pick a stricter threshold to force
refactors or a laxer one to avoid them; measure weighted cognitive complexity
rather than literal block nesting.

## Rationale

Depth, not length, is the control-flow smell, and it is invisible to the
function-size and parameter rules. An else-if or elif is a flat multi-way choice,
so continuing the same level keeps the measurement aligned with what the reader
experiences. A nested function is its own scope, consistent with measuring each
function's size and parameters on its own. Threshold 4 matches the
parameter-count boundary and marks a clear "too deep" line that this
repository's code already satisfies, so it is principled rather than weakened to
pass. The metric stays syntactic so it needs no type inference and keeps the
gate fast (D035).

## Consequences

A function nested beyond depth 4 becomes a delivery finding routed to
flatten-nesting, in the worker repository and in every consumer. Nesting inside
a distinct nested function or closure is attributed to that inner scope.
Cognitive-complexity weighting and non-control-flow nesting are not measured.
Sub-rules 4.2 and 4.3 of B029 remain separate later decisions.
