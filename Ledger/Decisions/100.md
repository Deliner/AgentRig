# D100 — Flag a path that reaches two module levels up through super::super

## Context

B058 (research arc, "super-super-reach", `meta/register.md` repair 3, agreed 2026-11-02;
implementation of the arc's findings authorized by the user on 2026-11-04 via /goal) observes that
a path `super::super::X` binds a file to its position in the module tree instead of to the item's
owner: moving a directory breaks the path, and a reader cannot see whose item it is. A single
`super::` names the enclosing module, which moves together with the file; a `crate::` path or a
re-export at the parent names the owner. The form is decidable from syntax alone (D035, D059):
tree-sitter parses `super::super` as a `scoped_identifier` whose `path` and `name` are both
`super` nodes, exactly once per path, whether the path sits in a `use` declaration, an expression
or a type. The repository has eight production sites in six files
(`architecture/runner/analysis.rs`, `architecture/source/rust/macros.rs`,
`resolution/rust/tree.rs`, `resolution/rust/macros.rs`, `initialization/init.rs`,
`initialization/wizard.rs`) and several under `tests/`.

## Chosen

Add a `super-super-reach` rule kind (target file, error level), Rust only, on a
`scoped_identifier` dispatch in `languages/super_reach.rs`: the detector fires on the node whose
`path` and `name` fields are both `super`, so every `super::super` path yields exactly one finding
at its line, with the reached item (the enclosing path's `name`, or `super::super` for a use
list) as the symbol. A `DECISION:` or `INVARIANT:` reference on the line directly above removes
the finding (D065/D069/D082); test code is excluded by `in_test_context` (D082) and by the
delivered rule's `**/tests/**` and `tests.rs` excludes, since test modules legitimately reach
the unit under test. A new `anchor-at-crate` repair skill ships with the kind (write the path
from `crate::`, or re-export the item at the parent), so the rule-kind and skill sets grow by one
each and stay equal (I020). The kind, descriptor, detector and tests land first, the stable
binary is pinned so the repository configuration can name the kind (D051), then `catalog::ALL`,
the Rust handler, the repository rule, the skill and its delivery entry follow, and the
repository's own production sites are rewritten to `crate::` paths (or the existing module
alias) during dogfooding.

## Rejected

Matching the text `super::super`: `super::super_reach` and a string literal would false-positive,
whereas the parsed node pair is exact (D035). Flagging a single `super::`: the parent module moves
with the file and is the conventional way to reach a sibling; flagging it would be noise. Flagging
`crate::` paths of any depth: they name the owner, which is the repair. Flagging test code: a
`tests/` module reaching `super::super` names the unit it verifies and moves with it. Resolving
whether the reached item is re-exported closer: outside the syntactic engine (D059). Extending
`wildcard-import` or `directory-architecture` instead of a kind: the violation (position-bound
reach), repair and skill differ from a glob import and from a directory dependency cycle.

## Rationale

The `super::super` pair is a fixed, syntactic signal meeting the type-free bar (D035) and the one
place a reach through two levels always passes, so one dispatch arm and a two-field check cover
`use` declarations, expression paths and type paths alike without enumerating path shapes. The
kind reuses the justification and test-context machinery; the dedicated skill names the two
repairs the violation admits.

## Consequences

A consumer's or this repository's `super::super` path in non-test Rust becomes a gate error on
`init` and before commit; a `crate::` path, a parent re-export or a reference on the line directly
above passes. `just lint-rule super-super-reach` describes the kind, the rule-kind and skill sets
both grow by one (I020), and the repository's eight production sites are rewritten during
delivery. It ships B058 in full; it supersedes nothing.
