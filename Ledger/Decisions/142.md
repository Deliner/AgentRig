# D142 — Architecture findings carry the edges they count, and every lint finding prints as a group

## Context

B088. The dependents-budget finding of D079 named only the count and the budget. The cycle finding named the
directory chain and one location, the closing edge. On voxel-rust the user had to write a separate edge oracle to find
which files caused a budget overrun; that oracle missed crate roots and disagreed with lint. Lint text output printed
a single finding on one line and a group of findings with one cause as a header followed by indented locations, so
the same finding looked different depending on whether another one shared its cause. The user's /goal of 2026-11-10
selected B088 with every other Backlog card and left the choices to the executor.

## Chosen

One function in the architecture graph collects the directory edges the budget counts: a measured edge that is not a
module declaration and whose source and target files lie in different directories. For each target directory it keeps
every source directory with the first such edge in analysis order, which is files sorted by path and references in
source order. The budget finding lists each dependent directory in path order with that edge as
`file:line uses target`, after the count and the budget and before the repair advice.

The cycle finding keeps its directory chain and its location at the closing edge, and appends every edge of the
cycle in the same form: the first measured edge between each pair of consecutive directories, then the closing edge.

Lint text output prints every group of findings with one cause the same way: a header with the number of locations
and the shared action, then one indented line per location with its message. A single finding is a group of one.
JSON output is unchanged.

## Rejected

Choosing the smallest file and line as the example: analysis order is already deterministic, and the cycle graph
already keeps the first edge, so a second selection rule could make the two findings name different edges for the
same pair of directories. Listing every edge of every dependent in the finding: a widely used directory would produce
very long findings, while one edge per dependent already identifies the relationship. Moving the cycle location to a
stable file: the closing edge is already deterministic, and the appended edges now carry the explanation. Keeping the
one-line form for single findings and only renaming the group header: the card asks for one form.

## Rationale

A finding that names the edges it counted can be repaired from its own text. Taking those edges from the same
function the measurement uses keeps the finding and the count in agreement by construction.

## Consequences

Budget and cycle messages grow by one entry per dependent or per edge of the cycle. Text readers that matched
`LEVEL [rule] path` on the header line find the path on the indented line below it. D079's budget, default and level
and D049's warning visibility are unchanged.
