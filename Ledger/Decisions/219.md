# D219 — A lint exception names its rule, and its decision lists it

## Context

Since D065 about forty lint rules are lifted by any `DECISION:` or `INVARIANT:` marker on the line above the finding.
The marker does not name the rule, so a reference written for another reason lifts whatever finding stands under it:
`// DECISION: D123` above `fn lowered(baseline: &Counts, current: &Counts)` lifts `same-type-parameters`, though D123
is about the baseline. D216 only ties a decision marker to a file its decision links. B174 asks that an exception name
its rule and decision, that the decision list its exceptions, and that neither an exception nor a list entry outlive
the other.

## Chosen

- An exception is the comment `DECISION: DNNN RULE` on its own line, written `// DECISION: D042 panic-path` or
  `# DECISION: D042 panic-path`; RULE is the configured lint rule ID, one word without whitespace. It also counts as a
  reference to its decision under D037 and D216. An `INVARIANT:` marker never names a rule.
- Exceptions are read from the comments of Rust, Python and shell sources and from whole-line comments of YAML and
  TOML files, the documents lint reads.
- The decision lists each exception under Applies in as `[exception RULE](FILE)`, which is also its link to the file.
- The memory check reads every file of the working tree. It refuses an exception that its decision does not list and a
  listed exception that the file does not carry, naming the decision, the rule and the file of each.

## Rejected

- Naming the repair skill, as the card's example `handle-panic` does: a skill can serve several rules, and the
  finding names the rule ID, so only the rule ID selects one finding.
- A separate exception list file: the decision already owns the reason and its application links, so a second list
  would need its own consistency check against the decisions.
- Listing exceptions with their line numbers: every edit above an exception would change the list, while the file and
  the rule already identify what the decision allows.
- Checking only `paths.sources`: lint also reads configuration files outside them, and an exception there would lift a
  rule without being listed.

## Rationale

A named rule turns an accidental lift into an explicit choice, and listing it in the decision keeps the reason next to
the place it applies. The check in both directions removes an exception whose decision dropped it and a list entry
whose exception was deleted, the leftovers B174 asks to track.

## Consequences

An exception and its list entry change together. Several exceptions of one rule in one file share one entry. Until
lint lifts only named rules, a named exception lifts as any marker does; a later decision makes lint lift only the
named rule and refuse an exception that lifts nothing.
