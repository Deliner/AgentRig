# D025 — Worker capability ownership

## Context

The user clarified that this repository builds the reusable worker, not a separate reviewed application. Review had been delivered under Project even though it belongs to the worker, alongside structural lint.

## Chosen

Supersede D008 for ownership in this repository. Keep reusable worker capabilities under tooling/worker and durable development memory in Ledger. Reserve Project for consumers and examples. Ship lint with the worker while preserving an independent CLI over the same rule engine. Consumers configure enabled capabilities in worker.toml and their detailed lint/review policies separately.

## Rejected

Maintain review as a separate product under Project, duplicate lint engines for worker and standalone use, or create a second installation/update ownership system.

## Rationale

The worker is the user's intended product. Shared implementation and installation ownership make its capabilities portable without requiring an unrelated project to adopt the whole environment for a lint assessment.

## Consequences

Move review into the worker distribution and implement declarative setup using the existing manifest and upgrade ownership model. Preserve user configuration, source and memory; keep credentials separate. D008 remains historical evidence, and consuming projects retain their own configurable layout.
