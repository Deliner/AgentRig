# D069 — Ship the silent-error rule for Python except-only-pass to init

## Context

B028 (cluster 3 of the quality set, agreed 2026-10-29) asks that a swallowed
error be caught (3.1). In Python the clearest silent swallow is an `except`
clause whose body is only `pass`: the caught failure leaves no trace and the
program continues. On 2026-10-30 the user chose (Option A) to ship this
clean-syntactic case to init as a structural rule, while the type-dependent
Rust half (`let _ = <Result>`) stays on the development gate (D068, no type
inference — D059). The structural engine is purely syntactic (D035), and the
except-only-pass shape is decidable from syntax alone.

## Chosen

A new `silent-error` structural rule, delivered to consumers through
`catalog::ALL` and installed into `lint.yaml` at error level, Python only. The
Python handler flags every `except` clause whose body is a single `pass`
statement. The escape mirrors `unsafe-justification` (D065): a `DECISION:` or
`INVARIANT:` reference comment on the line directly above the `pass` records why
the swallow is sound and clears the finding. Its repair skill `handle-error`
directs the author to handle, retry, clean up, log or re-raise the error, narrow
a broad `except`, or justify the swallow with a reference. The reference-escape
helper `justified` is shared in the `languages` module so Rust and Python reuse
one owner.

## Rejected

Shipping the Rust `let _ = <Result>` half to init as the same rule: it needs
type inference the engine omits (D068/D059). Flagging broader Python swallows
(a bare `except`, or an `except` that only logs) at init: these are not
unambiguously errors from syntax alone and would be false-positive-prone,
against D035. Matching the inline `except E: pass` form separately: tree-sitter
aliases both the inline and indented suites to a `block`, so one measurement
covers both. Accepting a trailing comment on the `pass` line as justification:
the escape stays on the line directly above, exactly as D065.

## Rationale

An `except` body of only `pass` is a syntactically unambiguous silent swallow,
so it meets the high-signal, type-free bar for an init rule (D035) where the
Rust half does not. Reusing the D065 reference-escape keeps one justification
mechanism across the unsafe and swallow rules and one shared `justified` owner.
Delivering through `catalog::ALL` keeps the init delivery and this repository
identical (I020).

## Consequences

Consumers receive the `silent-error` rule and the `handle-error` skill on
`init`. An `except: pass` without a reference above the `pass` is an error in
Python source, in this repository and in consumers. AgentRig has no such handler
today, so the repository is already clean. The rule ships to init, unlike the
D068 dev-gate half. It extends the structural-lint corpus (D065, D067) and
supersedes nothing.
