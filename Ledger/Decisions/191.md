# D191 — each feature commit carries the State of its VAC, and the hooks and merge reset it

## Context

B142 asks State to describe only the current VAC: every commit carries the State of its VAC, State resets itself after
a commit and after a merge, and the agent gets no new command for it. The user wants State kept in Git, not ignored.
Before this choice AGENTS.md asked the agent to refresh State at task and VAC boundaries, D047's hook stopped the first
VAC commit in a context until edit-state was delivered, and nothing checked whether State described the commit.

## Chosen

- `format::state_template()` is the empty State: its sections each say `Not recorded.`. `init` writes it.
- On a feature branch `guard-commit` refuses a commit whose staged State equals the template, unless State is its only
  staged change. The message names the absolute State path and the absolute edit-state skill. A failing Git call on
  that path denies the commit.
- The generated `post-commit` hook runs `state-reset` before `feature-push`. On a branch with the feature prefix it
  writes the template to State and stages it; elsewhere, including a detached rebase, it does nothing.
- `feature-merge` requires a clean tree except State. State must equal the template or HEAD's State, otherwise it holds
  uncommitted notes and the merge stops. The merge writes and stages the template and, unless HEAD already holds it,
  commits it as `Reset State before integration` on the feature, then rebases, checks and merges as before.

## Rejected

| Alternative | Why |
| --- | --- |
| Ignore State in Git | the user wants each commit to carry the State of its VAC |
| A separate command that resets or commits State | the user wants no more commands for the agent |
| Reset State in the working tree without staging it | a forgotten `git add` would commit the previous VAC's State |
| Refuse a commit that only resets State | the merge's own reset commit would be refused |
| `feature-start` commits the reset State | after a merge the base already holds the template |
| `feature-merge` discards State notes it cannot place | notes of the next VAC would be lost silently |

## Rationale

Staging the template after each commit turns a forgotten State update into an empty template the guard sees, so the
rule holds without a new command. The reset commit on the feature puts the template on the base through the ordinary
merge, so a later branch starts from the empty State and branches never conflict on it.

## Consequences

Every feature commit except a reset-only one edits State. A branch ends with the reset commit, which runs the gate like
any other commit. The repository's hand-written `post-commit` hook calls `state-reset`, so it needs a runtime with
that command; until the pin of B142 reaches the installed runtime its post-commit stops before `feature-push`.
