# D182 — The rig owns the Rust compiler flags; flags in a Cargo configuration move into its list

## Context

B133 under D151. Probes on Clippy 1.100 on 2026-11-13: `--cap-lints allow` in `RUSTFLAGS`, in `build.rustflags` or in
`target.<triple>.rustflags` of a `.cargo/config.toml` let the rig's gate pass on code with an unused variable and an
`unwrap`, and `-A lint` there silenced that lint under `-D warnings`. `--config build.rustflags=[]` in the command did
not override `RUSTFLAGS`, and `--cap-lints forbid` at the end of the command did not help. An empty
`CARGO_ENCODED_RUSTFLAGS` overrode all three sources: cargo reads it before `RUSTFLAGS`, `target.*.rustflags` and
`build.rustflags`. Neither the rig nor voxel-rust has a `rustflags` key.

## Chosen

- The optional module `.agentrig/rust.yaml` holds `rustflags`, a list of compiler flags, empty by default. Another
  form or another field fails config-check with an error naming the module.
- Every process the rig launches for a catalog command, a gate check, a background job, doctor or scratch code gets
  `CARGO_ENCODED_RUSTFLAGS` set to the list joined by the unit separator, so each cargo run inside compiles with
  exactly that list, read anew on each run.
- `allow-justification` also reads YAML: an item of a `rustflags` sequence starting with `-A`, `--allow` or
  `--cap-lints` needs a `DECISION:` or `INVARIANT:` reference on the line directly above and is repaired with
  `justify-allow`. Init adds `.agentrig/rust.yaml` to the include of that rule.
- The new kind `cargo-rustflags`, level error, reports every `rustflags` key in any table of a selected TOML file;
  init selects `**/.cargo/config.toml`. No reference lifts it; the skill `move-rustflags` moves the flags into the list
  and deletes the key.
- Init in a Rust project copies `build.rustflags` of the root `.cargo/config.toml`, a string split at whitespace or an
  array, into the list and leaves the file unchanged. `cargo-rustflags` reports the remaining key; deleting it
  completes the move.
- The kind ships with a mid-branch pin (D051), and the repository applies both rules to its own files.

## Rejected

| Alternative | Why |
| --- | --- |
| `--config build.rustflags=[]` in each cargo command | does not override `RUSTFLAGS` |
| `--cap-lints forbid` at the end of the command | the probe still passed with silenced findings |
| Unsetting only `RUSTFLAGS` | Cargo configuration flags still act |
| Adding the Cargo configuration flags to the rig's | a second, unchecked place whose silencing flag reaches the gate again |
| A separate kind for silencing flags | `allow-justification` already owns this hazard and repair for attributes and manifests |
| Copying `target.<triple>.rustflags` | one list acts on every target; such flags need their own card |

## Rationale

When the rig sets the flags itself, the list that config-check and lint read is the only source a silencing flag can
come from, so no environment variable or Cargo configuration lowers the gate's lint levels unseen, and the flags a
project needs, such as `--cfg`, stay available in one checked place.

## Consequences

rust-analyzer and a plain `cargo` run do not see the list. `RUSTDOCFLAGS` is not covered. A project with
`target.*.rustflags` fails lint until a new card supports per-target flags. B133 leaves open whether a rig command
reports that it ignored flags from the environment; nothing is reported. The YAML check reads only `-A`, `--allow` and
`--cap-lints`; other level flags such as `--force-warn` are not reported.
