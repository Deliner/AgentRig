# D048 — Flat-memory registry size policy for the Plan archive

## Context

The memory validator requires each archived plan detail at exactly
Archive/Plan/NNN.md and rejects a detail link that does not match its ID.
Archiving P025 adds the sixteenth immediate entry including architecture.yaml,
conflicting with the general directory-entry limit of fifteen. D029 and D030
exempt Ledger/Plan and Ledger/Backlog for the same flat indexed representation.

## Chosen

Apply the existing numeric directory-size exemption to Ledger/Archive/Plan,
limited to that exact directory and referenced from the lint configuration.
Keep memory indexing, required sections, file-size policy and architecture
registration for every archived card.

## Rejected

Raise the general limits; exclude the entire Ledger; move archived cards into
nested paths the validator does not accept; merge independent archived
outcomes to fit the limit; delete completed cards whose evidence Archive must
preserve; or change the memory format solely to store another archived outcome.

## Rationale

The archive's layout is fixed by the authoritative memory contract and has one
responsibility: retaining completed outcomes. Its entry count measures how many
outcomes were completed, not source cohesion. The same reasoning that exempts
the current Plan applies to its archive.

## Consequences

Archiving a completed outcome is no longer blocked by registry length. Source
directories keep the numeric limits. Reassess this exception together with
D029 if the memory format later permits a meaningful nested archive layout.
