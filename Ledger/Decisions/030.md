# D030 — Backlog as a flat memory registry

## Context

The user requested a durable idea collector beside Plan in the same indexed Markdown format. Backlog uses stable BNNN identities and Backlog/NNN.md cards, validated by the existing memory parser. The repository already exempts flat Plan, Decisions and Invariants registries from the source-directory entry limit; applying that limit to Backlog would restrict how many independent ideas can be retained.

## Chosen

Apply the same exact-directory numeric size exemption to Ledger/Backlog. Retain idea index/card validation, file-size limits and complete architecture inventories. This extends the existing flat-memory policy without changing D029 or its Plan applicability.

## Rejected

Limit the number of saved ideas using a source-code cohesion threshold, merge unrelated ideas to fit it, invent a different nested memory format, or exclude the whole Ledger from lint.

## Rationale

Each idea has the same registry owner and stable reference scheme. The number of independently recorded ideas does not measure source-module cohesion. The existing exact-directory policy accommodates that representation without adding another storage mechanism.

## Consequences

Agents can retain independent indexed ideas without a source-directory count cap. Missing, duplicate or malformed records remain errors, and the architecture inventory must still account for every card. No production directory limit or delivery authorization changes.
