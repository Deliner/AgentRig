# D189 — init reproduces the rig's setup, and the rig lists each remaining difference with its reason

## Context

B145 makes the rig's own setup the source of truth: «источник истины – текущий сетап рига… Так и должно быть в любых
других проектах». Before this, `init` kept its runtime in `.agentrig/runtime` with the reminder schedule in
`.agentrig/reminder.json`, linted only `Project/**` under the rule ids `function-size`, `parameters` and `named-if`,
had no `rustfmt` check, no `read`, `write`, `test` or `lint-rules` recipe and never wrote a Git remote (D179), while
the rig's recipes and hooks called `tooling/worker/run` directly. Nothing compared the two setups, so they drifted.

## Chosen

- The runtime directory is `.cache/runtime`; init writes `.cache/.gitignore` with `*`, so `.cache/` stays out of Git.
  The reminder schedule and the discipline skill come from the skills' `complexity-discipline` directory.
- Lint covers the whole repository: every catalogued rule includes `**`, and the shared exclude names `.git`,
  `.cache`, `**/__pycache__`, `**/.venv`, `**/target` and the skills directory. `file-size` counts 15 extensions and
  skips the lint configuration, `Ledger/Assets/**` and lock files; `directory-entries` skips the memory registries;
  `dump-name` and `architecture` select `Project` and `Project/**` with `feature_root: Project`, and a feature root
  that does not exist yet counts as selected when the rule's include selects it. The default ids are
  `function-lines`, `parameter-count` and `named-if-condition` with unchanged thresholds, and `recursive-deletion`
  skips test code.
- The recipes add `just read`, `just write`, `just test` and `just lint-rules` and call `.agentrig/bin/agentrig`
  from the root without `--root`.
- A Rust project gets the commands `rustfmt`, which runs `cargo fmt --manifest-path <manifest> --check`, and `clippy`
  without extra arguments, and the checks `rustfmt`, `clippy` and `rust-test`; a Python project keeps `tests`. Both
  run their language checks for `Project/**`.
- When the repository has a remote named `origin`, init writes `remote: origin` to `git.yaml`.
- The rig's `.agentrig/bin/agentrig` forwards to `tooling/worker/run`, and its recipes, Git hooks and agent hook
  registrations call that launcher like a project's.
- `rig_differences.yaml` lists every remaining difference with its reason, and the test `rig.rs` runs init for a Rust
  project with `origin` and the rig's manifest and fails on an unlisted difference, an unused listed path or an empty
  reason in the files under `.agentrig`, `justfile`, `just`, `.codex` and `.claude`, leaving out Claude Code's
  personal `settings.local.json`; invariant I023 states this norm.

## Rejected

| Alternative | Why |
| --- | --- |
| Run the rig from a copied platform binary like a project | the rig launches its installed development revision (D051) |
| Run Rust checks for `**` as the rig does | a project without a manifest yet would fail every commit |
| Pass `--locked`, `--lib` or `--` in init's cargo commands | a project may have no lock file, library or test layout |
| List the compared files through Git | the gate checks an exported tree without a Git repository |
| Keep the allowed differences in the test code | AC3 asks for one list with reasons |
| Write any existing remote | the card names `origin`; another remote stays a manual choice |

## Rationale

One executable comparison turns "init equals the rig" into a failing test whenever either side changes, and the list
keeps each deliberate difference visible with the reason it exists.

## Consequences

Projects set up earlier move `.agentrig/runtime` to `.cache/runtime`, rename their rule ids and add the new recipes
and checks by hand (D185). A new rig setting either becomes an init default or gets a listed reason. Supersedes D179's
consequence that init does not write `remote`.
