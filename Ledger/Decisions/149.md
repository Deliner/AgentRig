# D149 — Method calls add no dependency edges; D059 still applies

## Context

B096. The architecture graph resolves `use` declarations, qualified paths, module declarations and macro paths to
files; a receiver call `x.foo()` adds no edge (D059). The card asked to measure which directory dependencies are
visible only through method calls, to add an edge for confirmed cases that need no type inference, and left the
decision about the remaining cases to the user. The user's /goal of 2026-11-10 selected B096 with every other Backlog
card and delegated such decisions to the executor.

The measurement used a scratch oracle outside the rig. It took every non-test `.name(` call, kept the names defined as
a `self` method in exactly one project directory and not defined as any `fn` in the std library sources or the locked
dependency sources, and compared the caller and owner directories with the edges `lint-edges` reports.

| Project | Rig directory edges | Lost edges found | Name-only upper bound | Names dropped as external |
| --- | --- | --- | --- | --- |
| AgentRig | 235 | 2 | 64 | 53 of 170 |
| voxel-rust `71440d0` | 105 | 1 | 28 | 128 of 235 |

All three lost edges were checked by hand and are real. In AgentRig, `project_setup` and `project_setup/initialization`
call `config.paths.service_path(…)`, owned by `project_config/settings`; the rig records their edge to
`project_config`, which reexports `Config` from `settings`. In voxel-rust, `native/android/fixture.rs` calls
`game.near.resident()`, owned by `render/near`. Each receiver is a field chain whose type is declared in another file.
No method name defined in several project directories reached a directory the caller does not already use. Adding
the three edges would raise no dependents budget above its limit and close no cycle: `settings` would go from 1 to 3
dependents and `render/near` from 3 to 4, both under the default 6.

## Chosen

Keep D059: the rig adds no edge for method calls, and B096 changes no rig behavior. The three edges and the oracle's
numbers stay recorded here.

## Rejected

An edge to the only project directory defining a method name. Without the list of external method names it reports 64
pairs in AgentRig and 28 in voxel-rust, nearly all false; with only the std library names voxel-rust still gets two
false edges from egui's `Rect::center`. The list that removes them comes from dependency sources in the Cargo
registry, which a portable rig does not have.

Resolving the receiver's declared type through parameters and struct fields. This is the cross-file type resolution
D059 rejected as a type-resolving frontend, and here it would recover three edges that change no finding.

## Rationale

The remaining cases need type inference, and their measured effect on budgets and cycles is nil in both projects. A
signal that is sound only with dependency sources would make the graph depend on the machine running the gate.

## Consequences

The architecture graph is unchanged. A project whose budgets or cycles depend on method-only dependencies can still
be under-measured; reconsider when such a case appears or when a type-resolving frontend is funded (D059).
