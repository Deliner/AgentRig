# D143 — `lint-edges` lists a directory's measured edges from the measurement the budget uses

## Context

B088. To repair a dependents-budget finding on voxel-rust the user wrote a separate edge oracle; it missed crate roots
and disagreed with lint. The card asks for a separate command that shows the incoming and outgoing edges of a
directory, and AC3 requires that on voxel-rust the command for `src/core/world` shows as many dependents as lint
counts. The user's /goal of 2026-11-10 selected B088 with every other Backlog card and left the choices to the
executor.

## Chosen

`lint-edges DIR [--json]` exists in the integrated worker and in the standalone `agentrig-lint`, with a Just recipe
here and in the recipes delivered to consumers; the shell guard lets it through like `lint-explain`. It reads the same
configuration as `lint`. For every directory-architecture rule that selects DIR as a directory, it runs the same
measurement as `lint` and lists, grouped by the other directory in path order, every distinct edge as
`file:line uses target` whose target file lies directly in DIR (incoming) or whose source file does (outgoing). The
edges are the ones the dependents budget counts: module declarations and edges inside one directory are left out. The
JSON form is `{"path", "rules": [{"id", "incoming": {directory: [edge]}, "outgoing": {directory: [edge]}}]}`. When no
rule selects DIR the command fails with that reason.

## Rejected

Adding the edges to `lint-explain`: it answers selection questions without reading sources, and the full analysis
would slow every explanation. A flag on `lint`: its output is findings, and edges are not findings. Structured
source, line and target fields per edge: the `file:line uses target` text already has one owner shared with the
findings, and a second representation could drift from it. Repeating identical edges: several names imported on one
line resolve to the same file and would print the same line again.

## Rationale

Running the measurement `lint` runs and grouping the edges the budget counts makes the command's dependents equal the
budget's count by construction, which is what AC3 checks. A separate command keeps lint output to findings.

## Consequences

The command costs one full analysis per selecting rule. The cycle check also lifts edges to the boundary of sibling
subsystems; the command shows the underlying file edges, not the lifted ones. The root directory is `.`.
