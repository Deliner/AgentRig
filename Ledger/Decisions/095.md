# D095 — Bound the foreground drain and restore signal defaults after forwarding

## Context

B045 AC3/AC4 (medium re-review finding, agreed 2026-11-01). `execute` spawns a
reader thread per child pipe; each reads to EOF. When a foreground command's main
child exits but a detached descendant inherited and still holds the pipe's write
end, EOF never arrives, so the finishing join blocks the worker indefinitely
(AC4). Independently, `signal-hook`'s `Signals` installs an OS handler for
SIGINT/SIGTERM/SIGHUP and, on drop, unregisters its callback but leaves the
installed OS handler in place; once forwarding ends the three signals are
caught-and-swallowed, so the worker becomes terminable only by SIGKILL (AC3).
Both reproduce: a silent descendant hangs the worker, and during that hang
SIGTERM is ignored. D066 justifies the existing eleven `command_runner/jobs` libc
FFI sites under one shared soundness argument, and its consequence requires a new
libc call in those files to extend or supersede that justification rather than
inherit it silently.

## Chosen

Two coordinated changes to `execute`'s post-child-exit path, plus the D066
extension. For AC4, the reader loop waits for readability with `libc::poll` on the
pipe file descriptor rather than issuing a bare blocking read, and stops when a
shared `exited` flag — set by `execute` the moment `child.wait()` returns — is
true and `poll` reports no further data; because the main child has exited, no
more of its bytes can arrive, so an empty buffer means every byte it produced is
captured, and the worker returns without waiting on a descendant-held write end
and without killing the descendant. A normal run still ends on the pipe's EOF
(`POLLHUP` then a zero-length read); an `EINTR` from `poll` retries. For AC3,
after the forwarding thread joins, `execute` resets SIGINT/SIGTERM/SIGHUP to
`SIG_DFL` with `libc::signal`, replacing signal-hook's leftover handler so a
signal arriving once forwarding has stopped terminates the worker by default; the
worker installs no other signal handlers (D066's sites are the only FFI), so
`SIG_DFL` is the pre-`execute` disposition. Both new `unsafe` libc calls — `poll`
in the reader, `signal` in `execute` — carry a `DECISION: D095` reference and
extend D066's shared FFI-soundness argument: arguments built to the libc
signature, the return value and `errno` checked, the `pollfd` struct fully
kernel-filled, no aliasing and no borrowed pointer outliving the call.

## Rejected

Killing the process group on foreground completion to force EOF: it contradicts
the observed foreground containment contract — detached descendants are
deliberately not contained — and would terminate descendants meant to outlive the
command. A fixed time or byte cap on the drain: a grace window risks truncating a
legitimately large tail of the main child's own output, and a cap is a
configuration dimension with no current requirement, whereas the
buffer-empty-and-child-exited condition is the exact, non-truncating bound for the
finding. Making the descriptor non-blocking and busy-reading: a spin loop, where
`poll` with a short re-check interval is the platform primitive for waiting with a
wakeup budget. Bounding the drain for a chatty detached descendant that keeps
writing: intentionally out of scope — AC4 bounds the silent-holder hang that was
found, and AC3's restored disposition is the operator's guaranteed way to abort a
worker still relaying a chatty orphan. Restoring the previous handler through
signal-hook: its API does not restore the prior OS disposition on unregister,
which is the defect itself; resetting to `SIG_DFL` at the owner is the direct
correction. A pretend invariant for either behavior: norm-or-choice — these are
reviewed design choices verified by behavioral worker tests, not a single
statically-checkable oracle.

## Rationale

The hang and the swallow share one code region (the end of `execute`) and one
scenario (the main child exits while a descendant holds the pipe), so one decision
records both. The poll-gated drain with an empty-buffer stop is the minimal
mechanism that returns promptly without killing descendants or truncating output,
and the `SIG_DFL` reset is the minimal owner-level correction for signal-hook's
leftover handler. Verification is by subprocess behavioral tests because
`command_runner` has no in-process Rust signal tests — in-process signal
assertions would pollute the process-global signal disposition.

## Consequences

A foreground command whose main process exits lets `execute` return once the pipe
buffer is drained, even when a detached descendant still holds the write end; the
descendant is neither killed nor waited on. Once signal forwarding ends,
SIGINT/SIGTERM/SIGHUP again terminate the worker by default instead of being
swallowed. The new `libc::poll` (reader) and `libc::signal` (`execute`) sites are
justified under this decision and extend D066; D066's eleven-site statement and
detail are unchanged. The delivered behavior is verified by
`test_foreground_drain_is_bounded_when_descendant_holds_pipe` and
`test_worker_stays_signal_controllable_after_child_exits`. It ships the rest of
B045 (medium re-review); it supersedes nothing.
