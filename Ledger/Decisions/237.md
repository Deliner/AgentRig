# D237 — Memory indexes outside the file-size limit

## Decision

The `file-size` rule does not measure the six memory index files `Decisions.md`, `Invariants.md`, `Plan.md`,
`Backlog.md`, `Archive/Plan.md` and `Archive/Backlog.md` of the memory directory: they get neither the error at 500
nonblank lines nor the warning at 300. The rig's `.agentrig/lint.yaml` and the lint configuration that `init` writes
exclude them alike. Their cards, `Norms.md`, `Requests.md` and the other memory files keep the limits. The user
called the exclusion temporary and set no condition for the limit to return.

## Reasons

- The user asked: «Давай исключим файлы индексов из 500 строк ограничения пока что» (B206).
- At `733c37d`, `Ledger/Decisions.md` holds 500 nonblank lines, so the row of the next decision exceeds the error
  limit.
- An index holds one row per record, so its length measures the number of records, not cohesion, as D116 says of
  the rule registry.
- Every project after `init` has the same six indexes, and `init` already ships the `Assets/**` exclusion of D172.
- D020 keeps committed decision statements unchanged, so the index cannot shrink by condensing its rows.

## Alternatives

- Raise the general limit: room for every index at once. Not applied: every other file would lose the bound that
  D116 and D172 kept.
- Split an index into several files: each file under the limit. Not applied: B206 keeps the structure of the
  `Decisions.md` index.
- Condense rows to fit: no exclusion. Not applied: D020 keeps committed statements unchanged.
- Exclude only `Decisions.md`, the one index at the limit: the narrowest change. Not applied: the user named the index
  files, and all six grow alike, one row per record.
- Exclude the whole memory directory: one entry. Not applied: the cards and the other memory files stay under the
  limit (B206).
- Exclude the indexes only in the rig: no change for projects after `init`. Not applied: their indexes are the same,
  and the `Assets/**` exclusion already ships to them (D172).
