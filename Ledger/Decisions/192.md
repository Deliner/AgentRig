# D192 — lint bounds State at 100 nonblank lines and width 120 with edit-state

## Context

B142 AC5 asks for a short State: more than 100 nonblank lines or a line wider than 120 characters is a lint error
that stops the commit and names the absolute path of edit-state. The rig and `init` already bound README and AGENTS
with the `nonblank-lines` and `line-width` rule kinds and the condense-markdown skill, and exclude memory from them.

## Chosen

The rig's `lint.yaml` and the `init` lint template add two rules on the memory directory's `State.md`:
`state-size`, kind `nonblank-lines` with error 100, and `state-width`, kind `line-width` with error 120. Both name
edit-state as warning and error skill, so a finding names its absolute path, and the gate's lint check stops the
commit.

## Rejected

| Alternative | Why |
| --- | --- |
| Add State to the README and AGENTS rules | their limit is 70 lines and their skill condenses documentation, not State |
| A new rule kind for State | the existing kinds already measure both bounds |
| A State check in memory-check | lint already reports file size and width with a repair skill |

## Rationale

Separate rules keep the user's limits and the State skill apart from the documentation bounds while reusing the
measured rule kinds.

## Consequences

A State longer than 100 nonblank lines or wider than 120 characters fails `lint` and the commit gate in the rig and in
initialized projects.
