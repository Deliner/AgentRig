# D059 — Static TC2/TC4 require a type-resolving frontend; keep the review norm

## Context

B025/P034 funded a semantic symbol layer for the structural lint engine so that
TC2/TC4 (public-only-for-tests; backdoors into privates) could become static
rules where D057 left them review norms. Delivering B025 began with a feasibility
spike reading the engine's source extractor, source model and Rust resolver.

## Chosen

Keep TC2/TC4 review norms in the testing-discipline skill (D057/D054). Add no
visibility extraction, symbol-level resolution, reverse index, rule, rule kind,
invariant, oracle or dependency. Record the measured cost of the only approach
that would work, so a frontend choice can be made later with open eyes.

## Rejected

Build a type-resolving frontend now (rust-analyzer-class resolution for Rust,
type inference for Python) — measured as a large effort and heavy dependency that
breaks the fast-gate norm (D035) and the portable install. Or ship a best-effort
rule over path references only, accepting false positives on method and value
references — which would require relaxing B025's no-false-positive acceptance and
yields a rule reviewers cannot trust.

## Rationale

The engine is a syntactic tree-sitter dependency analyzer: `inspect` records
use / qualified-path / module / macro references and resolves each to a FILE;
method calls by receiver (`x.foo()`) and value or bare-identifier references are
not captured, and `RustItem` carries no visibility. A clean "public only for
tests" rule must prove the ABSENCE of product references to a symbol, but product
code reaches symbols mainly through receiver method calls and value references,
which need the type inference and lexical resolution the engine deliberately omits
("block-local modules require lexical scope resolution"; "lexical bindings require
analysis"). A backdoor into a genuinely private item does not compile, so TC4
reduces to TC2 (visibility widened for a test) and hits the same wall. Only a
type-resolving frontend removes the barrier, at a cost that conflicts with D035
and portability. The one clean partial signal — a test importing a `_private`
Python name — is naming-convention based and already allowed to stay a norm by
B025.

## Consequences

TC2/TC4 remain enforced by review beside TC1 (D057/D058). B025/P034 complete as a
recorded norm with no engine change; the measured cost of a type-resolving
frontend is the recorded lever, reconsiderable only if that frontend is funded.
No lint rule, rule kind, invariant, oracle or dependency is added; the I020
universal-capability guard is unchanged.
