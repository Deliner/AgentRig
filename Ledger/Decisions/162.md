# D162 — `Option<Option<T>>` has one owner, the Clippy lint `option_option`

## Context

B111. D137 made the shared Clippy profile deny `clippy::option_option` and rejected a structural-lint rule for the
same pattern because it would give the pattern a second owner. D156 then shipped `ambiguous-option` over both
`Option<bool>` and `Option<Option<..>>`, so P114 found that one nested option fails the commit twice, once in the
`lint` check and once in the `clippy` check, against B106's boundary that each form has one owner. On 2026-11-11 the
user chose Clippy as the only owner of the nested form and kept `Option<bool>` with `ambiguous-option`.

A probe with Clippy 1.98.1, `-D clippy::option_option` and the rig's `clippy.toml` (`avoid-breaking-exported-api =
false`, D154) reported a nested option as an exported or private parameter, an exported return type and an exported
struct field. It reported no `type` alias, exported or private, no parameter typed through such an alias and no `let`
annotation.

## Chosen

`ambiguous-option` reports only `Option<bool>`; its descriptor, test and the `name-the-states` skill describe that
form alone. A nested option is reported by the `clippy` check alone; D137 keeps its repair, an enum per state or a
justified exception of the Clippy lint.

## Rejected

Keeping the nested form in `ambiguous-option` only where Clippy is silent, for aliases and `let` annotations: the
form would still have two owners, and the rule would have to track which places Clippy covers in each Clippy version.
Dropping the Clippy lint and keeping the structural rule: the user chose Clippy, and D137 already rejected the
structural rule as a second owner.

## Rationale

One finding per problem gives an agent one repair to apply. Clippy already owns the nested form in the shared profile
for the rig and for new Rust projects.

## Consequences

A nested option spelled in a `type` alias or a `let` annotation, and a parameter or field typed through such an alias,
is no longer reported by any rig check. A project whose gate lacks the shared Clippy profile loses the check for the
nested form entirely. D162 supersedes D156's inclusion of `Option<Option<..>>` in `ambiguous-option`; the rest of
D156 remains.
