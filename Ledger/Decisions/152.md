# D152 — The shared Clippy profile denies five lints without target code in the rig

## Context

B102 under D151. The lists of Rust bans of 2026-11-10 name forms that Clippy already detects: a variable assigned
in an `if` after its declaration (II-10), a method returning `Self` whose result may be dropped (II-26), several
unsafe operations in one block (II-28), positional format arguments (III-12) and a lock guard living through a
`match` (III-27). D127 set such zero-hit lints aside because the rig had no target code. With Clippy 1.98.1 the five
lints report one finding in the rig, a positional `format!` argument in `project_memory/history.rs`, and none in
voxel-rust with default features or with `native`.

## Chosen

`PROFILE` in `Project/project_setup/clippy.rs` and the dev-gate argv add `useless_let_if_seq`,
`return_self_not_must_use`, `multiple_unsafe_ops_per_block`, `significant_drop_in_scrutinee` and
`uninlined_format_args`, so the shared profile that `init --language rust` writes denies 29 lints. The rig's finding
uses an inline argument. For each lint a violating fragment fails `just run clippy` and the profile passes after its
removal.

## Rejected

Waiting until the rig contains such code: D151 keeps a check that raises quality without target code.

Excluding the nursery lints `useless_let_if_seq` and `significant_drop_in_scrutinee`: B102 excludes a nursery lint
only on a false finding in the rig or voxel-rust, and neither reports one.

## Rationale

Each lint forbids a form with a concrete failure that compiles: a binding whose final value depends on branches read
apart from its declaration, a builder call whose result is discarded, one safety argument stretched over several
unsafe operations, a lock held for a whole `match` arm, and a format argument matched by position.

## Consequences

`return_self_not_must_use` checks only exported methods. A false finding of a nursery lint after a toolchain update
is handled by a successor decision rather than a local allow.
