# D103 — Extend unsafe-justification to every Rust unsafe site

## Context

B046 (research arc, cross-project review `wf_f2a6f63a-7ff` of 2026-11-01; selected as
P062 under the user's /goal of 2026-11-04). The `unsafe-justification` rule (D065)
promises a recorded reference above every Rust `unsafe`, but its detector matched
only an `unsafe_block` node and a function whose modifiers contain `unsafe`. It never
saw `unsafe impl` or `unsafe trait`, a `static mut` declaration, or an `unsafe`
written inside a `macro_rules!` body or a macro invocation's arguments, because
tree-sitter keeps macro contents as an opaque `token_tree` (D094). Evidence from
rustdesk: `unsafe impl Send for vpx_codec_ctx_t`, `static mut VIRTUAL_INPUT_MTX` and
`unsafe` inside `macro_rules!`. A reference placed above an item's attribute lines
also broke the line-adjacency check, so `#[cfg(..)]` between the comment and the
item produced a false finding. AgentRig's own code has none of the new forms: its
unsafe sites are justified blocks and functions (D066, D095).

## Chosen

The detector moves from `rust.rs` into `languages/unsafe_site.rs` and flags every
unsafe site: an `unsafe_block`; a `function_item` or `function_signature_item`
whose `function_modifiers` carry the `unsafe` keyword; an `impl_item` or
`trait_item` carrying the `unsafe` keyword; a `static_item` carrying a
`mutable_specifier` (symbol `static mut`); and every `unsafe` keyword that is a
direct token of a `token_tree` or `token_repetition`, which covers `macro_rules!`
rule bodies and macro invocation arguments, reported at the keyword's own line.
The `DECISION:`/`INVARIANT:` reference is read on the line directly above the
site after skipping the site's directly preceding `attribute_item` siblings, so
attribute lines between the comment and an item keep the adjacency. As in D065
the rule has no test-context exemption. No new rule kind, repair skill, oracle or
`lint.yaml` entry is added; the descriptor text and the justify-unsafe skill
describe the wider surface, and the branch needs only the final D051 pin.

## Rejected

Re-parsing macro bodies through the D094 fragment mechanism: metavariables such as
`$name` make most `macro_rules!` bodies fail to parse as Rust and D094 skips a
broken fragment, whereas the `unsafe` keyword survives as a token in the token
tree, so a direct token walk is both simpler and complete. Textual search for the
word `unsafe`: it would match identifiers, strings and comments and abandon the
syntactic basis (D059). A per-site list of hazardous primitives (`transmute`,
`set_len`, `get_unchecked`) or marking raw-pointer fields: needs types and breaks
the near-zero-FP bar (D035). Checking that the referenced text matches the code:
the rule stays presence-only (D059); drift is B051's concern. `unsafe extern`
blocks and `#[unsafe(..)]` attributes: outside the card. A test-context exemption:
the card keeps today's policy, and the repository rule already selects the paths.
A mid-branch pin: no new kind or configuration reaches the stable binary.

## Rationale

The rule now matches the intent D065 recorded, every `unsafe` surface a consumer
writes carries a reviewable reason, and it does so inside the syntactic engine
(D059) with one bounded token walk and one sibling walk, both near-zero-FP (D035):
an `unsafe` keyword in a token tree is an unsafe site by definition, and an
attribute is never a justification. Moving the detector into its own module keeps
`rust.rs` within the file-size rule and gives the unsafe surface one owner.

## Consequences

An unjustified `unsafe impl`, `unsafe trait`, `static mut` or macro-body `unsafe`
becomes an error finding routed to justify-unsafe, in the worker repository and in
every consumer; a reference directly above the site, or above its attributes,
satisfies it. The D065 application links migrate to `unsafe_site.rs` and its
tests. Dogfooding stays at zero findings because AgentRig has no such forms. D094
is unchanged: its fragment scan needs no unsafe detector because the token walk
reports invocation bodies at their real lines. It completes B046 and supersedes
nothing.
