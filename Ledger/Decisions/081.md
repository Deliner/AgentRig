# D081 — Flag a Rust dbg! macro invocation as a leftover debugging artifact

## Context

B036 (Набор II cluster C9, local consistency and self-description, agreed
2026-10-31) asks that debug artifacts not survive into committed code. The
`dbg!` macro prints its argument's file, line and value to stderr and returns
the value: it exists for a momentary local inspection and is never deliberate
shipped behavior. Whether a call is `dbg!` is decidable from syntax alone — a
`macro_invocation` whose `macro` path is `dbg` — with no symbol or type
resolution (D035). Unlike unsafe (D065), a swallowed error (D069), a disabled
test (D074) or a broad allow (D080), a committed `dbg!` has no legitimate use,
so it carries no justifying-reference escape. The gate's Clippy already denies
`clippy::dbg_macro` in this repository (commands.yaml), but a consumer project
need not run that Clippy configuration; the lint rule carries the check and its
repair guidance to every consumer.

## Chosen

Add a `debug-artifact` rule kind (target file, error level), Rust-only: a
`macro_invocation` whose `macro` field text is `dbg` is a finding,
unconditionally. The Rust detector dispatches on `macro_invocation` and keys on
the macro name, reusing the shared `text` helper. The kind ships to consumers
through `catalog::ALL` and the delivered per-kind config template, with a
repository rule over `.rs`. A new repair skill `remove-debug` joins the
`references` group — remove the macro and keep any value it wrapped — and ships
through `project_setup/assets.rs`, so the delivered and live skill sets both
grow by one and stay equal (I020); the rule-kind set grows too.

## Rejected

A justifying-reference escape (as D065/D069/D074/D080): a committed `dbg!` is
always a defect, so no reference can make it right; an unconditional finding is
simpler and correct. Flagging `println!`/`eprintln!`: deliberate output is the
D060 choice, not a debug artifact. A Python analogue (`breakpoint()`, a `pdb`
import): a separate language and construct, left to its own decision rather than
widened here. A regex over source text: a `dbg!` inside a string literal would
false-positive, whereas the AST distinguishes a macro invocation from a string.
Relying on Clippy alone: `clippy::dbg_macro` is not portable to a consumer's
gate, which the delivered rule and skill are.

## Rationale

The macro name is unambiguous and syntactic, meeting the high-signal, type-free
bar for the gate (D035). Keying on the fixed name `dbg` keeps false positives
near zero, mirroring the fixed-set philosophy of hardcoded-secret (D067) and
dump-name (D072). An unconditional finding — no reference mechanism — is the
lowest sufficient design, since the artifact has no legitimate committed form,
and it keeps the detector simpler than the justification family. The repository
contains no `dbg!`, so the rule is green on delivery.

## Consequences

A consumer's or this repository's Rust `dbg!` becomes a gate error on `init`
and before commit; removing the macro and keeping any wrapped value passes. The
rule-kind set and the skill set both grow by one and stay equal across delivery
and repository (I020). It joins the fixed-name approach (D067/D072) and shares
the `macro_invocation` dispatch introduced here with no other current consumer.
With D080 it completes B036's two static C9 cores; B036's remaining points stay
covered or norms (D037/D060/D070). It supersedes nothing.
