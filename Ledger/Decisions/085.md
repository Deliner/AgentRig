# D085 — Flag a glob import as coupling to another module's evolving surface

## Context

B040 (Набор II cluster C10, API/data evolution, agreed 2026-10-31) asks
that a consumer's shipped code not bind a file to the whole, evolving
public surface of another module. A glob import — Rust `use path::*`,
Python `from module import *` — pulls in every name the target exposes,
so when that module later adds, removes or renames a name, the set of
names in scope changes silently: a new upstream name can shadow a local
one or collide, and a reader (or an editing agent) cannot tell where a
name comes from. The compiler does not warn about a name that silently
appeared through a glob. An agent reaches for a glob to avoid listing
names under pressure. Whether an import is a glob is decidable from
syntax alone — a Rust `use_wildcard` node, or a Python
`import_from_statement` with a `wildcard_import` child — with no symbol
or type resolution (D035); the dependency analyzer already names these
nodes. Test code legitimately writes `use super::*`, so Rust test code
is excluded.

## Chosen

Add a `wildcard-import` rule kind (target file, error level), covering
Rust and Python. The Rust detector dispatches on the `use_wildcard` node
(a top-level glob or one inside a `use {...}` group) and reports through
a `wildcard_use` that mirrors `report_panic`: a `DECISION:`/`INVARIANT:`
reference on the line directly above removes the finding, reusing the
justification mechanism (D065/D082), and test code is excluded by the
same ancestor `#[cfg(test)]`/`#[test]` walk (`in_test_context`, D082)
plus the delivered rule's `**/tests/**` and `tests.rs` excludes. The
Python detector dispatches on `import_from_statement`, flags one whose
named children include a `wildcard_import`, and uses the same
line-above justification escape (D069/D074). The kind ships to consumers
through `catalog::ALL` and the delivered per-kind config template. A new
repair skill `narrow-import` (replace the glob with an explicit import
list, or justify with a reference) joins the `references` group and
ships through `project_setup/assets.rs`, so the delivered and live skill
sets both grow by one and stay equal (I020); the rule-kind set grows too.

## Rejected

Flagging a wildcard `_` match arm to force exhaustiveness: a scalar
`match` (integers, strings, byte patterns) legitimately needs `_`, and a
`#[non_exhaustive]` enum from another crate requires it, so the finding
would false-positive without type information (D059); enum exhaustiveness
is already enforced by the compiler, so this is left a norm. Requiring
`#[non_exhaustive]` on public types: irrelevant to a binary crate and
opinionated for a consumer, left a norm. Flagging serde or schema
versioning: configuration-specific and high false positive, left a norm.
A regex over source text: a `use x::*` inside a string literal would
false-positive, whereas the AST distinguishes a glob import node from a
string. Flagging `pub use path::*` re-exports separately: a deliberate
facade is covered by the same justification escape, so no separate case
is added. Removing the justification escape: a prelude or a deliberate
`__init__.py` re-export is a recognized legitimate glob (the ecosystem
marks it `# noqa: F403`), so the reference escape keeps the finding
near-zero false positive, consistent with the justification family.

## Rationale

The glob import node is a fixed, syntactic signal, meeting the
high-signal, type-free bar for the gate (D035) and mirroring the
fixed-set philosophy of panic-path (D082) and debug-assertion (D084).
Reusing the justification escape and, for Rust, the `in_test_context`
ancestor walk keeps the behavior consistent with the justification
family (D065/D069/D074/D080/D082) and adds no new mechanism. Covering
both Rust and Python in one kind matches disabled-test (D074), which also
spans both languages. This repository uses explicit import lists
throughout and has no real glob import (the one `::*` in a test fixture
is inside a string literal, which the AST detector does not match), so
the rule is green on delivery.

## Consequences

A consumer's or this repository's non-test Rust `use path::*`, or any
Python `from module import *`, becomes a gate error on `init` and before
commit; narrowing it to an explicit import list, or recording a
`DECISION:`/`INVARIANT:` reference on the line directly above it, passes.
The rule-kind set and the skill set both grow by one and stay equal
across delivery and repository (I020). It reuses the `use_wildcard` and
`import_from_statement` dispatch and adds no new mechanism. It ships
B040, the C10 cluster of Набор II; C10's remaining points stay norms
(the wildcard `_` match arm, `#[non_exhaustive]`, serde/schema
versioning), with enum exhaustiveness enforced by the compiler. It
supersedes nothing.
