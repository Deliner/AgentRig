# D177 — One reference kind names the current form of a superseded Rust form

## Context

B128 AC8 asks the rig's lint to find Rust forms that the rig's toolchain
replaces directly: `x.strip_prefix(p).unwrap_or(x)` and its `strip_suffix`
variant, `Infallible` and `(0..n).map(f).collect::<Vec<_>>()`. Each finding
shows the place, the old form and the new form, a `DECISION:` comment above the
line keeps the old form, and the rule works in the rig and in the lint
configuration init writes for Rust. A model trained before the toolchain keeps
writing the old forms; the AGENTS.md section of D175 names the new ones. The
lint reports a finding as `path:line (symbol): message`. Type-dependent forms
stay out of scope.

## Chosen

The Rust-only reference kind `superseded-form` with the repair skill
`use-the-current-form`, level error and no shipped exclude, so test code counts.
It measures every `.unwrap_or` call whose single argument, or the operand of `&`
in it, has the text of the receiver of the `.strip_prefix` or `.strip_suffix`
call it is chained to, every `Infallible` type name, and every `.collect()` of a
`.map(f)` over a parenthesized `0..n` or `0usize..n` whose turbofish or `let`
type is `Vec`. The symbol names the old and the current form, such as
`Infallible -> !`. A `DECISION:` or `INVARIANT:` reference on the line directly
above keeps the site. Init's configuration includes the kind with every
reference kind and ships the skill. The kind is enabled after a mid-branch pin
(D051).

## Rejected

One kind per form: three identifiers and skills for one repair, while the
symbol already names the form. Excluding test code: an old form in a test is as
old, and AC2 updates rig tests as well. Only the turbofish collect: the
`untyped-conversion` skill offers the `let` type as an equal spelling, so the
same old form would pass in it; a rig test builds its names that way. The `&x` operand left
out: the rig's own sites fall back to `&path` and `&file`.

## Rationale

The finding carries the replacement, so an agent repairs it without knowing the
toolchain, and the code base converges on the forms the toolchain provides. The
current forms state the intent in one call or name, and a trimmed value cannot
fall back to anything but its receiver.

## Consequences

Types are not resolved: a method of the same name on another type counts, and a
`0..n` range of another integer type is flagged although `Vec::from_fn` takes
`usize`; the skill sends such a site to a reference. Old forms inside macro
arguments are not found. Neither the metric nor the skill names the version, so
a new toolchain changes only the version file and the forms it adds.
