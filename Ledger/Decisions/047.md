# D047 — Coordinated hook requirements

## Context

B002 requires one understandable hook response per event: a permitting result
must not cancel a required stop, retries must not repeat delivered reminders,
architecture guidance must precede the first edit in an area, and the user
configures events, conditions, skills and order. D014 kept route guidance as
context without a permission decision or delivery state. Context offered by
PreToolUse reaches the agent only together with the action's result, so only a
stop delivers a requirement before the action.

## Chosen

One dispatcher collects the requirements of an event: the due complexity
reminder first, then configured routes in list order. A route names a skill,
path patterns, events (edit with explicit paths, opaque shell write, VAC check
entry through `just check` or a visible `git commit`; edit and shell by
default) and an optional block. Requirements are keyed by skill and area: the
directory of an edited path, otherwise the event. Each is delivered once per
context window in per-session state cleared by SessionStart and by a detected
context reset. An undelivered blocking requirement stops the action; the
response lists every undelivered requirement with reasons and route sources.
Routes of one skill must be adjacent, and configuration check rejects a skill
ordered both before and after another.

## Rejected

Separate hooks per requirement, numeric priorities, a rule language, proving
that a skill was read from transcripts, blocking Ledger edits, and predicting
the targets of opaque shell commands.

## Rationale

Delivery state lets a retry pass while owners of persistent conditions, such
as the shell guard and configuration recovery, still evaluate every call.
Area keys bring the contracts of each newly touched directory without
repeating them within a series of edits.

## Consequences

Routes without block keep D014's context-only guidance, including Ledger
routes under I012, but the same skill and area are not repeated within a
context window. Unavailable session state turns blocking requirements into
guidance instead of repeating a stop that cannot be recorded. Projects created
by init remind edit-state at the VAC check entry. The repository's own routes
can use events and block only after the runtime pin supports them.
