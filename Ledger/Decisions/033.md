# D033 — Retire capabilities outside the lint-first target state

## Context

About 1500 later commits made on another machine were lost. The user restated the
remembered target state in Requests.md on 2026-10-26: the linter is the main
product, initialization is auxiliary, installation is as simple as possible with
no backward compatibility, updates or rollback, only Git is supported, Rust and
Python are the analyzed languages, and nothing unnecessary may remain.

## Chosen

Remove the review capability with its MCP server, project delegation with its MCP
server, the upgrade transition with its installation receipt and recovery journal,
declarative setup, preview and reconciliation with resource-package composition,
project agent and environment sections, the Mercurial and external VCS backends,
and JavaScript, TypeScript and TSX analysis. Keep init, the interactive wizard,
doctor, background jobs, Ledger memory, the staged gate and Git-only delivery.
The configuration key for branch policy is git, with base and prefix only.

## Rejected

Keep the removed capabilities disabled behind configuration, retain compatibility
readers for removed formats, or migrate existing installations automatically.

## Rationale

Every retained capability adds tests, configuration and documentation that slow
delivery and blur the product. The user explicitly asked for complete removal.

## Consequences

D023 and D024 no longer have application owners; their history remains. D025's
review ownership no longer applies; its lint ownership remains. I020 is retired
with the receipt. Existing installations are reinitialized rather than upgraded.
