# D046 — Configuration repair can read its files through cat

## Context

D045 allowed only edits of configuration sources and `just config-check`
while the configuration is invalid, assuming the agent's own file reading
stays available. Codex has no separate read tool: it reads files through
shell commands, and `just read` depends on the broken command catalog. In a
real Codex session the denied reads left the agent editing blind; it deleted
and rewrote .agentrig/commands.yaml from guesses and replaced the test command
with `true`. Codex also passes apply_patch text in `tool_input.command`, which
the hooks did not read, so the permitted repair edit was denied.

## Chosen

While the configuration is invalid, hooks also allow one top-level `cat`
whose arguments all resolve to configuration sources or the configured repair
skill, with the same outer-control parsing as the shell guard. Patch text in
`tool_input.command` is read like the other apply_patch payload keys. D045's
other recovery rules remain.

## Rejected

Run inspection through the configured read command; allow general read-only
shell commands or sed; embed configuration or skill contents in the denial.

## Rationale

`cat` of exactly the repairable files and their instruction restores reading
for shell-only agents without depending on the command catalog or permitting
writes, redirections or other files.

## Consequences

When project.yaml is unreadable the configured skill path is unknown, so only
the configuration sources are readable through `cat`. Ledger edit guidance
also recognizes Codex apply_patch payloads.
