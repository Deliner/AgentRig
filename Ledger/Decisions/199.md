# D199 — Resolved paths take the spelling the file system stores

## Context

B152 AC3: on a file system that ignores case, such as the macOS default, `ledger/State.md` names the same file as
`Ledger/State.md`, yet hook routes, written-path checks and configured-path comparisons received the spelling the
agent wrote, so a route to `Ledger/State.md` did not reach an edit of `ledger/State.md`. Every such comparison goes
through `shared::paths::resolve`, which already resolved symbolic links component by component.

## Chosen

`resolve` replaces each existing component that is not a symbolic link with the name the file system stores for it,
read as the last name of its canonical path. A component that does not exist keeps its written spelling, and a
case-sensitive file system keeps every spelling, because there a different spelling names a different file.

## Rejected

| Alternative | Why |
| --- | --- |
| Case-insensitive route globs | wrong on a case-sensitive file system, where another spelling is another file, and leaves the other comparisons |
| Lowercase every path before comparing | the same error, and configured paths would lose their spelling |
| Compare files by inode in each consumer | every consumer would repeat the check; the resolver already owns path identity |

## Rationale

The file system decides which file a path names, so asking it for the stored name gives one spelling per file
without guessing its case rules. Fixing the resolver fixes routes, written-path checks and configured paths at once.

## Consequences

Resolving a path costs one canonicalization per existing component. A new file's own name keeps its written
spelling until it exists; its existing parent directories take their stored names.
