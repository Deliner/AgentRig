# D037 — Allow only decision and invariant references as source comments

## Context

The user stated on 2026-10-26 that code forbids every comment except those
referencing a decision or an invariant, with `DECISION:` and `INVARIANT:`
markers (Requests.md). Backlog B008 records a similar idea: documentation,
license and tool-directive comments get no exemption, and a marker followed by
an explanation is not a reference. Rust and Python are the supported
languages.

## Chosen

Lint gains the comment-reference rule kind for Rust and Python. A comment is
accepted only when its whole text is `// DECISION: DNNN` or
`// INVARIANT: INNN` in Rust, or the same with `#` in Python. Line, block and
documentation comments are measured, as are Python statements consisting of a
lone string literal, including docstrings. Each other comment is a finding
routed to the replace-comment skill. Consumer defaults include the rule like
the other language rules.

## Rejected

Exempt documentation comments, tool directives or license headers; accept a
reference followed by an explanation; ignore Python docstrings; check whether
the referenced record exists within lint.

## Rationale

The whole-text form leaves no room to keep an explanation beside a marker, so
explanations move to the records meant for them or disappear. A docstring is
Python's documentation comment. Lint has no access to project memory, so
reference existence belongs to the memory check.

## Consequences

Existing comments and docstrings are replaced by references, records or
clearer code. Comments in other languages and the existence of referenced
records are not checked yet.
