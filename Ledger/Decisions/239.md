# D239 — Lint runs the rig's Clippy profile on the configured manifest

## Decision

`agentrig lint` and the gate's `lint` check run Clippy with the rig's profile, `-D warnings` and a `-D` for each lint
of `structural_lint/clippy/profile.rs`, on the library, binaries and examples of the `Cargo.toml` that the optional
key `manifest` of `.agentrig/rust.yaml` names; tests stay outside the profile. Each compiler message becomes an error
finding with its rule, file, line and the configuration skill, in one list with the other findings and in `--json`.
A run that cannot check the project, such as a missing manifest, a failed `cargo metadata` or a failed
`cargo clippy` without messages, becomes one finding naming the cause. `init --language rust` writes `manifest`, the
`Cargo.toml` it finds in `Project` or the root, else `Project/Cargo.toml`, and no `clippy` command or check; the rig
names `Project/Cargo.toml` and has neither, so the profile is one list. A project weakens the run only through forms
that need a decision reference, a lint attribute, an `allow` level under `[lints]` of `Cargo.toml` and a `rustflags`
item, and denies more lints under `[lints.clippy]`. `allow-justification` no longer reads the `argv` of commands and
still reads `rustflags`, which reach the run. The run passes no `--locked`; the rig's `build` and `test` commands keep
it.

## Reasons

- B137 requires that lint and the gate's `lint` check run Clippy with the rig's profile on the configured
  `Cargo.toml` (AC1), that a run which cannot check the project fail with its cause (AC2), that weakening need a
  decision reference (AC3), that init write the manifest path instead of a `clippy` command and check (AC4) and that
  command `argv` stop being checked (AC5).
- Under D132 the profile was a copied `argv` in each project's `.agentrig/commands.yaml` and in the rig's, kept equal
  by a test only in the rig; deleting a `-D` item from a project's copy passed every check, and D184 reported only
  added lowering flags (B137).
- `command_runner::output` launches the run with the `rustflags` of `.agentrig/rust.yaml` (D182), so the flag list
  still reaches Clippy and stays checked (D183).
- Commands no longer feed the gate's Clippy, so a lowering flag in a command's `argv` lowers nothing the gate relies
  on (B137 AC5).
- D132 runs a project's Clippy without `--locked`, and the rig's `build` check, first in its gate and without an
  `affected` filter, runs cargo with `--locked` (D077).
- A project initialized by an older rig removes its `clippy` command and check by hand (D185).

## Alternatives

- Keep the `clippy` command and check that init writes and compare them with the rig's profile: the profile stays
  visible and editable in the project. Not applied: a removed `-D` item still passes silently in a project, which
  B137 removes, and two lists need a test to stay equal.
- Keep reading command `argv` in `allow-justification` (D184): a hand-written Clippy command stays checked. Not
  applied: the gate no longer runs such a command, so the finding would guard nothing (B137 AC5).
- A key for Clippy flags in `.agentrig/rust.yaml`: a project tunes its run in one place. Not applied: B137 AC3 leaves
  no place for Clippy flags in the project configuration besides `manifest`.
- Pass `--locked` to the run: lint also catches a stale `Cargo.lock`. Not applied: D132 runs a project's Clippy
  without it, and the rig's `build` check already runs with `--locked` before `lint`.
