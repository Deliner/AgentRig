# D144 — `config-check` compares cargo targets with the module path the declared tree gives a test file

## Context

B090. D124 took a Rust test file's module prefix from the nearest `lib.rs`, else `main.rs`, and accepted a target that
the prefix contained or that began with it. cargo instead selects a test when the filter is a substring of its full
name. In voxel-rust `src/native/` is mounted by `#[path]` from the library root `src/core/lib.rs`, while
`src/native/main.rs` is a binary root, so the guess named `host::game::` and rejected `game::tests::`, which cargo
runs. The card asks to follow the `mod` and `#[path]` tree from the crate root and to accept a target when cargo's
filter selects tests of the file. The user's /goal of 2026-11-10 selected B090 with every other Backlog card and left
the choices to the executor.

## Chosen

For a check whose command runs `cargo … test`, `config-check` reads the manifest the command names with
`--manifest-path`, resolved from its working directory, else `Cargo.toml` there. The crate roots are the ones `init`
derives from that manifest and its workspace members. From each root it follows the `mod` declarations, `#[path]` and
literal `include!` that the architecture source extraction records, among the `.rs` inventory files under the
manifest directory; content the architecture analysis cannot measure and declarations that cannot be located do not
stop the walk. A test file's module path is accepted when a target lies inside it or begins with whole trailing
segments of it, the whole path included; a crate root accepts every target, as before. A file reached by several
roots or mounts is accepted when any of its paths is. A file that no root reaches is not reported, as a file without a
`lib.rs` or `main.rs` above it was not. `lint` is unchanged.

## Rejected

Collecting the names of `#[test]` functions and matching the target as a substring of each: tests generated by
macros or other attributes are invisible to syntax, so the check would reject targets that cargo honours, and it
would need a second parser. Reusing the architecture resolver whole: it stops a crate at the first unmeasurable
construct or derive, which would silence the check for most real crates. Keeping the guess as a fallback: it is the
behavior that rejected working targets. Modelling `--lib`, `-p` and auto-discovered `tests/`, `src/bin/` and
`examples/` roots: the card does not ask for it.

## Rationale

The declared tree gives the path cargo prints, so a target written the way cargo is used is accepted without a prefix
chosen for the crate layout, and one that matches no part of the path is still rejected. Whole trailing segments keep
a target from matching on a fragment such as `::`.

## Consequences

A target that lies wholly after the module path, such as `tests::`, is still rejected even though cargo would run
it. A target shaped like the file path instead of the module path, such as `host::parts::thing::` for a file mounted
as `widget`, is now rejected. `config-check` parses the crate's Rust files once for each cargo check.
