# D137 — The shared Clippy profile denies `clippy::option_option`

## Context

B084. On 2026-11-07 the user saw `Option<Option<String>>` in the Rust analyzer on `feature/rust-expansion` and asked
whether it is an antipattern that should be blocked, since it carries no architectural meaning. The outer and inner
`None` encode two absent states whose meaning is visible only from the surrounding code; that site became the
`Binding` enum. The shared Clippy profile of D132, the dev gate in `.agentrig/commands.yaml` and the `clippy` command
that `init --language rust` writes, denied 23 lints without the pedantic `option_option`. A probe with Clippy 1.98.1
showed that the lint fires on a private struct field, enum variant, parameter, return type and a nested
`Vec<Option<Option<u8>>>`, skips exported items unless `clippy.toml` sets `avoid-breaking-exported-api = false`, and
never fires on a `type` alias, a `let` annotation or an inferred type. Master `ef216b2` and voxel-rust contain no such
type.

## Chosen

`PROFILE` in `Project/project_setup/clippy.rs` and the dev-gate argv add `option_option`, so the shared profile denies
24 lints. A violating fragment in a private function fails `just run clippy` and the profile passes after its removal.
A legitimate tri-state, such as a serde PATCH field, keeps the type under a justified
`#[allow(clippy::option_option)]` (D080). `avoid-breaking-exported-api` keeps its default.

## Rejected

Setting `avoid-breaking-exported-api = false`: `enum_variant_names`, `upper_case_acronyms`, `wrong_self_convention`,
`box_collection`, `vec_box` and `redundant_allocation`, which the profile denies through `-D warnings`, honour the same
setting and would extend to exported API, and `init` would have to write and own a `clippy.toml` that a project may
already have. A structural-lint rule over syntax that would also see aliases, locals and exported API: it would give
the same pattern a second owner beside Clippy.

## Rationale

An enum names each state where it is declared. Clippy already measures the pattern, and the shared profile delivers it
to AgentRig and to new Rust projects at once.

## Consequences

`Option<Option<_>>` in a non-exported signature or type definition fails the `clippy` check in AgentRig and in new
Rust projects; exported API, type aliases and locals stay unchecked. Existing projects keep their configuration
because `init` has no update path. It supersedes D132's count of 23 lints; the rest of D132 remains.
