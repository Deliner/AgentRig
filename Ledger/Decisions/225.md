# D225 — Rule kind `file-cycle` reports cycles among the files of one directory

## Context

B175. On 2026-11-20 the user said that any cycle of uses between files is a defect to refactor, and selected B175 with
B176, B177, B178 and B179 for autonomous delivery. D093 had rejected the candidate `sibling-cycle` because the
directory-architecture model treats a size-bounded directory as one unit and detects cycles only between directories
(D079); the user revised that. The directory-architecture rule already resolves every use between files of Rust and
Python sources, test code included, and keeps one dependency per use with its file and line. A measurement of the rig
found cycles among files in eight directories, the longest through four files.

## Chosen

- A policy kind `file-cycle` with target `directory`, default level error, repair skill `break-file-cycle` and no
  exception. It reads the dependencies that the enabled directory-architecture rules of the same configuration
  resolve, so no roots or extensions are repeated, and the configuration check refuses an enabled `file-cycle`
  without an enabled directory-architecture rule.
- A use counts when its source and target are different files of one directory that the rule selects and neither is
  the entry `mod.rs`, `lib.rs`, `main.rs` or a file with the stem `__init__`; module declarations are not uses, and
  test uses count.
- The directory cycle search runs over these file uses and reports each back edge once at its use: the message names
  the whole chain and `file:line uses file` for every link. Directory cycles are unchanged.
- `init` delivers the rule and the skill to Rust and Python projects. Delivery takes two phases with a mid-branch pin
  (D218); until the repository configuration names the kind, `init` leaves it out so its output matches the rig
  (I023).

## Rejected

- Keeping D093's position that a directory is one cohesive unit: files in a cycle can only be read, changed and tested
  together, which the user named a defect.
- Settings of its own for roots and extensions: they would repeat the directory-architecture settings and could
  disagree with them, and B175 asks not to repeat them.
- Counting the entry: the entry declares and re-exports the files of its directory, and the files use the items it
  defines for the whole directory, so every directory with a surface would report a cycle.
- A finding per file of the cycle: one repair breaks the whole cycle, so one finding names it once.

## Rationale

A file whose dependencies run one way can be read from the files it uses and changed without reading the files that
use it. Reading the existing resolved dependencies keeps one resolution of uses for both cycle checks.

## Consequences

Each cycle among files of a selected directory blocks the commit until a shared item moves to its owner or files of
one responsibility are joined. Cycles through the entry are not measured; a use routed through a re-export in the
entry hides a link, which the skill forbids.
