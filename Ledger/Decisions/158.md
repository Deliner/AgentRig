# D158 — The rig's cargo test command carries the universal tests capability

## Context

D053 made the check capabilities memory, lint, tests and tools universal and listed the toolchain checks, `rust-test`
among them, as worker-local. The rig realized the universal tests capability with a pytest command `test`, while its
Rust tests ran under the worker-local command `rust-test`. B108 moved every Python test of the rig to Rust, and on
2026-11-11 the user decided to rewrite the remaining launcher test in Rust within P115, so the pytest command has
nothing left to run. `init` delivers the tests capability as a check running the command `test`, which is `cargo test`
for a Rust project; without a `test` command in the rig, I020 reports `checks only in init delivery: ["test"]`.

## Chosen

The rig's cargo test command is named `test`, as `init --language rust` names it, and carries the universal tests
capability. The check keeps its id `rust-test`, which the invariant oracles name. `rust-test` leaves the worker-local
manifest `WORKER_LOCAL_CHECKS`, since no check command of that name remains. The rest of D053 remains.

## Rejected

Declaring `test` worker-local: the manifest filters both sides, so the universal tests dimension would no longer be
compared. Keeping a pytest `test` check over the example consumer's `test_sample.py`: it keeps pytest in the rig's
gate for a file the delivery test already runs, against the user's decision. Renaming the check id as well: twenty
oracle bindings would change without any change in what I020 compares.

## Rationale

I020 names a command check's capability by its command, so the command name carries the capability. The rig's tests
are now exactly the capability a Rust consumer receives, and the guard keeps comparing it.

## Consequences

`just run test -- FILTER` and `just test` run the rig's Rust tests, and the gate reports them under the check
`rust-test`. Build, formatting, Clippy, Ruff, mypy, typos and Vulture stay worker-local.
