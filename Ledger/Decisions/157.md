# D157 — A cargo oracle names the marked function by the trailing segments of its target

## Context

B108 moves the rig's invariant oracles to Rust tests placed in the features they verify, such as
`change_delivery::git::tests::reference_guard_rejects_deletion_when_the_tip_cannot_be_resolved` in
`Project/change_delivery/git/tests/mod.rs`. `memory-check` looked the whole cargo target up among the function names
of the linked file, which are qualified only within that file. A cargo oracle could therefore bind only a test whose
module path is the crate root, such as `tests::doubles` in `lib.rs`; every test in a nested module file was reported
as a missing marked function. The pytest runner names a function inside its file and keeps its file check.

## Chosen

For a cargo oracle `memory-check` takes the functions of the linked file whose file-local qualified name equals the
target or ends it after a `::` boundary. Exactly one such function must exist and carry `INVARIANT: INNN`; no match,
a match on part of a segment and several matches fail as a missing or ambiguous marked function. Discovery through the
configured check still requires cargo to list the target. Pytest matching is unchanged.

## Rejected

Deriving the linked file's module path from the `mod`, `#[path]` and `include!` tree, as `config-check` does for
D144, and requiring the target to be that path plus the local name: it binds the oracle to the file exactly, but the
walk and the manifest layout live in `project_setup`, which already depends on `project_memory`, so they would have to
move to a shared owner. That stronger guarantee is a new product outcome for Backlog, not part of B108. Keeping exact
equality: it rejects every nested test module and so every Rust oracle placed with its feature.

## Rationale

A file's module path is a prefix of each test path inside it, so the file-local name is the target's trailing
segments. Requiring one match keeps a marker on a function of another scope or a same-named function at another
depth from passing; whole segments keep `oubles` from matching `doubles`.

## Consequences

A file whose own scope and a nested module both hold a function matching the target, such as `doubles` and
`tests::doubles` for `feature::tests::doubles`, fails as ambiguous even when one of them is the test cargo runs. A
marked function with the target's local name in a different file than the one cargo runs is not detected by
`memory-check`; the break-and-fail proof of each moved oracle covers it within B108.
