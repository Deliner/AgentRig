# D178 — superseded-form takes Vec from the return type of the nearest function or closure

## Context

D177 reports `(0..n).map(f).collect()` only when its turbofish or `let` type
names `Vec`. B129 asks for the same finding when the collect is the last
expression of a function or closure that returns `Vec<..>`, or the value of a
`return` in one, and leaves a collect in an `if` or `match` branch, an argument
or a field, and one into `Option<Vec<_>>` or `Result<Vec<_>, _>`, out of scope.
A rig test built its edges from a closure declared `-> Vec<Dependency>`, and the
rule kept silent there.

## Chosen

The detector also takes the target type from the `return_type` of a
`function_item` or `closure_expression` in two places: when the collect is a
direct child of the block that is the owner's `body`, which the grammar admits
only for the block's tail expression, and when the collect is the value of a
`return_expression`, whose owner is its nearest enclosing function or closure.
The type counts as before: a generic type whose last path segment is `Vec`.
The symbol, the skill and the `DECISION:` exception stay those of D177. This
supersedes D177's list of `Vec` targets; the rest of D177 holds.

## Rejected

Following branches of `if`, `match` and nested blocks to the function's return
type: B129 leaves branches out, and each further shape adds a path the reader
has to trace. Resolving types to cover arguments and fields: the lint has no
type information. Taking the return type of the nearest function for a
`return` inside a closure: the `return` leaves the closure, whose own return
type decides.

## Rationale

The return type states the target as plainly as a `let` type, so the same old
form should not pass because it is written as the result of a function. The
two grammar positions are exact without type resolution.

## Consequences

A collect returned from a closure without a declared return type stays
unreported, as an inferred `let` does. A `return` inside an `async` block is
measured against the enclosing function's return type, although it leaves the
block.
