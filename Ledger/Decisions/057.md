# D057 — Keep test public-surface discipline (TC2/TC4) a review norm; no static rule

## Context

B023 asked to turn TC2 (an item made public solely so a test can reach it) and
TC4 (no back doors into private internals) from the testing-discipline skill
into a static lint, by giving the engine symbol-visibility extraction and a
reverse-reference index. Implementing B023 required first establishing whether a
false-positive-free rule is possible on the current engine. The structural lint
engine is a syntactic module-dependency analyzer: item declarations are
collected without visibility and only at module level (associated and trait
functions are not collected at all); references are use, qualified-path, module
and macro forms resolved to files, while method calls through a receiver are not
captured; a qualified path that needs type resolution is reported as
unanalyzable.

## Chosen

Keep TC2 and TC4 review norms in the testing-discipline skill, already shipped to
consumers by P031. Add no lint rule, rule kind, invariant or oracle for them.

## Rejected

Build symbol-visibility extraction plus a reverse-reference index for a
"public only for tests" rule; ship a rule restricted to free module-level items
only; weaken the no-false-positive requirement; or record a pretend invariant
for a norm the engine cannot check (norm-or-choice).

## Rationale

The most common case TC2/TC4 target — an associated or trait function widened to
pub or pub(crate) just so a test can call it — is invisible to the engine, which
captures neither method declarations nor method-call references and does no type
resolution. For free module-level items a reverse symbol index is still defeated
by glob imports, re-exports, macro bodies and items passed as values, each a
false-positive source. A rule that misses the main case and still misfires on
real code cannot satisfy B023's no-false-positive acceptance. This is the
symbol-visibility and reverse-reference gap D054 and D055 named.

## Consequences

TC2 and TC4 remain enforced by review through the testing-discipline norm,
beside TC1 (D055). A static rule becomes reconsiderable only if the engine gains
semantic resolution: method-receiver types, and reference tracking through glob
imports, re-exports and value positions. B023 completes as a recorded norm with
no code change.
