# D031 — Current execution Plan and unordered Backlog

## Context

The user explicitly changed memory policy: Plan is only for work selected to execute now in the current session; future ideas, improvements and hypotheses should be saved without a delivery sequence. The old Plan retained completed history and seven unselected future outcomes. D012's broader future queue and the previous promotion-on-planning guidance conflict with this instruction.

## Chosen

Supersede that future queue semantics with a current execution Plan and unordered Backlog. Selection to execute now moves an idea into Plan; a request to remember or plan it for later does not. Preserve an unfinished authorized task across interruption and context reset. Automatically rotate completed rows/cards into Archive/Plan.md and Archive/Plan/ through edit-plan, retaining their format, identities, acceptance and verification. Transfer deferred work with its context, requirements and handoff facts. Keep existing schemas, dependency validation, at most one active feature, VACs and commit/merge gates.

## Rejected

Keep future work in Plan merely because it is useful or was previously discussed, infer execution priority from Backlog order, discard acceptance when moving records, reuse retired IDs, delete completed cards, or add a session registry or automatic scheduler.

## Rationale

This follows the user's distinction between present commitment and remembered possibilities. Existing Markdown memory, its Archive directory and Git preserve both. The agent performs rotation through the canonical skill; the existing memory checker validates archived records and references. Canonical skills and shipped instructions guide the choice; structural validation does not claim to infer the user's intent.

## Consequences

P010-P016 become B001-B007 with retained requirements and source references. P001-P009 remain in the repository under Archive. Current links and architecture inventories follow the new owners. Empty Plan is valid. The instruction is an attributed workflow policy, not a new executable invariant or proof that an agent understood it.
