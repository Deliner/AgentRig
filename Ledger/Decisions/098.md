# D098 — Extend allow-justification to expect, cfg_attr suppressions and allow levels in TOML lint tables

## Context

B053 (research arc, "cfg-attr-suppression", agreed 2026-11-02; implementation of the arc's
findings authorized by the user on 2026-11-04 via /goal) observes that the `allow-justification`
rule kind (D080) sees only `#[allow(...)]`/`#![allow(...)]`. A lint can be silenced in three
other syntactic forms the gate does not see: an `#[expect(...)]`/`#![expect(...)]` attribute,
which suppresses exactly like `allow` and only adds an error when the lint does not fire; a
conditional `#[cfg_attr(cond, allow(...))]`, `… expect(...)` or `… ignore`, which is the same
suppression behind a configuration predicate; and the `"allow"` level under Cargo's `[lints.*]`
or `[workspace.lints.*]` tables, which silences a lint for a whole package without any attribute
in the code. Each form is decidable from syntax alone (D035, D059). The repository contains
none of them. The `toml` crate is already a dependency and parses a document with byte spans
on every key and value.

## Chosen

Extend the existing kind instead of adding one. In Rust, the attribute dispatch moves from
`rust.rs` into `languages/suppression.rs` (taking its D074/D080 ownership with it) and keys on
`allow`, `expect` and `ignore`; for `cfg_attr` it takes the first identifier that follows a
top-level comma of the argument token tree and is one of those names — the suppression head as
a direct argument — and reports it through the same name-to-kind mapping, so a conditional
`ignore` is a `disabled-test` finding (D074) and a conditional `allow`/`expect` an
`allow-justification` finding, outer and inner attributes alike, with the head name as the
symbol. The line-above justification (`justified`) is unchanged; a `reason = "…"` inside the
attribute is not a reference, and the violation text says so. In TOML, a new `toml` language
handler (`.toml`, rule set: `allow-justification`) analyzes the whole document with the installed
`toml` crate's spanned `DeTable` rather than a line scan: for every entry of every table under
`lints` or `workspace.lints` (dotted keys included), a value that is the string `"allow"` or a
table whose `level` is `"allow"` is a finding at the key's line unless a `# DECISION:` or
`# INVARIANT:` reference sits on the line directly above the key (the same `justified_line`
helper the tree-sitter handlers use); a TOML syntax error is reported as the shared `syntax`
diagnostic like a Rust or Python parse error. The handler registry replaces the never-`None`
optional inspect function with an `Inspect` enum: `Tree` for tree-sitter node handlers,
`Document` for whole-document analysis. No new rule kind, skill or oracle: `justify-allow`
describes the three forms, the delivered extension defaults of the kind now include `.toml`,
and the repository rule gains `.toml` after a mid-branch pin (D051), so the I020 sets are
unchanged.

## Rejected

A new rule kind per form: the violation (a silenced lint without an owned reason) and the repair
are the same, so separate kinds would multiply configuration and skills without a behavioral
difference. Accepting `reason = "…"` as justification: the reason stays in the code instead of
being owned knowledge in the Ledger (D080). A tree-sitter TOML grammar: a new dependency where
the installed `toml` crate already parses with spans. A text scan of Cargo.toml for `"allow"`: a
dependency named `allow` or a description containing the word would false-positive, whereas the
parsed table path locates lint entries exactly (D035). Restricting the TOML analysis to files
named `Cargo.toml`: the `lints`/`workspace.lints` table path already identifies Cargo's lint
tables, and any other TOML file simply yields nothing. Resolving a suppression head nested
deeper than a direct `cfg_attr` argument, or a lint level reached through `workspace = true`
inheritance from another manifest: outside the syntactic, single-file engine (D059).

## Rationale

All three forms are the same decision — silence a lint — spelled differently, so one kind with
one repair skill is the lowest sufficient mechanism (D080's justification family: D065, D069,
D074). Keying `cfg_attr` on a direct argument head keeps the check near-zero-false-positive
(D035): `derive`, `cfg` predicates and unrelated attributes never match. Parsing TOML with the
installed crate reuses a dependency and a spanned representation that already exist; the
`Inspect` enum names a distinction the registry now genuinely has (two analysis mechanisms)
and removes a dead `None` path. Moving the attribute dispatch into its own module keeps `rust.rs`
under the repository's hard file-size limit along a real responsibility boundary (attributes
that silence a lint or a test), not a count.

## Consequences

A consumer's or this repository's `#[expect]`, conditional `cfg_attr` suppression or `"allow"`
lint level without a reference on the line directly above becomes a gate error on `init` and
before commit; `cfg_attr(…, ignore)` reports as `disabled-test`. The `allow-justification` and
`disabled-test` descriptors name the new forms, `just lint-rule allow-justification` lists
Rust and TOML, and the delivered per-kind template includes `.toml`. D074 and D080 keep their
statements; their Rust owner link migrates to `languages/suppression.rs` (D020). It ships B053
in full; it supersedes nothing.
