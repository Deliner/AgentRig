# D147 — A referenced Clippy allow on an enclosing item justifies the panics it permits

## Context

B099. A project whose Clippy profile denies `clippy::expect_used` and similar lints must put `#[allow]` on the item
that keeps such a panic, and allow-justification (D080) requires a `DECISION:` or `INVARIANT:` reference above that
attribute. panic-path (D082) then required a second reference directly above each panic. voxel-rust repeated D008
and D009 this way in `controller.rs` and `local.rs`. The user's /goal of 2026-11-10 selected B099 with every other
Backlog card and left the choices to the executor.

## Chosen

A panic that panic-path measures is justified when an enclosing item, statement or module carries an outer
`#[allow(...)]` or `#[expect(...)]` listing the Clippy lint that forbids that panic form, with a reference directly
above the attribute: `clippy::unwrap_used` for `.unwrap()` and `.unwrap_err()`, `clippy::expect_used` for
`.expect(...)` and `.expect_err(...)`, and `clippy::panic`, `clippy::todo`, `clippy::unimplemented` or
`clippy::unreachable` for the macro of the same name. The rule also applies to panics found in macro arguments.
`resume_unwind` has no such lint and keeps needing its own reference. A reference directly above the panic still
justifies it as before.

## Rejected

Accepting only `#[allow]`: `#[expect]` suppresses the same lint, and allow-justification already treats both alike;
switching to `#[expect]` would otherwise bring back the second reference.

Accepting `#[cfg_attr(…, allow(…))]` or inner `#![allow(…)]` attributes: a conditional allow does not cover every
build, and no current project relies on inner attributes for this.

Checking that the project's Clippy profile actually denies the lint: the allow already names the lint, and reading
the profile would tie the measurement to one command configuration.

Accepting any reference on an enclosing item: only an allow of the matching lint states that the item deliberately
keeps that kind of panic.

## Rationale

The reference above the allow already records why the item keeps the panic, and Clippy enforces the same scope. One
reference per item keeps the reason in one place and covers panics added to the item later.

## Consequences

On voxel-rust the second references to D008 and D009 can be removed without new findings: the installed runtime
reports 3 panic-path findings after the removal, the candidate none. An allow of `unwrap_used` does not cover
`.expect(...)`. Other rules keep their own line-above references.
