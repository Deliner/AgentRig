# D231 — The rig ships its compaction mod as a project plugin marketplace

## Context

B203 AC8: the rig installs its compaction mod in every project it sets up and in its own repository, so that Claude
Code opened there offers the tool `compact` without an install in the user's profile, and the mod no longer suggests
compacting after commits. The user's mod `self-compact` lived unconnected in `~/.claude/skills/self-compact`. Claude
Code loads a mod as a plugin whose `hooks/hooks.json` names a TypeScript module, and reads a plugin only from a
marketplace. A project's `.claude/settings.json` can name a marketplace in a project directory under
`extraKnownMarketplaces` and enable its plugin under `enabledPlugins`; Claude Code offers both once the user trusts the
folder. D198 allows a project's programs only in its listed languages and excludes the generated hooks and launcher.
Codex has no mod that could compact its context (D230), so it receives nothing.

## Chosen

- The mod's source lives in `Project/shared/mods` as a marketplace `agentrig` with the one plugin `self-compact`. Its
  module is the user's without the suggestion after `git commit` and `git merge`: it registers the tool `compact`,
  queues a compaction for the end of the turn and resumes with the given hint.
- `init` writes the marketplace to `mods/` in the service directory and adds to `.claude/settings.json` the directory
  marketplace `agentrig` at that path and the enabled plugin `self-compact@agentrig`.
- The installed `mods/` is protected like `bin/` and `hooks/`: a mod runs inside the agent's client. `init` marks
  executable only the files in `bin/` and `hooks/` of the service directory, so the mod's own `hooks/` stays data.
- The program-language rule that `init` writes also excludes `mods/**` in the service directory; the rig's rule also
  excludes the source `Project/shared/mods/**`, a listed difference from `init`.
- The rig's repository holds the same files and settings as `init` output, which the rig test compares.

## Rejected

- Install the mod into the user's profile: the user asked for the mod in each project and the profile copy removed.
- Link the rig's `.agentrig/mods` to its source like skills: an agent in the rig would change the running mod without
  approval, while the installed copy stays protected.
- Allow TypeScript in the rig's or the projects' rule: it would admit TypeScript anywhere, while only the mod needs it.
- Rewrite the mod in an allowed language: Claude Code loads a mod only as a TypeScript module.

## Rationale

A project marketplace travels with the repository, so each clone and collaborator gets the same mod as the rig that
requires its tool, and the mod's version follows the rig rather than each user's profile. Narrow excludes keep D198's
policy for every other file.

## Consequences

Claude Code asks the user to trust the folder and to install the marketplace and plugin once per machine; until then
the agent asks the user to type `/compact` after a merge. A change of the mod's source needs the approved copy in
`.agentrig/mods` in the same commit, since the rig test compares them. A Codex session ignores the marketplace.
