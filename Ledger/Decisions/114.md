# D114 — Extend discarded-result to bare Option combinators and `.err()`

## Context

B047 (cross-project review, agreed 2026-11-01; selected by the user's /goal
2026-11-07). rustdesk drops `Option` combinator results in statements such as
`opt.map(|x| x.fallible());`; the compiler's `unused_must_use` does not see a
`Result` through the `Option`, and `discarded-result` (D090, D099) flags only a
bare `.ok();` and the propagated `.status()?;`/`.output()?;`. A bare `.err();`
drops the error `Option` the same way `.ok();` drops the value. AgentRig's own
code has no such statement: the candidate lint on the repository stays clean.

## Chosen

Extend the existing kind. `discarded_method` matches, besides `ok`, the bare
(non-propagated) statement whose last call is `err`, `map`, `and_then`, `map_or`
or `map_or_else`, keyed on the method name as `ok` is, outside test code and
without a `DECISION:` or `INVARIANT:` reference on the line directly above, with
the method name as the symbol. A `let` binding, an assignment, an argument, a
returned tail expression and a call under `?` are not flagged. The descriptor,
the `handle-discarded` skill and its directory purposes name the new forms. No
rule kind, skill, configuration or oracle changes, so the I020 sets are
unchanged and only the final pin applies (D051).

## Rejected

A new rule kind: the violation and the repair are those of `.ok();`. Resolving
whether the receiver is an `Option` or whether the closure is fallible: outside
the syntactic single-file engine (D059); a discarded combinator without effects
is rare and binding or removing it is the repair, so the card accepts it as
near-zero false positive. Matching other combinators (`filter`, `map_err`,
`inspect`): not in the card, and `Result` forms already raise `unused_must_use`.
Matching the call under `?`: the `?` keeps the propagated part, as D090 chose
for `ok`.

## Rationale

The new statements are the same decision as `.ok();` — throw the outcome away —
so one kind and one repair skill stay the lowest sufficient mechanism; the change
is a longer name list on the existing `expression_statement` dispatch.

## Consequences

A consumer's or this repository's bare `.err();` or Option-combinator statement
in non-test Rust becomes a gate error on `init` and before commit; binding,
handling or a reference on the line directly above passes. D090 and D099 keep
their statements and owners. It ships B047 in full; it supersedes nothing.
