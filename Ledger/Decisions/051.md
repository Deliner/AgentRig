# D051 — The agent pins and bootstraps each merged runtime

## Context

D027 pins a verified commit and installs it explicitly after acceptance, but
promotion happened in occasional separate changes. After D049 merged, the
installed runtime still ran 937d3f0 and the agent asked the user whether to
update it. The user instructed the agent to always update the pin and run
bootstrap itself after merging a branch, and to record the rule.

## Chosen

As the final VAC of every branch that changes Project, after its head passes
the commit gate, write that hash to stable.txt and run bootstrap in the same
command, restoring the previous pin if bootstrap fails; then commit the pin and
run feature-merge. Branches without Project changes keep the pin. No user
confirmation is requested.

## Rejected

Pin the merge commit afterwards on another branch, which adds a second merge
for every branch; ask the user each time; replace the runtime on every source
edit; write the pin without installing it.

## Rationale

The merge then integrates exactly the pinned product, so master always has its
own runtime installed, and the merge gate already runs on that runtime.
Pinning and installing together keeps hooks working.

## Consequences

Each branch that changes Project ends with a pin commit, and the installed
runtime matches master after every merge. D027's explicit installation after
acceptance remains; this decides when and by whom it happens.
