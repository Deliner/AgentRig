# D082 — Flag a Rust panic path outside test code as an unhandled error

## Context

B037 (Набор II cluster C6, effects and errors, agreed 2026-10-31)
asks that a consumer's shipped Rust not carry an abort-on-failure into
the runtime. `.unwrap()`/`.expect(...)` on an Option or Result and the
`panic!`, `todo!`, `unimplemented!` and `unreachable!` macros terminate
the program instead of returning or handling an error — the agent
reaches for them under "make it compile" pressure. Whether a call is
one of these is decidable from syntax: a `call_expression` whose
`function` is a `field_expression` with field `unwrap`/`expect`, or a
`macro_invocation` whose `macro` path is one of the four macros — with
no symbol or type resolution (D035). The gate's Clippy already denies
these in this repository (commands.yaml), but a consumer project
without that Clippy configuration gets no such check; the lint rule
carries it and its repair guidance to every consumer. Test code
legitimately panics on a failed expectation, so it is excluded.

## Chosen

Add a `panic-path` rule kind (target file, error level), Rust-only.
The detector dispatches on `call_expression`, keying on a
`field_identifier` method name `unwrap`/`expect`, and extends the
existing `macro_invocation` dispatch (D081) to key on `panic`, `todo`,
`unimplemented` and `unreachable`. A `DECISION:`/`INVARIANT:` reference
on the line directly above the call removes the finding, reusing the
justification mechanism (D065/D080): the invariant attests the panic is
unreachable. Test code is excluded two ways — the detector walks the
node's ancestors and skips any node inside a `mod` carrying
`#[cfg(test)]` or a `fn` carrying `#[test]` (attributes read as the
item's preceding siblings), and the delivered repository rule excludes
`**/tests/**` for separate test files whose helpers are not themselves
test-attributed. The kind ships to consumers through `catalog::ALL` and
the delivered per-kind config template. A new repair skill
`handle-panic` joins the `references` group and ships through
`project_setup/assets.rs`, so the delivered and live skill sets both
grow by one and stay equal (I020); the rule-kind set grows too.

## Rejected

A whole-value swallowed Result (a Result returned and dropped) needs
type inference, rejected (D059), left a norm. Flagging
`println!`/`eprintln!` or `assert!`/`assert_eq!`: deliberate output is
the D060 choice and assertions are the sanctioned expectation
mechanism, not an unhandled error. A Python analogue: silent-error
(D069) already covers swallowed exceptions, and raising is not
panic-equivalent. Relying on Clippy alone: `clippy::unwrap_used` and
friends are not portable to a consumer's gate, which the delivered rule
and skill are; the strict Clippy profile (D060) stays this repository's
dev gate and the rule is the portable baseline, not its replacement. A
regex over source text: `.unwrap()` inside a string literal would
false-positive, whereas the AST distinguishes a call from a string.
Dropping the `#[cfg(test)]`/`#[test]` detector exclusion and relying on
the path exclude alone: this repository's inline `#[cfg(test)] mod`
blocks live in ordinary files outside `tests/` and would
false-positive, so the ancestor walk is required for a green gate.

## Rationale

The method and macro names are a fixed, syntactic set, meeting the
high-signal, type-free bar for the gate (D035) and mirroring the
fixed-set philosophy of hardcoded-secret (D067) and dump-name (D072).
Reusing the justification mechanism keeps the escape consistent with
unsafe (D065), silent-error (D069), disabled-test (D074) and broad
allow (D080). The two-part test exclusion is the lowest sufficient
mechanism: the path exclude handles separate test files whose helpers
are not test-attributed, and the ancestor walk handles inline test
modules the path cannot see. This repository's lib code is already
unwrap-free (D060), so the rule is green on delivery once test code is
excluded.

## Consequences

A consumer's or this repository's non-test Rust `.unwrap()`/`.expect`
or panic macro becomes a gate error on `init` and before commit;
returning or handling the error, or recording a `DECISION:`/`INVARIANT:`
reference above the call, passes. The rule-kind set and the skill set
both grow by one and stay equal across delivery and repository (I020).
It shares the `macro_invocation` dispatch introduced by D081 and adds a
`call_expression` dispatch with no other current consumer. It ships
B037, the C6 cluster of Набор II; C6's remaining points stay covered
(D068/D069/D078) or norms (D059). It supersedes nothing.
