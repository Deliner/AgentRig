# D028 — Directory architecture contracts

## Context

P006 requires a small per-directory description, multi-language dependency checks, public/private boundaries and cycle diagnostics. AgentRig already owns strict YAML and glob matching.

## Chosen

Use directory-owned architecture.yaml declarations for purpose, allowed/denied dependencies and public file boundaries. Apply shared policy checks to resolved source dependencies supplied by language handlers. Check each crossed configured boundary, including parent boundaries; a child cannot open a parent's private interface or widen its outbound permissions. Build the cycle graph from measured dependencies, not permission declarations.

## Rejected

A second configuration language, per-language copies of graph policy, a central duplicate directory registry, and treating allowed dependencies as evidence that code uses them.

## Rationale

One contract owner and the existing YAML/glob implementation satisfy the current requirements. Shared resolved edges permit different language syntax without different architecture semantics. Parent boundaries retain the declared public/private ownership when implementation files are nested.

## Consequences

Language handlers must report their actual resolution coverage and unsupported forms. Permission declarations do not prove absence of cycles. The delivery guide defines path matching and defaults; feature acceptance still requires actual source extraction, CLI integration and independent consumers.
