# D121 — Bound how many other project directories one source file uses

## Context

B072 (idea from the interview of 2026-11-07; selected by the user's /goal
2026-11-07, which leaves the default budget and the unit of a project part to
delivery). D079 bounds a directory's incoming coupling; nothing bounds what one
file reaches, so a file using seven parts of the project passes the gate. On
the resolved directory-architecture edges, 157 AgentRig source files use other
directories: 154 use at most 7, and three use 11, 12 and 14
(`change_delivery/gate/mod.rs`, `structural_lint/mod.rs`,
`command_line/mod.rs`). The engine fails on the corpus crate roots with
unsupported macros, so the r8 corpus was measured by a proxy over `use` paths
calibrated on AgentRig (mean absolute difference 0.44 per file over 158
files). Of about 10,944 files, counting directories inside one crate, 96
exceed 6, 55 exceed 7, 36 exceed 8 and 13 exceed 10. Counting other workspace
crates as well, bevy has 226 of 1,307 files above 10, uv 70 of 643 and ruff
56, while alacritty, coreutils, ripgrep, tokio, vaultwarden and zed have none.

## Chosen

The directory-architecture rule measures, for each selected source file, the
distinct exact directories of other Rust and Python source files (`.rs`,
`.py`, `.pyi`) it reaches through resolved references. Its own directory,
module declarations and resource targets such as `include_str!` files are not
counted. A file above the budget is a file-level finding at the rule's level
and with its repair skill, listing the counted directories. The default budget
is 10; the rule's `architecture.fan_out` setting replaces it for the whole
project. Program entry points are exempt: the files listed in `rust_roots` and
Python `__main__.py`. The repair skill `refactor-large-directory` gains a wide
file repair. No new rule kind or skill, so I020 is unchanged. AgentRig splits
its three files by responsibility: check execution into
`change_delivery/gate/check.rs`, rule evaluation into
`structural_lint/evaluation.rs`, the commands that need the loaded project into
`command_line/project.rs`, and the configuration check into
`project_setup/doctor.rs`.

## Rejected

Counting top-level modules: it merges the `shared` capabilities and nested
features that have their own contracts, and differs from D079's exact
directory. A per-directory budget in architecture.yaml, like `dependents`: the
corpus shows the need differs by project shape, many-crate workspaces against
single crates, not by directory, and a per-directory opt-in leaves the default
unchecked. A default of 6 or 7: three ordinary AgentRig files sit at 7, and 55
corpus files exceed 7 inside one crate against 13 above 10. Counting module
declarations: `mod child;` is composition, as for cycles and D079. Counting
resource targets: `project_setup/assets.rs` embeds files from 45 directories
that are data, not code it depends on. A separate rule kind: the graph and its
resolution already belong to the directory-architecture rule.

## Rationale

The directories a file uses are visible in its references, so the finding
names what the file mixes and where to split it. A program entry point wires
the program together, which is its responsibility. The default of 10 catches
the three AgentRig files that combine several responsibilities and leaves
ordinary files of single crates quiet.

## Consequences

A consumer source file using more than 10 other project directories fails
lint where the directory-architecture rule is enabled; a workspace of many
crates may raise `fan_out`. The engine's analysis limits apply, so a crate
root it cannot analyze yields incomplete-analysis findings rather than fan-out.
It ships B072 in full, extends D079's coupling bounds with the outgoing side
and supersedes nothing.
