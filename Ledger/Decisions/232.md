# D232 — The release profile compiles incrementally

## Context

The gate's `build` check, every `just candidate` call and the test helper build the candidate runtime with
`cargo build --release` through `tooling/worker/build`, and each change of `Project` rebuilds the crate `agentrig` of
about 52 thousand lines. On the rig's machine that rebuild took 11–13 s without load and about 21 s inside a gate, near
half of a commit gate that changes `Project`. Release packaging copies the binaries this build produces.

## Chosen

`Project/Cargo.toml` sets `[profile.release] incremental = true`.

## Rejected

- A separate profile for development builds: the build launcher, the test helper and packaging all name
  `release/agentrig`, so each would change, and packaging would build the crate a second time.
- `CARGO_INCREMENTAL=1` in the build launcher: the launcher is protected and packaging runs it too, so the result is
  the same through a protected change.
- Keep non-incremental release builds: they cost 7–9 s more per rebuild for no measured runtime gain.

## Rationale

Measured on 2026-11-22: after a one-line code change the rebuild took 2.7–4.0 s instead of 11.3 s, and the candidate's
lint of the rig repository took a median of 0.638 s against 0.644 s for the non-incremental binary over five runs each.

## Consequences

Each target directory, the staged one included, keeps a release incremental cache of some hundred megabytes. Packaged
binaries are incremental builds with the same behavior.
