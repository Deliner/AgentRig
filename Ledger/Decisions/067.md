# D067 — Flag literals matching known credential formats

## Context

The user selected the code-quality set (clusters 1–8, B026–B033) on 2026-10-29
for dogfooded delivery. Backlog B026 sub-rule 1.3 asks that a hardcoded secret be
caught by the gate before review, by pattern over keys and tokens, purely
syntactically, only on Project, as a capability that ships to `init`
(D053/I020). The card authorizes recording 1.3 as a norm if it cannot be checked
cleanly without false positives (norm-or-choice). The ruff bandit group (D064)
already flags Python credentials by variable name (S105–S107). On 2026-10-30 the
user chose a pattern rule over a norm or a broader name-based rule.

## Chosen

Lint gains the hardcoded-secret rule kind for Rust and Python at error level, a
finding when a string literal matches a fixed set of unambiguous credential
formats: a private-key block, an AWS access key, a GitHub token, a Google API key
or a Slack token. A shared matcher classifies the literal text; the measurement
is shared by both language handlers, which route string-literal nodes to it. The
rule ships to consumers through `catalog::ALL`, routed to a new remove-secret
repair skill added top-level; the three refactor-* skills move under a `refactor`
group so the skills directory stays within its size limit.

## Rejected

Record 1.3 as a norm, which leaves consumer Rust unprotected when a clean rule is
available; a name-based rule on `key`/`token`/`secret` identifiers, which largely
duplicates bandit for Python and is badly false-positive-prone on those overloaded
names in this domain; entropy or broad regex scanning, foreign to the syntactic
engine (D035) and false-positive-prone; a tunable pattern set in configuration,
when one fixed high-signal set is required; adding remove-secret as a new
top-level skill past the directory-size limit instead of making room by grouping.

## Rationale

Each chosen format is a distinct, well-known credential shape that almost never
appears except as a real secret or a deliberate example, so matching it by value
is high-signal and near-zero false positive, and additive to bandit's name-based
Python checks because it matches regardless of variable name and covers Rust too.
A fixed set keeps the rule one behavior with no configuration dimension, and the
match stays syntactic, needing no type inference, which keeps the gate fast
(D035). Grouping the cohesive refactor-* skills is the directory-size rule's own
intended repair, not a weakening of the threshold.

## Consequences

A string literal matching a known credential format becomes a delivery finding
routed to remove-secret, in the worker repository and in every consumer. The
worker has no such literals; its matcher test builds each sample by concatenation
so no single source literal is a complete pattern, keeping the repository clean
under its own rule. replace-comment stays under references; the refactor-* skills
move under `refactor` with symlink aliases preserving their paths and hook routes.
With 1.1 (D065/D066), 1.2 (D064) and 1.3 delivered, B026 (P037) is complete.
