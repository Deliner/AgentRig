# D077 — B033 lockfile discipline is already satisfied and the dependency budget stays a norm

## Context

B033 (cluster 8 of the quality set, agreed 2026-10-29), besides the
never-imported rule shipped as D076, proposes two further candidates: 8.2 —
builds and tests pin their dependencies through committed lockfiles and
`--locked`/`--frozen`, so a resolution cannot drift silently; 8.3 — a soft budget
on the number of dependencies a feature declares, flagged above a threshold. 8.2
is a reproducibility property of the build and command configuration, not of
source syntax; 8.3 is a soft, project-specific threshold and would require a new
per-feature dependency count the engine does not compute.

## Chosen

8.2 stays a configuration norm, already satisfied, not a new rule or check:
`Project/Cargo.lock` and `tooling/uv.lock` are committed, every cargo and uv
command in `.agentrig/commands.yaml` and the build launcher passes `--locked`,
and `init` ships no build commands (it delivers lint configuration and memory, not
cargo/uv invocations), so there is nothing to ship to consumers and nothing to
enforce beyond the command configuration that already owns it (D005/D060). 8.3
stays a norm, not an init rule: a dependency budget is a soft threshold, and a
sensible count needs per-feature aggregation the structural engine does not
perform. Only the decidable part of cluster 8 — a declared external that is never
imported — ships as the rule extension (8.1, D076).

## Rejected

A `--locked` lint rule or gate check for 8.2: the command configuration already
pins every invocation and the lockfiles are committed, so a rule would re-assert
an existing, enforced property and add a dimension for no behavior change; a
pretend invariant for an already-true configuration fact is forbidden by
norm-or-choice. A hard or soft dependency-count rule for 8.3: a numeric budget is
inherently a soft, context-dependent threshold (a feature legitimately needs the
dependencies it needs), so a blanket limit is noise against the gate's
near-zero-false-positive bar (D035), and it would need a new per-feature counting
mechanism; norm-or-choice forbids a pretend invariant for it.

## Rationale

Norm-or-choice: a rule fits a decidable, high-signal, source-syntactic check; a
configuration property already enforced elsewhere needs no rule, and a soft
project-specific threshold is a norm. 8.1 is decidable and shipped (D076); 8.2 is
already true and owned by the command configuration; 8.3 is soft and uncomputed,
so both stay norms rather than redundant or noisy rules.

## Consequences

B033 ships one capability, the never-imported rule (8.1, D076). Lockfile and
`--locked` discipline (8.2) remains a property of the committed lockfiles and the
command configuration (D005/D060), re-verified by the gate running those pinned
commands, not a new check. The dependency budget (8.3) remains a review norm. No
new rule kind, skill or invariant is added for 8.2/8.3, so the I020 delivery sets
are unchanged. With 8.1 (D076) and 8.2/8.3 (this), B033/P042 — the last card of
the clusters-1–8 quality set — is complete. It supersedes nothing.
