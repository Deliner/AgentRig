# D071 — B030 families and one-file-per-capability stay norms, not init rules

## Context

B030 (cluster 5 of the quality set, agreed 2026-10-29) proposes, besides the
purpose-quality check shipped as D070, two further candidates: 5.1 — a trait and
its impls, or a base class and its subclasses, live in one directory; 5.3 — one
capability per file (a separate CLI command, lint rule or handler gets its own
file). The card's boundary routes anything that needs symbol or type resolution,
or that is inherently declarative, to a norm with a recorded reason
(norm-or-choice). The structural engine is purely syntactic (D035) and omits the
symbol and type resolution a type-resolving frontend would add (D059).

## Chosen

5.1 and 5.3 stay norms, not init rules. Their intent is already carried by the
existing structural discipline: feature types and directory contracts
(D043/D044) place a feature's parts together, and `refactor-large-directory`
guides organization by responsibility and the facade-and-leaves shape. Only 5.2,
which is decidable from the contract text, ships as a rule (D070).

## Rejected

A 5.1 rule: it must resolve each `impl`'s trait, or each class's base, by name to
its defining file and compare directories. The engine resolves import-bound names
but not wildcard, re-export or prelude names (a documented analysis limit), so the
check would carry false-negative holes and require a new impl/inheritance
extraction subsystem — the same cost/benefit that D059 settled against a
type-resolving frontend. A 5.3 rule: "a CLI command, rule or handler" is not
syntactically identifiable without framework-specific semantics, and the generic
decidable proxy (one public item per file) would flag the legitimate cohesion the
facade guidance already allows (`refactor-large-directory`: keep cohesive
implementation together, do not require empty entries).

## Rationale

Norm-or-choice: a norm fits a behavior that cannot be checked statically without
false positives or a disproportionate subsystem; a rule fits a decidable,
high-signal check. 5.2 is decidable (D070); 5.1 and 5.3 are not, so they stay
norms with this recorded reason rather than a weakened or false-positive-prone
rule that would relax the high-signal bar (D035).

## Consequences

B030 ships one init rule, the purpose-quality check (5.2, D070). Families-together
(5.1) and one-capability-one-file (5.3) remain guidance under the existing
structure discipline; no new rule kind, skill or invariant is added for them.
Reassessing either as a rule would require the symbol-resolution frontend deferred
by D059. It supersedes nothing.
