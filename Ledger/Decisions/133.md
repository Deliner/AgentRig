# D133 — Rule kinds are grouped into family enums

## Context

P089 adds the 37th rule kind for B080. With one flat `Kind` enum, adding it made `Kind::descriptor` 41 nonblank lines,
over the 40-line `function-size` limit, and `structural_lint/rules/descriptor.rs` 502 lines, over the 500-line
`file-size` limit, so P089 was paused. On 2026-11-07 the user saw the code before and after a split into family enums
and accepted it.

## Chosen

`Kind` becomes a wrapper with five variants, each holding a family enum in its own file under
`Project/structural_lint/rules/`: `Structure` for file, line, directory and architecture rules, `ControlFlow` for
conditions, nesting, branching and boolean expressions, `Signature` for function signatures and derived traits,
`Ownership` for resources, global state, deletion and lock guards, and `Reference` for code sites repaired by handling,
removing or justifying them. Each family file holds its enum with kebab-case names, its `descriptor` match and the
descriptor constants with their `DECISION:` references. `descriptor.rs` keeps the `Descriptor` shape, the shared
test-code exclusion and one match that dispatches to the family. `Kind` serializes untagged, so every serialized name
stays as it was. `Kind` is parsed by name in `catalog/mod.rs` among `catalog::ALL`, and an unknown name fails with
"unknown variant `x`, expected one of" and the shipped names. Code writes the full form `Kind::Family(Family::Variant)`.

## Rejected

A wildcard or grouped arm in the one `descriptor` match: the function and the file still grow with every kind. A table
of kind and descriptor pairs searched at run time: a new kind without a descriptor would compile. A `macro_rules!`
generator: the architecture analyzer rejects files that contain one, and it hides the code from the other rules.
Raising the `function-size` or `file-size` limit: policy forbids weakening a threshold to pass. A derived untagged
`Deserialize`: its error names no accepted kind, and an agent repairs a configuration from that list. `From`
conversions from a family to `Kind`: a second way to write the same value.

## Rationale

A kind added to a family touches one enum, one match arm and one constant in a file sized by that family, and the
compiler still checks that every variant has a descriptor. Related rules read together.

## Consequences

Configuration, the catalog output and the names in `lint-rule` stay byte-identical. The list in the unknown-name error
follows `catalog::ALL` order. A kind not yet in `catalog::ALL`, as during the first phase of D051, cannot be named in
configuration. Index links of 36 decisions move from `descriptor.rs` to the family file that holds their constant. A
new kind chooses a family; a family file that outgrows its limits splits again. The `Display` of D129 is kept.
