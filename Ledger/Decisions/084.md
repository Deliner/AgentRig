# D084 — Flag a Rust debug_assert outside test code as a release-stripped contract

## Context

B039 (Набор II cluster C5, behavior contracts, agreed 2026-10-31)
asks that a consumer's shipped Rust not anchor a behavior contract on a
check the release build removes. The `debug_assert!`, `debug_assert_eq!`
and `debug_assert_ne!` macros expand only under `cfg(debug_assertions)`,
so the precondition or invariant they state holds in debug and tests but
is silently unchecked in an optimized release — exactly where it matters.
An agent reaches for `debug_assert!` to "write down the contract" under
pressure, not realizing it evaporates. Whether a macro call is one of the
three is decidable from syntax alone: a `macro_invocation` whose `macro`
path is `debug_assert`, `debug_assert_eq` or `debug_assert_ne`, with no
symbol or type resolution (D035). Test code legitimately uses the
debug-only family, so it is excluded. The gate's Clippy profile (D060) is
this repository's dev gate and carries no such check to a consumer, so the
portable baseline is the lint rule.

## Chosen

Add a `debug-assertion` rule kind (target file, error level), Rust-only.
The detector extends the existing `macro_invocation` dispatch (D081/D082)
with an `assertion_macro` arm keying on the three macro paths, reporting
through a `report_assertion` that mirrors `report_panic`: a
`DECISION:`/`INVARIANT:` reference on the line directly above the call
removes the finding, reusing the justification mechanism (D065/D082), and
test code is excluded by the same ancestor `#[cfg(test)]`/`#[test]` walk
(`in_test_context`) plus the delivered rule's `**/tests/**` and `tests.rs`
excludes. The kind ships to consumers through `catalog::ALL` and the
delivered per-kind config template. A new repair skill `firm-up-assertion`
(promote to `assert!`, remove if redundant, or justify with a reference)
joins the `references` group and ships through `project_setup/assets.rs`,
so the delivered and live skill sets both grow by one and stay equal
(I020); the rule-kind set grows too.

## Rejected

Flagging `assert!`/`assert_eq!`/`assert_ne!`: these hold in every build
and are the sanctioned contract mechanism, not a release-stripped one;
flagging them would be wrong. A Python analogue (`assert`, stripped under
`-O`): a non-test `assert` is common and `-O` is rare, so the rule would
false-positive — left a norm. A documented contract in prose: the comment
ban (D037) already forbids free-text comments. A swallowed `#[must_use]`
result: needs type inference, rejected (D059), covered on the dev gate by
Clippy (D068). The `INVARIANT:` mechanism (D020) is this repository's
contract machinery, not a portable `init` rule. A regex over source text:
`debug_assert!` inside a string literal would false-positive, whereas the
AST distinguishes a macro call from a string. Relying on Clippy alone:
not portable to a consumer's gate; the strict Clippy profile (D060) stays
this repository's dev gate and the rule is the portable baseline.

## Rationale

The three macro names are a fixed, syntactic set, meeting the high-signal,
type-free bar for the gate (D035) and mirroring the fixed-set philosophy
of panic-path (D082), hardcoded-secret (D067) and dump-name (D072).
Reusing `report_panic`'s shape — the justification escape and the
`in_test_context` ancestor walk — keeps the behavior consistent with the
justification family (D065/D069/D074/D080/D082) and adds no new mechanism.
Keeping `assert!` legal draws the line precisely at the release-stripped
family, so the finding is near-zero false positive. This repository calls
no `debug_assert` family macro (only string literals naming them in the
resolver's known-macro list), so the rule is green on delivery.

## Consequences

A consumer's or this repository's non-test Rust `debug_assert!`,
`debug_assert_eq!` or `debug_assert_ne!` becomes a gate error on `init`
and before commit; promoting it to `assert!`, removing it, or recording a
`DECISION:`/`INVARIANT:` reference on the line directly above it passes.
The rule-kind set and the skill set both grow by one and stay equal across
delivery and repository (I020). It shares the `macro_invocation` dispatch
(D081/D082) and adds no new dispatch. It ships B039, the C5 cluster of
Набор II; C5's remaining points stay covered (D037/D059/D068) or norms
(the Python analogue, the `INVARIANT:` mechanism). It supersedes nothing.
