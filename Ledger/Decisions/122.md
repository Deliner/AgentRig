# D122 — Error on Rust string literals spanning more than twenty lines

## Context

B073 (idea from the interview of 2026-11-07; selected by the user's /goal
2026-11-07, which leaves the threshold to delivery). A SQL query, JSON
document, HTML page or template of dozens of lines can sit in a code file as
one string literal, and no rule sees it. The card leaves the threshold and
the corpus frequency unknown and defers Python. On the r8 corpus, 13,846
Rust files outside the machine-translated bun tree, outside test code,
literals spanning more than 10 lines number 363, more than 15 lines 199 and
more than 20 lines 149; zed holds 49 of them, nushell 29, ripgrep 21, ruff
18, cargo 15 and bevy 5. Every sampled literal above 20 lines is data: a
shell script, Dockerfile, a 213-line HTML template in cargo's timings, CLI
help or documentation text, a completion template, license text. Samples of
11 to 20 lines mix data with benchmark inputs, templates of generated scripts
and short help text. AgentRig has one multi-line literal outside tests, of
four lines.

## Chosen

A new rule kind `embedded-text` with the repair skill `extract-embedded-text`,
a threshold rule with error above 20 lines and no warning, for Rust only.
One measurement per string literal, plain, raw or byte, at the literal's
first line with the symbol `literal`; its value is the number of lines from
the opening to the closing delimiter, both included. Literals inside macro
arguments are measured, since `format!` and `concat!` carry text as often as
a `const` does. Test code is exempt twice: a literal inside a `#[cfg(test)]`
or `#[test]` item is not measured, and the shipped rule excludes
`**/tests/**` and `**/tests.rs`. Two-phase delivery with a mid-branch pin
(D051).

## Rejected

Threshold 10: the 11 to 20 range holds borderline text that is often
clearer beside its code, and the card speaks of dozens of lines. A warning
level: the sibling size limits are errors, and a hidden warning (D049) would
not move text out of code. Python now: the card defers it, since Python has
no `include_str!` and the repair needs a resource read at run time.
Counting only the content lines between delimiters: the difference is at
most two lines, and the span is the same for every literal form.

## Rationale

The span of a literal is visible in the syntax, and the repair, moving the
text to its own file and reading it with `include_str!` or
`include_bytes!`, is mechanical and keeps the value a compile-time constant.
Twenty lines is half the function budget of 40, the point from which the
sample consists only of data.

## Consequences

A consumer's Rust literal spanning more than 20 lines outside test code
fails lint on `init` and before commit; a project can raise the threshold or
override it per path through configuration. Text built from many one-line
literals or written with escaped newlines on one line stays unseen, and a
test module in a separate file declared with `#[cfg(test)] mod name;` is
measured unless its path matches the exclusion. It ships B073 in full; it
supersedes nothing.
