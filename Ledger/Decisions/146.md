# D146 — Test-only uses do not spend a directory's dependents budget

## Context

B089. The dependents budget of D079 counted every measured edge between directories, so a directory used only by the
tests of another directory gained a dependent. On voxel-rust three of the ten dependents of `src/core/terrain` were
test code only, and the committed budget was raised to cover them. Moving test files into `tests/` directories (D145)
would add more such dependents. The card names test code the way the other rules do: the path patterns of the lint
descriptors and inline Rust modules under `#[cfg(test)]`. It leaves open whether subdirectories of one consumer count
as one dependent. The user's /goal of 2026-11-10 selected B089 with every other Backlog card and left the choices to
the executor.

## Chosen

A measured edge is test-only when its source file matches the lint's test-code patterns, `**/tests/**` or
`**/tests.rs`, in any language, or when its Rust reference lies inside an item the lint already treats as test
context: a module or function marked `#[cfg(test)]` or `#[test]`, found by the same function the lint rules use.
A test-only edge is not counted by the dependents budget, by the dependents named in its finding or by `lint-edges`,
which lists exactly the edges the budget counts (D143). Directory cycles, file fan-out (D121) and feature-type
checks still read every edge. Each subdirectory of a consumer remains a separate dependent.

## Rejected

Dropping test references during extraction: cycles, fan-out and incomplete-analysis findings still need them.

Propagating test status through module declarations, so that any file declared under `#[cfg(test)]` counts as test
code: it needs a second module walk, and D145 already requires such files to live under `tests/` or in `tests.rs`,
where the path patterns apply.

Treating a bare `#[cfg(test)]` on a `use` or other non-module item as test context: the lint's test context does not
recognise it, and a second definition of test code would let the budget and the lint rules disagree.

Counting all subdirectories of one consumer as one dependent: it needs a rule for which ancestor is the consumer,
while each directory already has its own contract and budget, and no acceptance criterion depends on it.

## Rationale

Tests of a directory use what they verify, not what the production code depends on. Counting them made a budget grow
with test coverage and pushed projects to raise it, hiding real coupling. Reusing the lint's own test patterns and
test context keeps one definition of test code across rules.

## Consequences

On voxel-rust the budget of `src/core/terrain` drops from 10 to 7 with or without the D145 move: `src/core/control`,
`src/native/host` and `src/native/storage` reach it only from tests. Budgets of AgentRig itself are unchanged.
Consumers split into subdirectories still spend one dependent per subdirectory, so flattening done for that reason
stays.
