# D032 — Agree feature contracts before autonomous delivery

## Context

The user reports drift from business language to recorded requirements and code,
including agent-invented validation, restrictions and formats. The user wants to
discuss business behavior and acceptance, not code patterns or architecture.
They require showing and revising full cards in chat until approving their
Backlog version, followed by autonomous execution of the selected Plan set.

## Chosen

Use the existing edit-backlog skill as the owner of chat drafting, grounded
requirements, a user journey and criterion-based acceptance. Preserve the shown
version on explicit approval. Every new product outcome passes through agreed
Backlog before Plan. Plan references the same contract and source revision;
execution and verification preserve its wording and criterion IDs.

Reject unsupported behavioral additions. Resolve genuine behavioral ambiguity
before selection; implementation choices remain the agent's responsibility.
Once selected, ready cards execute autonomously without repeated questions.
Record genuine blockers, continue independent authorized work and report gaps.
Acceptance evidence covers each criterion and unsupported behavioral additions.

This supersedes immediate proactive saving of new or revised requirements under
D031 and the D012 route that could introduce a new product outcome directly as a
prerequisite. D031's current-only Plan, unordered Backlog, automatic completed-card
archival and the existing VAC/gate workflow remain. Explicit maintenance remains
independently authorized; this choice does not require a self-referential card.

## Rejected

Treat silence or a saved historical card as agreement; silently turn assumptions
into requirements; require the user to choose code design; rewrite acceptance to
fit code; ask again before each selected card; or build a new approval registry,
runtime semantic validator or mandatory review service for this skill change.

## Rationale

A shared observable contract and explicit differences expose misunderstanding
before implementation. Existing Markdown sections, skills, Git history, hook
guidance and verification workflows already provide the necessary owners.

## Consequences

Update canonical drafting, planning and execution skills and shipped guidance
together. Existing Backlog cards remain unchanged until their revised content is
approved. The structural memory checker remains compatible; it does not prove
semantic agreement, compliance with the skill or absence of all agent errors.
This is an attributed workflow choice, not a new executable invariant.
