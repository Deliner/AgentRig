# D117 — Warn on a std lock guard held across a later `.await`

## Context

B050 (cross-project review, agreed 2026-11-01; selected by the user's /goal
2026-11-07). rustdesk binds a std `Mutex`/`RwLock` guard and then awaits in the
same block, once with the `.await` inside an `allow_err!` macro body. A guard
alive at a suspension point blocks every task that needs the lock, deadlocks a
single-threaded executor and makes the future `!Send`. clippy's
`await_holding_lock` catches it only for clippy users. Without symbol
resolution (D059) the check cannot tell a std lock from an async one, so the
card asks for a warn-level finding. AgentRig's own code is synchronous, so the
candidate lint on the repository stays clean. Adding the detector pushed the
`languages` directory past its 15-entry limit.

## Chosen

A new rule kind `guard-across-await` with the repair skill `release-the-guard`.
A `let` whose pattern is a plain name and whose initializer has no `.await` and
ends in a zero-argument `.lock()`, `.read()` or `.write()` call, optionally
followed by `?`, `.unwrap()`, `.expect(…)` or `.unwrap_or_else(…)`, is a finding
when a later statement of the same block contains an `.await`, also as a token
inside a macro body, before an expression statement `drop(name)`. An `.await`
inside a closure, an async block or a nested function does not count, since it
runs later and elsewhere. Test code and a binding with a `DECISION:` or
`INVARIANT:` reference on the line directly above are not flagged. The symbol
is the bound name.

The descriptor's `Level` parameters gain a default severity, so the kind ships
at `warning` while every existing level rule keeps `error`; the repository rule
sets `level: warning` explicitly. The kind and the skill grow together (I020)
through a two-phase delivery with a mid-branch pin (D051).

`languages` becomes a composite feature: the Rust dispatcher and its detectors
move into a flat part `languages/rust/`, and the measurement record with the
language-neutral measurements shared by the Rust and Python handlers moves
into a flat part `languages/measure/`, so no part uses the root. The `rules` fan-in budget rises
from 7 to 9 for the two new parts that name rule kinds, and the `diagnostics`
budget from 10 to 11 because rule descriptors now name the shared severity
(D079).

## Rejected

Error level: an async-aware guard returned by a custom `lock()` without `.await`
would block the gate with no way to tell it apart syntactically. Matching
`read`/`write` calls with arguments: `file.read(&mut buffer)` is I/O, not a
lock. Flagging `let _ = …lock()`: the guard drops at once. Tracking a guard
moved into another binding or returned from a helper: needs data flow beyond
the card. `block_on`, `spawn` and `join` variants: rejected in the card. A
string default level: a second representation of the severity vocabulary.
Keeping the detectors in the root with a raised directory limit: the limit is a
hard policy, and the detectors form a separate responsibility.

## Rationale

The binding, the block and the `drop` are all visible in syntax, so the rule
needs no types and stays near-zero false positive among std-lock users; the
warn level covers the remaining ambiguity the card names. One default-severity
field on the existing `Level` parameters reuses the diagnostics severity
instead of a parallel switch. Moving the shared measurement vocabulary into
its own part restores an acyclic directory graph without re-export tricks.

## Consequences

A consumer's non-test async Rust that holds a std lock guard across `.await`
gets a warning on `init` and before commit, visible with `--warnings` (D049),
unless justified by a reference on the line directly above. Every existing
rule keeps its level. It ships B050 in full; it supersedes nothing.
