# D175 — One capability list of the rig's Rust for the rig and Rust projects

## Context

B128 AC7 asks for a short section in the rig's AGENTS.md telling agents to use
every capability of the rig's Rust where it fits, one line per item, so that a
model trained before the release still writes current Rust. Init writes the
same section into a new Rust project's AGENTS.md, and a rig test checks that
the two match. AC5 keeps the version number only in the root
`rust-toolchain.toml` and that section's heading (D173). Lint forbids Markdown
files in Project other than README, AGENTS and SKILL files, and routes long
literals in Rust code into files of their own (D122). Init generates the
delivered AGENTS.md in `project_setup/assets.rs`, and its bundle knows a Rust
project by the Clippy settings it carries.

## Chosen

The section body lives in `Project/project_setup/rust/capabilities.txt`,
embedded at build. Its heading `## Rust MAJOR.MINOR` is built from the rig's
toolchain channel. Init appends heading and body after the generated
instructions in the AGENTS.md of a Rust project; a Python project gets none.
The rig's AGENTS.md ends with the same section under the literal heading. A
test initializes a Rust and a Python project and compares the text from the
`## Rust ` heading to the end of each AGENTS.md with the rig's: the Rust one is
equal and the Python one has none. The impact map runs that test when the
rig's AGENTS.md changes and every test when `rust-toolchain.toml` changes.

## Rejected

Embed the rig's AGENTS.md and cut the section out of it: the product would
depend on a repository instruction file outside Project that bootstrap does
not archive and the worker build signature does not cover. A Markdown asset in
Project: markdown placement forbids it. A Rust string literal: embedded text
belongs in its own file. The heading inside the text file: it would repeat the
version number outside `rust-toolchain.toml`.

## Rationale

The text file is the one source of the delivered list. The rig keeps a copy
because its own agents read only its AGENTS.md, and the test turns any
divergence into a gate failure. Building the heading from the channel keeps
the version in one file.

## Consequences

Changing the list means editing `capabilities.txt` and the rig's section
together. Raising the rig's channel to a new minor version changes the
delivered heading, so the test fails until the rig's heading and list are
revised for that release. Projects initialized earlier keep their AGENTS.md;
init never rewrites it.
