# D154 — `init` completes the project's Clippy file with the AgentRig thresholds

## Context

B104 under D151. Clippy takes thresholds only from a configuration file, never from command-line flags. D132 rejected
rewriting existing configurations and D137 kept `avoid-breaking-exported-api` at its default partly because `init`
would have to write and own a project's `clippy.toml`; D151 removed both grounds. The lists of Rust bans of
2026-11-10 allow at most one `bool` field per struct (II-21) and ask the naming and type checks to cover exported API.
With Clippy 1.98.1, `max-struct-bools = 1` reports 7 structs in the rig and `avoid-breaking-exported-api = false` one
variant name, `Reference::CommentReference`. A probe showed that Clippy reads exactly one file: from the manifest
directory upward, the first directory holding `.clippy.toml` or `clippy.toml`, the dotted name first, with no merging;
`CLIPPY_CONF_DIR` only names the directory of that one file. B104 also asks that gate selection, an `Option` whose
`None` meant a full run, become an enum.

## Chosen

`Project/clippy.toml` holds `avoid-breaking-exported-api = false` and `max-struct-bools = 1`. Clippy reads it for the
rig, and `Project/project_setup/clippy.rs` includes it as the one source of the thresholds that `init` ships.

`init --language rust` finds the file Clippy reads for the manifest of the `clippy` command, the first `.clippy.toml`
or `clippy.toml` from the manifest directory up to the project root. It prepends each missing threshold and keeps the
rest of the file byte for byte; without a file it creates `clippy.toml` in the root. A threshold set to another value
is an init collision reported before anything is installed. The interactive wizard lists the file with the others.

The rig's seven structs with two `bool` fields name their states with enums:

- `Command` and the job record replace `read_only` with `Access` (`ReadOnly`, `Writable`), one type in
  `project_config` instead of three copies; the job record replaces `process_group` with `Grouping`. Commands
  configuration and job records keep their boolean `read_only` and `process_group` fields through serde callbacks.
- `Observation` replaces the merge and rebase flags with `operation: Option<Operation>`; a rebase wins when both
  markers exist, and `resume` reports `vcs.operation` as `null`, `merge` or `rebase`.
- The check evidence record replaces `revision_export`, `staged` and the optional fingerprint with `source`:
  `worktree`, `index` with its fingerprint, or `revision`. Older `checks.json` files read as `worktree`, so an older
  index or revision record is not current evidence and its gate runs again.
- The architecture dependency replaces `module_declaration` with `Relation` (`Declaration`, `Use`), the lint output
  replaces `json` and `validate_only` with `Format` and `Mode`, and the reminder returns a context reset from `advance`
  instead of keeping it in `Progress`.

`Reference::CommentReference` becomes `Reference::Comment` and keeps the configuration name `comment-reference`. Gate
selection returns `Scope` with `Full` and `Only(targets)`.

## Rejected

`CLIPPY_CONF_DIR` pointing at a rig file: Clippy would then ignore the project's own file, so `init` would still have
to merge both into a copy that drifts from the project, and a catalog command has no environment field.

Writing a second file beside an existing one or replacing it: Clippy reads one of them and warns about the other, and
a replaced file loses the project's settings.

Keeping a project's different value: the rig's threshold would not apply, against B104 AC3.

Changing the stored `read_only` and `process_group` booleans to variant names: existing configurations and the records
of running jobs would fail strict parsing.

## Rationale

The thresholds belong in the one file Clippy reads; completing that file keeps a project's settings and makes the
rig's apply. An enum names each state the code allows, so an impossible pair of flags cannot be written.

## Consequences

A struct with a second `bool` field fails the `clippy` check in AgentRig and in new Rust projects, and
`enum_variant_names`, `upper_case_acronyms`, `wrong_self_convention`, `box_collection`, `vec_box` and
`redundant_allocation` also check exported API. A member crate with its own Clippy file shadows the completed one for
its sources. Existing projects keep their configuration because `init` has no update path. The architecture analyzer
does not resolve serde `with`, so the callbacks are named by `deserialize_with` and `serialize_with`.

D154 supersedes D137's choice that `avoid-breaking-exported-api` keeps its default and re-decides the alternatives
that D151 reopened in D132, rewriting an existing configuration, for the Clippy file, and in D137, `init` writing a
project's `clippy.toml`; the rest of D132 and D137 remains.
