# D115 — Cover debug-gated asserts, the `_err` unwraps, `resume_unwind` and panic catches

## Context

B048 (cross-project review, agreed 2026-11-01; selected by the user's /goal
2026-11-07). bevy wraps `assert!` in `#[cfg(debug_assertions)]` or
`if cfg!(debug_assertions)`, a `debug_assert` in disguise that `debug-assertion`
(D084) misses because it matches only `debug_assert*!` names. `panic-path`
(D082) lists `unwrap` and `expect` but not `unwrap_err`, `expect_err` or
`resume_unwind`. `catch_unwind` and `AssertUnwindSafe` carry no justification
requirement, though catching a panic and vouching for unwind safety let a bug
continue on state the panic left half-updated. AgentRig's own code uses
`unwrap_err` only in tests and has no `catch_unwind` or debug-gated assert; the
candidate lint on the repository stays clean.

## Chosen

AC1 extends `debug-assertion`: an `assert!`, `assert_eq!` or `assert_ne!` is
flagged like a `debug_assert*!` when the macro, its statement or an enclosing
item carries a `cfg` attribute whose predicate requires `debug_assertions`
(directly or through `all`/`any`, as the test-context walk already decides for
`test`), or when it sits in the then-branch of an `if` whose whole condition is
`cfg!(debug_assertions)`; the predicate walk in `test_context.rs` becomes one
flag-parameterized owner for both `test` and `debug_assertions`. AC2 extends
`panic-path` with the methods `unwrap_err` and `expect_err` and with
`resume_unwind` called through a path or a bare name, in source and in macro
bodies like the existing calls. AC3 adds the rule kind `unwind-justification`
and the repair skill `justify-unwind`: a call whose path or bare name ends in
`catch_unwind` or `AssertUnwindSafe`, or whose method is `catch_unwind`, outside
test code without a `DECISION:` or `INVARIANT:` reference on the line directly
above is a finding, with the callee as the symbol. All three use the existing
justification and test-context mechanisms. The kind and the skill grow together
(I020), so delivery is two-phase (D051): the inert kind, detector and tests with
the AC1/AC2 extensions first, a mid-branch pin, then the catalog, capability,
repository rule, skill and shipped asset.

## Rejected

A plain `assert!` as a panic path: it is the idiomatic release contract.
Evaluating any condition that merely mentions `cfg!(debug_assertions)`, such as
`cfg!(debug_assertions) && ready`: the card names the direct gate, and partial
evaluation of boolean conditions would widen the syntax the check must
interpret. A separate tier for blocking calls in `Drop` and a word count on
`.expect` messages: rejected in the card. Folding panic catches into
`panic-path`: the repair differs — a catch is legitimate at a boundary that must
not unwind, where an unwrap has a recoverable alternative — so a separate kind
and skill keep each repair exact. Matching `UnwindSafe` trait bounds or types:
only the construction of `AssertUnwindSafe` vouches for a particular value.

## Rationale

Each extension adds a name or a context to an existing syntactic check, and the
new kind reuses the line-above justification, so the gate stays near-zero
false positive without type information (D059). One flag-parameterized `cfg`
walk replaces a `test`-only copy instead of duplicating it for
`debug_assertions`.

## Consequences

A consumer's or this repository's debug-gated assert, `unwrap_err`,
`expect_err`, `resume_unwind`, `catch_unwind` or `AssertUnwindSafe` in non-test
Rust becomes a gate error on `init` and before commit unless justified by a
reference on the line directly above. D082 and D084 keep their statements and
owners. It ships B048 in full; it supersedes nothing.
