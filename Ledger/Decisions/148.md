# D148 — panic-path measures panics inside macro_rules! bodies

## Context

B097. panic-path (D082) measured panics in parsed source and, through D094, in macro invocation arguments that parse
as expressions. A `macro_rules!` body is a token tree, so `.unwrap()`, `panic!` and the other forms inside it were never
measured, while unsafe-justification (D103) already flags unsafe tokens there. On voxel-rust at `71440d0` the installed
runtime reported nothing for `writeln!(…).unwrap()` in `src/exports/typescript.rs` and `values.next().unwrap()` in
`src/schema/abi/records.rs`, both inside `macro_rules!` bodies of shipped code. The user's /goal of 2026-11-10 selected
B097 with every other Backlog card and left the choices to the executor.

## Chosen

panic-path scans the tokens of every token tree inside a `macro_rules!` definition. Within one tree, `.` followed by
`unwrap`, `expect`, `unwrap_err` or `expect_err` and a parenthesized token tree is a method panic; `resume_unwind` not
preceded by `.` and followed by a parenthesized token tree is a panic call; `panic`, `todo`, `unimplemented` or
`unreachable` followed by `!` and a token tree is a panic macro. Each one is reported on the line of its name token and
is justified as in ordinary code: a reference on the line directly above that token, a referenced Clippy allow on an
enclosing item (D147), or test context. Test context now also includes a `macro_rules!` definition marked
`#[cfg(test)]` or `#[test]`, besides test modules and functions. Macro invocation arguments keep the D094 re-parse;
their token trees are not scanned again.

## Rejected

Re-parsing a macro body as Rust like invocation arguments: metavariables and `$(…)*` repetitions do not parse, so most
bodies would be skipped silently.

Scanning every token tree, including invocation arguments: the arguments that parse would be measured twice, and the
token scan sees less structure than the re-parse.

Requiring a bare macro name as `panic_macro` does for parsed source: inside a body `std::panic!` and `$crate` paths
are common, and the token after the path is the macro name in either case.

## Rationale

A panic written in a macro body reaches shipped code at every expansion and needs the same justification as one
written directly. The token patterns match the method, call and macro forms panic-path already measures without
attempting to expand the macro.

## Consequences

On voxel-rust the candidate reports the two unwraps above, and the installed runtime none. AgentRig has no
`macro_rules!` in shipped code and gains no findings. A panic form split across token trees or produced by a nested
macro expansion stays unmeasured.
