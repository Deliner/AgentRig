# D195 — AGENTS.md and CLAUDE.md carry one text, checked by a same-text lint rule

## Context

B148: `init` wrote `AGENTS.md` for Codex and `.claude/CLAUDE.md` holding the single line `@../AGENTS.md`, through which
Claude Code imports the rules; the rig did the same. The user asked for both files to be generated with the same
content and for a commit check that they have not drifted apart, as in a production setup where both files lie at the
root and a check fails the commit when they differ, and chose two files with a check over the import.

## Chosen

`init` writes `CLAUDE.md` at the root as a byte copy of the final `AGENTS.md` and no longer writes `.claude/CLAUDE.md`,
so Claude Code reads the rules once; the rig keeps the same pair. A `same-text` lint rule reports every selected file
whose bytes differ from the first selected file in path order; the `init` catalog selects `AGENTS.md` and `CLAUDE.md`,
so the commit gate's lint fails while they differ and names the condense-markdown skill, which says to merge the
intended edits of both into one text and write it to each.

## Rejected

| Alternative | Why |
| --- | --- |
| Keep the `@../AGENTS.md` import | the user chose two files with a check |
| Link `CLAUDE.md` to `AGENTS.md` symbolically | a link is not a file both agents read the same way on every platform and checkout |
| Regenerate `CLAUDE.md` from `AGENTS.md` at commit | an edit made only in `CLAUDE.md` would be overwritten instead of reported |
| A project command check comparing the two files | each project would carry its own script; a lint kind is portable and names its skill |
| A separate repair skill for the rule | the condense-markdown skill already owns the rule files of both agents |

## Rationale

Two identical files let each agent read its own file without an import or a link, and a lint rule makes the identity
a commit condition with the same diagnostics, skill path and configuration as every other rule.

## Consequences

An agent edits `AGENTS.md` and `CLAUDE.md` together; a commit with only one of them changed fails until both carry one
text. The rule only compares, so a project may select other files that must stay identical.
