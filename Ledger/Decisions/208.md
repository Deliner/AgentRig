# D208 — Report a filter by a known flag on a computed value

## Context

B164 under D151. The voxel-rust review at `2304625`, template 5, found `call(..).filter(|_| flag)` in eleven places:
the call runs even when the flag is false and its result is thrown away. In two of them the discarded work is real, a
session clones a save batch (`src/host/session/dispatch.rs:199`) and lighting walks an array
(`src/core/light/bricks.rs:98`). The card asks for a lint error on `.filter(|_| name)` on the result of a call and a
skill that checks the flag first with `if flag` or `flag.then(..)`. It leaves to the executor which calls count as
cheap and stay unreported, naming `as_ref`, `as_mut` and `get`, and notes that `Iterator::filter` differs from
`Option::filter`. The rig's own code uses the form too.

## Chosen

A Rust kind `outer-flag-filter` at level error with the repair skill `check-the-flag-first`. It reports a `.filter(..)`
method call whose receiver contains a call expression and whose sole argument is a closure with the single parameter
`_` and a body that contains no call expression. Test code is included. A `DECISION:` or `INVARIANT:` reference on the
line directly above lifts a finding. The kind enters the runtime first, is pinned (D051) and is then enabled in the
rig's `lint.yaml`, the catalog and init with its skill, together with the repair of the rig's own sites.

No call counts as cheap. A receiver containing any call is reported, a method call through a chain or `?` included.
The receiver's type is not resolved: an `Option`, a `Result` turned into one and an iterator are reported alike,
because in each the flag decides the whole result before any value is looked at, and the skill gives the repair for
each.

## Rejected

- Leave cheap calls such as `as_ref`, `as_mut` and `get` unreported: the rig resolves no types, so it cannot tell the
  std accessor from a project's own method of that name, nor see the work in its arguments or in the receiver before
  it; the review counted the cheap sites in its eleven; and the flag checked first is no less clear for a cheap call.
- A configurable list of cheap methods: a second policy per project for one form, and a project would list its own
  accessors to keep the form.
- Report only a body that is a bare name, as the card writes it: `|_| !flag`, `|_| state.flag` and a comparison of
  names are flags known before the call just as well, and a rename into a name would evade the rule.
- Report a body that calls: then the flag costs work too, and which of the two runs first is a trade-off the form does
  not decide.
- Report a closure with a named or typed parameter that is unused, such as `|_value|`: the card names `|_|`.
- Exclude test code, as most standard-form kinds do: the card reports the form without that limit, as D205 did.

## Rationale

A filter whose closure ignores its value is a branch on a flag written after the value it guards, so the value is
computed, and cloned, walked or loaded, before the flag can throw it away. Checking the flag first runs the call only
when its result is kept. A flag computed without a call costs nothing to check first, so the repair never adds work.

## Consequences

The rig's sites are rewritten to check the flag first when the kind is enabled. In voxel-rust the kind reports the
review's sites with a call receiver, the cheap accessors among them; the sites whose receiver is a field or a binding,
and those whose flag calls, stay unreported. A named unused parameter evades the kind and is left to review.
