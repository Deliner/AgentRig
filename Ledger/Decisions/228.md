# D228 — Rule kind `entry-bypass` reports uses of another directory past its entry

## Context

B178. On 2026-11-20 the user said that what is needed from a feature, the feature gives through its API, checked on
every level, and that tests are checked too and test only through public entries. D043 had removed the contract
fields `public`, `allow` and `deny` together with their check; they do not return, since the entry file serves as
the way in. D057 kept the access of tests to a public surface a review norm; the user turned it into a check. A
measurement of the rig found 289 pairs of files past an entry in working code and 159 in tests. The user also said
that only the file the rig requires is an entry, a project adopting the rig conforms to it, and the `fan_out` and
`dependents` budgets change with the delivery without separate agreement.

## Chosen

- A policy kind `entry-bypass` with target `directory`, default level error, repair skill `go-through-entry` and no
  exception. It reads the dependencies that the enabled directory-architecture rules resolve, and the configuration
  check refuses an enabled `entry-bypass` without one.
- A use counts when its source lies in a selected directory, test code included, and its target is a Rust or Python
  source, `.rs`, `.py` or `.pyi`. Module declarations and the packages a Python import initializes (D227) are not
  uses, and neither is an embedded resource such as an `include_str!` text.
- From the deepest directory that holds both files the check walks toward the target. The first directory on the way
  that is not a group is the boundary: the use passes only when the target is that directory's entry `mod.rs`,
  `lib.rs`, `main.rs` or a file with the stem `__init__`. A directory without such a file is closed to every outside
  use. A use within the source's own directory or a directory above it passes.
- A directory contract may declare `group: true`. A group has no boundary of its own: its files are open, and each of
  its subdirectories has its own boundary. Without the field a directory is ordinary. The rig declares
  `Project/shared` a group.
- The finding stands at the using line and names the target, the crossed directory and its entries.
- The agent sets the `fan_out` and `dependents` budgets by measurement in the same delivery and reports the numbers
  before and after.
- `init` delivers the rule and the skill to Rust and Python projects. Delivery takes two phases with a mid-branch pin
  under the user's consent (D226); until the repository configuration names the kind, `init` leaves it out (I023).

## Rejected

- Returning the `public`, `allow` and `deny` fields of D043: the entry file already states the surface, and a second
  list could disagree with it.
- Accepting `foo.rs` beside `foo/` as an entry: the rig forbids it through Clippy's `self_named_module_files`, and the
  user named only the four entry files.
- A separate rule that a subdirectory does not take from above: when an entry exposes its subdirectory and that one
  takes from its parent, the directory cycle check already reports it.
- Checking what an entry opens: an entry that opens everything passes, and the skill forbids it.
- Counting embedded resources: an embedded text is data of the file that embeds it, and a directory of texts has no
  module entry to go through.

## Rationale

The inside of a directory can be rebuilt without editing its consumers and their tests, and everything it promises
to other directories is seen in one file.

## Consequences

Each use past an entry blocks the commit until it goes through the entry or the work moves to its owner. A test of a
directory's inside moves into that directory's `tests/`. Files of a group stay open, so a group must consist of
independent parts.
