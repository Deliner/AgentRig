# D138 — config-check inspects a check's affected map only on files its include selects

## Context

B085. On 2026-11-09 the user selected B085 for execution while voxel-rust moved to the current AgentRig. voxel-rust
has two checks running `cargo test`: `tests` runs the library tests without features and its include covers
src/core, src/render, src/schema and the build files; `native-tests` runs `cargo test --features native --lib`. The
tests in src/native/game.rs, hardware.rs, worker.rs and src/native/storage/tests.rs compile only with the `native`
feature. D124 inspected every inventory file with the runner's extension against every inspected check, ignoring the
check's include, so it required targets of `tests` to select those four files. The only passing map gave `tests`
targets that select nothing under its own command.

## Chosen

`config-check` applies the D124 coverage inspection of a check only to the inventory files that the check's include
matches. A file outside the include gives that check neither the error for a file matched only by groups without
targets nor the error for an unselected test. A test file inside the include that no target selects is still
reported. A check whose include is the default `**` inspects every file as before. The gate's affected selection does
not change. The rest of D124, including the module prefix derived from the nearest `lib.rs`, else `main.rs`, remains.

## Rejected

Asking voxel-rust to keep targets that select nothing: a map that passes `config-check` while describing no real
selection. A new field naming the files whose tests a check must select: the include already states which files the
check concerns. Compiling the include globs again in `project_setup`: lint refused it as a 14th dependent of
`shared/paths` over its budget of 13, as D124 foresaw for the group globs, so the gate owns the include matching that
its check skipping already used.

## Rationale

The include is the check's own statement of the files it concerns; the gate skips a check only when no repository file
matches its include. A file the check does not concern cannot be a coverage gap of that check.

## Consequences

Projects with separate test checks per feature set pass `config-check` with honest maps. A test file outside every
inspected check's include is not reported by any check. The gate does not filter changed paths by include, so a
changed file outside the include still passes through the check's groups; one matched only by groups without targets
selects no tests for that check and is no longer reported. It refines D124 only in which files are inspected and
supersedes nothing else.
