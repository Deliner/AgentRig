# D119 — Error on manual order and equality that read different fields

## Context

B068 (research rounds 4–5: 9 sites in 19 repositories, 7 of 7 confirmed blind
as std contract violations; selected by the user's /goal 2026-11-07, which
leaves the trigger condition, level and kind name to delivery). The standard
library requires `a == b` exactly when `a.cmp(&b) == Equal`; otherwise
`BTreeSet`, `BTreeMap`, sort with dedup and binary search disagree with `==`.
The compiler does not check it and clippy only checks a derive paired with a
manual impl. The research probe erred on a cache field excluded from the order
and on delegation through a shared key method. On the r8 corpus, 125 Rust
files with a manual `Ord` or `PartialOrd` yield 10 findings, all contract
violations: the 6 known sites in bevy `polygon.rs:128`, `examples.rs:27`,
`features.rs:18`, meilisearch `score_details.rs:751` and nushell
`symbols.rs:40`, `deps.rs:193`, and 4 new ones in nushell
`nu-experimental/src/lib.rs:229` and zed `client/src/user.rs:80`,
`gpui/src/tab_stop.rs:52`, `language/src/syntax_map.rs:2056`, the last with an
`eq` that always answers false. Several are latent because a compared field is
unique by construction. The known uv `request.rs:843` is missed: its `cmp`
reads every field, some only as context.

## Chosen

A new rule kind `ord-eq-mismatch` with the repair skill
`align-order-with-equality` in the `signature` skill group, shipped at
`error`. The ordering impl of a type is its manual `Ord`, or its manual
`PartialOrd` when the file has no manual `Ord` for it, so a `partial_cmp` that
delegates to `cmp` is not reported twice. The set of `self` fields its `cmp`
or `partial_cmp` reads is compared with the equality set: the fields read by
the `eq` of a manual `PartialEq`, or every named field of a struct deriving
`PartialEq` in the same file. Reads follow `self.method()` calls into methods
of the same type defined in that file, so one key method and a delegate are
seen through. A comparison is skipped when a `self` use is neither a field
read nor such a resolvable call: a bare `self` argument, a match on `self`, a
method defined elsewhere, `self` inside a macro. An impl of a trait with type
arguments, such as `PartialOrd<i32>`, is not the same-type contract. A tuple
struct, and a type whose equality is not visible in the file, are skipped.
The finding sits on the ordering impl line with the symbol
`Type: equality-only a, b; order-only c`. Test code is excluded, and a
`DECISION:` or `INVARIANT:` reference on the line directly above the impl
justifies a deliberate difference such as a cache field. The detector runs
once per file at its root. Two-phase delivery with a mid-branch pin (D051).

## Rejected

Warning level: the corpus shows no false positive, and an intended difference
should carry a recorded reason. Comparing a partially unresolved set: every
key method from another file would be flagged, the probe's error. Comparing
expressions such as `a % 10` against `a`: field sets cannot see them (D059).
Exempting `PhantomData` or cache-named fields by name: not seen in the corpus,
and a cache is justified by a reference. `Hash` against `Eq`: clippy covers
the derived form and the manual form had no sites after the cache twin.

## Rationale

Field sets, `self` method calls and derives are visible in one file's syntax,
and refusing to compare what the file does not show keeps the corpus result at
no noise. Error level enforces the recorded reason the card asks for.

## Consequences

A consumer's non-test Rust type whose manual order and equality read
different fields fails lint on `init` and before commit unless justified by a
reference on the line directly above the impl. Equality by expression and
reads through other files stay unseen. It ships B068 in full; it supersedes
nothing.
