# D230 — A merged branch requires the agent to compact its context

## Context

B203. After `just feature-merge` the details of the merged branch live in Git, the archived cards and State, while
the agent's context still carries them into the next task. On 2026-11-22 the user asked the rig to require the agent
to compact its context after a branch is fully merged, and answered «требовать» when offered a reminder instead.
Claude Code compacts on the user's `/compact` or through the tool of the user's mod `self-compact`; Codex compacts only
on the user's `/compact` or automatically. Both agents start a session with source `compact` after a compaction, and
the rig's hook registration already receives that event. A command that the agent runs receives no session identity.

## Chosen

- A `feature-merge` that merges records the requirement `compaction` in the runtime directory and ends its output
  with one instruction: compact the conversation before the next task, keeping the user's standing instructions, open
  questions, the merged branch and the next step, through the tool `mcp__self-compact__compact` with those
  instructions and the next step as its resume hint, or else end the turn and ask the user to type `/compact`. A merge
  that fails records nothing, and a merge the user runs from a terminal records it too.
- While the requirement exists, the agent hook refuses every tool call with the same instruction. When it cannot read
  the requirement, it refuses with the cause. The tool `mcp__self-compact__compact` always passes: it neither runs
  commands nor writes files.
- A session start with source `compact`, `clear` or `startup` removes the requirement; `resume` and Codex `fork` keep
  it, since their context is the one before. A removal that fails is reported in the session context.
- The record is closed to agents like the other runtime records of the hook and the approval.

## Rejected

- A reminder that does not refuse: the user chose to require compaction.
- Detecting the merge in the hook after the tool call: it needs another registration, the agents report failed calls
  differently, and a merge from the user's terminal would escape it.
- A requirement per session: the merge command does not know the session that called it.
- Lifting the requirement on the agents' compaction events: both agents already report a compaction as a session start
  with source `compact`, which the hook receives.
- Letting the compaction tool pass only while compaction is required: the tool neither runs commands nor writes files,
  so refusing it at other times protects nothing.

## Rationale

Each next task starts with a short context. The merge owns the moment of success, the hook owns refusal, and the
session start owns the moment the context is renewed, so each part acts where the fact is known.

## Consequences

Without the compaction tool the agent stops after every merge until the user types `/compact`, an autonomous Plan run
included. The requirement belongs to the working copy: two sessions in one copy both receive it, and a compaction,
`/clear` or new session in either lifts it for both.
