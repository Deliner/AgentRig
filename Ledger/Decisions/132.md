# D132 — `init` ships the dev-gate Clippy profile to new Rust projects

## Context

B082. On 2026-11-07 the user asked for a separate card on Clippy delivery: the AgentRig linter serves new projects
that write AI-first, agent-native, cross-platform Rust maintained for 20 years, and AgentRig verifies it by
dogfooding. D060 kept the Clippy profile, later extended by D068, D107, D109, D127 and D129, in
`.agentrig/commands.yaml` as this repository's dev gate, because the `init` template shipped no external tools.
`init --language rust` created the commands `read`, `write` and `test` and the checks `lint`, `memory`, `tests` and
`tools`, so a new Rust project ran no Clippy at all, although its `test` command already runs `cargo` on the manifest
`init` finds.

## Chosen

`init --language rust` writes a `clippy` command, `cargo clippy --manifest-path <test manifest> -- -D warnings`
followed by `-D clippy::<lint>` for each of the 23 lints of the dev-gate profile, built in
`Project/project_setup/clippy.rs`, and a `clippy` command check with the `repair` skill and the source include of the
`tests` check, last in the check order. `test_clippy_profile.py` fails when a lint is in only one of the shipped and
dev-gate lists. `init --language python` writes neither. The interactive wizard offers the checks the scaffold
generated, so a Rust project lists `clippy`.

## Rejected

Pinning the toolchain as the dev gate does with `+1.98.1`: a consumer project chooses its own toolchain. `--locked`
and `--all-targets`: neither the shipped `test` command nor the dev gate uses them, so tests stay outside the profile.
Dropping `print_stdout`, `print_stderr` and `exit` from the shipped set: a project prints and exits through one owner
with a justified `#[allow]`, as `shared/console` does in AgentRig (D109). Reading the list from
`.agentrig/commands.yaml` at build time: the dev-gate configuration is not a product source, and one test keeps both
lists equal. Rewriting existing configurations: `init` has no update path.

## Rationale

The profile catches panics, debug output and defect classes that need types, which the structural linter cannot see
without type inference (D059). A new project gets it from its first commit, and dogfooding keeps the shipped set the
one AgentRig itself passes.

## Consequences

In a new Rust project `check` runs Clippy after `tests` and `tools`. A `Some(1).unwrap()` fails the `clippy` check;
because `lint` runs first and stops the gate, the full `check` reports the same line as `panic-path` before Clippy
runs. Lint names follow Clippy 1.98.1, and an older Clippy may reject an unknown name. A lint added to the dev gate
must also be added to `clippy.rs`, or the test fails. It supersedes the dev-gate-only scope of D060 and the same clause
of D068, D107, D127 and D129; their deny sets and the rest of their choices remain.
