# D056 — Flat-memory registry size policy for the Backlog archive

## Context

D050 moves the Backlog row and card of each completed outcome to
Ledger/Archive/Backlog, which now holds eleven indexed BNNN cards and keeps
growing as outcomes complete, already exceeding the directory-size warning of
ten and heading for the error limit of fifteen. The memory validator fixes each
archived idea at exactly Archive/Backlog/NNN.md. D029, D030 and D048 already
exempt Ledger/Plan, Ledger/Backlog and Ledger/Archive/Plan for the same flat
indexed representation.

## Chosen

Apply the existing numeric directory-size exemption to Ledger/Archive/Backlog,
limited to that exact directory and referenced from the lint configuration.
Keep memory indexing, required sections and file-size policy for every archived
card.

## Rejected

Raise the general limits; exclude the entire Ledger; move archived cards into
nested paths the validator does not accept; merge independent archived ideas to
fit the limit; or delete completed cards whose agreed contracts Archive must
preserve.

## Rationale

The Backlog archive's layout is fixed by the authoritative memory contract and
has one responsibility: retaining the agreed contracts of completed outcomes.
Its entry count measures how many outcomes were completed, not source cohesion.
The same reasoning that exempts Backlog and the Plan archive applies here.

## Consequences

Archiving a completed outcome's Backlog card is no longer blocked by registry
length. Source directories keep the numeric limits. Reassess this exception
together with D029, D030 and D048 if the memory format later permits a
meaningful nested archive layout.
