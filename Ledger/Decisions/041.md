# D041 — Develop the worker under Project

## Context

D025 kept the worker under tooling/worker and reserved Project for consumers and
examples. On 2026-10-26 the user asked to move all code that initializes the
system into Project and develop AgentRig on its own layout (Requests.md, part 2,
items 3–4). D040 makes Project the default source directory of an initialized
repository.

## Chosen

The Rust crate, embedded assets, examples and the Python verification harness
live under Project, the source root of this repository. tooling keeps only the
development launchers (tooling/worker/build and run) and distribution. This
supersedes D025's placement; D025 keeps only lint ownership as a portable
capability with an independent CLI.

## Rejected

Keep the worker under tooling/worker; also move the launchers and release
scripts into Project; rename Project to describe the worker.

## Rationale

The repository then has the layout it gives consumers, so its own development
exercises that layout. Launchers and release scripts serve development of this
repository, not the product, so they stay outside Project.

## Consequences

Python tests import Project.src and run from Project; the candidate build reads
Project/Cargo.toml. Bootstrap archives the pinned revision's tooling/worker
until a revision with this layout is pinned, then it must archive Project.
Decision links name Project paths.
