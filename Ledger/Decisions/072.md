# D072 — Reject generic dumping-ground directory names

## Context

B031 (cluster 6 of the quality set, agreed 2026-10-29) asks that names reflect
responsibility rather than hide a dump, and specifically to restore a mechanical
rule against dump names (6.1). The `refactor-large-directory` norm already states
that "reuse alone does not justify shared/common/utils buckets", but nothing
enforced it mechanically, so a dumping-ground directory passed the gate. A
directory's name is decidable from the inventory alone, with no symbol or type
resolution (D035).

## Chosen

Add a `dump-name` rule kind (target directory, error level): a directory whose own
basename is one of a small fixed set of generic dumping-ground words — `utils`,
`helpers`, `misc`, `common` — is a finding. `shared` is deliberately not in the
set; it is the legitimate home for genuine cross-feature leaves. The measurement
reads the directory basename from the inventory and adds no language handler. The
repair skill is the existing `refactor-large-directory`, which already rejects
reuse buckets, so no new skill is added and the delivered skill set is unchanged
(I020); only the rule-kind set grows. The kind ships to consumers through
`catalog::ALL` and the delivered per-kind config template, with a repository rule
scoping it to `Project`.

## Rejected

A config-glob rule over the existing `forbidden-file` kind: it flags every file
inside a dump directory (one finding per file, not the name), and a
repository-specific rule does not reach the delivered per-kind template, so the
capability would not ship to `init`. A fuzzy or larger word list (`util`, `core`,
`stuff`, `temp`): higher false-positive risk against the near-zero-false-positive
bar (D035) — `core` and singular forms are common legitimate names. A new repair
skill: `refactor-large-directory` already owns this guidance. Checking file stems
as well as directories: the norm and the smell are about containers, so file-stem
checking is an unneeded extension.

## Rationale

A directory whose whole name is one of these four words is an unambiguous bucket,
so it meets the high-signal, type-free bar for the gate (D035). A small fixed set
keeps the check decidable and near-zero-false-positive — this repository has no
such directory — mirroring the fixed-set philosophy of the hardcoded-secret rule
(D067) and the placeholder-purpose check (D070). Reusing the existing skill is the
lowest sufficient rung.

## Consequences

A consumer's or this repository's directory named `utils`, `helpers`, `misc` or
`common` becomes a gate error on `init` and before commit; `shared` and
responsibility-named directories pass. It mechanizes the `refactor-large-directory`
norm and extends the fixed-set approach of D067/D070. The delivered skill set is
unchanged and only the rule-kind set grows (I020). It supersedes nothing.
