# D201 — The hook allows a just command only as the shell and just will run it

## Context

B153 AC1–AC4, from the audit of 2026-11-19. zsh runs code inside an allowed command before just starts:
`just read -- cat =(touch x)` and `just read -- ls *(e:'cmd':)` passed, because the hook looked only for `;|&<>`, a
newline, a backtick and `$(`. Any file named `just`, such as `./x/just`, passed as the first word. The hook let the
`lint*`, `jobs` and `job-*` recipes through unchecked, and just reads a further word after a recipe without parameters
as a second recipe, so `just jobs bootstrap` ran `bootstrap` too. `job-start NAME` runs a catalog command, but the hook
gave it neither the catalog checks nor the write routes of `run NAME`. The runtime took `--root` from anywhere in its
arguments, so `just read cat --root /tmp/e x` read the catalog of `/tmp/e`.

## Chosen

The shell guard refuses an unquoted `(`, which opens every zsh form that runs code before just: `=(…)`, `<(…)`,
`>(…)`, a glob qualifier, a subshell and arithmetic. Inside double quotes it refuses `$(`, a backtick and `${(`, whose
flags such as `(e)` evaluate the expansion. The same text in quotes stays text and passes. The first word must be
`just` itself, which the shell finds by name.

The hook resolves the recipe through the recipe table `init` generates. A recipe without parameters takes no further
word, and a bare `just` names no recipe; both are refused. `run NAME`, `job-start NAME` and the recipes that run a
catalog command get the catalog checks and the written-path routes of that command; a word outside the table names a
catalog command, as the rig's `bootstrap`, `candidate` and `release` do. `check` and `feature-start` keep their
argument checks, and the other recipes hand their words to the runtime command that parses them.

Every generated and rig recipe passes `--root .` to the runtime before the agent's words. Just runs a recipe in its
justfile's directory and the runtime takes the first `--root`, so an agent's `--root` cannot move the project.

## Rejected

| Alternative | Why |
| --- | --- |
| Refuse every unquoted expansion character, such as `*`, `{` and `$` | they change words but run no code, and agents read globbed paths |
| Refuse `(` inside double quotes as well | `"=(touch x)"` is text, and AC1 requires quoted text to pass |
| Ask just for each recipe's parameters on every hook call | the generated table already owns them and needs no second process |
| Refuse a repeated `--root` in the option parser | the recipe's `--root` comes first, so a later one never selects the project |
| Put the agent's words after `--` in each recipe | every runtime option parser would then have to skip `--` |

## Rationale

Code runs before just only through a parenthesis or a substitution, so refusing those characters outside quotes closes
the forms the audit found and keeps quoted arguments usable. The recipe table already decides which recipes forward
words, so the hook reads that owner instead of keeping a second list. Fixing the root in the recipe keeps the runtime's
option parsing unchanged.

## Consequences

An agent quotes a parenthesis that is meant as text. A recipe added to the table needs only its table entry, while a
recipe outside it must be a catalog command whose `accepts_args` matches its just parameters. Globs, braces and
variables still expand before just, so the hook sees their unexpanded text; they run no code.
