# D026

## Context

The user selected AgentRig and explicitly required YAML configuration without a TOML fallback. P004 also requires reusable configuration packages and explicit migration of installed worker environments.

## Chosen

Use strict YAML as AgentRig's sole configuration format. Composition belongs to explicit AgentRig package semantics, not YAML anchors, aliases, tags or merge keys. Reuse one typed decoding boundary with source/field diagnostics. Legacy TOML is read only by explicit migration; external tool settings and machine protocols retain their own formats.

## Rejected

Keeping TOML as a runtime fallback, supporting two equivalent project formats indefinitely, silently coercing scalar types, or using YAML's own inheritance constructs alongside AgentRig composition.

## Rationale

This follows the user's selected configuration interface and gives composed settings one interpretation across setup, lint, review and delegates. Explicit conversion separates historical installations from current execution.

## Consequences

D016's TOML format choice is superseded; its identity and detail remain historical. Configuration, templates, fixtures and current guidance move together. Migration preserves policy values and provides reviewed preimages for recovery; differences in formatting/comment handling must be visible. P004 remains incomplete until all loaders, composition, setup and migration meet their acceptance.
