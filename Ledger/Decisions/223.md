# D223 — Tests live only in `tests/` directories, in Rust and Python

## Context

B179. On 2026-11-20 the user asked why a `tests.rs` file may lie among the files of a directory, said that tests need
a separate directory and that the same rule applies to Python, and selected B179 with B175 to B178 for autonomous
delivery. D145 accepts both `tests.rs` and `tests/` as test positions, and the lint test-code patterns `**/tests/**`
and `**/tests.rs` exempt both from the rules and, through D146, from the dependents budget. The rig had nine
`tests.rs` files, fifteen `tests/` directories and no Python test file outside `tests/`; P168 moved the nine files to
`tests/mod.rs` before changing the rule.

## Chosen

- `test-placement` covers Rust and Python. A Rust file named `tests.rs` and a Python file named `test_*.py` or
  `*_test.py`, the names pytest collects by default, yield one finding at line 1 naming the file when no component of
  its path is `tests`. Each language handler names its test files.
- A Rust test-only `mod` declaration without a body counts as placed only when an enclosing inline module is named
  `tests` or a component of its `#[path]` value, or of its module name without one, is `tests`; `tests.rs` no longer
  places it. The rest of D145's declaration measurement remains.
- The lint test-code patterns are `**/tests/**` alone: in the shipped excludes, in the rig's rules and their allow
  lists, and for the test-only edges of D146.
- The finding and the skill `relocate-tests` move test code into the `tests/` directory of the code it tests:
  `tests.rs` becomes `tests/mod.rs` under the same declaration, a large set splits by the behavior it verifies into
  files inside `tests/`, and each new `tests/` gets its `architecture.yaml`.

## Rejected

- Keeping `tests.rs` as a second test position: the tests of a directory would have two places, and a growing
  `tests.rs` has to move once more.
- Reporting `#[cfg(test)] mod tests;` instead of the file: the same declaration loads `tests.rs` or `tests/mod.rs`, so
  only the file on disk tells them apart.
- Recognising Python tests by content, such as `def test_` functions: the runner selects files by name, and a test
  helper module without tests would escape.
- Relying on the shipped exclude alone to spare files inside `tests/`: a configuration without it would report every
  test file there as misplaced.

## Rationale

One test position per directory lets a reader, the rules and the test runner agree on test code through a single
pattern, and the skill names one move for every case. File names are what cargo's module files and pytest's
collection use, so the finding needs no guess about content.

## Consequences

A project with `tests.rs` files or Python test files beside its code gets one error per file until it moves them. A
Python `tests.py` or `conftest.py` is not reported. Delivery takes two phases with a mid-branch pin (D218): the
runtime that accepts Python for the kind is pinned before the repository configuration names `.py`, and until then
`init` keeps the kind's Rust extension so its output matches the rig (I023); the second phase drops `**/tests.rs`
from the patterns and the configuration together.
