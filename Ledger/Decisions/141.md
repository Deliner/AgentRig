# D141 — The unused-external finding names where the rule looked and waits for complete analysis

## Context

B100. D076 reports every declared external dependency that no scanned source imports as "declared external …
dependency is never imported: …". In the first voxel-rust run about ten dependencies, wgpu and winit among them, got
that finding although the code uses them: in the same run 4302 findings said no crate root could be analyzed, so the
references that name those dependencies were never resolved, and build.rs was outside the rule's selection. The
finding asked the user to delete needed declarations. The user's /goal of 2026-11-10 selected B100 with every other
Backlog card and left the choices to the executor.

## Chosen

The finding says that the dependency is not named in the files the rule reads, gives their number and the deepest
directory containing every selected directory, and offers two ways out: add the file that uses the dependency to the
rule's selection, or remove the declaration. The resolution pass keeps the issues that leave analysis incomplete apart
from disallowed-dependency findings: a reference the source inspector cannot model, a file it cannot read and a
reference the resolvers cannot resolve. When any selected file has such an issue, the rule reports no unused external
of either language. A crate root that fails to build reaches this through its files, whose references then have no
analyzed crate root.

## Rejected

Keeping the old text and only suppressing it: the remaining finding still points at deletion when the user is a file
outside the selection. Suppressing per language: a failure in one language rarely coexists with a correct unused
claim in the other, and the incomplete findings already block the gate, so the claim returns once they are fixed.
Recognizing incompleteness by its message prefix: the message is presentation, and the resolution pass already knows
which issues it produced for missing evidence. Naming the rule's include patterns instead of a root: the card asks
for the root, and the patterns can be long.

## Rationale

An unused claim is only true when every reference in the read files was resolved, so incomplete analysis cannot
support it. Naming the count and root tells the user where the rule looked, which turns a misleading deletion prompt
into the actual cause: a file outside the selection or a declaration nothing needs.

## Consequences

The finding stays on the feature owner, or `.` without one, with the same level and skill. While analysis is
incomplete the unused check is silent and the incomplete findings carry the failure; once they are fixed, stale
declarations are reported again. Disallowed-dependency findings and their D105 and D125 rules are unchanged.
