# D012 — Adaptive feature delivery plan

## Context

User-authorized delivery must support blockers, necessary prerequisites, planned follow-ups, instructions arriving during work, and finishing the last feature. D009's exactly-one-active consequence and fixed execution order cannot express these states. Its product-outcome contract and agent ownership of implementation remain appropriate.

## Chosen

Supersede D009's activity and sequencing rules with at most one active feature and pending, active, paused, and complete states. Keep stable feature IDs, use row order for priority, and record actual prerequisite IDs in Depends on. Preserve outcome-based Feature, User capability, and Acceptance sections; allow Delivery context and require it for paused and complete entries. Replace I009 with the revised executable plan contract. Extend D010's retained branches with a documented plan-only handoff and resumption sequence using existing Git operations.

## Rejected

Require an active feature after all work is finished, turn implementation steps into product features, silently shrink acceptance, merge unfinished product work to deliver a prerequisite, or build a second plan database or automatic manager agent.

## Rationale

The existing Markdown plan can represent changes in delivery intent while Git retains verified work. Validated dependencies prevent active or completed outcomes from claiming unfinished prerequisites. Agent judgment still owns product meaning, evidence, and VAC scope.

## Consequences

The checker rejects malformed rows, duplicate IDs or dependencies, unknown prerequisites, cycles, incomplete details, multiple active features, and active or complete features with unfinished dependencies. Paused delivery records its blocker, retained branch, and resume condition; completed delivery records acceptance verification. New work must have a current requirement, observed constraint, or user/authorized manager source. Technical difficulties can remain inside a VAC. Plan handoff commits carry no unfinished product code. Resumption reconciles current master and Plan without resurrecting stale states. D009's historical record and the existing memory layout remain intact.
