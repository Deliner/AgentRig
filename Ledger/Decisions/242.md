# D242 — One card per task in three directories, named by the queue key and a number

## Decision

A task has one card from idea to archive. The card is named by the queue key, 2 to 10 uppercase Latin letters that
`init` takes as `--key` and writes to `.agentrig/project.yaml`, `RIG` for the rig, and by a number one above the
highest that the three card directories hold. A card without materials is the file `KEY-N.md`; a card with materials is
the directory `KEY-N/`, which holds that file and only `assets/`, `results/` and `scenarios.md`. The first line of the
card is `# KEY-N — title`, and its sections stay Context, Proposal and Expected benefit.

The card lies in exactly one of `Backlog/` (agreed, not selected), `Plan/` (selected for execution) and `Archive/`
(delivered) in the memory directory and moves between them as the same file or directory with the same number; no index
lists the cards, and `init` creates the three directories. `Plan/` runs in ascending order of numbers, and an
`After: KEY-M, KEY-K` line under the heading puts a card after the cards it names, which exist and form no cycle. The
active card is the one whose number the current branch `feature/KEY-N-name` carries: the session start names it, and on
another branch it names `Plan/`. `just consent` records the cards in `Plan/` and holds while any of them stays there; with
an empty `Plan/` it refuses.

The delivery record of a card, its acceptance verification or, for a stopped card, its blocker, retained branch and
resume condition, lies in its `results/`, and `file-size` skips the `assets/` and `results/` of a card. In the rig,
`Backlog.md`, `Plan.md` with its selection log and cards, `Requests.md` and `Norms.md` are deleted, and each open task
keeps its Backlog card under its number as `RIG-N.md`; `Archive/Plan.md`, `Archive/Backlog.md`, their cards and
`Ledger/Assets/` stay as they are, and the memory check accepts them without reading them.

## Reasons

- B209 AC1 to AC9 require one card per task, the queue key, the file or directory form, the three directories without
  indexes, the numbers, the order by number and `After:`, the active card from the branch, consent by named cards and a
  migration that keeps the old archive in place.
- B209 Context: a task has two cards and two numbers, B205 and P198, B205 needed four service commits of six, and
  `Plan.md` weighs 36 KB with an empty table.
- B209 keeps the sections Context, Proposal and Expected benefit, while D012 requires that a paused delivery record its
  blocker, retained branch and resume condition and a completed delivery its verification, so the record lies beside
  the text in `results/`.
- D185: a project of an older rig updates by hand, so the memory check keeps no mode for the Plan and Backlog indexes
  outside the archive written before cards.

## Alternatives

- Keep the Plan and Backlog indexes beside numbered cards: one table to scan. Not applied: each move would edit an index
  as well as the card, the service work that B209 removes, and B209 AC3 rules out indexes of cards.
- Convert the old archive into cards: one layout for the whole memory. Not applied: B209 AC8 keeps the archive in place,
  and the conversion would rewrite its registries and the decision links into it without changing any behavior.
- Keep a `Delivery` section in the card: the record stays in one file. Not applied: B209 keeps the three sections, and
  the check would need a section that only some directories allow.
- Write the state of a card as a line in the card: the state stays visible inside the file. Not applied: the directory
  already gives the state, and two records of it could disagree.
