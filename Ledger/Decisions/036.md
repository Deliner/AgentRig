# D036 — Limit README and AGENTS.md size and width, and keep other Markdown out of Project

## Context

The user asked on 2026-10-26 for an immediate lint rule and skill limiting
Markdown files to 70 lines and 120 characters (Requests.md, part 2, items
5–7). The limit applies to README and AGENTS.md wherever they appear,
including project code, and not to Ledger. Other Markdown in Project is
forbidden; code may carry README files within the limits, or skills. The
skill states that a file which does not fit contains something superfluous.

## Chosen

Lint gains two rule kinds: line-width measures characters per line and
reports each line over the limit; forbidden-file reports every selected file.
The repository configures markdown-size (nonblank-lines, error above 70) and
markdown-width (line-width, error above 120) for README.md and AGENTS.md
outside Ledger, and markdown-placement (forbidden-file) for Markdown under
Project except README.md, AGENTS.md and SKILL.md. All three route to the
condense-markdown skill.

## Rejected

Count physical lines including blank separators, split or rename a file to
pass, exempt tables or links from the width limit, or add a Markdown-specific
rule kind instead of configuring generic measurements.

## Rationale

Nonblank lines are the existing size measurement, so the Markdown limit counts
content the same way as every other size rule. Generic kinds keep the limits
and the allowed names in reviewable configuration. Reporting each wide line
lets one repair pass fix the whole file.

## Consequences

Existing README and AGENTS.md files are condensed to the limits. Placement
binds when product code moves into Project; until then Project holds only an
allowed README. Consumer defaults do not include these rules yet; they
follow the initialization layout.
