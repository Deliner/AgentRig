# D093 — Keep B044's four higher-FP Tier-B candidates as norms, not rules

## Context

B044 (Tier B of the workflow Rust-review, agreed 2026-11-01) proposed five
candidate rules. AC2 `disabled-raii` is decidable from syntax and shipped as a
rule (D092). The other four are not clean syntactic signals at the gate's
near-zero-false-positive bar (D035):

- `unchecked-index`: a `[]` index expression that may be out of bounds.
- `toctou`: a filesystem check (such as `.exists()`) paired with a later use,
  leaving a time-of-check/time-of-use race window.
- `lossy-int-cast`: an `as` cast that silently narrows an integer.
- `sibling-cycle`: an import cycle between files in the same directory.

## Chosen

Keep all four as discipline norms, not `init` rules. No rule kind, repair skill,
executable oracle or pretend invariant is added, so the I020 delivery sets stay
balanced and only `disabled-raii` (D092) ships from B044. Cross-directory cycles
stay covered by the existing directory-architecture rule (D079); the remaining
three carry no automated check.

## Rejected

Shipping any of the four as a portable `init` rule. `unchecked-index` cannot be
flagged by the syntactic engine, which cannot tell a panicking `Vec`/slice/
`HashMap` index from a non-panicking `serde_json::Value` index that returns
`Null` — the dominant form in this repository, relied on deliberately — without
type inference (D059); a blanket rule would be almost all false positives.
`toctou` needs data-flow to pair a check with its later use across a race
window, which the engine does not provide (D059). `lossy-int-cast` needs the
source and target integer widths that only type resolution supplies to separate
a narrowing from a widening cast (D059); flagging every `as` would swamp the
legitimate widening and constant casts. `sibling-cycle` is syntactically
decidable — the analyzer already builds file-to-file edges — but Rust's module
system makes mutually referencing sibling files idiomatic (this repository's own
`structural_lint/languages` siblings cross-reference), and the directory-
architecture model intentionally treats a size-bounded directory as one cohesive
unit, detecting cycles only between directories on the dependency graph it
already builds (D079); flagging intra-directory cycles would be high false
positive and would contradict that committed model. Also rejected: enabling the
corresponding Clippy restriction lints (`indexing_slicing`,
`cast_possible_truncation`/`cast_sign_loss`) in the dev gate — they are
allow-by-default for the same reason the portable rule is rejected (they fire on
every index and every narrowing-capable cast), so adding them would import the
same false-positive problem, not solve it.

## Rationale

Each candidate either needs the type-resolving or data-flow frontend the engine
omits (D059) or, for `sibling-cycle`, is decidable but idiomatic and at odds
with the directory-as-unit model (D079), so each falls below the
near-zero-false-positive rule bar (D035). The dev-gate Clippy profile (D060) is
panic-risk-scoped and denies none of these; it is deliberately not broadened,
since the only Clippy lints that would cover them are the same high-FP
restriction lints rejected above. Recording the choice once prevents
re-proposing these as rules and keeps the delivered capability set minimal,
matching how prior feature families parked their higher-FP candidates as norms
(D071/D086/D087).

## Consequences

B044 ships one rule (`disabled-raii`, D092); the four norms carry no code, skill
or invariant and leave the I020 delivery sets balanced. The portable disciplines
they describe remain covered where an owner already exists — the directory-
architecture rule and `refactor-large-directory` skill for cross-directory
dependency structure (D079), and the `complexity-discipline` norm skill for
resource and panic care generally — while `unchecked-index`, `toctou` and
`lossy-int-cast` stay review disciplines with no automated gate on `init` or
before commit. Revisiting any as a rule requires the rejected type/data-flow
frontend (D059) or an explicit change to the directory-architecture cycle model
(D079). It supersedes nothing.
