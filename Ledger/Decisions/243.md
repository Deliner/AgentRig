# D243 — The reminder invariant checks the Plan guidance after compaction on a card

## Decision

After compaction, the oracle test of I007, `portable_reminder_schedule_retry_and_compaction`, checks that an edit of
the Plan card `Ledger/Plan/RIG-7.md` receives the `edit-plan` guidance, in place of an edit of `Ledger/Plan.md`, and
checks `Decisions.md` and `Invariants.md` as before. The predicate of I007 does not change.

## Reasons

- D242 deletes `Plan.md`, and the routes that `init` writes give `edit-plan` for `Plan/**` and `Archive/**` only, so an
  edit of `Plan.md` receives no guidance.
- I023 requires the rig's routes to equal those that `init` writes, except the differences that `rig_differences.yaml`
  lists with reasons.
- The test checks after compaction that the memory routes still give their guidance, and the Plan card is the file that
  the `edit-plan` route covers now.

## Alternatives

- Keep a route on `Plan.md`: the test stays as it is. Not applied: the route would name a file that D242 deletes, in
  `init` and in the rig.
- Drop Plan from the check after compaction: a shorter test. Not applied: the `edit-plan` route would lose the check
  after compaction that the test makes for the other memory routes.
