# D091 — Discard the best-effort process teardown on the attach-failure path

## Context

B043 (Tier A) delivery, dogfooding the new `discarded-result` rule (D090). In
`command_runner/jobs/process.rs`, `attach` binds a spawned child to its job
record; when that binding fails it must tear the child down before returning the
original attach error. It sends SIGTERM to the process group (D066), then calls
`child.kill()` and `child.wait()`, each returning an `io::Result`. Written as
bare `child.kill().ok();` and `child.wait().ok();`, these are exactly the
discarded-`Result` statements D090 flags — and D090's own rationale names this
cleanup pair as the legitimate case its justification escape exists for.

## Chosen

Keep the two statements as bare `child.kill().ok();` and `child.wait().ok();`,
each carrying a `// DECISION: D091` reference on the line directly above it. The
teardown is best-effort: the child may already have exited, so kill and wait may
fail for benign reasons, and the error worth surfacing is the attach error being
returned, not a cleanup outcome the caller cannot act on.

## Rejected

Propagating with `?`: it would mask the attach error that caused the teardown,
which is the failure that matters. `let _ = child.kill();`: the strict Clippy dev
gate (D060) rejects `let _ =` bindings on the library target. `drop(child.kill())`:
risks `clippy::drop_non_drop` and reads no clearer than `.ok()`. Logging the
cleanup failure: there is no logging sink on this path and a best-effort teardown
failure is not actionable.

## Rationale

The attach-failure path already owns the teardown through D066's process-group
signal; the `kill`/`wait` are a belt-and-suspenders reap whose outcome carries no
information the caller can use. Discarding it is the correct behavior, and a
justified `.ok()` records that intent at the site — the precise escape the
`discarded-result` rule (D090) provides, keeping it near-zero false positive.

## Consequences

`command_runner/jobs/process.rs` is an owner of D091; the two `.ok()` statements
stay justified and pass the gate. This is a context-specific choice — best-effort
teardown on an error path — not a universal license to discard a `Result`. If the
teardown ever needs to report a cleanup failure, D091 is superseded explicitly
rather than silently broadened. It supersedes nothing.
