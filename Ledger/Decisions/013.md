# D013 — Current recovery state

## Context

Fresh sessions and interrupted simulations or development need the current task, unfinished work, verification outcome, and next action without reconstructing the conversation. Plan describes product intent and Git stores completed VACs, but neither alone records the current handoff.

## Chosen

Keep one versioned Ledger/State.md snapshot with nonempty Focus, Workspace, Progress, Verification, Blockers, and Next action sections. Read it at session start and reconcile against Git and current contracts. Refresh it at meaningful boundaries and known interruptions within the relevant VAC, using the compact edit-state skill.

## Rejected

Copy the conversation, add a second Plan or VAC registry, update after every tool call, or treat the snapshot as an authoritative live state machine that cannot become stale.

## Rationale

A compact explicit handoff preserves the unfinished task and recovery step while existing Git and Ledger contracts remain authoritative. Structural validation catches incomplete recovery notes without pretending to verify their factual accuracy.

## Consequences

State records observed branch/revision and check results, distinguishes attempts from success, and grants no new authorization. Session context points to it even when reminder persistence fails. Abrupt crashes can leave stale notes; resuming agents inspect actual work before retrying. Branch handoffs reconcile the snapshot for the destination. This adds current working context alongside D008's durable memory and D011's commit-based VAC history.
