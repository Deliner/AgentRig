# D053 — Split delivered capabilities into universal and worker-local

## Context

The configuration `init` generates and this repository's live configuration are
maintained apart: the template is `init`'s code, while `.agentrig/*.yaml` and the
skills are repository files. Universal capabilities already drifted silently — the
`architecture` rule, the three markdown rules, the `condense-markdown` skill and
the structure route reached the repository before `init` shipped them, and no
check failed. The dogfooding audit required a manifest that fixes which
capabilities must exist on both sides and which exist only in the repository that
builds the worker.

## Chosen

Divide delivered capabilities into universal and worker-local.

- Universal, required in both the `init` delivery and this repository: lint rule
  kinds, skills, the memory hook routes and the structure route, and the check
  capabilities memory, lint, tests and tools.
- Worker-local, present only in the worker-building repository: the toolchain
  checks (build, formatting, Clippy, rust-test, Ruff, mypy, typos, Vulture) and
  the candidate/bootstrap/pin machinery (D051).

The division is executable data: `WORKER_LOCAL_CHECKS` names the worker-local
check capabilities excluded from the comparison. Invariant I020 asserts the
consistency predicate over the universal dimensions.

## Rejected

Compare raw native check kinds, which flags the repository's command-wrapped lint
and test checks as divergences although they deliver the same capabilities — the
repository must build the candidate before it can lint or test. Compare the whole
command catalogue, adding a dimension the universal set does not need because the
check capabilities already cover lint and tests. Leave the split in prose only,
which cannot fail when a universal capability drifts to one side.

## Rationale

A capability built for consumer projects must be realized here for AgentRig to
prove "good quality out of the box" by dogfooding; a capability only the worker
build needs must not be forced onto consumers. Fixing the division as committed
policy, with an executable manifest of the worker-local exceptions, lets one
invariant detect drift without re-flagging the worker's own build toolchain.

## Consequences

Invariant I020 compares the `init` delivery against the live repository across the
universal dimensions, excluding the manifest's worker-local checks, and names what
diverges and on which side. Adding a universal rule kind, skill or route to one
side fails the check until it reaches both sides or is declared worker-local. The
toolchain checks and the candidate/bootstrap/pin machinery stay in the repository
without failing the guard. This refines D025's portable-capability split with an
enforced boundary; project parameters — thresholds, paths and affected-test maps —
remain free.
