# D172 — Keep Plan card assets whole in Ledger/Assets

## Context

P128 produced files its Delivery depends on: the baseline tree of Project, the
tree and path map of the best variant v36, and the blind-test question and
stage 2 rubric whose hashes the frozen protocol cites. They existed only in
temporary session storage. The archived card reached the `file-size` limit of
500 nonblank lines, so its result names the five confirmed steps and the
journal instead of listing every v36 change. The trees have 714 and 750 lines.
On 2026-11-12 the user asked to keep these files in the project, in a separate
Ledger directory with a subfolder for each Plan card holding its additional
files, and chose to keep the trees whole with a file-size exclusion.

## Chosen

`Ledger/Assets/PNNN/` holds the asset files of Plan card PNNN: inputs and
results its Delivery cites that do not belong in the card text. The folder is
named by the Plan ID and stays in place when the card moves to Archive. The
repository `file-size` rule excludes `Ledger/Assets/**`, with a reference to
this decision in the lint configuration; every other rule keeps selecting the
folder. The first folder is `Ledger/Assets/P128/`.

## Rejected

Split each tree by top-level directories into files under the limit: the tree
is one `lint-tree` output, and the parts would have to be joined to be read or
compared. Store only the map and regenerate the trees: v36 is rebuilt by the
P128 bench, which stays outside Git. Raise the general limit. Keep the files
only outside the repository, where Git does not preserve them.

## Rationale

A stored tree is one artifact read and compared as a whole, like the lint rule
registry of D116. Its length measures the project it describes, not cohesion
of code or prose, so the size limit there signals no structural defect.

## Consequences

Card assets have no index row and no memory-check validation; the card's
Delivery links them. `Ledger/Assets` grows by one folder per card with assets
and remains under the directory-entries rule. Source and prose files keep
their size limits everywhere else in Ledger.
