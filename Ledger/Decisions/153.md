# D153 — The shared Clippy profile denies wildcard enum arms, `as` conversions and `#[allow]`

## Context

B103 under D151 revisits D107, which left out `wildcard_enum_match_arm` and the `cast_*` lints by the user's
decision of 2026-11-02 without a measurement. The lists of Rust bans of 2026-11-10 name a wildcard arm that absorbs
a new variant (II-11), a silent numeric `as` (II-18) and an `#[allow]` that outlives its finding (II-27). With Clippy
1.98.1 the three lints report 20, 12 and 4 sites in the rig. In voxel-rust with the `native` feature they report 6,
319 and 3; its `as` sites convert between integers and floats, narrow floats and read enum discriminants.

## Chosen

`PROFILE` in `Project/project_setup/clippy.rs` and the dev-gate argv add `wildcard_enum_match_arm`, `as_conversions`
and `allow_attributes`, so the shared profile denies 32 lints. For each lint a violating fragment fails
`just run clippy` and the profile passes after its removal.

- **Match arms.** Every match on an enum lists its remaining variants, own and foreign. `Command` in `command_line`
  splits into context-free variants, `Runner` for `command_runner` commands and `Configured` for commands run on a
  loaded configuration, so each dispatch is exhaustive and the unreachable "unknown scaffold command" error is gone.
- **Numbers.** A conversion that can fail uses `TryFrom` and propagates the error: a transcript offset, a digest
  length prefix, a response size and a report average. The structural lint measures counts, limits and diagnostic
  values as `usize`, the type its sources count in, so its seven count casts disappear with no conversion.
- **Suppressions.** The four `#[allow]` and the inner `#![allow]` of the console owner become `#[expect]` with their
  DECISION references. The `panic-path` violation text and the `justify-allow` skill tell an agent to write
  `#[expect]`.

## Rejected

Listing only the 13 matches on the rig's own enums: B103 AC1 requires foreign enums to be matched fully too.

`match_wildcard_for_single_variants` instead of `wildcard_enum_match_arm`: B103 names it only if AC1 is rejected.

`allow_attributes_without_reason`: a `reason` repeats the DECISION reference that D080 already requires.

Converting the structural lint's counts with `u64::try_from`: the counts come from `len` and `count`, so a common
`usize` type removes the conversions instead of adding an error path that cannot occur.

## Rationale

A wildcard arm, a silent `as` and an `#[allow]` each compile and pass tests while hiding a change: a new variant, a
value that no longer fits, a suppression with nothing left to suppress. Denying them makes the compiler point at every
affected site.

## Consequences

The configuration thresholds and the lint diagnostic's `actual` and `limit` are `usize`; their YAML and JSON forms do
not change. `allow_attributes` checks only outer attributes, so an inner `#![allow]` stays a review norm. Standard Rust
has no `From` or `TryFrom` from a float to an integer, so a project converts floats in one owner with a referenced
`#[expect(clippy::as_conversions)]` (D080). `init` writes the three lints for a new project; an existing `clippy`
command keeps its list (D132), and voxel-rust is repaired by its own work. D153 supersedes D107's exclusion of
`wildcard_enum_match_arm` and of numeric casts and the `#[allow]` form chosen by D107, D109, D127 and D129; the rest
of those decisions remains.
