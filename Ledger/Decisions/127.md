# D127 — Five type-aware Clippy lints join the dev-gate profile

## Context

B075 (from the Clippy triage `agentrig-research/clippy-triage.md`; selected by the user 2026-11-07, which leaves the
VAC order to delivery). With clippy 1.98.1, the gate's pin, a pedantic, nursery and restriction run over product code
without tests at master `c1935e4` fired 81 lints with 5,400 hits. D060 set the panic-risk deny profile and D107 added
five lints, one VAC each, proven by a violating fragment. Five of the 81 need type information a tree-sitter rule
cannot see and duplicate no AgentRig rule. At `52cfe55`, the delivery base, `string_slice` fired on 16 sites and
`iter_over_hash_type` on one; the other three fired on none.

## Chosen

The clippy command in `.agentrig/commands.yaml` denies `clippy::string_slice`, `clippy::iter_over_hash_type`,
`clippy::collection_is_never_read`, `clippy::read_zero_byte_vec` and `clippy::unchecked_time_subtraction`, one VAC
per lint, each proven by a fragment appended to the crate root that fails the catalog clippy and passes once removed.

For `string_slice` 15 sites slice no `&str`: `strip_prefix`, `get(..)` with `?` or an `Option` consumer,
`trim_start_matches` and `bytes()`. `text()` in `structural_lint/languages/measure`, the owner of tree-sitter
node-range slices, keeps its slice under `#[allow(clippy::string_slice)]` with this reference (D080); `utf8_text`
would return a `Result` to every caller. For `iter_over_hash_type` the `project_memory` Plan dependency graph becomes
a `BTreeMap`. The profile keeps running without `--all-targets` and stays this repository's dev-gate; `init` does not
ship it.

## Rejected

From the triage, with its reasons. `indexing_slicing`: 127 hits, none reachable, 16 false positives on
`serde_json::Value`, and `get` with unreachable error paths would complicate the code. `arithmetic_side_effects`: 78
guarded hits, mostly `row + 1`; checked operations everywhere add noise. `must_use_candidate`, `unnecessary_wraps`,
`similar_names`, `match_same_arms` and the micro-performance lints: annotation, API shape, naming or speed, not
defects. `default_numeric_fallback` and `integer_division`: intended behavior. `shadow_unrelated` and
`case_sensitive_file_extension_comparisons`: visible from syntax. `undocumented_unsafe_blocks`, `unused_result_ok` and
`allow_attributes`: duplicate `unsafe-justification`, `discarded-result` or the D080 justification, and
`unused_result_ok` contradicts D068. `filetype_is_file`: a false positive pointing the wrong way.
`missing_asserts_for_indexing` and `borrow_as_ptr`: hints on guarded or confined code. The cast lints,
`map_err_ignore`, `wildcard_enum_match_arm` and `allow_attributes_without_reason`: rejected by the user (D107).
`mod_module_files`: conflicts with the denied `self_named_module_files`. Zero-hit lints about locks, unsafe or panics
are covered elsewhere or have no target code. A second slice owner for `project_memory` in `shared/syntax`: one
justified owner suffices, and `get` keeps the remaining sites panic-free.

## Rationale

Each selected lint names a defect class the syntactic rules cannot decide: a panic on a non-ASCII byte offset,
run-dependent output order, collected findings never read, a read into a zero-length buffer taken for end of file and
a panicking time subtraction. The toolchain is pinned, so the two nursery lints cannot drift under the gate.

## Consequences

Slicing a `&str` in product code fails the gate outside `text()`. A `for` loop over a hash map or set fails, while
`collect()` from one is not seen. A write-only local collection, a zero-length read buffer and an unchecked time
subtraction fail too; a future subtraction is repaired with `saturating_sub` or `checked_sub` with context, since
`checked_sub(..).unwrap()` fails `unwrap_used`. Linux-only branches are not compiled on macOS and stay unlinted. It
extends D060 and D107 and supersedes nothing.
