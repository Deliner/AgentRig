# D145 — Rule kind `test-placement` reports a Rust test-only module file outside `tests.rs` and `tests/`

## Context

B091. voxel-rust declares 13 test files named `*_tests.rs` under `#[cfg(test)]`, two of them through `#[path]` as
`mod tests`. Every rule measured them as production code, so the project excluded `**/*_tests.rs` from 16 rules. The
shipped test exemptions of the rules are the paths `**/tests/**` and `**/tests.rs` and the items under
`#[cfg(test)]` or `#[test]` in the same file, following the Rust Book's inline `tests` module and rust-lang/rust tidy,
which keeps tests in `tests.rs` or a `tests/` directory. On 2026-11-10 the user chose that projects move to this
convention instead of the rig adapting to their file names; the /goal of the same day selected B091 with every other
Backlog card and left the choices to the executor.

## Chosen

A Rust-only policy kind `test-placement` with default level error, repair skill `relocate-tests` and the shipped
exclude `**/tests/**`, `**/tests.rs`. Each `mod` declaration without a body that carries `#[cfg(test)]`, including
`all(test, ..)`, or sits inside a test-only item of the same file yields one finding at the declaration line, unless
an enclosing inline module is named `tests` or a component of its `#[path]` value, or of its module name when it has
none, is `tests` or `tests.rs`. The symbol is the `#[path]` value, else the module name. The measurement reads only
the declaring file's syntax: a declaring file in test position is removed by the shipped exclude, and its plain
declarations resolve under `tests/`. Other rules measure the declared file as before. `init` ships the rule with the
other kinds, and this repository enables it in `.agentrig/lint.yaml`. The kind is delivered in two phases with a
mid-branch pin (D051), because the installed runtime must know a kind before the repository configuration names it.

## Rejected

Treating every file declared under `#[cfg(test)]` as test code and exempting it from the rules: it is the variant the
card rejects, and each rule would depend on a cross-file analysis of the module tree. Recognising test files by a
name such as `*_tests.rs`: names are project conventions, and `#[path]` hides them. Reporting the declared file
instead of the declaration, or resolving it on disk to print its exact path: both need the module tree, while the
gate that makes the file test-only and the fix both sit at the declaration.

## Rationale

File position is the one place where cargo, the shipped excludes and a reader agree that code is test code. A finding
at the declaration names the cause, the declared file and the skill, so the project fixes the placement once instead
of excluding its own pattern from every rule.

## Consequences

A test-only helper such as `#[cfg(test)] mod fixtures;` outside `tests/` is reported as well; a module gated by a
feature such as `cfg(feature = "test-fixtures")` is not. `..` components are not resolved, so a `#[path]` that leaves
a `tests` directory through `..` is accepted. A configuration that drops the shipped exclude also measures the
declarations inside test files.
