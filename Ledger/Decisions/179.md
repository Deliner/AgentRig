# D179 — Branches go to the configured remote after a feature commit and after feature-merge

## Context

B130 asks that no feature branch be lost with the machine: the user chose to
push a feature branch after each of its commits as well as on merge. Until then
`feature-merge` merged into the base and kept the branch but pushed nothing, and
an agent could push only through `just scratch`, since `just write` refuses
`git push`.

## Chosen

- `git.yaml` gains the optional `remote`, the name of a Git remote, validated
  like a branch name so it cannot read as an option. Without it nothing is
  pushed. Init leaves it out; the rig sets `remote: origin`.
- After a successful merge, `feature-merge` pushes `refs/heads/BASE` without
  force and then `refs/heads/FEATURE` with
  `--force-with-lease=refs/heads/FEATURE`, each in its own `git push`. It prints
  the pushed branches. A refused push prints the branch, Git's error output and
  the exact retry command, keeps the merge and makes `feature-merge` exit 1.
- The new command `feature-push`, run by a generated `post-commit` hook, pushes
  the current branch with the same lease when `remote` is set and the branch has
  the configured prefix. The base and a detached HEAD, as during a rebase, are
  skipped. A refused push prints a warning with Git's error output and the retry
  command and exits 1, which Git ignores after a commit, so the commit stays.
- The lease expects the remote branch at the remote-tracking reference this
  clone last pushed or fetched, and absent when there is none.

## Rejected

One `git push` for both branches: a refused feature would leave it unclear
which branch failed, and `--atomic` would also hold back the base. Plain
`--force` for the feature: it overwrites a copy another clone changed.
Fast-forward only for the feature: every branch rebased by `feature-merge`
would be refused. Pushing from the shell hook itself: hook logic belongs to the
runtime (D015), and the hook would have to read `git.yaml`. A `remote` written
by init: the card keeps pushing a one-line choice of the project.

## Rationale

The lease lets a rebased feature replace its own earlier copy while a copy
changed elsewhere stays, and the base is never rewritten. Full reference names
cannot be mistaken for a tag of the same name. Separate pushes name each
unpushed branch with its own reason.

## Consequences

Remote branches are never deleted. Every commit runs one more runtime process,
which ends after reading the configuration when `remote` is absent. A project
initialized before this revision lacks the `post-commit` hook, and doctor
reports its hooks as changed until it has the generated one.
