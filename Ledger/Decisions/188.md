# D188 — skills live in `.agentrig/skills` and each agent reaches them through its own directory

## Context

On 2026-11-19 the user answered the open questions of B145: «источник истины – текущий сетап рига», the skills stay
in AgentRig's service directory with symbolic links in the Codex and Claude Code directories, and «в ошибках должны
быть абсолютные пути до скиллов… до конкретного скилла путь должен вести, а не просто на директорию со скиллами».
Before this, `init` wrote the skills to `.agentrig/skills` without agent links, the rig kept them behind
`.agents/skills`, the hook printed a skill with every link resolved, such as
`Project/shared/skills/memory/edit-plan/SKILL.md`, and lint and gate printed the configured relative path. A probe with
Codex and Claude Code showed that the hook input names no agent and that Codex hook processes get no Codex variables,
while commands run by Codex get `CODEX_THREAD_ID` and commands run by Claude Code get `CLAUDECODE=1`.

## Chosen

- `init` writes the skills to `paths.skills`, by default `.agentrig/skills`, and links `.agents/skills` for Codex and
  `.claude/skills` for Claude Code to it with relative symbolic links; a `--skills` path inside or around one of these
  directories is refused before writing.
- The rig's `.agentrig/skills` links to `Project/shared/skills`, its `.agents/skills` and `.claude/skills` link to
  `.agentrig/skills`, and its configuration names skills under `.agentrig/skills`.
- A message that names a skill, in a hook requirement, a lint or gate finding or a configuration error, gives the
  absolute path of that `SKILL.md` through the calling agent's directory without resolving links:
  `<root>/.claude/skills/edit-plan/SKILL.md` for Claude Code and `<root>/.agents/skills/edit-plan/SKILL.md` for Codex.
- The hook learns the agent from its registration: each client's registration passes `--agent codex` or
  `--agent claude-code`. Other commands read the agent's variable: `CODEX_THREAD_ID` names Codex, otherwise
  `CLAUDECODE` names Claude Code; with neither, the path goes through the configured skills directory. The root is the
  agent's working tree, also when the gate checks an exported tree.

## Rejected

| Alternative | Why |
| --- | --- |
| Copy the skills into each agent directory | the copies drift; the user asked for links |
| Print the path with links resolved | the agent gets a file outside its own directory; the user asked for the agent's link |
| Print the skills directory instead of the `SKILL.md` | the user asked for the path to the specific skill |
| Detect the hook's agent from its input or environment | the input names no agent and Codex hook processes get no Codex variables |
| Keep `.agents/skills` as the rig's configured skills path | the rig is laid out like a project after `init` (B145) |

## Rationale

Each agent discovers skills in its own directory, so a path through that directory is one it already knows and can
open, and one installed copy behind links keeps a single source.

## Consequences

Projects set up earlier add the links and repoint their configuration by hand (D185). A skill outside the directory an
agent link reaches, or a project without that link, is printed as an absolute path under the root. Test processes run
without the agents' variables.
