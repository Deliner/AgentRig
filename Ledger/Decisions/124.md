# D124 — config-check reports affected-map gaps by the language its command runs

## Context

B077 (from the agent-error research; selected by the user 2026-11-07, which
leaves to delivery which files must select a check's tests). Four repairs in
two repositories fixed impact maps that silently skipped tests, and on master
`3a5bcf2` `Project/shared/console/**` and `Project/shared/mod.rs` reached
`rust-test` only through the catch-all group without targets. The gate treats
only a check without groups as unmapped, so a catch-all made every other gap
silent.

## Chosen

`config-check` inspects each check that has `affected` groups and whose
command argv runs a known test runner: an element named `pytest` makes it a
Python check, an element named `cargo` followed later by `test` a Rust check.
Other commands are not inspected. Among the gate inventory files with the
runner's extension, `.py` or `.rs`, matched against the groups by the gate's
own affected selection, it reports two errors through the configuration
repair skill with the `config-check` rerun:

- a file that matches at least one group and only groups without targets,
  because changing it selects no tests; the repair names a group whose
  targets exercise it, or `::` for Rust and `.` for pytest when its consumers
  are unknown;
- a test that no target of the check selects: a `test_*.py` file under no
  target path, the path part before `::`, resolved from the command's working
  directory; or a Rust file containing `#[test]` whose module prefix, derived
  from its path below the nearest ancestor holding `lib.rs`, else `main.rs`,
  neither contains a target nor is a prefix of one. A Rust file outside such
  a crate has no module prefix and is not reported.

A file matching no group is not a finding: the gate already runs the whole
command for it. The analysis is static; no test runs, and whether the chosen
targets really exercise a file is not judged. The check belongs to
`config-check` in `project_setup` and runs after the lint configuration
check; the exit code is the lint code when nonzero, else 1 on any finding.
The gate's group matching becomes one shared type that both the change
selection and this check use.

AgentRig maps `Project/shared/mod.rs` and `Project/shared/console/**` to
`::` in `rust-test`, and selects the consumer example
`Project/shared/testing/examples/python/application/test_sample.py`, which
the full pytest run collects, when the shared testing tree changes.

## Rejected

An explicit per-group or per-check declaration of the files that must select
tests: a second description of what the command already states, and one more
field that each consumer map would need to stay correct. Making such a field
required: it would break every existing consumer configuration under strict
loading. Reporting files that match no group: they are already safe. Reading
Cargo manifests for crate roots: the nearest `lib.rs` or `main.rs` fixes the
module prefix for the standard layouts, while the manifest reader serves
`init` and only adds path overrides that no repair needed. Placing the check
beside the affected selection in the gate: reading Rust files there would
make the gate a 21st dependent of `shared/fs`, over its budget of 20, while
`project_setup` already reads through it. Compiling the group globs again in
`project_setup`: a second copy of the matching, and a 14th dependent of
`shared/paths` over its budget of 13.

## Rationale

The command already names the language whose tests a check runs, so the
inference needs no configuration and applies at once to every consumer map.
Both reported shapes are silent: the gate passes while selecting nothing, the
way each repaired defect passed review.

## Consequences

A new source directory caught only by a catch-all, or a new test outside the
targets of its group, fails `config-check` before it reaches a commit.
Checks run through wrappers that hide the runner name stay uninspected. It
ships B077 in full; it supersedes nothing.
