# D092 — Flag a Rust call that deliberately defeats RAII

## Context

B044 (Tier B of the workflow Rust-review, agreed 2026-11-01). A handful of Rust
calls deliberately defeat RAII: a `tempfile` guard's `.keep()` or `.into_path()`
persists the temp dir/file instead of deleting it on drop; `mem::forget` skips a
value's destructor; `ManuallyDrop::new` suppresses it; `Box::leak` releases heap
to a `'static` reference. Each lets a resource outlive its owner with no visible
cleanup, which the complexity and error rules and the strict Clippy dev gate
(D060) do not catch. Whether a call is one of these is decidable from syntax — a
`call_expression` whose method `field` is `keep`/`into_path`, or whose
`scoped_identifier` function ends in `mem::forget`, `ManuallyDrop::new` or
`Box::leak` — with no type resolution (D035). The review flagged
`command_runner/jobs/storage.rs` persisting its job directory with `.keep()`.

## Chosen

Add a `disabled-raii` rule kind (target file, error level), Rust only, on the
existing `call_expression` dispatch (beside `panic-path` and `eager-fallback`).
The detector `disabled_raii` fires when the call's function is a method named
`keep` or `into_path`, or a `scoped_identifier` whose last two `::` segments are
exactly `mem`+`forget`, `ManuallyDrop`+`new` or `Box`+`leak`. A
`DECISION:`/`INVARIANT:` reference on the line directly above removes the finding
(justification mechanism, D065/D082); test code is excluded by `in_test_context`
(D082) and the delivered rule's `**/tests/**` and `tests.rs` excludes. The method
forms are matched by name, as `panic-path` matches `.unwrap()`/`.expect()`
(D082). Ships through `catalog::ALL` with a new `own-the-resource` repair skill,
so the rule-kind and skill sets both grow by one and stay equal (I020).

## Rejected

Resolving the receiver type to confirm `.keep()`/`.into_path()` is a `tempfile`
guard: the engine is syntactic with no type inference (D059), and the method
names are distinctive enough that flagging them by name with a justification
escape keeps the rule near-zero false positive, exactly as `panic-path` treats
`unwrap`/`expect`. Matching the `::leak`/`::forget` tail by suffix instead of an
exact segment pair: a `MyBox::leak` or an unrelated `.leak()` method would then
be flagged, so only the exact two-segment tails `mem::forget`/`ManuallyDrop::new`/
`Box::leak` and the two method names match. Flagging `drop(...)` or a bare
`let _ = guard;`: `drop` runs the destructor (the opposite of the smell), and
dropping a guard early is a different, higher-FP concern needing data-flow (D059).
Making it a norm the way an indexing/slicing panic path stays one: those
constructs are ubiquitous and need type inference to tell a panicking index from
a non-panicking one, whereas these leak calls are rare, explicit and almost
always deliberate, so they clear the near-zero-FP bar as a rule.

## Rationale

The five call shapes are fixed, syntactic signals meeting the type-free bar
(D035). They reuse the justification and `in_test_context` machinery on the
existing `call_expression` dispatch, adding only one detector and its skill, so
the near-zero-FP leak primitives ship as a rule while higher-FP resource concerns
stay norms.

## Consequences

A `.keep()`, `.into_path()`, `mem::forget`, `ManuallyDrop::new` or `Box::leak`
call in non-test Rust becomes a gate error on `init` and before commit; letting
the value drop, holding the guard, or recording a reference on the line directly
above, passes. `command_runner/jobs/storage.rs`'s deliberate `.keep()` on the
persisted job directory is justified with a reference during delivery. The
rule-kind set and the skill set both grow by one and stay equal across delivery
and repository (I020). It ships part of B044 (Tier B); it supersedes nothing.
