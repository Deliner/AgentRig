# D044 — Features without nested features declare an architecture type

## Context

D043 limited directory contracts to purpose, files and directories. On
2026-10-27 the user agreed B018: a feature without nested features declares an
architecture type in its contract, the type requires its parts, dependencies
between parts follow the type's scheme, and lint checks all of it. Composite
features have no type (Requests.md, "Архитектурные типы фич").

## Chosen

The directory-architecture rule takes an optional feature_root whose
subdirectories are features. An untyped feature is composite and its
subdirectories except tests are features; a feature without them must declare
type. Contracts accept type flat, layered, hexagonal, onion, clean or custom.
Each type except custom requires exactly its parts plus optional tests, and a
part may use only itself and inner parts. This supersedes D043's three-field
limit; D043's removal of allow, deny and public remains.

## Rejected

Optional parts; custom features declaring their own ordered parts; types on
composite features; hand-written dependency permissions.

## Rationale

The user's target layout recalls typed leaf features. Deriving dependency
direction from a named style keeps contracts free of per-directory permissions.

## Consequences

Every feature without nested features under Project declares a type; moving
code into hexagonal or other parts is separate work. The installed hook
validates lint configuration with the pinned runtime, so feature_root is
configured only after the pin includes it.
