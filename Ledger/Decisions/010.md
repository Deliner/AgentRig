# D010 — Retained feature branches

## Context

Concurrent feature development must not place development commits directly on master or integrate work against an outdated master.

## Chosen

Start each feature from master on a feature-prefixed branch. If master advances before integration, rebase the feature onto current master, verify it, create an explicit merge into master, and retain the feature branch.

## Rejected

Commit directly on master, flatten feature history, merge from an outdated base, or delete a merged feature branch.

## Rationale

The branch boundary isolates development, rebasing exposes integration conflicts before merge, and retaining both commits and the branch preserves provenance.

## Consequences

Agents use the feature-start and feature-merge recipes, direct master commits fail, and merged feature references cannot be deleted.
