# D106 — `shared/fs` owns filesystem access with errors naming the action and path

## Context

B057 AC2 (research arc, `coverage-map.md` step 6 "fs-context"; repairs 1 and 5), selected as P064
under the user's /goal of 2026-11-04. A bare `std::fs::x(..)?` returns an `io::Error` without the
path, so a failure surfaces as "os error 2" and the reader hunts for the file; AgentRig had 43 such
production sites across 38 files, four of which match `ErrorKind::NotFound` to treat absence as a
value. D105 gives the project a `disallowed` policy, so the owner that the policy points to had to
exist before AgentRig's own entries could be written (B057 AC3).

## Chosen

The leaf `Project/shared/fs` owns filesystem access for production code. It wraps each operation
the product performs (`read`, `read_to_string`, `write`, `open`, `open_with` for `OpenOptions`,
`create_dir_all`, `read_dir`, `metadata`, `symlink_metadata`, `read_link`, `set_permissions`,
`symlink`, `remove_file`, `remove_dir_all`) and returns `fs::Error { action, path, source }`:
its display is "<action> <path>", its source is the `io::Error` and `kind()` exposes the kind for
callers that treat absence as a value. `read_dir` yields entries whose errors carry the directory.
The handle and permission types callers need (`File`, `OpenOptions`, `OpenOptionsExt`,
`Permissions`, `PermissionsExt`) are re-exported by the owner. Production
code outside the owner uses the wrappers; tests may use `std::fs`. The wrapper keeps the name
`remove_dir_all`, so the recursive-deletion rule (D102) and the existing call-site justifications
apply unchanged, and the owner declares its dependents budget (D079) as the product's radius.

## Rejected

An anyhow context at each call site: 43 copies of one decision, which is exactly what was missing.
Wrapping `File` and `DirEntry` handles: handle operations are not path operations, and the
operations AC2 names are all path-addressed. Optional-read variants per absence site: one `kind()`
accessor serves the four sites. A trait over `Path`: an indirection without a second
implementation. Replacing `std::fs` in tests: tests exercise behavior and are exempt by the
`allow` globs of the policy.

## Rationale

One owner carries the one decision that was duplicated or missing everywhere, so every filesystem
failure the product reports names what it did and where (the agent-native goal of the research
arc), and the D105 policy can name a concrete replacement. The wrappers add a table of actions and
a `map_err`, not a second filesystem model (complexity-discipline, D059).

## Consequences

Filesystem errors raised by AgentRig name the action and the path. `shared/fs` is a declared hub
whose budget grows with each migrated feature. AgentRig's `lint.yaml` gains `disallowed` entries
for `std::fs` and `std::os::unix::fs` with `allow: [Project/shared/fs/**, '**/tests/**',
'**/tests.rs']`, and the gate holds the owner boundary. Supersedes nothing.
