# D096 — Flag process-global mutable state: a static lock or a public static cell

## Context

B052 (research arc of seven rounds, accepted form R2 of 2026-11-02; implementation
of all arc findings authorized by the user on 2026-11-04). A `static` holding a
lock (`Mutex`, `RwLock`, `DashMap`, `DashSet`, usually wrapped in `LazyLock`,
`OnceLock`, `Lazy` or `Arc`), or a `pub static` holding any interior-mutable cell,
is process-global mutable state with no owner in the directory tree: the
architecture map does not show it, every writer has to be found by search, and a
behavior change needs all of them. The same items are declared through
`lazy_static!` and `thread_local!`, whose bodies tree-sitter leaves as an opaque
`token_tree`. The form "lock or public cell" was selected on the research corpus
as near-zero false positive: a private `Atomic*`, `Cell` or `RefCell` is a
legitimate once-flag or counter and is not taken. AgentRig itself declares no
`static` items, so adoption produces no findings.

## Chosen

Add a `global-state` rule kind (target file, error level), Rust only, on a new
`static_item` dispatch in `rust.rs`, with the detector in
`languages/global_state.rs` because `rust.rs` is near the file-size limit. The
detector collects every `type_identifier` in the item's type, following `type`
aliases declared at the top level of the same file up to three levels, and
reports the item when a lock name is present, or when the item has a visibility
modifier and any cell name (the locks, `RefCell`, `Cell`, `UnsafeCell`,
`Atomic*`) is present; the finding's symbol is the item name. `static mut` is skipped (B046's form). For a
`lazy_static!` or `thread_local!` invocation the `token_tree` body is re-parsed
as Rust items after rewriting `static ref` to `static` and terminating an
unterminated single item, D094 style, and each `static_item` inside gets the same
check with lines mapped back to the file (an item inside a macro body resolves
no alias); a reference on the line directly above the item inside the body, or
above the macro for an item on the macro's first line, justifies it. Justification (D065/D082) and `in_test_context` (D082) apply;
the delivered rule excludes `**/tests/**` and `tests.rs`. Ships through
`catalog::ALL` with a new `own-the-state` repair skill, so the rule-kind and
skill sets both grow by one and stay equal (I020).

## Rejected

Flagging every static with interior mutability: a private atomic or cell is the
idiomatic once-flag or counter, and the corpus measurement put that form below
the near-zero-FP bar (D035), so only a lock or a public cell counts. Resolving
aliases across files or through the module tree: that needs the type and path
frontend the engine deliberately lacks (D059); top-level same-file aliases are
the accepted narrowness, and an alias declared elsewhere is simply not followed. Expanding
`lazy_static!` or `thread_local!`: the engine does not expand macros (D059);
re-parsing the literal body as items is a syntactic view, as D094 re-parses call
arguments. Treating `OnceLock` or `LazyLock` themselves as cells: a write-once
global holding an immutable value has no writers to find. Flagging `static mut`:
that unsafe surface belongs to B046's extension of D065. A configurable lock or
cell list: the sets are fixed by the accepted form, and a project-specific lock
type is justified by a reference like any other site.

## Rationale

The two shapes are fixed syntactic signals meeting the type-free bar (D035) and
were measured near-zero-FP on the corpus; they reuse the justification machinery
and the D094 re-parse approach, adding one detector file, one kind and one skill.

## Consequences

A static lock or a public static cell in non-test Rust, declared directly or
through `lazy_static!`/`thread_local!`, becomes a gate error on `init` and before
commit unless a reference on the line directly above justifies it; the repair is
to give the state an owner. Delivery is two-phase (D051): the inert kind, detector
and tests first, a mid-branch pin, then the live rule and skill. AgentRig's own
code has no static items, so dogfooding yields no findings. The rule-kind and
skill sets both grow by one and stay equal (I020). It ships part of B052; it
supersedes nothing.
