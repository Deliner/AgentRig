# D184 — Flags lowering lint levels after the `--` of a cargo clippy or rustc command need a reference

## Context

B136 under D151 and D183. The gate runs the `clippy` command of `.agentrig/commands.yaml`, init writes such a command
into every Rust project, and Clippy receives every item after its `--` as a compiler flag. D183 checks the four flags
lowering lint levels only in the `rustflags` list of `.agentrig/rust.yaml` and leaves command argv unread. A probe on
Clippy 1.100 on 2026-11-13 ran the gate's form `cargo clippy -- -D warnings -D clippy::panic -D clippy::unwrap_used`
on code with an unused variable, `panic!` and `unwrap`, appending one flag after `--`: `-A` or `--allow=` for the three
lints after the `-D` list, `--cap-lints allow` or `warn` and `--force-warn` in any position made Clippy exit 0. `-A`
before the `-D` list and `-A warnings` still hid the unused variable, which only `-D warnings` made an error. `-W` for
the three lints left three errors.

## Chosen

- `allow-justification` reports every item of a YAML `argv` sequence after its first `--` that starts with `-A`,
  `--allow`, `--cap-lints` or `--force-warn`, when the first item is `cargo` and `clippy` or `rustc` stands before the
  `--`, without a `DECISION:` or `INVARIANT:` reference on the line directly above the item.
- The same prefix list as the `rustflags` check decides which items lower lint levels.
- Init's rule template adds `.agentrig/commands.yaml` to the include of `allow-justification` beside
  `.agentrig/rust.yaml`, so a project with the shipped clippy command gets the check.
- The violation text and the skill `justify-allow` describe the command case. The kind stays unchanged, so no
  mid-branch pin is needed; the branch ends with the D051 pin.

## Rejected

| Alternative | Why |
| --- | --- |
| Reading every argv item regardless of the program | `-A` of `grep` and `--allow-dirty` of `cargo package` are not compiler flags |
| Reading items before the `--` | cargo, not the compiler, reads them |
| Parsing wrappers such as `env`, `sh -c` or a script | their argv has no fixed shape; B136 leaves them out |
| Reporting `-W` and `--warn` | under the gate's `-D warnings` they did not let the probe pass |
| Reporting a removed `-D` item | it needs a reference form of the command; B136 leaves it out |
| A separate kind for command flags | `allow-justification` already owns flags lowering lint levels and their repair |

## Rationale

A flag after the `--` of the gate's Clippy command lowers lint levels exactly as the same flag in the rig's list, so
one rule and one prefix list cover both places and the agent gets one repair. Requiring `cargo` first and `clippy` or
`rustc` before the `--` keeps the check on arguments that reach the compiler and away from other programs.

## Consequences

Supersedes D183's rejection of reading flags in `.agentrig/commands.yaml` argv and its consequence that flags in
command argv stay unchecked. A flag hidden in a wrapper, `-W`, `--warn` and a removed `-D` item stay unchecked.
