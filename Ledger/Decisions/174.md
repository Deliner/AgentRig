# D174 — init and doctor require the rig's Rust in Rust projects

## Context

D173 made the root `rust-toolchain.toml` the one source of the rig's Rust,
1.100.0. B128 AC6 asks `init --language rust` to require at least that version
in the project and `doctor` to report the same refusal, while init and doctor
never edit the project's Cargo.toml or toolchain file. D132 rejected pinning a
consumer's toolchain: a consumer project chooses its own.

The Rust a project's cargo uses is the one rustup selects in the project
directory, from its `rust-toolchain.toml`, an override or the default, so
`rustc --version` run there names it. rustc prints `rustc X.Y.Z (hash date)`,
with a suffix such as `-beta.3` or `-nightly` on a prerelease.

## Chosen

The runtime embeds the rig's `rust-toolchain.toml` at build and reads its
channel as the required version. `init --language rust` runs `rustc --version`
in the project root before it writes anything, or in its nearest existing
ancestor while the interactive wizard has not created the root yet, where
rustup selects the same toolchain. When no version is printed or it
is older than the required one, init refuses with the found version or its
absence, the required version and the update path: `rustup update` or a higher
channel in the project's `rust-toolchain.toml`. A prerelease suffix is ignored,
so a nightly or beta of the required version or later passes. `doctor` runs the
same check when a configured command's program is `cargo`, prints the found and
required versions and fails on the same refusal. Python projects are not
checked.

## Rejected

Write a `rust-toolchain.toml` or `rust-version` into the project: init and
doctor do not edit the project's toolchain or manifest, and a pin would remove
the consumer's choice kept by D132. Check `cargo --version`: the compiler
version decides which language and library features build. A build script that
exports the version: the same file read by `include_str!` needs no extra build
step. Compare prerelease suffixes: a nightly of the required version already
carries its features.

## Rationale

The minimum keeps the AGENTS.md list and lint hints of B128 valid in every
project the rig creates, while the project still chooses its toolchain at or
above it. One embedded file keeps the version in one place.

## Consequences

Changing the rig's channel changes the minimum for new and checked projects
with no other edit. A machine whose `rustc` is missing or older cannot
initialize a Rust project until it updates. This limits D132's free choice of
the consumer toolchain by that minimum; the rest of D132 remains.
