# D063 — Budget decision points per function; count a match as one

## Context

The user selected the code-quality set (clusters 1–8, B026–B033) on 2026-10-29
for dogfooded delivery. Backlog B029 sub-rule 4.3 asks that an overloaded
function be caught by the gate before review, purely syntactically, only on
Project, as a capability that ships to `init` (D053/I020). Rust and Python are
the supported languages. A first measurement that counted each `match`/`case`
arm put flat exhaustive dispatchers at the top (`descriptor` at 12, a configured
command at 11, a syntax `inspect` at 9) — functions a cleaner structure cannot
shorten — so an arm-counting threshold would only pass at a toothless value. On
2026-10-30 the user chose "match = одно ветвление": each `match` or `case` is one
multi-way decision regardless of arms.

## Chosen

Lint gains the branch-budget rule kind for Rust and Python at error level, a
finding when a function's decision points exceed 5. Each `if`, else-if and
ternary condition counts one, and each `match` or `case` counts one however many
arms it has; a nested function or closure body is measured on its own. The rule
ships to consumers through `catalog::ALL`, routed to the reduce-branching skill.
The threshold 5 is read from the worker's own option-B distribution — a dense
cluster at four and five decisions, a thin tail at six and seven — and brings the
four functions above it back to five or fewer by proper refactors.

## Rejected

Count each `match`/`case` arm separately, which punished the clearest form of
dispatch and forced the threshold above real overload; add a warning tier below
the error; set the threshold above the distribution knee merely to spare the
worker's own functions; or lower a flagged function's count through a helper that
takes a boolean, which D062 forbids.

## Rationale

The metric measures how many independent decisions one function carries. A flat
`match` states a single multi-way choice once, so counting its arms contradicts
"one decision" and would have needed a threshold too high to catch genuine
overload. Counting each `if`/else-if/ternary and each `match` as one keeps the
number aligned with the decisions a reader must hold. Threshold 5 sits at the
knee: it leaves the common four-and-five-decision functions alone and bites only
the over-branchy tail, so it is principled rather than weakened to pass. The
measurement stays syntactic, needing no type inference, which keeps the gate fast
(D035).

## Consequences

A function over five decision points becomes a delivery finding routed to
reduce-branching, in the worker repository and in every consumer. Four worker
functions were brought within budget by behavior-preserving refactors: the shell
guard classifies each character's role through a helper and dispatches on it, the
process executor decides group leadership and its side effect together, a
parametrized architecture test dispatches on its failure case with one `match`,
and the lint runner derives mode and command from one decision. Each fix stays
within the boolean-parameter (D062) and named-if-condition (D017) rules. The
reduce-branching skill joins a new `control-flow` skill group beside
flatten-nesting. With 4.1 (D061), 4.2 (D062) and 4.3 delivered, B029 (P036) is
complete.
