# D043 — Contracts describe only purpose, files and directories

## Context

D028 gave directory contracts allow and deny permissions for outbound
dependencies and public files for inbound ones, checked at every crossed
boundary. On 2026-10-26 the user stated that allow, deny and public are not
needed: a contract holds only the meaning of its directory, its files and its
subdirectories, and does not list itself (Requests.md, "Состав архитектурных
YAML"). Code without dependency cycles remains required (Requests.md, part 2).

## Chosen

architecture.yaml accepts only purpose, files and directories, and the contract
file needs no files entry. The rule reports invalid or missing contracts,
inventory mismatches, incomplete analysis and directory cycles in measured
dependencies; forbidden-dependency and private-access findings are removed.
This supersedes D028's permission and public-boundary checks; its
directory-owned contracts and measured cycle graph remain.

## Rejected

Keep the fields as optional extras; keep listing each contract in its own
inventory.

## Rationale

The user's target layout uses contracts to describe ownership, and cycles are
the dependency constraint they require.

## Consequences

Contracts that still contain allow, deny or public fail as unknown fields.
Resolver tests prove that an edge is measured by closing a cycle instead of a
forbidden finding. Architecture types of leaf features are recorded in
Requests.md and not implemented.
