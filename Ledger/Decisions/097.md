# D097 — Extend silent-error to Rust: collapsed read_dir chains and Err arms that answer a verdict

## Context

B049 (cross-project review `wf_f2a6f63a-7ff` of 2026-11-01; AC2 added on
2026-11-04 from the research arc's coverage map, form "silent-err-arm (b)";
implementation of all arc findings authorized by the user on 2026-11-04). D069
shipped the Python half of the silent-error discipline (`except: pass`) and left
Rust without a counterpart; D090 took the bare `.ok();` statement and explicitly
left the general `Err(_) =>` arm a norm because it is high-FP. Two narrow Rust
shapes are syntactically unambiguous swallows: a directory walk rooted at
`read_dir(..)` whose `Result<DirEntry>` stream is collapsed by `.flatten()`,
`.into_iter().flatten()`, `.filter_map(Result::ok)`, `.filter_map(|e| e.ok())` or
`.map_while(Result::ok)`, so an unreadable directory silently reads as empty; and
a `match`/`if let` arm `Err(_)`/`Err(..)` whose body is `Ok(false)`, `Ok(true)` or
a `return` of one inside a function whose declared return type is literally
`Result<bool, …>`, so a failed check silently becomes the answer "no" or "yes".
The arc measured both forms near-zero false positive. AgentRig's own code walks
directories with `entry?` everywhere and has one verdict arm,
`change_delivery/git/mod.rs` `merged_reference`, where an unresolvable branch tip
answered `Ok(false)` and permitted the deletion (B062 AC1).

## Chosen

Extend the existing `silent-error` kind to Rust instead of adding a kind: the
Rust handler lists `Kind::SilentError`, the repository rule gains `.rs`, and the
descriptor describes the three Rust forms next to the Python one. The detector
lives in `languages/silent_error.rs` (rust.rs is near the file-size limit) on the
`call_expression`, `match_arm` and `if_expression` dispatches. A chain is rooted
when, after stripping `?` and `.into_iter()`, the receiver is a call whose callee's
last segment is `read_dir` (`fs::read_dir(p)`, `std::fs::read_dir(p)`,
`read_dir(p)`, `path.read_dir()`); the finding's symbol is the collapsing method.
An arm matches when its pattern text is exactly `Err(_)` or `Err(..)` (a guard
makes it another pattern), its body is `Ok(<bool literal>)`, `return Ok(<bool>)`
or a block holding only one of those, and the nearest enclosing `function_item`
(a closure in between ends the search) has a `generic_type` return whose last
path segment is `Result` and whose first type argument is the primitive `bool`;
the finding's symbol is the function name. Justification (D065/D069) on the
line directly above the chain or the arm and `in_test_context` (D082) apply.
Delivery is two-phase (D051): the stable binary validates a rule's extensions
against handler support, so the handler change is pinned before `.rs` enters
`lint.yaml`. The `handle-error` skill gains the Rust repairs (iterate with
`entry?`, propagate the error instead of answering a verdict). Dogfooding makes
`merged_reference` fail-closed: a Git error while resolving the tip propagates
and the deletion is not permitted, fixed by invariant I021.

## Rejected

A new `rust-silent-error` kind: the category (a silently swallowed error), the
level and the repair skill are the same, and a kind already spans languages
(D074). Flagging the general `let Ok(x) = … else { return … }`, an `Err(_)` arm
with any other body, `unwrap_or(default)` or `walkdir`-style chains: idiomatic or
flow-dependent, above the near-zero-FP bar (D035), so the general arm stays the
norm D090 left it. Chains rooted at `.unwrap()`/`.expect()`: the panic is already
panic-path's finding (D082). Resolving a return-type alias (`type Flag =
Result<bool>`): that needs the type frontend the engine lacks (D059); the
literal `Result<bool, …>` is the accepted narrowness. Arms inside closures:
their value belongs to the closure, not the function's verdict. Excluding
`**/tests/**` by path for the shared rule: it would narrow the Python half; Rust
test code is excluded syntactically.

## Rationale

Both shapes are fixed syntactic signals measured near-zero-FP on the arc corpus,
they close the Rust gap D069 left with the same kind, skill and justification
mechanism, and they add one detector file and no new kind or skill.

## Consequences

A collapsed `read_dir` chain or a verdict-answering `Err` arm in non-test Rust is
a gate error in this repository and in consumers' `init` configurations unless a
reference on the line directly above justifies it; the repair is to handle or
propagate the error. The rule-kind and skill sets are unchanged (I020).
AgentRig's only site becomes fail-closed: an unresolvable feature-branch tip now
rejects the deletion transaction instead of permitting it (I021). It ships part
of B049; it supersedes nothing.
