# D052 — Directory contracts live only in the Project source tree

## Context

The architecture rule selected the whole repository (`.` and `**`), so every
directory carried an architecture.yaml: memory under Ledger, configuration under
.agentrig, launchers and verification under tooling, the Just groups, and the
VCS and editor directories. Only the Project source tree has measured Rust and
Python dependencies and feature types; the memory checker never validated these
contracts. The user directed that architecture.yaml exist only under Project and
nowhere else.

## Chosen

Scope the architecture rule to `Project` and `Project/**` with `feature_root:
Project`, and delete every architecture.yaml outside Project. A new directory
under Project still needs its contract; directories elsewhere do not.

## Rejected

Keep repository-wide contracts, which maintain empty-purpose inventories for
trees with no measured dependencies; add a second narrower rule, when no second
behavior is required; move the inventories into READMEs, duplicating what the
lint already derives from the tree.

## Rationale

A directory contract pins ownership and the acyclic dependencies of measured
source; non-source trees have neither. Confining contracts to the source tree
keeps the inventory where it carries meaning and removes maintenance of
contracts that only restate a directory's name.

## Consequences

Lint analyzes only Project directories. Decisions application links that pointed
to removed contracts (D038, D039, D041, D042) migrate to surviving owners.
Plan rotation, edit-plan and develop-tools no longer mention architecture
inventories outside Project. The flat-memory size exemptions D029, D030 and D048
keep their effect; their architecture-validation clause no longer reaches Ledger
registries. This narrows D028's application to the source tree; D028's statement
and measured-cycle graph remain.
