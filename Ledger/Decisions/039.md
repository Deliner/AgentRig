# D039 — Keep Just recipes in grouped files under just/

## Context

The user stated on 2026-10-26 that all commands go through Just, but instead of
one large justfile the recipes live in a separate directory of files grouped by
meaning (Requests.md, part 1, item 10; part 2, item 2). After initialization a
repository has Ledger, the configuration directory, the Just files directory
and Project (part 2, item 4). Just finds only a root `justfile` or `.justfile`,
and an imported file's recipes run in the root directory with the root
settings.

## Chosen

The root `justfile` sets positional arguments and imports each group file from
`just/`; it holds no recipes. Each group file holds the thin recipes of one
responsibility: `commands.just` (catalog listing and execution), `checks.just`
(gate and configuration checks), `delivery.just` (resume, report and feature
branches), `lint.just` and `jobs.just`. init writes the same layout for
consumers. This repository adds `development.just` for bootstrap, candidate and
release, and its commands group keeps read, write and test.

## Rejected

One justfile; one file per recipe; Just modules (`mod`), which namespace
recipe names and change the working directory; a configurable recipe
directory; a hidden directory name.

## Rationale

Imports keep every recipe name and invocation unchanged while each file states
its responsibility. The root entry is required by Just's discovery. A fixed
directory needs no configuration, and a visible name matches the requested
layout of directories an agent reads.

## Consequences

Decision links to recipes point at group files, which are non-source like the
justfile. Hooks and the shell guard are unaffected because they never parse
recipes.
