# D215 — Compare decisions and invariants with the fork from the base

## Context

The bypass audit of 2026-11-19 (B158, group E) found that the memory history check of D020 compares memory only with
the parents of the checked revision or with `HEAD`. A decision text changed by an earlier commit of the branch, for
example one made without the hook, is already the parent's text, and at `feature-merge` the worktree equals `HEAD`, so
the change reaches the base unchecked (E5). An invariant's predicate, its oracle in `oracles.yaml` and the test that
enforces it can change freely, although norm-or-choice asks to change a predicate together with its decision and tests
(E6). B158 asks that both be refused relative to the base at commit and at `feature-merge`, and that an invariant change
pass when the same branch adds a decision introducing it.

## Chosen

- `history::check` also compares memory with the fork: the `git merge-base` of the configured base branch and the
  checked revision, or `HEAD` when the worktree or the index is checked. Without the base branch or a common commit it
  compares only the parents or `HEAD`, as before.
- Each decision recorded at the fork keeps its statement and detail, as D020 requires for parents.
- Each invariant recorded at the fork keeps its index statement, its detail, its `oracles.yaml` entry and the text of
  the functions marked with its ID in the linked test file. A difference or a removal is refused, naming the invariant
  and the base, unless a decision absent at the fork names the invariant ID in its statement.

## Rejected

- Checking every commit of the branch: an intermediate change that a later commit reverts never reaches the base, and
  one comparison with the fork judges what the merge brings.
- Approving invariant changes with `just approve`: an invariant change is product work that the agent delivers with
  the decision that explains it, and B158 lets it pass that way.
- Requiring the new decision to link the invariant under Applies in: those links name the code that applies a choice,
  and decisions already introduce invariants by naming their IDs in the statement.
- Comparing the whole linked test file: a change of another test in the same file would then need a decision.

## Rationale

The base holds what was accepted, so the fork is the one point that judges the whole branch at any depth, and reading it
costs one more Git tree. The function text is the part of the test that decides the predicate, while its position in
the file may move.

## Consequences

A rewrite of the base branch moves the fork; D204 lets only `feature-merge` advance the base inside catalog commands.
A test moved into another scope changes its indentation and needs a decision. Projects whose base branch does not exist
keep the parent comparison only. Checking a dirty worktree on the base itself compares it with `HEAD`.
