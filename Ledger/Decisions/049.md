# D049 — Lint warnings are shown only on request

## Context

Lint printed warning findings next to blocking errors in text and JSON output,
including the gate's lint check. Warnings exit 0 under D016, and the user
observed that agents ignore them, so they add output without changing work.
D017's consequences expected new defaults to expose existing debt visibly.

## Chosen

By default lint prints and serializes only error findings, including
configuration errors. The `--warnings` argument of `lint` restores warning
findings in text and JSON output. The gate's lint check uses the default.
Exit codes and thresholds are unchanged.

## Rejected

Remove warning thresholds from rules; convert warnings to errors; add a
configuration field for visibility; hide warnings only in the gate or only in
text output; change gate-level warning checks, which are not lint findings.

## Rationale

Filtering at the single output owner removes noise for every consumer without
changing measurement, policy or exit status. One explicit argument keeps the
existing debt inspectable when a person or agent asks for it.

## Consequences

Agents see only findings that block work. Warning thresholds remain valid
policy and are visible with `--warnings`. Tests that assert warning findings
request them explicitly. This supersedes D017's visible-by-default warnings.
