# D065 — Require a recorded reference above every Rust unsafe

## Context

The user selected the code-quality set (clusters 1–8, B026–B033) on 2026-10-29
for dogfooded delivery. Backlog B026 sub-rule 1.1 asks that an `unsafe` without a
recorded justification be caught by the gate before review, purely syntactically,
only on Project, as a capability that ships to `init` (D053/I020). Rust is the
only supported language with `unsafe`; Python has none. The worker's own `unsafe`
is eleven libc FFI calls in `command_runner/jobs`, none carrying a reason. The
repository already enforces a `DECISION:`/`INVARIANT:` reference convention for
comments (D037) through a shared marker parser.

## Chosen

Lint gains the unsafe-justification rule kind for Rust at error level, a finding
when an `unsafe` block or `unsafe` function lacks a `DECISION:` or `INVARIANT:`
reference comment on the line directly above it. It reuses the comment-reference
marker parser, ships to consumers through `catalog::ALL`, and is routed to a new
justify-unsafe repair skill. That skill joins a new `references` skill group
beside replace-comment — the two rules built on the reference marker — with a
top-level symlink alias, so the skills directory stays within its size limit.

## Rejected

Count `unsafe` without requiring a specific reason, which flags nothing a reviewer
can act on; accept any plain comment, which the existing marker convention already
supersedes; analyse soundness with type inference, which the syntactic engine
cannot do (D035/D059); route the repair to replace-comment, whose responsibility
is comments, not `unsafe`; add justify-unsafe as a sixteenth top-level skill,
which would breach the directory-size rule rather than pass it.

## Rationale

An `unsafe` block is an explicit soundness obligation, so requiring it to point at
a recorded decision or invariant makes the reason reviewable and reuses the
`DECISION:`/`INVARIANT:` convention (D037) and its parser, keeping the gate
syntactic and fast (D035). Rust only, because Python has no `unsafe` to justify.
Grouping justify-unsafe with replace-comment under `references` names one honest
responsibility — repairing source that must carry an owned reference marker — and
holds the real-directory count steady rather than weakening the size limit.

## Consequences

An `unsafe` block or function without a reference marker becomes a delivery
finding routed to justify-unsafe, in the worker repository and in every consumer.
The worker's eleven libc FFI `unsafe` blocks (macOS and Linux identity sampling,
process signal forwarding, process-group control) each carry a `// DECISION: D066`
reference. replace-comment moved into the new `references` group with a symlink
alias preserving its path; its hook routing is unchanged. With 1.1 delivered and
1.2 shipped (D064), B026's 1.3 remains.
