## User capability

Агент использует доступные возможности, свободно выполняет временные исследования и получает компактные результаты. Обвязка контролирует маршруты запуска и принимаемую структуру, очищает одноразки и сохраняет историю удалённых инструментов.

## Delivery

Активна с 2026-10-27 на feature/target-state. К4 использует общий механизм
[P021](../Archive/Plan/021.md). B015 и runner ревью удалены
([D033](../Decisions/033.md)): смысловую проверку К5 и К7 выполняет
исполнитель при приёмке.

Начальные правила, которые карточка требует определить до реализации, выбраны
исполнителем из действующих механизмов; пользователь меняет их конфигурацией
(К1, К3):

- Инструмент — файл репозитория с shebang или битом исполнения. Постоянные
  места — `tooling/**` и `.agentrig/hooks/**` (сейчас там все шесть таких
  файлов); временная область задачи — `.cache/scratch/<задача>/` вне Git.
- Базовые вызовы `just read` и `just write` принимают только настроенные
  программы и формы аргументов (для git — подкоманды, для остальных —
  запрещённые формы вроде `find -exec`). Оболочки и интерпретаторы с кодом
  в аргументах базовыми не являются; временный код запускается через общую
  операцию временного запуска.
- Задача — ветка фичи: записи запусков уже хранят ветку. Событие завершения —
  успешный `feature-merge`, который уже очищает задачи этой ветки. Прерывание,
  суммаризация и конец сессии завершением не считаются.
- Порядок: после merge сохраняется `results/` области задачи, затем удаляются
  остальные её файлы и журналы её временных запусков. Ошибка очистки
  сообщается с командой повтора; merge не откатывается.
