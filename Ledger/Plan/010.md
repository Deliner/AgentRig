# P010 — Recoverable configuration errors

## Feature

Remove the configuration-repair deadlock: an invalid agentrig.yaml currently prevents the hook from processing even the read and edit operations needed to fix that file. Report the underlying configuration failure accurately and provide a working recovery path independent of the broken command catalog.

## User capability

The user or agent can inspect the real configuration error, read the relevant file and repair it in place without manually disabling hooks, restoring the file from Git or losing unfinished edits. Once the configuration is valid, normal command routing and checks work again.

## Acceptance

- Missing configuration, malformed YAML, unknown fields and invalid command/check settings produce diagnostics that identify the file and actual cause, including the field or source location when available. Do not label every decoding failure as a missing file or a required legacy migration.
- Configuration loading failures leave a supported path for necessary read-only diagnosis and direct configuration repair, including ordinary agent file edits without a just write operation. This recovery path also works when the configured Just command catalog cannot load; merely changing the hook response is insufficient.
- Repair preserves unrelated files and unfinished edits. Recovery does not require git restore, a clean working tree, a valid copy of the broken configuration, disabling all hooks or a manual edit outside the agent session.
- Preserve the existing authorization and verification boundaries: configuration repair is not a blanket bypass for arbitrary commands, failed commit checks or merge gates. After correction, normal configuration validation and configured hook behavior resume without leaving a persistent bypass enabled.
- Behavioral regression coverage reproduces the failure through supported Codex and Claude Code hook event formats. Exercise malformed YAML, schema and semantic validation errors, the diagnostic read and corrective edit, and a subsequent successful normal operation. Verify that ordinary valid-config hook restrictions and commit/merge checks remain effective.
- Document the supported repair route and link actionable diagnostics to the canonical repair skill. Validate the installed-runtime recovery flow in a consumer fixture before considering the fix delivered.

## Delivery

Requested while P009 is active after the user reported the same deadlock in the voxel-rust project on AgentRig 0.3.0. Recovery there required restoring agentrig.yaml manually. The same failure also occurred earlier in this repository while editing command settings and attempting an unsupported root configuration package.

Reproduced on the current development candidate in an isolated temporary project: agentrig.yaml containing an unterminated YAML sequence makes both an exec_command read event and an apply_patch repair event return permissionDecision=deny with only the generic agentrig.yaml-required message. hooks::dispatch loads Context before routing either event; main's hook error response displays the outer error context and hides the decoding cause. This evidence establishes that the bug remains unfixed; no changes were made to voxel-rust.

P010 is pending after P009 by delivery priority and depends on the existing installed-runtime distribution capability P005. P009 remains active. Choose the smallest recovery mechanism that satisfies these outcomes; no new configuration format or general hook-disable mode is required.
