# P061 — recursive-deletion: `remove_dir_all` с владельцем или обоснованием

## Feature

[B055](../Backlog/055.md): новый вид правила `recursive-deletion` — вызов с последним сегментом
пути или именем метода `remove_dir_all` вне тестов без ссылки-обоснования прямо выше. Источник —
исследовательская дуга (`coverage-map.md` шаг 4, решение пользователя 2026-11-02 п. 1); реализация
авторизована пользователем 2026-11-04 (/goal). Исходный контракт — ревизия карточки B055 в Git.
Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: каждое рекурсивное удаление каталога либо выполняется владельцем
с проверкой границ, либо несёт записанное обоснование; `remove_file`/`remove_dir` не трогаются.
Навык ремонта `contain-the-deletion`. Наш код: два сайта `command_runner/scratch.rs:42,53`
получают строки-обоснования.

## Acceptance

Карточка **B055 (AC1, границы)**.
- **AC1** — `remove_dir_all(...)` (любой источник или метод) вне тестового контекста без
  обоснования → находка; с обоснованием — нет; внутри тел макросов — тот же обзор
  ([D094](../Decisions/094.md)).

Новый `kind:` → двухфазная доставка с мид-бранч пином ([D051](../Decisions/051.md)): источник →
пин → проводка (`catalog::ALL`, `lint.yaml`, навык в `assets.rs`, I020) → догфуд: обоснования на
двух сайтах, `just candidate lint` → 0 находок; живая проба. Пороги не ослабляются.
