# P043 — Зонирование модулей

## Feature

[B034](../Backlog/034.md): модуль помечается классом зоны из фиксированного набора, и
структурные правила применяются с интенсивностью этого класса. Первый кластер Набора II
(agent-native, переносимо на любое приложение); фундамент для зонозависимых правил следующих
кластеров. Исходный контракт — ревизия карточки B034 в Git; согласовано пользователем
2026-10-31 в составе набора C1–C10.

## User capability

Проект объявляет класс зоны модуля (напр. `pure`, `io-adapter`, `api-surface`, `hot-core`,
`test`); одно переносимое правило применяется с разными порогами/включённостью по зонам, так
что единый набор дисциплины ложится на любой домен. Граница зоны явная (модуль/каталог).

## Acceptance

Карточка **B034 (AC1–AC3)**, включая границы. AC1: класс зоны в архитектурном контракте,
фиксированный набор, неизвестный класс — ошибка `lint-config-check`. AC2: хотя бы одно правило
детерминированно меняет поведение по классу зоны, аддитивно — без ослабления действующих
порогов ([D035](../Decisions/035.md)). AC3: возможность уезжает в `init`
([D053](../Decisions/053.md)/[I020](../Invariants/020.md)); наш код зелёный (догфуд).
Расширение схемы `architecture.yaml` ([D043](../Decisions/043.md)) фиксируется отдельным
решением в первом VAC; что не чисто синтаксически — норма (norm-or-choice), без притворного
инварианта. Перечень классов и демонстрирующее правило выбирает исполнитель спайком (гейт
держится зелёным).
