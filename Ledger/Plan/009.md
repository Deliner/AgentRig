# P009 — Complete architecture maps and feature ownership

## Feature

Extend P006 contracts into complete, checked maps of directory and file responsibilities. Apply the policy to AgentRig itself and repair its structure around modules and cohesive features while preserving behavior and consumers.

## User capability

The user and agent find where changes belong through architecture.yaml: one line explaining the directory's purpose, explicit file responsibilities, a separate block describing child directories, and enforceable dependency/public boundaries. Projects compose modules and modules contain features. Each feature keeps the implementation, data, adapters and tests it owns together; shared capabilities remain with their actual owners and expose public interfaces.

## Acceptance

- Every directory in the configured architecture scope requires architecture.yaml, including directories containing only documentation, resources or child directories. Service, generated and third-party trees have explicit exclusions. Source-language extensions must not silently exclude files from inventory coverage.
- Extend the existing strict YAML format with files and directories mappings. purpose is a nonempty single-line explanation of the shared responsibility. files maps exact immediate filenames to nonempty descriptions of what belongs there; directories separately maps immediate child names to descriptions of their roles. Each child has its own contract. Register architecture.yaml itself. Keep existing allow, deny and public dependency semantics.
- Every in-scope file is registered at least once, in its own directory's files mapping. Every in-scope immediate child directory is described by its parent; a selected root needs no out-of-scope parent contract. Missing contracts/entries, stale or wrong-kind targets and invalid descriptions produce actionable findings. Document exclusions and symlink handling consistently with existing discovery. Wildcard inventories must not replace individual responsibilities.
- Inventory checks are language-independent. Actual dependency checks retain Rust, Python, JavaScript and TypeScript support, enforcing outbound permissions, private access, every crossed enclosing boundary and cycles in measured edges. Permissions do not create actual dependencies. Unsupported or unresolved forms report incomplete analysis, never verified absence of dependencies.
- Diagnostics identify missing entries or source edges/cycles, link the existing repair skill and provide the normal rerun command. Embedded and standalone lint agree. Configuration, discovery and format documentation explain expanded coverage and updating existing P006 contracts.
- Strengthen the canonical refactor-large-directory skill: inspect enclosing contracts and consumers; identify the responsible feature/module; colocate what it owns, including behavior tests; keep shared dependencies with their owners; repair direction through public interfaces; move complete responsibilities and update contracts and consumers. Separate build packages or onion layers require an actual need, not navigation alone.
- The skill rejects arbitrary folders for counts, generic shared dumping grounds, widening permissions or exclusions merely to silence findings, cycles hidden by reexports and unnecessary interfaces/layers. Linters check measurable structure and dependencies; semantic agreement between descriptions and implementation remains an agent/review responsibility.
- Enable the rule in AgentRig's checked configuration with explicit, justified scope/exclusions covering maintained source, tests, documentation and resources. Inventory the covered tree, inspect ownership and actual dependencies, and repair findings and misplaced responsibilities while preserving CLI, hooks, public interfaces and consumers. Documenting the existing tree alone is insufficient. Address analysis limitations actually encountered; do not hide unresolved local code as external or promise universal compiler analysis.
- Behavioral tests demonstrate valid inventories, missing contracts in source-free directories, missing/stale/invalid entries, exclusions and dependency/private/cycle findings. Existing four-language consumers and both binaries remain verified. The repaired AgentRig tree passes the expanded rule and affected behavior checks, followed by mandatory commit/integration gates. Retain the feature branch.
