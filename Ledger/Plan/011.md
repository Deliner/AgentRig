# P011 — Coordinated hooks and timely architecture guidance

## Feature

Extend the existing dispatcher, configured routes and canonical skills to deliver architectural guidance before relevant edits and combine overlapping hook requirements into one coherent response. Preserve the existing lint-to-repair-skill flow.

## User capability

The agent receives the relevant directory contracts and skills when changing code, ownership or architectural policy. Simultaneous reminders and guidance neither overwrite each other nor cause endless denials. Conflicts identify their sources and affected operation.

## Acceptance

- Before the first relevant code edit in a module, guidance requires inspection of enclosing architecture contracts, the behavior owner and existing consumers. Creating or moving files prompts an ownership assessment; editing architecture.yaml prompts responsibility and boundary assessment before blessing current placement. Define bounded repetition using the existing session lifecycle where sufficient.
- Guidance uses canonical skills and configured paths. Extend existing skills or introduce a distinct skill only for an independent responsibility. Ordinary file edits remain permitted without just write. Opaque shell writes receive honest scoped guidance; do not claim that paths alone reveal arbitrary interface changes or shell write targets.
- All applicable internal handlers contribute outcomes with source, reason, affected paths, skill references and whether the operation must stop. One dispatcher response retains all compatible requirements. Duplicate skills appear once with their reasons; different skills remain scoped to their corresponding files.
- A stopping outcome prevents the current operation without losing other guidance. Full complexity refresh precedes task-specific guidance. Results do not depend on handler registration order or terminate aggregation at the first reminder.
- Recognizable incompatible structured requirements produce an explicit conflict naming both sources, affected operation and corrective guidance. Do not silently choose the last handler or invent precedence. Arbitrary contradictions in natural-language skills are outside automatic detection; the agent must surface those when encountered.
- Retry behavior distinguishes delivered reminders from persistent violations. No endless reminder denial; actual violations remain checked. A delivered message or read event does not prove understanding. Preserve P010 diagnosis and repair when configuration or routing is invalid.
- Widening allow/public or exclusions and weakening checks are identified from the actual change and explicitly assessed in the existing review flow against the original responsibility and acceptance. Skill reminders alone do not validate policy changes. Semantic cohesion requires implementation review; lint enforces measurable inventories and edges.
- Completion guidance traces significant acceptance obligations to observed behavior and consumers. Architecture review assesses ownership, public boundaries, unnecessary abstractions and policy weakening from task contracts and code. Commit checks stay selective and integration checks remain full.
- Behavioral coverage includes duplicate skills, compatible skills on separate files, reminder plus guidance, full refresh plus architecture edit, conflicting requirements, handler-order independence, retry, persistent violations and configuration recovery. Verify supported Codex and Claude Code behavior and preserve memory routes and lint repair diagnostics.
- Group existing lint diagnostics for the same measured cause into one actionable message with one applicable repair-skill reference. Preserve affected paths, violated boundaries, severity and rerun guidance; do not merge unrelated findings merely because they reference the same skill. Use existing diagnostic data rather than a new cause-inference subsystem.
- Changes to hook behavior are covered by ordinary focused tests of its relevant interactions with existing handlers: reminder plus route, two skills, stopping outcome plus guidance, and retry. Extend the current test suite; no separate hook-testing framework or exhaustive combination generator is required.
- Keep implementation within the existing dispatcher/workflow and meaningful owners. No separate service, duplicate instruction registry or universal natural-language conflict engine is required. Document event-to-guidance sequences and limits.
- Limit these additions to diagnostic grouping and ordinary interaction tests. Do not add skill-read tracking, repetition-based error escalation counters or a separate agent-evaluation system. Use the existing reminder lifecycle for the required retry behavior rather than introducing those deferred mechanisms.

## Delivery

The user requested planning coordinated overlapping/conflicting hooks and preventive architecture guidance first, then improving AgentRig itself. Existing memory-path routes, periodic complexity reminders and lint repair messages are the starting mechanisms.

P010 precedes this feature so combined routing preserves configuration recovery. P012 subsequently applies this guidance to repository restructuring. This feature is pending; planning does not authorize starting implementation or establish verification evidence.

The user subsequently accepted only the simple additions: grouping diagnostics with the same cause and testing hook combinations in the ordinary test suite. Skill-read tracking, repeated-error counters and a separate agent-evaluation system were explicitly left out to avoid overcomplication. This narrows the additional ideas, without removing the previously requested dispatcher coordination and conflict handling.
