# P002 — Portable worker capabilities and setup

## Feature

Deliver lint and isolated review as reusable capabilities of the worker, with declarative project setup and shared installation/update ownership.

## User capability

The user configures a consuming project, runs worker setup and receives a ready environment. Review models, executors, roles, prompts, tools, contracts and visibility are project-configurable. The same linter can assess another project independently without installing worker files there.

## Acceptance

The repository overview, agent instructions and initialization templates correctly distinguish development of the worker from its consumer projects. Review runner, MCP, validator, hooks and standard skills are shipped with the worker; their existing behavior is preserved and the separate Project implementation is removed.

Lint has one rule/language implementation shared by worker and standalone CLI. The standalone invocation accepts a project root and explicit lint configuration, does not require setup, memory, hooks or MCP in that project, and leaves it unchanged. Its findings and severity agree with worker execution under the same policy.

worker.toml selects project capabilities and references separate lint/review configuration. Review supports configurable executors, reviewers, models, prompts, tools, contracts and visible files; unsupported capabilities/executors and invalid configurations fail clearly.

worker setup validates the declarations, prepares required assets/adapters/MCP configuration and runtime directories, and diagnoses required dependencies. Authentication is separate. Repeated setup preserves user changes and explicitly reports conflicts. Setup and upgrade share the existing manifest and ownership rules, including upgrade/rollback of enabled components without losing settings or memory.

Verify on a separate consumer: setup, real MCP review, repeated setup, changed configuration, upgrade and rollback. Independently verify standalone lint parity/nonmutation, isolation, reports, cleanup and preserved consumer content. Update guides/examples and remove obsolete instructions, pass the worker gates and integrate. Apply complexity-discipline throughout without weakening existing constraints or adding unsupported machinery.
