# P054 — Medium-находки повторного обзора: макросы, тест-контекст, сигналы, дренаж

## Feature

[B045](../Backlog/045.md): четыре находки уровня medium из повторного воркфлоу-ревью
(`wf_5e9ed727-485`, 2026-11-01). Две — поведение поставляемого линтера (видимость паттернов
внутри макросов; честное определение тест-контекста); две — робастность worker-рантайма
(управляемость сигналами между запусками; ограниченный по времени дренаж). Исходный контракт —
ревизия карточки B045 в Git; согласовано и выбрано на исполнение пользователем 2026-11-01
(«бери в работу и приступай»). Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: (1) правила `panic-path`/`eager-fallback-with-?`/`disabled-raii`
находят свой паттерн и когда вызов записан в теле макроса (`json!`, `format!`, `vec!`, …), эскейп
`// DECISION:`/`// INVARIANT:` сохраняется; (2) исключение по тест-контексту применяется только к
действительно тест-онли коду (`#[cfg(not(test))]` не глушит правила, `#[tokio::test]` распознаётся
как тест). Оператор worker получает: (3) worker остаётся завершаемым сигналами
(SIGINT/SIGTERM/SIGHUP) между выполнениями команд и после них; (4) выполнение команды возвращает
управление за ограниченное время и не повисает на отсоединённом потомке, держащем конец пайпа.

## Acceptance

Карточка **B045 (AC1–AC4 + границы)**.
- **AC1** — `panic-path`/`eager-fallback-with-?`/`disabled-raii` находят паттерн внутри тела макроса;
  `record.finished.unwrap_or(now()?)` в `json!(…)` без ссылки — находка `eager-fallback`, со ссылкой —
  нет. Граница движка (нет вывода типов, [D059](../Decisions/059.md)) сохраняется; FP от обзора тел
  макросов измеряется на репозитории, при неясности граница сужается (norm-or-choice).
- **AC2** — тест-контекст истинен только для настоящего тест-онли кода: `#[cfg(not(test))]` — не тест,
  `#[cfg(feature = "…")]` — не тест, `#[tokio::test]` — тест; закреплено негативными фикстурами по
  публичной поверхности линтера.
- **AC3** — worker управляем сигналами между/после выполнений команд (а не только при первом).
- **AC4** — `execute()` завершается за ограниченное время при отсоединённом потомке с удерживаемым
  пайпом; намеренно фоновые задания под AC4 не попадают.

AC1/AC2 меняют поведение существующих правил/детекторов → двухфазная доставка с мид-веткой бутстрапом
и финальным пином ([D051](../Decisions/051.md)) там, где это нужно stable-бинарю; это способ доставки,
не критерий. AC3/AC4 — поведение рантайма, проверяется поведенческими тестами worker. Приёмка заземлена
на near-zero-FP бар ([D035](../Decisions/035.md)); пороги не ослабляются, притворных инвариантов нет.
Наш код приводится к зелёному (догфуд).
