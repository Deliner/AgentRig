# P008 — Selectable agent harnesses

## Feature

Prepare client-specific agent environments from AgentRig's shared configuration, retaining the selected client's actual capabilities.

## User capability

The user describes a workflow with models, API/authentication references, skills, hooks, programs and MCP services, selects its agent harness, and receives the concrete configuration and resources needed by that client for project work and delegated execution.

## Acceptance

- Support Codex and the requested second client, provisionally interpreted as Claude Code pending clarification of the speech-transcribed name. Selection is explicit in project and delegate environment declarations.
- Shared declarations are translated into each client's required configuration, paths, resources and supported event/protocol forms through client-specific owners. Existing composition, provenance, setup preview, repeat installation and conflict handling apply to both.
- Model and API/authentication settings are mapped according to the selected client's capabilities. Secrets remain external references. Unsupported settings or hook semantics produce actionable diagnostics rather than silent omission or a claim of equivalent enforcement.
- Configured skills, hooks, programs and MCP servers actually work in each prepared environment. AgentRig's required gates, task contracts, isolation and validation remain enforced independently of model completion claims.
- Review and read/artifact/code delegation use the selected supported client and preserve exact inputs, validated outputs, reports, cancellation, recovery and workspace isolation. Shared runner responsibilities remain shared; client differences stay at their actual boundary.
- Independent consumers demonstrate setup/repeat setup, discovery of skills, actual hook execution, MCP use and real review/delegate runs with both clients. Record tested client versions and limitations. Existing Codex consumers and configured gates continue to pass.
