# P060 — tuple-as-record внутри обобщённого типа

## Feature

[B054](../Backlog/054.md): расширение правила `tuple-as-record` ([D088](../Decisions/088.md)) на
кортеж из трёх и более элементов с хотя бы одним примитивом/`String`/`&str` внутри обобщённого
типа (на любой глубине, в том числе под ссылкой) в позиции параметра или возврата. Источник —
исследовательская дуга (`coverage-map.md` шаг 4, решение пользователя 2026-11-02 п. 2); реализация
авторизована пользователем 2026-11-04 (/goal). Исходный контракт — ревизия карточки B054 в Git.
Порядок и границы VAC — за исполнителем.

## User capability

Потребитель получает из коробки: безымянная запись в `Vec<(String, u64, bool)>`/`Option<(…)>`/
`&[(…)]` в сигнатуре — находка; пары, кортежи без примитивов, псевдонимы и поля структур не
трогаются; форма D088 для верхнеуровневого кортежа не меняется. Навык `name-the-record`
дополняется.

## Acceptance

Карточка **B054 (AC1, границы)**.
- **AC1** — `tuple_type` внутри `generic_type` в параметре/возврате, ≥3 элементов, ≥1 примитив,
  без обоснования над объявлением → находка; два элемента, без примитивов, `type`-псевдоним, поле
  структуры — нет.

Изменение существующего детектора без изменения `lint.yaml` → ожидается только финальный пин
([D051](../Decisions/051.md)); decision, расширяющий D088, при доставке; догфуд
`just candidate lint` → 0 находок (в продакшн-сигнатурах таких кортежей нет); живая проба. Пороги
не ослабляются.
