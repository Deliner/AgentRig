Пользователь явно попросил крупное напоминание и правило: агент может редактировать файлы напрямую инструментами редактирования без операции `just write`. Действующее правило закреплено в [AGENTS.md](../AGENTS.md); здесь сохранено происхождение требования.

## Запрошенные направления и уточнения

1. **Архитектурный линтер — первым.** Реализовать в собственном линтере AgentRig. У каждой смысловой директории в проверяемой области должен быть простой файл с назначением, допустимыми и запрещёнными зависимостями и публичными/приватными границами. Проверять реальные зависимости и циклы. Решение должно быть максимально простым и применимым к нескольким языкам; согласованы Rust, Python, JavaScript и TypeScript. Исключения для служебных, генерируемых и внешних директорий задаются конфигурацией. Диагностика должна направлять к соответствующему skill. Усилить существующий skill разбиения больших директорий: осмысленные обязанности, направление зависимостей, публичный API, приватная реализация и сохранение потребителей. Механическое перекладывание файлов в произвольные A/B ради лимита не решает задачу. Контракт: [P006](Archive/Plan/006.md).
2. **Другие VCS — вторыми.** Сохранить Git и добавить как минимум одну настоящую другую систему с проверками на потребительском проекте. Выбрать любую доступную с наиболее простой достаточной интеграцией; пользователь делегировал выбор агенту. Цель — практически проверить расширяемую архитектуру. Предусмотреть подключение закрытой корпоративной реализации без публикации её кода и переписывания общих workflow. Arc упомянут как возможное будущее расширение, его реализация сейчас не требуется; предположение пользователя о его проприетарности не является проверенным фактом. Не смешивать поддержку VCS с хостингом GitHub. Контракт: [P007](Archive/Plan/007.md).
3. **Harness — третьим.** Поддержать Codex и именно **Claude Code** — пользователь уточнил распознанное голосом название. Из общего внутреннего описания workflow, моделей, API, skills, hooks, программ и MCP генерировать конкретную настройку выбранного клиента. Выбор harness должен определять нужный формат и размещение настроек. Общие обязанности остаются общими, реальные различия клиентов учитываются явно. Контракт: [P008](Archive/Plan/008.md).
4. Пользователь сначала хотел ответить на уточнения и затем отдельно дать команду реализации. Его ответы подтвердили Claude Code, собственный линтер, свободный выбор второй VCS и предложенные варианты. Ответы «Да, эти подойдут», «Да все так», «Подходит» не содержат самостоятельной спецификации; конкретика сохранена в указанных контрактах.
5. Последняя просьба: сохранить все замечания на диск и дать короткий промпт-цель для начала или продолжения разработки. Не терять уже выполненную работу и сверять план с Git перед продолжением.

## Уточнение об архитектуре и применении линтера к AgentRig

2026-09-07: согласовано продолжение [P009](Archive/Plan/009.md). В каждой директории
проверяемой области нужен architecture.yaml: одна строка общего смысла,
перечисление файлов с указанием размещаемых обязанностей и отдельный блок
назначения дочерних директорий. Линтер проверяет полноту покрытия директорий
и регистрацию каждого файла хотя бы в одном контракте; согласованное место
регистрации — контракт собственной директории. Сохраняются проверки реальных
зависимостей, публичных границ и циклов. Покрытие состава не ограничивается
языками исходников; исключения явные.

Организация: проект из модулей, модули из фич, внутри фичи всё, чем она владеет,
включая её тесты и адаптеры. Цель — узкий скоуп изменений и навигация агента.
Общий renderer для нескольких фич остаётся самостоятельным владельцем;
потребители обращаются к его API. Обязательные onion-слои и отдельные сборочные
пакеты ради навигации не нужны. Усилить существующий refactor-large-directory
и применить правило к AgentRig с исправлением структуры. Линтер проверяет
измеримые условия, агент и ревью — смысловое соответствие. Сейчас поручено
записать план и дать промпт-цель; реализация будет делегирована отдельно.

## Уточнение о локальном Claude и OpenRouter

2026-09-07: пользователь подтвердил локальную авторизацию Claude на
`admin@macbook.local`; отсутствие входа в SSH не означает отсутствия локального
входа. Затем разрешил локальный запуск Claude Code через OpenRouter, указав
соседний `3d-worker` как источник сведений о настройках. На счёте мало денег:
выбирать самую дешёвую доступную либо бесплатную модель для теста.
Справка 3d-worker ведёт к установленным общим skills; действующий ключ загружается
внешним credential helper, его содержимое в репозиторий не переносится.
Рабочее подключение и результаты сохранены в State и PORTABILITY.md.

## Исходное описание проекта от пользователя — 30 пунктов

1. AgentRig — переносимый комплект окружения для агентской разработки.
2. Реализован на Rust; первая платформа — Linux.
3. Опубликован на GitHub под лицензией MIT.
4. Релиз поставляет бинарники agentrig и agentrig-lint.
5. init создаёт окружение, включая интерактивную настройку.
6. setup подготавливает существующий проект по конфигурации.
7. Предварительный просмотр показывает изменения перед применением.
8. Конфигурация использует строгий YAML без TOML fallback.
9. Части конфигурации можно компоновать и переиспользовать между проектами.
10. Композиция проверяет конфликты, циклы и явные переопределения.
11. config-check проверяет конфигурацию, doctor — готовность окружения.
12. Настраиваются skills, hooks, вспомогательные программы и MCP-серверы.
13. Установка учитывает происхождение ресурсов, хеши и права файлов.
14. Обновление обнаруживает конфликты и поддерживает восстановление и откат.
15. Реализована миграция версии 0.2.0 → 0.3.0.
16. Память проекта хранит план, состояние, решения и инварианты.
17. Для редактирования файлов памяти предусмотрены специализированные skills и хуки.
18. Разработка организована через feature-ветки и проверяемые атомарные изменения — VAC.
19. Проверки перед commit и merge обеспечивают соблюдение правил.
20. Complexity discipline требует минимального решения без лишнего усложнения.
21. Just служит интерфейсом команд; файлы агент читает и редактирует напрямую.
22. Процессы учитываются по владельцу и рабочему контексту, предусмотрена очистка.
23. Линтер входит в AgentRig и отдельно работает на других проектах.
24. Каталог правил описывает настройки, применимость и поддержку языков.
25. Линтер поддерживает выбор областей, исключения, пороги, предупреждения и блокировки.
26. Проверяются размеры файлов и каталогов; Rust/Python — условия if, длина функций и параметры.
27. MCP-ревью конфигурирует tools и критиков; runner проверяет ответы и вычисляет итог.
28. Ревью использует Git snapshot, bubblewrap, машинный контракт и сохраняемые отчёты.
29. Делегирование поддерживает профили, режимы чтения, артефактов и кода, ожидание и отмену.
30. AgentRig развивается через закреплённую установленную версию; кандидат собирается и принимается отдельно.
